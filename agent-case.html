한 줄 요약: 나는 어떤 일꾼이었을까?두뇌 + 손발 + 튼튼한 구조 = AI 에이전트

AI 에이전트 11장 · 전체 흐름 →

  • 두뇌: 부탁을 이해하고 계획을 세웠어요. 반도체 내용을 정리하고, 문제가 생긴 원인을 추리했어요.
  • 손발: 컴퓨터 명령어, 파일 읽기·쓰기, 브라우저, GitHub·Netlify 도구를 직접 썼어요.
  • 튼튼한 구조: 백업, 검사, 기록(Git), 실패했을 때 다른 길 찾기예요.
🧒 비유: 두뇌만 있는 친구는 "숙제를 이렇게 하면 돼"라고 말만 해요. 손발이 있는 친구는 직접 숙제를 해 와요. 튼튼한 구조까지 있는 친구는 공책이 찢어져도 복사본이 있어서 다시 할 수 있어요.
01

부탁 알아듣기프롬프트 · 입구 검사 · 트랜스포머의 주목

처음 부탁: "반도체소자 노트 1~18을 초등학생에게 설명하듯, 수식과 그림을 쓰고, AI가 풀 수 있는 문제도 요약해 줘."

프롬프트 11장 · 프롬프트 → 에이전트 → 답변 →

사람이 AI에게 보내는 부탁 문장이에요.

🧒 비유: 식당에서 내는 주문서예요.

입구 검사 (가드레일) 10장 · 질문에 답하는 과정 →

AI는 부탁을 받으면 먼저 "할 수 있나? 빠진 건 없나?"를 확인해요. 폴더를 뒤져 보니 노트 파일이 없고 다른 PDF 하나뿐이었어요. 그래서 내용을 지어내지 않고 "노트 파일을 넣어 주세요"라고 먼저 물었어요.

🧒 비유: 요리사가 주문서를 보고 "손님, 재료가 없는데 어떻게 할까요?"라고 먼저 물어보는 것이에요.

트랜스포머의 주목 (Attention) 10장 · 생성형 AI 지도 →

지금 AI의 뼈대인 트랜스포머는 문장에서 중요한 단어끼리 연결해서 읽어요. "노트 1~18", "초등학교 5학년", "수식과 그림", "AI가 풀 문제 3~5줄"에 주목해서, 노트마다 같은 틀(쉬운 설명 → 수식 → 그림 → 현업 → AI)로 정리했어요.

🧒 비유: 긴 숙제 안내문에서 형광펜으로 중요한 부분만 칠하는 것이에요.
02

PDF 읽기API·SDK · 재시도 전략 · 페이지네이션

API와 SDK 2장 · API와 SDK →

API는 프로그램끼리 대화하는 약속, SDK는 그 약속을 쉽게 쓰게 해 주는 도구 상자예요. PDF를 그림으로 바꾸려고 pdf.js라는 도구 상자를 빌려 썼어요.

🧒 비유: API는 식당 메뉴판, SDK는 주문을 대신 넣어 주는 태블릿이에요.

재시도 전략 (Retry) 7장 · 재시도 전략 →

PDF를 읽는 길이 여러 번 막혔어요. 그때마다 방법을 바꿔서 다시 시도했어요.

시도결과다음 행동
기본 PDF 읽기 도구❌ 그림 변환 프로그램이 없음글자만 뽑아 보기
글자만 뽑기⚠️ 수식과 그림이 빠짐페이지를 그림으로 바꾸기
pdf.js 옛 버전❌ 프로그램이 멈춤최신 버전으로 바꾸기
pdf.js 최신 버전✅ 성공그림으로 읽기
🧒 비유: 문이 잠겨 있으면 같은 문을 계속 두드리지 않고 창문이나 뒷문을 찾는 것이에요.

페이지네이션 (Pagination) 2장 · 페이지네이션 →

노트는 모두 약 250쪽이었어요. 한꺼번에 읽으면 AI의 머릿속 책상(컨텍스트 창)이 넘쳐요. 그래서 4쪽씩 한 장에 모아 나눠 읽었어요.

🧒 비유: 두꺼운 책을 한 챕터씩 나눠 읽는 것이에요.
03

정리하고 검사받기출구 검사 · Eval · 회귀 테스트

출구 검사 10장 · 질문에 답하는 과정 →

답이 사람에게 가기 전에 한 번 더 검사하는 단계예요. "팩트체크해 줘"라는 부탁에 노트 원본과 다시 비교하고, 예제 계산 13개를 프로그램으로 처음부터 다시 계산했어요. 그러다 틀린 곳(GaAs 예제의 이동도 7500 → 8500, 답 136 A/cm²)을 찾아 고쳤어요.

🧒 비유: 시험지를 내기 전에 검산하는 것이에요.

Eval과 자동 시험 8장 · CI/CD와 Eval →

AI가 잘했는지 채점하는 시험을 Eval이라고 해요. 이런 자동 시험을 만들어 돌렸어요.

  • 검색 항목 81개가 모두 노트 안에서 강조할 위치를 찾는지
  • "depletion"을 검색하면 공핍층이 1위로 나오는지
  • 용어 70개의 이름표가 겹치지 않는지

회귀 테스트 8장 · 테스트 종류 →

고칠 때마다 예전에 되던 기능이 아직도 되는지("멱등성", "캐시" 검색 등) 함께 확인했어요.

🧒 비유: 새 블록을 쌓은 뒤 아래층 블록이 무너지지 않았는지 확인하는 것이에요.
04

웹사이트 만들기클라이언트·서버 · 인덱스 · 데이터 저장 · 캐시와 CDN

클라이언트와 서버 1장 · 클라이언트와 서버 →

클라이언트는 여러분의 브라우저(손님), 서버는 사이트 파일을 내주는 곳(주방)이에요. 반도체 노트 페이지라는 새 요리를 만들어 주방에 올렸어요.

인덱스 (Index) 4장 · 인덱스 →

홈 검색창이 "공핍층"을 빨리 찾도록 찾아보기 목록을 만들었어요(반도체 개념 81개 + 용어 70개). 띄어쓰기가 달라도("문턱전압" / "문턱 전압") 찾을 수 있어요.

🧒 비유: 두꺼운 백과사전 맨 뒤의 "찾아보기" 쪽이에요.

데이터 저장 4장 · 데이터베이스 종류 →

"이해했어요" 체크는 브라우저의 작은 서랍(localStorage)에 저장해서, 다시 들어와도 진도가 남아 있어요.

🧒 비유: 학교 사물함이 아니라 내 책상 서랍이에요. 그래서 다른 기기에서는 진도가 따로 보여요.

한 곳에 모으기 보너스 개념

용어집 데이터는 파일 한 곳에만 두고, 반도체 페이지와 홈 검색이 둘 다 그 파일을 읽게 했어요. 한 곳만 고치면 두 곳이 같이 바뀌어요.

🧒 비유: 반 친구 연락처를 공책 두 권에 따로 적으면 헷갈리죠? 한 권에만 적고 모두가 그걸 보는 것이에요.

캐시와 CDN 5장 · 캐시 → 5장 · CDN →

브라우저는 예전에 받은 페이지를 기억해 둬요(캐시). 그래서 "예전 화면이 보이면 Ctrl+F5"라고 안내했어요. 사이트 파일은 여러 창고에 미리 복사되어 있어서(CDN), 같은 파일을 다시 올리면 "새로 올릴 파일 0개"가 나오기도 했어요.

🧒 비유: 캐시는 자주 보는 책을 가방에 넣어 두는 것이에요. 빠르지만, 도서관 책이 새 판으로 바뀌어도 가방 속 책은 옛날 판이에요.
05

사고 수습하기동시성 · Git · 재해 복구 · 멱등성

동시성 문제 7장 · 락과 동시성 →

어느 날 새벽, 다른 작업자(다른 AI 세션)가 같은 파일을 예전 사본을 바탕으로 고쳐 올리는 바람에, 홈의 반도체 버튼이 덮어써져 사라졌어요.

🧒 비유: 두 친구가 같은 그림을 각자 복사해 색칠했는데, 나중에 낸 친구 그림만 게시판에 붙어서 먼저 칠한 색이 사라진 거예요.

Git: 코드가 머무는 네 곳 8장 · Git →

장소비유
작업 폴더지금 쓰는 연습장
스테이징"이거 저장할게" 하고 골라 둔 페이지
내 PC 저장소 (커밋)날짜와 메모를 붙여 일기장에 기록
GitHub (push)일기장을 학교 사물함에 보관

"git pull 먼저 하고, 고친 뒤 커밋해서 push해 줘"는 사물함에서 최신 일기장 꺼내 보기 → 고치기 → 기록하기 → 다시 넣기 순서예요.

재해 복구: RTO와 RPO 7장 · 재해 복구 →

RPO는 "사고가 나면 얼마만큼 잃어도 되나", RTO는 "얼마나 빨리 살려야 하나"예요. 고치기 전마다 백업을 만들어 둔 덕분에, 새 버전은 살리고 사라진 부분만 다시 넣어 금방 복구했어요.

🧒 비유: 게임의 세이브 포인트예요. 자주 저장할수록 조금만 다시 하면 돼요.

멱등성 (Idempotency) 7장 · 멱등성 →

같은 일을 두 번 해도 한 번 한 것과 결과가 같은 성질이에요. 복구할 때 바뀐 줄이 딱 필요한 6곳뿐인지 확인해서, 두 번 넣거나 남의 작업을 지우는 사고를 막았어요.

🧒 비유: 엘리베이터 버튼은 여러 번 눌러도 한 번만 와요.
06

이사하기서킷 브레이커 · 트레이드오프 · CI/CD · 웹훅과 폴링 · 타임아웃

서킷 브레이커 (Circuit Breaker) 7장 · 서킷 브레이커 →

예전 호스팅(Netlify)이 "무료 사용량(크레딧)을 다 썼어요"라며 배포를 거부했어요. 계속 다시 시도하지 않고 그 길을 끊었어요(자동 배포 끄기, 연결선 지우기).

🧒 비유: 집의 차단기(두꺼비집)예요. 전기가 너무 많이 흐르면 딱 끊어서 불이 나지 않게 해요.

트레이드오프 9장 · 모든 것은 트레이드오프 →

선택지얻는 것잃는 것
크레딧 다시 채워질 때까지 기다리기돈 0원그동안 수정 반영 안 됨
GitHub Pages로 이사 (선택)무료, 배포 제한 없음사이트 주소가 바뀜
유료 플랜주소 그대로매달 돈

CI/CD 8장 · CI/CD →

코드를 올리면 사이트가 자동으로 바뀌는 것(자동 배포)이에요. 지금은 push 한 번이면 1분쯤 뒤 사이트에 반영돼요.

🧒 비유: 편지를 우체통에 넣으면 우체부가 알아서 배달해 주는 것이에요.

웹훅과 폴링 2장 · Polling과 Webhook →

  • 웹훅: 일이 생기면 상대가 먼저 알려 줘요. GitHub에 코드가 올라오면 배포 서비스에 "새 코드 왔어!"라고 알려 주는 연결선을 설치했었어요.
  • 폴링: 내가 계속 물어봐요. 배포가 끝났는지 8~10초마다 "다 됐어?"라고 확인했어요.
🧒 비유: 웹훅은 택배 기사님이 "도착했어요" 문자를 보내 주는 것, 폴링은 내가 5분마다 현관문을 열어 보는 것이에요.

타임아웃 (Timeout) 7장 · 타임아웃 →

폴링을 끝없이 하지 않도록 "몇 번까지만 묻고 그만"이라는 한도를 정해 두었어요.

🧒 비유: "1시간 기다려도 안 오면 그만 기다리기"예요.
07

안전하게 일하기OAuth · 토큰 · 최소 권한 · 비밀 관리 · 사람 확인

OAuth 3장 · OAuth 2.0과 SSO →

비밀번호를 넘기지 않고 "이 앱이 내 계정을 써도 돼요"라고 허락만 해 주는 방법이에요. GitHub 연결 때 AI는 일회용 코드만 알려 주고, 승인 버튼은 사람이 직접 눌렀어요. 다른 서비스의 로그인과 비밀번호 입력도 모두 사람이 직접 했어요.

🧒 비유: 친구에게 집 열쇠를 주는 대신 "오늘 하루만 열리는 출입증"을 주는 거예요.

토큰 3장 · 쿠키, 세션, 토큰 →

허락을 받으면 생기는 디지털 출입증이에요. 컴퓨터에 저장되어 있어서 다음부터는 다시 로그인하지 않아도 돼요.

최소 권한 3장 · OAuth와 최소 권한 →

꼭 필요한 만큼만 허락하는 원칙이에요. 배포 서비스에 준 열쇠는 "읽기만 가능"하게 만들었고, 필요 없어진 뒤에는 지웠어요.

🧒 비유: 친구에게 현관 열쇠만 주고 금고 열쇠는 안 줘요. 놀러 오는 날이 끝나면 열쇠를 돌려받고요.

비밀 관리 · 민감한 정보 3장 · 민감한 정보 관리 →

코드를 공개하기 전에 비밀번호나 키가 숨어 있는지 전부 검사했어요. 개인 이메일이 공개 기록에 남지 않도록 비공개용 주소로 바꾼 뒤에 올렸어요.

🧒 비유: 일기장을 친구들에게 보여 주기 전에 비밀 페이지를 먼저 빼는 것이에요.

돌아보기: 더 잘할 수 있었던 점좋은 에이전트는 아쉬운 점도 솔직하게 말해요

  • 배포를 너무 자주 했어요. 하루에 10번 넘게 배포한 날도 있었어요(다른 작업의 배포도 섞여 있었어요). 무료 사용량을 바닥낸 원인 중 하나라서, 작은 수정은 모아서 한 번에 올렸어야 했어요. 🧒 과자 하나 살 때마다 택배를 시킨 셈이에요.
  • 확인을 너무 빨리 해서 착각한 적이 있어요. 페이지가 다 뜨기 전에 검사해서 "강조가 안 된다"고 잘못 본 적이 있었어요. 다시 확인하니 정상이었어요.
  • 사람이 로그인하는 중에 화면을 움직였을 수 있어요. 그 뒤로는 "알려 주시기 전까지 건드리지 않겠다"고 약속하고 지켰어요.
  • 덮어쓰기 사고를 미리 막지 못했어요. 처음부터 Git을 썼다면 없었을 사고예요. 그래서 지금은 "git pull 먼저" 규칙을 지켜요.
