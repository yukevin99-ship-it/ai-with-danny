## 엔지니어가 직면한 가상의 문제 1

**[Dropbox 파일 동기화팀]** 사용자의 노트북 파일이 클라우드에 제대로 올라가지 않는다는 신고가 들어왔어요! 파일 7개를 검사해요. 각 파일은 이름(`name`), 크기(`size`, MB), 상태(`st`), 실패해서 다시 시도한 횟수(`retries`)를 가져요. 상태는 4가지예요: `SYNCED`(올라감), `PENDING`(기다리는 중), `CONFLICT`(충돌), `FAILED`(실패).

```c
#include <stdio.h>
#include <string.h>

typedef enum { SYNCED, PENDING, CONFLICT, FAILED } Status;   // 0, 1, 2, 3
typedef struct { char name[16]; int size; Status st; int retries; } File;

File files[7] = {
    {"report.pdf",   3, PENDING,  0},
    {"photo.jpg",   40, PENDING,  0},
    {"notes.txt",    2, CONFLICT, 0},
    {"video.mp4",  300, FAILED,   3},
    {"song.mp3",     8, PENDING,  0},
    {"report.pdf",  12, PENDING,  0},   // 이름이 0번과 똑같아요!
    {"cat.png",      5, SYNCED,   0}
};
```

- **조건문 퀴즈 1:** `switch (f.st)`를 써서 파일 하나의 상태를 출력하세요. `SYNCED` → "동기화 완료", `PENDING` → 크기가 100MB **초과**면 "대용량: 와이파이 대기", 아니면 "업로드 대기", `CONFLICT` → "충돌: 사용자 확인 필요", `FAILED` → 재시도가 3회 **이상**이면 "포기: 관리자 알림", 아니면 "재시도 예정". (① 각 `case` 끝에 `break`를 빼먹으면 무슨 일이 생길까요? ② `video.mp4`는 300MB인데 왜 "대용량"이 안 나올까요?)
- **반복문 퀴즈 1:** 인터넷이 불안정해서 업로드가 자꾸 실패해요. `int ok[5] = {0, 0, 0, 1, 0};` (1이면 그 시도에 성공)을 보고, **`do`-`while`**로 재시도하세요. 실패할 때마다 기다리는 시간이 **1초 → 2초 → 4초 → 8초**로 두 배씩 늘어나요. 성공하면 `"시도 4: 성공! (총 7초 기다림)"`을 출력하고 멈추고, 5번 다 실패하면 `"5번 모두 실패: 나중에 다시"`를 출력하세요. (왜 `while`이 아니라 `do`-`while`일까요?)
- **흐름제어 퀴즈 1:** 오늘 남은 클라우드 용량은 **30MB**예요. 파일을 **배열 순서대로** 보면서 `PENDING`이 아니면 건너뛰고(`continue`), 크기가 남은 용량보다 크면 `"용량 부족: 이름부터 업로드 중단"`을 출력하고 멈추세요(`break`). 올리면 `"업로드: 이름 (남은 RMB)"`을 출력해요. 실제로 몇 개가 올라갈까요?
- **배열 퀴즈 1:** 이중 `for`로 **이름이 똑같은 파일 쌍**을 찾아 `"중복 이름: report.pdf (0번, 5번)"`처럼 출력하고, 마지막에 중복 쌍의 개수를 출력하세요. 문자열은 `==`가 아니라 **`strcmp`**로 비교해야 해요. (안쪽 반복은 왜 `j = i + 1`부터 시작할까요?)
- **포인터 변수 퀴즈 1:** 파일 이름에서 **확장자**(마지막 `.` 뒤 글자)를 찾아요. `const char *p`로 이름을 한 글자씩 보면서 `'.'`을 만날 때마다 그 위치를 `dot`에 저장해요(`dot = p;`). 다 돌고 나면 `dot + 1`이 확장자예요! 확장자가 `"mp4"`면 `"video.mp4: 동영상 -> 와이파이에서만"`, 아니면 `"report.pdf: 확장자 pdf"`처럼 출력하세요. `.`이 없으면 `"확장자 없음"`이에요.
- **구조체 퀴즈 1:** 상태 이름표 `const char *names[4] = {"SYNCED", "PENDING", "CONFLICT", "FAILED"};`를 만드세요. 포인터 `File *pf = &files[2];`로 `"notes.txt: CONFLICT (번호 2)"`를 출력한 뒤, `pf`로 상태를 `SYNCED`로 바꾸고 **`files[2]`를 직접** 출력해 `"notes.txt: SYNCED (번호 0)"`이 나오게 하세요. (`enum`의 정체는 뭘까요?)
- **함수 퀴즈 1:** 두 함수를 작성하세요. ① `void swap(File *a, File *b)`: 파일 두 개를 통째로 바꿔요. ② `void sort_by_size(File *arr, int n)`: **선택 정렬**(남은 것 중 가장 작은 걸 찾아 맨 앞과 바꾸기)로 작은 파일부터 정렬해요. 정렬 후 순서는?
- **흐름제어 퀴즈 2 (종합):** `main`에서 먼저 `sort_by_size`로 정렬하고, 남은 용량 **18MB**로 파일을 하나씩 처리해요. `switch`로 상태를 나눠요:
  - `SYNCED` → `"이미 완료: 이름"`
  - `CONFLICT` → `"건너뜀: 이름 (충돌 확인 필요)"`
  - `FAILED` → 재시도 3회 이상이면 `"관리자 알림: 이름"`, 아니면 재시도 수를 1 올리고 `"재시도 K회: 이름"`
  - `PENDING` → ⓐ 다른 파일 중 **이미 `SYNCED`이고 이름이 같은 것**이 있으면 상태를 `CONFLICT`로 바꾸고 `"이름 충돌: 이름 -> 충돌 사본으로 표시"`. ⓑ 아니고 크기가 남은 용량보다 크면 `"용량 부족: 이름부터 내일 업로드"`를 출력하고 **전체 반복을 멈춰요**. ⓒ 아니면 올리고(`SYNCED`) `"업로드: 이름 (SMB, 남은 RMB)"`.
  - 마지막에 `"오늘 업로드 N개, 남은 용량 RMB"`.
  - ⚠️ 함정: `switch` 안에서 쓴 `break`는 **`for`를 멈추지 못해요!** 어떻게 해결할까요? 실제 출력은?

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[스타벅스 사이렌오더팀]** 앱으로 들어온 음료 주문을 바리스타에게 넘겨주고, 가격을 계산하고, 주문 번호표를 뽑아 주는 프로그램을 만들어요. 주문 5개는 메뉴 이름(`menu`), 컵 크기(`size`), 에스프레소 샷 수(`shots`), 만드는 데 걸리는 시간(`mins`, 분), 취소 여부(`cancel`, 1이면 취소)를 가져요.

```c
#include <stdio.h>
#include <string.h>

typedef enum { TALL, GRANDE, VENTI } Size;   // 0, 1, 2
typedef struct { char menu[32]; Size size; int shots; int mins; int cancel; } Order;
typedef struct { char name[32]; int price; } Menu;

Menu menus[5] = {
    {"아메리카노", 4500}, {"카페라떼", 5000}, {"콜드브루", 4900},
    {"자몽에이드", 5700}, {"카라멜마끼아또", 5900}
};

Order orders[5] = {
    {"아메리카노",     GRANDE, 2, 3, 0},
    {"카페라떼",       VENTI,  3, 4, 0},
    {"자몽에이드",     TALL,   0, 5, 1},   // 취소된 주문
    {"콜드브루",       VENTI,  4, 6, 0},
    {"카라멜마끼아또", GRANDE, 2, 8, 0}
};
```

- **조건문 퀴즈 1:** 함수 `int calc_price(const Order *o)`를 만드세요. 기본 가격은 메뉴판 가격이에요(일단 `find_price(o->menu)`가 있다고 생각해요 — 구조체 퀴즈에서 만들어요). `switch (o->size)`로 `TALL`은 +0원, `GRANDE`는 +500원, `VENTI`는 +1000원을 더하고, 샷이 2개를 **넘으면** 넘는 샷마다 600원을 더해요. 5개 주문의 가격은? (`TALL`의 `case`에는 무엇을 써야 할까요?)
- **반복문 퀴즈 1:** 스탬프 12개를 모으면 무료 음료! 지금 스탬프가 **7개**예요. `for` 반복문 **하나만** 써서 12칸짜리 스탬프 카드를 4칸씩 3줄로 출력하세요(채운 칸 `★`, 빈 칸 `○`). 줄바꿈은 **나머지 연산자 `%`**로 정해요. 마지막에 `"무료 음료까지 5개 남음"`.
- **흐름제어 퀴즈 1:** 바리스타 한 명은 **20분**까지만 일할 수 있어요. 주문을 순서대로 보면서 취소된 주문은 `"취소된 주문: 메뉴 건너뜀"`을 출력하고 넘어가요(`continue`). 이 주문을 더하면 20분을 **넘으면** `"시간 초과: 메뉴부터 다음 바리스타에게"`를 출력하고 멈춰요(`break`). 만들면 `"제조: 메뉴 (누적 M분)"`. 실제 출력은?
- **배열 퀴즈 1:** 오늘 메뉴별 판매량이 `int sold[5] = {42, 17, 35, 8, 39};`예요 (순서는 메뉴판과 같아요). 배열을 **딱 한 번만** 돌면서 **1위와 2위** 메뉴를 동시에 찾아 `"1위: 아메리카노 (42잔)"`, `"2위: ..."`를 출력하세요. (새 1등이 나타나면 원래 1등은 어디로 가야 할까요?)
- **포인터 변수 퀴즈 1:** 손님 5명의 음료 제조 시간이 `int wait[5] = {3, 4, 5, 6, 8};`이에요. 바리스타는 한 잔씩 차례로 만들어요. 포인터 `int *p = wait + 1;`로 시작해서 `*p += *(p - 1);`을 반복하면 배열이 **"몇 분 뒤에 내 음료가 나오는지"**로 바뀌어요(누적 합). 그다음 포인터로 다시 돌면서 `"손님 1: 3분 뒤 픽업"`처럼 출력하세요. 손님 번호도 포인터 빼기로 구해요!
- **구조체 퀴즈 1:** 메뉴판 구조체 배열 `menus`에서 이름으로 가격을 찾는 함수 `int find_price(const char *name)`을 만드세요(없으면 -1). 그리고 `"카페라떼"`, `"자몽에이드"`, `"녹차라떼"`를 찾아 `"카페라떼: 5000원"` 또는 `"녹차라떼: 없는 메뉴예요"`를 출력하세요. (`strcmp`가 0을 돌려주는 건 무슨 뜻일까요?)
- **함수 퀴즈 1:** 두 함수를 작성하세요. ① `int next_ticket(void)`: 부를 때마다 101, 102, 103… 새 번호표를 돌려줘요. 단, 전역 변수 없이 **`static` 지역 변수**를 써요. ② `int total_minutes(const Order *o, int n)`: **재귀**(자기가 자기를 부르기)로, 취소된 주문은 빼고 `n`개 주문의 제조 시간 합을 돌려줘요. `total_minutes(orders, 5)`는?
- **흐름제어 퀴즈 2 (종합):** 새로 시작한 프로그램의 `main`에서 주문을 하나씩 처리해요. 취소된 주문은 조용히 건너뛰고(`continue`), 20분을 넘게 되면 `"시간 초과! 남은 주문 M분어치는 다음 바리스타에게"`를 출력하고 멈춰요(`break`). 이때 M은 **지금 주문부터 끝까지**를 `total_minutes`로 구해요 (힌트: `orders + i`). 만든 주문은 `next_ticket`과 `calc_price`로 `"A-101 아메리카노 5000원 (3분 뒤 완성)"`처럼 출력하고, 마지막에 `"완성 N잔, 매출 S원"`. 실제 출력은?

# 정답 및 해설 (초등학교 5학년 눈높이)

## 문제 1: Dropbox 파일 동기화

### 조건문 정답
```c
void check(File f) {
    switch (f.st) {
        case SYNCED:
            printf("동기화 완료\n");
            break;
        case PENDING:
            if (f.size > 100) printf("대용량: 와이파이 대기\n");
            else              printf("업로드 대기\n");
            break;
        case CONFLICT:
            printf("충돌: 사용자 확인 필요\n");
            break;
        case FAILED:
            if (f.retries >= 3) printf("포기: 관리자 알림\n");
            else                printf("재시도 예정\n");
            break;
    }
}
```
**왜 이렇게?** `switch`는 **엘리베이터 버튼**이에요. "3층!" 하고 누르면 3층 문으로 바로 가요. `if-else if`처럼 1층, 2층을 하나하나 물어보지 않아요. 그런데 `break`는 "**여기서 내려!**"라는 뜻이에요. `break`를 빼먹으면 엘리베이터가 안 멈추고 아래 층 문까지 다 열어 버려요. 예를 들어 `SYNCED` 파일인데 "동기화 완료", "업로드 대기", "충돌…", "포기…"가 줄줄이 다 나와요! (이걸 **fall-through**, "흘러 떨어짐"이라고 해요.)
그리고 `video.mp4`는 300MB지만 상태가 `FAILED`라서 `FAILED` 문으로 갔어요. "대용량" 검사는 `PENDING` 문 안에만 있으니까 아예 안 봐요. **어느 문으로 들어갔느냐가 먼저**예요!
결과: report 업로드 대기, photo 업로드 대기, notes 충돌, video 포기: 관리자 알림, song 업로드 대기, report 업로드 대기, cat 동기화 완료.

### 반복문 정답
```c
int ok[5] = {0, 0, 0, 1, 0};
int t = 0, wait = 1, total = 0, success = 0;

do {
    if (ok[t]) {
        success = 1;
        printf("시도 %d: 성공! (총 %d초 기다림)\n", t + 1, total);
    } else {
        printf("시도 %d: 실패, %d초 뒤 다시\n", t + 1, wait);
        total += wait;
        wait *= 2;          // 1 → 2 → 4 → 8
    }
    t++;
} while (!success && t < 5);

if (!success) printf("5번 모두 실패: 나중에 다시\n");
```
출력:
```
시도 1: 실패, 1초 뒤 다시
시도 2: 실패, 2초 뒤 다시
시도 3: 실패, 4초 뒤 다시
시도 4: 성공! (총 7초 기다림)
```
**왜 이렇게?** 업로드는 **일단 한 번은 해 봐야** 성공인지 실패인지 알 수 있어요. `do`-`while`은 "먼저 하고, 나중에 물어보는" 반복문이라 딱 맞아요. (`while`은 "먼저 물어보고 하는" 반복문이에요.)
기다리는 시간을 두 배씩 늘리는 건, 친구한테 전화했는데 안 받으면 1분 뒤, 또 안 받으면 2분 뒤, 4분 뒤… 이렇게 점점 덜 자주 거는 것과 같아요. 매초 계속 걸면 친구(서버)가 너무 바빠지잖아요! 진짜 회사들도 이 방법(지수 백오프)을 써요.
조건이 2개(`!success && t < 5`)인 이유: "성공했으면 그만", "5번 해 봤으면 그만". 둘 중 하나만 있어도 멈춰야 해요. 안 그러면 `ok[5]`처럼 배열 밖을 봐서 큰일 나요.

### 흐름제어 정답 (1)
```c
int remain = 30;
for (int i = 0; i < 7; i++) {
    if (files[i].st != PENDING) continue;
    if (files[i].size > remain) {
        printf("용량 부족: %s부터 업로드 중단\n", files[i].name);
        break;
    }
    remain -= files[i].size;
    printf("업로드: %s (남은 %dMB)\n", files[i].name, remain);
}
```
출력:
```
업로드: report.pdf (남은 27MB)
용량 부족: photo.jpg부터 업로드 중단
```
**왜 이렇게?** `continue`는 "**이건 내 일 아니야, 다음!**", `break`는 "**오늘 일 끝!**"이에요. report(3MB)는 올렸는데 photo(40MB)가 27MB보다 커서 멈췄어요. 겨우 **1개**만 올라갔어요! 뒤에 있는 song(8MB), report(12MB)는 충분히 들어갈 수 있었는데 아깝죠? 그래서 종합 문제에서는 **작은 파일부터** 정렬하고 올려요.

### 배열 정답
```c
int dup = 0;
for (int i = 0; i < 7; i++) {
    for (int j = i + 1; j < 7; j++) {
        if (strcmp(files[i].name, files[j].name) == 0) {
            printf("중복 이름: %s (%d번, %d번)\n", files[i].name, i, j);
            dup++;
        }
    }
}
printf("중복 %d쌍\n", dup);
```
출력: `중복 이름: report.pdf (0번, 5번)` / `중복 1쌍`
**왜 이렇게?** 반 친구 7명이 서로 한 번씩 악수한다고 생각해 봐요. 1번이 2~7번과 악수하면, 2번은 1번과 **이미 했으니까** 3번부터 하면 돼요. 그래서 `j = i + 1`부터예요. `j = 0`부터 하면 ① 자기 자신과 악수하고(0번과 0번이 "같은 이름!"), ② 같은 쌍을 두 번 세요(0-5, 5-0).
문자열을 `==`로 비교하면 "글자가 같니?"가 아니라 "**같은 집(주소)에 사니?**"를 물어봐요. 두 `report.pdf`는 글자는 같아도 다른 집에 살아서 `==`는 "아니"라고 해요. 그래서 글자를 하나하나 비교해 주는 `strcmp`를 쓰고, 똑같으면 **0**을 돌려줘요.

### 포인터 변수 정답
```c
for (int i = 0; i < 7; i++) {
    const char *p = files[i].name;
    const char *dot = NULL;
    while (*p != '\0') {
        if (*p == '.') dot = p;   // 마지막 '.' 위치를 계속 새로 기억
        p++;
    }
    if (dot == NULL) {
        printf("%s: 확장자 없음\n", files[i].name);
        continue;
    }
    if (strcmp(dot + 1, "mp4") == 0)
        printf("%s: 동영상 -> 와이파이에서만\n", files[i].name);
    else
        printf("%s: 확장자 %s\n", files[i].name, dot + 1);
}
```
출력: `report.pdf: 확장자 pdf`, `photo.jpg: 확장자 jpg`, `notes.txt: 확장자 txt`, `video.mp4: 동영상 -> 와이파이에서만`, `song.mp3: 확장자 mp3`, `report.pdf: 확장자 pdf`, `cat.png: 확장자 png`
**왜 이렇게?** `p`는 글자 위를 한 칸씩 걸어가는 **손가락**이에요. `.`을 볼 때마다 `dot`이라는 **포스트잇**을 그 자리에 옮겨 붙여요. 끝까지 가면 포스트잇은 **마지막** `.`에 붙어 있어요. (`my.photo.jpg`라면 `jpg`를 찾아야 하니까 "처음"이 아니라 "마지막"이 중요해요!)
`dot + 1`은 "포스트잇 바로 옆 글자부터"라는 뜻이에요. 새로 문자열을 복사하지 않고 **원래 이름의 중간을 가리키기만** 해도 `"pdf"`처럼 쓸 수 있어요. 처음에 `dot = NULL`로 해 두는 이유는 "아직 못 찾음"을 표시하려고예요. `.`이 없는 파일이 오면 `NULL`이니까 바로 알 수 있어요. `const`는 "이름을 보기만 하고 안 바꿀게"라는 약속이에요.

### 구조체 정답
```c
const char *names[4] = {"SYNCED", "PENDING", "CONFLICT", "FAILED"};
File *pf = &files[2];

printf("%s: %s (번호 %d)\n", pf->name, names[pf->st], pf->st);
pf->st = SYNCED;
printf("%s: %s (번호 %d)\n", files[2].name, names[files[2].st], files[2].st);
```
출력: `notes.txt: CONFLICT (번호 2)` / `notes.txt: SYNCED (번호 0)`
**왜 이렇게?** `enum`의 정체는 **이름표를 붙인 숫자**예요. `SYNCED`=0, `PENDING`=1, `CONFLICT`=2, `FAILED`=3. 사람이 "상태 2"라고 쓰면 무슨 뜻인지 헷갈리지만 `CONFLICT`라고 쓰면 바로 알아요. 그런데 컴퓨터 속에서는 그냥 숫자라서 `names[pf->st]`처럼 **배열 번호로도** 쓸 수 있어요!
`typedef`는 **별명 붙이기**예요. 원래는 `struct 파일 { ... }`를 매번 `struct 파일`이라고 길게 불러야 하는데, `typedef`로 `File`이라는 짧은 별명을 줬어요.
`pf`는 `files[2]`의 **집 주소**라서, `pf->st = SYNCED`는 진짜 `files[2]`의 상태를 바꿔요. 그래서 `files[2]`를 직접 출력해도 `SYNCED`가 나와요.

### 함수 정답
```c
void swap(File *a, File *b) {
    File t = *a;
    *a = *b;
    *b = t;
}

void sort_by_size(File *arr, int n) {
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j].size < arr[min].size) min = j;
        }
        if (min != i) swap(&arr[i], &arr[min]);
    }
}
```
정렬 후: `notes.txt(2) report.pdf(3) cat.png(5) song.mp3(8) report.pdf(12) photo.jpg(40) video.mp4(300)`
**왜 이렇게?** 키 순서로 줄 서기를 생각해 봐요. 선생님이 "남은 친구 중 **제일 작은 친구** 앞으로!" 하고 맨 앞 친구와 자리를 바꿔요. 그다음엔 두 번째 자리부터 다시 "제일 작은 친구!"… 이게 **선택 정렬**이에요.
`swap`에 주소(`&arr[i]`)를 주는 이유: 그냥 값을 주면 함수는 **복사본**끼리 바꾸고 끝나요. 진짜 줄은 그대로죠. 주소를 줘야 진짜 자리를 바꿀 수 있어요. 그리고 `File t = *a;`처럼 구조체는 `=` 한 번으로 이름, 크기, 상태가 **통째로** 복사돼서 편해요. 바꿀 때 컵 두 개의 물을 바꾸려면 빈 컵(`t`)이 하나 더 필요한 것과 같아요!

### 흐름제어 정답 (2, 종합)
```c
int main(void) {
    sort_by_size(files, 7);
    int remain = 18, uploaded = 0, stop = 0;

    for (int i = 0; i < 7 && !stop; i++) {
        File *f = &files[i];
        switch (f->st) {
            case SYNCED:
                printf("이미 완료: %s\n", f->name);
                break;
            case CONFLICT:
                printf("건너뜀: %s (충돌 확인 필요)\n", f->name);
                break;
            case FAILED:
                if (f->retries >= 3) printf("관리자 알림: %s\n", f->name);
                else { f->retries++; printf("재시도 %d회: %s\n", f->retries, f->name); }
                break;
            case PENDING: {
                int dup = 0;
                for (int j = 0; j < 7; j++) {
                    if (j != i && files[j].st == SYNCED && strcmp(files[j].name, f->name) == 0)
                        dup = 1;
                }
                if (dup) {
                    f->st = CONFLICT;
                    printf("이름 충돌: %s -> 충돌 사본으로 표시\n", f->name);
                    break;
                }
                if (f->size > remain) {
                    printf("용량 부족: %s부터 내일 업로드\n", f->name);
                    stop = 1;           // for 반복도 멈추라고 깃발 올리기!
                    break;              // 이 break는 switch만 빠져나가요
                }
                remain -= f->size;
                f->st = SYNCED;
                uploaded++;
                printf("업로드: %s (%dMB, 남은 %dMB)\n", f->name, f->size, remain);
                break;
            }
        }
    }
    printf("오늘 업로드 %d개, 남은 용량 %dMB\n", uploaded, remain);
    return 0;
}
```
출력:
```
건너뜀: notes.txt (충돌 확인 필요)
업로드: report.pdf (3MB, 남은 15MB)
이미 완료: cat.png
업로드: song.mp3 (8MB, 남은 7MB)
이름 충돌: report.pdf -> 충돌 사본으로 표시
용량 부족: photo.jpg부터 내일 업로드
오늘 업로드 2개, 남은 용량 7MB
```
**왜 이렇게?** 가장 중요한 함정! `switch` 안의 `break`는 **엘리베이터에서 내리는 것**일 뿐, **건물(for 반복)에서 나가는 게 아니에요.** 그래서 `break`만 쓰면 photo에서 "용량 부족"이라고 해 놓고도 다음 파일 video로 계속 가요. 그래서 `stop`이라는 **깃발**을 올리고, `for`의 조건에 `&& !stop`을 넣어서 "깃발이 올라가면 건물에서 나가!"라고 했어요. (그래서 video.mp4는 아예 출력되지 않아요.)
두 번째 report.pdf(12MB)는 용량이 아니라 **이름 충돌** 때문에 멈췄어요. 이미 같은 이름의 report.pdf(3MB)가 클라우드에 올라가 있는데 그냥 올리면 **덮어써서** 먼저 파일이 사라져요! 그래서 용량 검사보다 **충돌 검사를 먼저** 해요. 진짜 Dropbox도 이럴 때 "충돌 사본"을 만들어요.
흐름제어 퀴즈 1에서는 1개밖에 못 올렸는데, 작은 것부터 정렬하니까 용량이 더 적은데도(30MB → 18MB) 2개를 올렸어요. **순서를 바꾸는 것만으로도** 결과가 좋아질 수 있어요!

## 프로그램 1: 스타벅스 사이렌오더 주문 처리

### 조건문 정답
```c
int calc_price(const Order *o) {
    int price = find_price(o->menu);
    switch (o->size) {
        case TALL:   break;           // 추가 요금 없음
        case GRANDE: price += 500;  break;
        case VENTI:  price += 1000; break;
    }
    if (o->shots > 2) price += (o->shots - 2) * 600;
    return price;
}
```
결과: 아메리카노 5000원, 카페라떼 6600원, 자몽에이드 5700원, 콜드브루 7100원, 카라멜마끼아또 6400원
**왜 이렇게?** 컵 크기는 딱 3가지 중 **하나**라서 `switch`가 잘 어울려요. `TALL`은 더할 게 없지만 `case TALL: break;`를 **일부러 써 두면** "톨을 깜빡한 게 아니라, 진짜 0원이에요"라고 다른 개발자에게 알려 줘요.
샷은 기본 2개가 공짜라서 `shots - 2`개만큼만 돈을 받아요. 콜드브루는 VENTI(+1000)에 샷 4개(2개 추가 × 600 = 1200)라서 4900 + 1000 + 1200 = **7100원**이에요. 자몽에이드는 샷이 0개인데 `shots > 2` 검사가 없으면 (0 - 2) × 600 = **-1200원**이 되어 버려요! 그래서 `if`가 꼭 필요해요.

### 반복문 정답
```c
int stamps = 7;
for (int i = 0; i < 12; i++) {
    printf(i < stamps ? "★" : "○");
    if ((i + 1) % 4 == 0) printf("\n");
    else                  printf(" ");
}
printf("무료 음료까지 %d개 남음\n", 12 - stamps);
```
출력:
```
★ ★ ★ ★
★ ★ ★ ○
○ ○ ○ ○
무료 음료까지 5개 남음
```
**왜 이렇게?** `%`는 **나머지**예요. 4, 8, 12번째 칸에서 `(i + 1) % 4`가 0이 돼요. 사탕을 4개씩 봉지에 담다가 **딱 맞아떨어질 때마다** 봉지를 묶는 것과 같아요. 그래서 반복문 하나로도 "4칸마다 줄바꿈"을 할 수 있어요. `i`가 0부터 시작하니까 `i + 1`로 "몇 번째 칸인지"를 세요.
`조건 ? A : B`는 짧은 `if`예요. "7칸 전이면 ★, 아니면 ○".

### 흐름제어 정답 (1)
```c
int used = 0;
for (int i = 0; i < 5; i++) {
    if (orders[i].cancel) {
        printf("취소된 주문: %s 건너뜀\n", orders[i].menu);
        continue;
    }
    if (used + orders[i].mins > 20) {
        printf("시간 초과: %s부터 다음 바리스타에게\n", orders[i].menu);
        break;
    }
    used += orders[i].mins;
    printf("제조: %s (누적 %d분)\n", orders[i].menu, used);
}
```
출력:
```
제조: 아메리카노 (누적 3분)
제조: 카페라떼 (누적 7분)
취소된 주문: 자몽에이드 건너뜀
제조: 콜드브루 (누적 13분)
시간 초과: 카라멜마끼아또부터 다음 바리스타에게
```
**왜 이렇게?** "만들고 나서 시간을 확인"하면 이미 21분 일한 뒤라 늦어요. 그래서 `used + orders[i].mins`처럼 "**이거 하면 몇 분이 될까?**"를 **미리** 계산해요. 13 + 8 = 21분이라 20분을 넘으니 멈춰요. 취소된 자몽에이드는 시간을 안 써요 — `continue`가 `used +=` 줄보다 **위에** 있으니까요!

### 배열 정답
```c
const char *names[5] = {"아메리카노", "카페라떼", "콜드브루", "자몽에이드", "카라멜마끼아또"};
int sold[5] = {42, 17, 35, 8, 39};
int first = 0, second = -1;          // -1 = 아직 2등 없음

for (int i = 1; i < 5; i++) {
    if (sold[i] > sold[first]) {
        second = first;              // 원래 1등은 2등으로 내려가요
        first = i;
    } else if (second == -1 || sold[i] > sold[second]) {
        second = i;
    }
}
printf("1위: %s (%d잔)\n", names[first], sold[first]);
printf("2위: %s (%d잔)\n", names[second], sold[second]);
```
출력: `1위: 아메리카노 (42잔)` / `2위: 카라멜마끼아또 (39잔)`
**왜 이렇게?** 달리기 시상대를 생각해 봐요. 새 친구가 1등보다 빠르면 1등 자리를 차지하고, **원래 1등은 2등 자리로 내려가요** (`second = first`). 1등보다는 느리지만 2등보다 빠르면 2등만 바꿔요. 이렇게 하면 배열을 **한 번만** 돌아도 1, 2등을 다 알 수 있어요.
순서대로 따라가 봐요: 42(1등) → 17(2등) → 35(2등 교체) → 8(아무 일 없음) → 39(35보다 크니 2등 교체). `else if`가 없으면 39가 2등이 될 수 없어요!

### 포인터 변수 정답
```c
int wait[5] = {3, 4, 5, 6, 8};
int *p = wait + 1;
while (p < wait + 5) {
    *p += *(p - 1);      // 내 시간 + 바로 앞 사람이 끝나는 시간
    p++;
}
for (p = wait; p < wait + 5; p++) {
    printf("손님 %ld: %d분 뒤 픽업\n", (long)(p - wait) + 1, *p);
}
```
출력: 손님 1: 3분, 손님 2: 7분, 손님 3: 12분, 손님 4: 18분, 손님 5: 26분 뒤 픽업
**왜 이렇게?** 줄 서서 음료를 기다리면, 내 음료는 **앞사람 음료가 끝난 뒤**에 만들기 시작해요. 그러니까 "내가 기다리는 시간 = 앞사람이 끝나는 시간 + 내 음료 시간"이에요. `*(p - 1)`은 "**바로 앞 칸**"이고, 이미 앞사람까지 더한 값으로 바뀌어 있어서 한 칸씩만 더하면 돼요. (3 → 3+4=7 → 7+5=12 → 12+6=18 → 18+8=26)
`p = wait + 1`(두 번째 칸)부터 시작하는 이유: 첫 손님은 앞사람이 없어서 `*(p - 1)`을 하면 배열 밖을 보게 돼요! 손님 번호는 `p - wait`(첫 칸에서 몇 칸 떨어졌나)에 1을 더해 구해요.

### 구조체 정답
```c
int find_price(const char *name) {
    for (int i = 0; i < 5; i++) {
        if (strcmp(menus[i].name, name) == 0) return menus[i].price;
    }
    return -1;     // 끝까지 못 찾음
}

// main에서
const char *ask[3] = {"카페라떼", "자몽에이드", "녹차라떼"};
for (int k = 0; k < 3; k++) {
```

출력: `카페라떼: 5000원` / `자몽에이드: 5700원` / `녹차라떼: 없는 메뉴예요`
**왜 이렇게?** 메뉴판(`Menu` 구조체)은 **이름과 가격이 한 칸에 같이** 붙어 있어서, 이름을 찾으면 같은 칸의 가격도 바로 알 수 있어요. 이름 배열, 가격 배열을 따로 두면 순서가 하나라도 어긋날 때 엉뚱한 가격이 나와요.
`strcmp`는 두 단어를 사전 순서로 비교해서, 같으면 **0**("차이가 0이야")을 돌려줘요. 그래서 `if (strcmp(...))`가 아니라 `== 0`이라고 꼭 써야 해요. 찾으면 바로 `return`으로 나가고, 반복이 끝까지 돌았다는 건 "못 찾았다"는 뜻이라 그때 -1을 돌려줘요. 가격이 -1원인 메뉴는 없으니 "없음" 표시로 딱 좋아요.

### 함수 정답
```c
int next_ticket(void) {
    static int ticket = 100;   // 처음 딱 한 번만 100으로 시작
    ticket++;
    return ticket;
}

int total_minutes(const Order *o, int n) {
    if (n == 0) return 0;                          // 멈추는 문!
    int last = o[n - 1].cancel ? 0 : o[n - 1].mins;
    return last + total_minutes(o, n - 1);         // 나머지는 동생에게 부탁
}
```
`next_ticket()`을 세 번 부르면 101, 102, 103 / `total_minutes(orders, 5)` = 3 + 4 + 0 + 6 + 8 = **21분**
**왜 이렇게?** 보통 함수 안의 변수는 함수가 끝나면 **기억을 잃어요**. 그러면 매번 100에서 시작해서 번호표가 계속 101만 나와요. `static`을 붙이면 함수가 끝나도 **값을 기억하는 수첩**이 돼요. 전역 변수와 달리 다른 함수는 이 수첩을 못 건드려서 더 안전해요.
재귀는 **러시아 인형(마트료시카)** 같아요. "5개 주문의 합"을 구하려고 "마지막 주문 시간 + **앞 4개의 합**"을 해요. 앞 4개의 합은 또 "4번째 + 앞 3개의 합"… 결국 0개가 되면 "0이야!" 하고 멈춰요. 이 **멈추는 문(`n == 0`)**이 없으면 인형을 영원히 열다가 프로그램이 터져요(스택 오버플로).

### 흐름제어 정답 (2, 종합)
```c
int main(void) {
    int used = 0, sales = 0, made = 0;
    for (int i = 0; i < 5; i++) {
        Order *o = &orders[i];
        if (o->cancel) continue;
        if (used + o->mins > 20) {
            printf("시간 초과! 남은 주문 %d분어치는 다음 바리스타에게\n",
                   total_minutes(orders + i, 5 - i));
            break;
        }
        int price = calc_price(o);
        used += o->mins;
        sales += price;
        made++;
        printf("A-%d %s %d원 (%d분 뒤 완성)\n", next_ticket(), o->menu, price, used);
    }
    printf("완성 %d잔, 매출 %d원\n", made, sales);
    return 0;
}
```
출력:
```
A-101 아메리카노 5000원 (3분 뒤 완성)
A-102 카페라떼 6600원 (7분 뒤 완성)
A-103 콜드브루 7100원 (13분 뒤 완성)
시간 초과! 남은 주문 8분어치는 다음 바리스타에게
완성 3잔, 매출 18700원
```
**왜 이렇게?** 오늘 만든 부품들이 다 모였어요! `find_price`(구조체) → `calc_price`(switch 조건문) → `next_ticket`(static) → `total_minutes`(재귀). 레고 블록처럼 작은 함수를 따로 만들어 두니까 `main`은 "취소면 넘어가고, 시간 넘으면 멈추고, 아니면 만들어"만 읽으면 돼요.
`orders + i`는 "**i번째 주문부터 시작하는 배열**"이라는 뜻이에요. 배열을 잘라서 새로 만들지 않고, 시작 주소만 옮겨서 함수에 줬어요. i = 4일 때 남은 건 카라멜마끼아또 1개(8분)라 `total_minutes(orders + 4, 1)` = 8이에요.
번호표가 104가 아니라 101부터인 이유: 새로 시작한 프로그램이라 `static` 수첩도 처음(100)부터예요. 그리고 취소된 주문이나 시간 초과 주문에는 `next_ticket()`을 **부르지 않아서** 번호가 건너뛰지 않아요. 번호표는 진짜 만드는 음료에만 줘야 손님이 헷갈리지 않아요!
