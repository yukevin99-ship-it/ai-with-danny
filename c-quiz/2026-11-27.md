## 엔지니어가 직면한 가상의 문제 1

**[농업 IoT 스타트업 "초록손" 스마트팜팀 — 가상]** 어젯밤 갑자기 기온이 뚝 떨어졌는데, 비닐하우스 관리 프로그램이 히터를 안 켜서 오이 모종이 얼 뻔했어요! 조사해 보니 옛날 프로그램은 **고장 난 센서가 보낸 `-100`도** 를 보고 "엄청 춥다 → 모든 히터 최대로!"를 외쳤다가, 다른 칸에서는 아무 일도 안 하는 엉망진창이었어요. 엔지니어인 너는 **온실 5동의 온도를 확인하고, 히터·창문을 알맞게 조절하는 프로그램**을 새로 만들어야 해요.

**오늘의 규칙**

| 온도(`temp`, 도) | 상태 | 할 일 |
|---|---|---|
| `-50` 미만 | 센서 고장 | 아무것도 안 함 (건너뛰기) |
| `-50` ~ `14` | 추워요 | 히터 켜기 (+5도) |
| `15` ~ `29` | 적정 온도 | 그대로 두기 |
| `30` ~ `39` | 더워요 | 창문 열기 (-5도) |
| `40` 이상 | 위험! | 관리자 호출, 검사 중단 |

**오늘의 데이터**

```c
// 온실 5동의 온도(도). -100은 센서 고장
int temps[5] = {24, 31, -100, 12, 42};
```

### 조건문 퀴즈1

**📘 개념 설명 — 조건문 (`if / else if / else`)**
- **정의**: "만약 ~라면 이걸 하고, 아니면 저걸 해"라고 컴퓨터에게 **갈림길**을 알려주는 문법이에요.
- **적용 논리**: 위에서부터 차례로 검사하다가 **처음으로 참인 곳 하나만** 실행해요. 그래서 **말이 안 되는 값(센서 고장)을 제일 먼저** 걸러야 "엄청 춥다!"로 착각하지 않아요.
- **응용 가능성**: 실내 온도에 따라 보일러 켜기, 비가 오면 스프링클러 끄기, 배터리가 낮으면 절전 모드 켜기 등 **모든 자동 기계의 "판단"** 에 쓰여요.

**문제**: `temp` 값을 보고 규칙표대로 상태(`센서 고장`, `추워요`, `적정 온도`, `더워요`, `위험!`)를 출력하세요.

```c
#include <stdio.h>

int main(void) {
    int temp = 31;   // -100, 12, 24, 31, 42 로 바꿔 가며 테스트해 보세요

    /* 여기에 코드를 작성하세요 */
    // 출력 예: temp = 31 이면 "더워요"

    return 0;
}
```

### 반복문 퀴즈1

- **적용 논리**: `i = 0`부터 `i < 5`인 동안 돌고, 한 번 돌 때마다 `i++`로 1씩 커져요. 0, 1, 2, 3, 4 → 딱 5번!
- **응용 가능성**: 센서 100개 읽기, 반 학생 30명 출석 부르기, 게임 몬스터 50마리 움직이기 등 **"여러 개를 하나씩 다 보기"** 에 항상 써요.

**문제**: `for` 문으로 온실 5동의 온도를 `"1동: 24도"` 처럼 한 줄씩 출력하세요. (온실 번호는 **1동부터**예요!)

```c
#include <stdio.h>

int main(void) {
    int temps[5] = {24, 31, -100, 12, 42};

    /* 여기에 코드를 작성하세요 */

    return 0;
}
```

### 흐름제어 퀴즈1

**📘 개념 설명 — 흐름제어 (`continue`, `break`)**
- **정의**: 반복문 안에서 **이번 것만 건너뛰기(`continue`)**, **반복을 아예 멈추기(`break`)** 를 하는 명령이에요.
- **적용 논리**: `continue`를 만나면 아래 코드를 무시하고 **다음 차례**로 가요. `break`를 만나면 반복문을 **즉시 탈출**해요.
- **응용 가능성**: 고장 난 센서 값은 건너뛰기, 불이 날 만큼 뜨거우면 즉시 멈추고 사람 부르기 — 공장·농장 자동화 시스템의 기본 동작이에요.

**문제**: 온실을 1동부터 차례로 검사하세요.
1. 온도가 **-50 미만**이면 `"3동: 센서 고장, 건너뜀"` 출력 후 **건너뛰기**(`continue`)
2. 온도가 **40 이상**이면 `"5동: 위험! 관리자 호출"` 출력 후 **검사 중단**(`break`)
3. 그 밖에는 `"1동: 24도 확인"` 출력

```c
#include <stdio.h>

int main(void) {
    int temps[5] = {24, 31, -100, 12, 42};

    for (int i = 0; i < 5; i++) {
        /* 여기에 코드를 작성하세요 */
    }
    printf("검사 끝\n");
    return 0;
}
```

### 포인터 변수 퀴즈1

**📘 개념 설명 — 포인터 (`*`, `&`)**

- **응용 가능성**: 기계 상태를 바꾸는 함수(히터 켜기, 볼륨 올리기, 잔액 빼기)처럼 **"원본을 고쳐야 하는"** 모든 곳에 써요.

```c

void openWindow(int *temp) {

}

void turnOnHeater(int *temp) {
    /* 여기에 코드를 작성하세요 (온도 5도 올리기) */

int main(void) {
```

## 엔지니어가 창작해야되는 가상의 프로그램 1

**[반려동물 IoT 회사 "냠냠펫" 앱 개발팀 — 가상]** 회사가 새 **자동 급식기**를 만들었어요. 사료통에 사료를 넣어 두면, 정해진 시간에 기계가 알아서 사료를 한 그릇씩 줘요. 엔지니어인 너는 이 급식기 안에서 돌아갈 **"냠냠 급식기" 프로그램**을 처음부터 만들어야 해요. 사료통이 비었는지 알려 주고, 반려동물마다 하루에 먹을 양을 계산하고, 너무 많이 먹지 않게 막아야 해요!

**규칙 미리 보기**
- 사료통 남은 양(`food`, g): `0 미만` 센서 오류 / `0` 비었어요 / `1~99` 곧 떨어져요 / `100 이상` 충분해요
- 한 번에 주는 양: `60g`
- 사료통 최대 용량: `1000g`
- 하루 먹을 양: 몸무게(kg) × 20g (아기(0살)는 × 30g, 할머니·할아버지(7살 이상)는 × 15g)

- **응용 가능성**: 휴대폰 배터리 경고, 프린터 잉크 부족 알림, 자동차 기름 경고등 등 **"남은 양 알림"** 은 전부 이 모양이에요.

```c
#include <stdio.h>
```

### 조건문 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    int temp = 31;

    if (temp < -50) {
        printf("센서 고장\n");
    } else if (temp < 15) {
        printf("추워요\n");
    } else if (temp < 30) {
        printf("적정 온도\n");
    } else if (temp < 40) {
        printf("더워요\n");
    } else {
        printf("위험!\n");
    }
    return 0;
}
```

출력: `더워요`

**🧒 쉽게 설명하면**
엄마가 "밖에 몇 도야?" 하고 물었는데 온도계가 **-100도**라고 하면? "온도계가 고장 났네!" 하고 웃겠죠. 컴퓨터는 그걸 모르니까 **우리가 먼저 알려 줘야** 해요.
- **왜 `temp < -50` 이 맨 앞?** 옛날 프로그램은 이 검사가 없어서 -100도를 "엄청 춥다"로 믿고 히터를 마구 켰어요. **말도 안 되는 값은 제일 먼저** 거르기!
- **왜 `temp < 30` 만 쓰면 될까?** `else if`는 "앞의 것이 다 아닐 때만" 검사해요. 여기까지 왔다면 이미 15 이상이라는 뜻이라 `15 <= temp` 를 또 쓸 필요가 없어요.
- **경계값 조심!** 규칙표에서 30도는 "더워요"예요. `temp <= 30` 이라고 쓰면 30도를 "적정"으로 잘못 판단해요. `<`와 `<=` 하나 차이로 토마토가 익어 버릴 수 있어요!

### 배열 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    int temps[5] = {24, 31, -100, 12, 42};
    int sum = 0, count = 0;
    int highest = -50;

    for (int i = 0; i < 5; i++) {
        if (temps[i] < -50) continue;   // 고장 값은 계산에서 빼기

        sum += temps[i];
        count++;
        if (temps[i] > highest) {
            highest = temps[i];
        }
    }

    if (count > 0) {
        printf("정상 온도 %d개, 평균 %d도, 최고 %d도\n", count, sum / count, highest);
    } else {
        printf("정상 센서가 하나도 없어요!\n");
    }
    return 0;
}
```

출력: `정상 온도 4개, 평균 27도, 최고 42도`
(24 + 31 + 12 + 42 = 109, 109 ÷ 4 = 27.25 → 정수 나눗셈이라 **27**)

**🧒 쉽게 설명하면**
반 친구들 키 평균을 구하는데, 한 명이 장난으로 "내 키 -100cm!"라고 적었어요. 그걸 그대로 더하면 평균이 엉망이 되겠죠? 그래서 **이상한 값은 빼고** 더해요.
- **`sum`과 `count`는 왜 0에서 시작?** 빈 바구니에서 시작해서 하나씩 담아야 정확히 셀 수 있어요.
- **`highest`는 왜 -50에서 시작?** "지금까지 본 것 중 제일 높은 값"을 기억하는 칸이에요. 정상 온도는 모두 -50 이상이니까, 첫 정상 값을 만나자마자 바뀌어요.
- **`if (count > 0)` 은 왜?** 센서가 전부 고장이면 `count`가 0이에요. **0으로 나누면 프로그램이 멈춰 버려요!** 현업 엔지니어는 이런 경우를 꼭 막아 둬요.

친구에게 "우리 집 화분에 물 좀 줘"라고 부탁할 때, **화분 사진**을 주면 친구는 사진에 물을 줄 수밖에 없어요 (진짜 화분은 그대로!). **우리 집 주소**를 줘야 친구가 와서 진짜 화분에 물을 줄 수 있죠.
- `&t` = **우리 집 주소** 주기
- `int *temp` = "나는 주소를 받을게요"
- `*temp = *temp - 5` = "그 주소에 가서, 원래 온도에서 5를 빼고 다시 넣어"
- 만약 `void openWindow(int temp) { temp = temp - 5; }` 로 쓰면 **사진(복사본)** 에만 창문을 연 거라 `t`는 31 그대로예요. 이게 현업에서 자주 나오는 "분명 바꿨는데 안 바뀌어요!" 버그예요.

### 구조체 퀴즈1 정답

```c
#include <stdio.h>

typedef struct {
    int id;
    char crop[20];
    int temp;
} Greenhouse;

int main(void) {
    Greenhouse farm[3] = {
        {1, "딸기", 24},
        {2, "토마토", 31},
        {3, "상추", 18}
    };

    for (int i = 0; i < 3; i++) {
        if (farm[i].temp >= 30) {
            printf("%d동(%s): %d도 → 창문 열기\n", farm[i].id, farm[i].crop, farm[i].temp);
        }
    }
    return 0;
}
```

출력: `2동(토마토): 31도 → 창문 열기`

**🧒 쉽게 설명하면**
포켓몬 카드처럼 카드 한 장에 **번호, 이름, 온도**가 다 적혀 있다고 생각해요.
- `typedef struct { ... } Greenhouse;` = "**온실 카드** 모양을 이렇게 정할게요" (빈 카드 디자인)
- `Greenhouse farm[3]` = 그 카드를 **3장** 만들기
- `farm[i].temp` = "i번째 카드의 **온도 칸**을 보여 줘"
- **왜 구조체를 쓸까?** 배열 3개(`ids[]`, `crops[]`, `temps[]`)로 따로 관리하면, 하나를 정렬하다가 순서가 섞여서 "딸기 온실 온도가 토마토 온도로 바뀌는" 사고가 나요. 카드 한 장으로 묶으면 **항상 같이 움직여요.**
- 문자열은 `%s`, 정수는 `%d`로 출력해요.

### 함수 퀴즈1 정답

```c
#include <stdio.h>

int isGood(int temp) {
    if (temp >= 15 && temp <= 29) {
        return 1;
    }
    return 0;
}

int main(void) {
    int temps[5] = {24, 31, -100, 18, 42};
    int good = 0;

    for (int i = 0; i < 5; i++) {
        if (isGood(temps[i])) {
            good++;
        }
    }

    printf("적정 온도 온실: %d동\n", good);   // 2동
    return 0;
}
```

**🧒 쉽게 설명하면**
`isGood`은 **"합격/불합격 도장 기계"** 예요. 온도를 넣으면 1(합격) 또는 0(불합격) 도장을 찍어서 돌려줘요.
- `&&` 는 **"그리고"** 예요. "15 이상 **그리고** 29 이하" — 두 조건이 **둘 다** 맞아야 1이에요.
- `return 1;` 을 만나면 함수는 **그 자리에서 끝**나요. 그래서 그 아래 `return 0;` 은 조건이 틀렸을 때만 실행돼요. `else` 를 안 써도 되는 이유예요.
- `if (isGood(temps[i]))` 는 "도장이 1이면" 이라는 뜻이에요. C언어에서 0이 아닌 값은 모두 **참**이에요.
- 나중에 "적정 온도를 16~28도로 바꿔 주세요!" 라는 요청이 와도 **함수 한 줄만** 고치면 끝!

### 흐름제어 퀴즈1 (종합) 정답

```c
#include <stdio.h>

typedef struct {
    int id;
    char crop[20];
    int temp;
} Greenhouse;

int control(Greenhouse *g) {
    if (g->temp < 15) {
        g->temp += 5;      // 히터 켜기
        return 1;
    } else if (g->temp >= 30) {
        g->temp -= 5;      // 창문 열기
        return 1;
    }
    return 0;              // 적정 온도라 그대로
}

int main(void) {
    Greenhouse farm[5] = {
        {1, "딸기", 24},
        {2, "토마토", 31},
        {3, "상추", -100},
        {4, "오이", 12},
        {5, "파프리카", 42}
    };
    int changed = 0;

    for (int i = 0; i < 5; i++) {
        if (farm[i].temp < -50) {
            printf("%d동(%s): 센서 고장, 건너뜀\n", farm[i].id, farm[i].crop);
            continue;
        }
        if (farm[i].temp >= 40) {
            printf("%d동(%s): 위험! 관리자 호출\n", farm[i].id, farm[i].crop);
            break;
        }
        if (control(&farm[i])) {
            changed++;
        }
        printf("%d동(%s): %d도\n", farm[i].id, farm[i].crop, farm[i].temp);
    }

    printf("조절한 온실: %d동\n", changed);
    return 0;
}
```

출력:
```
1동(딸기): 24도
2동(토마토): 26도
3동(상추): 센서 고장, 건너뜀
4동(오이): 17도
5동(파프리카): 위험! 관리자 호출
조절한 온실: 2동
```

**🧒 쉽게 설명하면**
농장 관리 로봇이 아침에 온실을 한 바퀴 도는 모습이에요.
1. 온실 카드를 1동부터 한 장씩 봐요 (`for`).
2. 온도계가 고장 난 온실(상추)은 **그냥 지나가요** (`continue`).
3. 너무 뜨거운 온실(파프리카)을 보면 **순찰을 멈추고 사람을 불러요** (`break`).
4. 나머지 온실은 **조절 기계(`control` 함수)** 에 **온실 주소(`&farm[i]`)** 를 넘겨서 진짜 온도를 바꿔요.
- **`->` 는 뭐예요?** 포인터로 받은 구조체의 칸을 꺼낼 때 쓰는 화살표예요. `g->temp` 는 `(*g).temp` 를 짧게 쓴 거예요. "주소로 찾아가서 온도 칸을 봐!"
- **왜 `&farm[i]` 로 넘겨요?** 그냥 `farm[i]` 를 넘기면 **복사본 카드**만 고쳐져서, 출력할 때 토마토가 여전히 31도로 나와요.
- **왜 `control` 이 1/0을 돌려줘요?** 함수가 "나 뭔가 바꿨어!"라고 알려 줘야 `main` 이 **조절한 온실 수**를 셀 수 있어요. 함수는 일도 하고 **보고**도 할 수 있어요.
- **순서가 중요해요!** 고장(-100) 검사 → 위험(40 이상) 검사 → 조절 순서예요. 만약 `control` 을 먼저 부르면 -100도 온실에 히터를 켜 버려요 — 바로 어젯밤 일어난 사고예요!

### 반복문 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    int food = 500;
    int portion = 60;
    int times = 0;

    while (food >= portion) {
        food -= portion;
        times++;
    }

    printf("%d번 줄 수 있어요, 남은 사료 %dg\n", times, food);
    return 0;
}
```

출력: `8번 줄 수 있어요, 남은 사료 20g`
(500 → 440 → 380 → 320 → 260 → 200 → 140 → 80 → 20, 20g은 60g보다 적어서 멈춤)

**🧒 쉽게 설명하면**
과자 봉지에서 친구들에게 한 줌씩 나눠 주는데, **한 줌이 안 되면** 더는 못 주는 거예요.
- **왜 `for` 가 아니라 `while`?** 몇 번 줄 수 있는지 **미리 모르니까**요. "사료가 한 그릇 이상 **있는 동안**" 계속 주는 거예요.
- **왜 `food >= portion` 이고 `food > 0` 이 아닐까?** `food > 0` 으로 하면 20g 남았을 때도 60g을 빼서 **-40g** 이 돼요. 사료통이 마이너스가 되는 엉터리 기계가 되죠!
- **`food -= portion` 을 빼먹으면?** `food`가 영원히 500이라 **무한 반복** — 급식기가 사료를 끝없이 주는(척하는) 고장 기계가 돼요.

### 흐름제어 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {

```

출력:

```
2번째 급식: 안 먹음
```

하루 간식은 3개까지! 라고 엄마가 정했다고 생각해요. 간식을 먹을 때마다 세다가 3개가 되면 "오늘 끝!" 하는 거예요.

- 5, 6번째 급식(30g, 20g)은 `break` 때문에 아예 안 봐요. 고양이 배탈 방지 성공!

### 배열 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    int week[7] = {140, 150, 90, 160, 145, 30, 150};

            minVal = week[i];
            minDay = i;
        }
    }

    if (minVal < 50) {
        printf("%d일째에 %dg밖에 안 먹었어요. 병원에 가 보세요!\n", minDay + 1, minVal);
    }
    return 0;
}
```

출력:
```
일주일 합계 865g, 평균 123g
가장 적게 먹은 날: 6일째 (30g)
6일째에 30g밖에 안 먹었어요. 병원에 가 보세요!
```

- **왜 `minDay`도 기억해요?** "30g이 제일 적어요"만 알면 **언제**인지 몰라요. 칸 번호를 같이 기억해야 "6일째"라고 알려 줄 수 있어요.
- **`minDay + 1`** — 컴퓨터는 0일째부터 세니까, 사람에게 보여 줄 땐 +1!

### 포인터 변수 퀴즈1 정답

```c
#include <stdio.h>

void refill(int *food, int add) {
    *food += add;
    if (*food > 1000) {
        *food = 1000;
    }
}

int main(void) {
    int food = 850;

    refill(&food, 300);
    printf("사료통: %dg\n", food);   // 1000g

    return 0;
}
```

**🧒 쉽게 설명하면**
컵에 물을 따르는데, 컵이 넘치면 **딱 가득 찬 만큼만** 남잖아요? 그걸 코드로 만든 거예요.
- `&food` 로 **사료통의 진짜 주소**를 넘겨요. 그래야 함수가 진짜 사료통에 사료를 부어요.
- `*food += add` = "그 주소의 사료통에 add만큼 더해" → 1150g
- `if (*food > 1000) *food = 1000;` = "넘쳤으면 1000g으로 맞춰" → 1000g
- **왜 `add` 는 포인터가 아닐까?** `add`(300g)는 **읽기만** 하고 바꿀 필요가 없으니까요. **바꿔야 하는 것만 주소로** 넘기는 게 좋은 습관이에요.

### 함수 퀴즈1 정답

```c
#include <stdio.h>

int dailyFood(int weight, int age) {
    if (age == 0) {
        return weight * 30;
    } else if (age >= 7) {
        return weight * 15;
    } else {
        return weight * 20;
    }
}

int main(void) {
    printf("나비: %dg\n", dailyFood(4, 2));    // 80g
    printf("초코: %dg\n", dailyFood(12, 8));   // 180g
    printf("보리: %dg\n", dailyFood(6, 0));    // 180g
    return 0;
}
```

**🧒 쉽게 설명하면**
놀이공원 매표소에서 "어린이 요금, 어른 요금, 경로 요금"을 나이 보고 정하는 것과 똑같아요.
- 함수에 **몸무게와 나이 두 가지**를 넣으면(매개변수 2개), **하루 사료량 하나**가 나와요(`return`).
- 모든 갈림길에 `return` 이 있어서, 어떤 길로 가도 **반드시 답이 나와요.** `return`을 빼먹은 길이 있으면 이상한 숫자가 나올 수 있어요!
- 이 함수를 만들어 두면 다음 종합 문제나 앱 화면, 쇼핑몰 추천 기능 어디서든 **불러다 쓰기만** 하면 돼요.

### 흐름제어 퀴즈1 (종합) 정답

```c
#include <stdio.h>

typedef struct {
    char petName[20];
    int food;
    int portion;
} Feeder;

int feedOnce(Feeder *f) {
    if (f->food < f->portion) {
        return 0;               // 사료 부족, 못 줌
    }
    f->food -= f->portion;      // 진짜 사료통에서 빼기
    return 1;                   // 성공
}

int main(void) {
    Feeder myFeeder = {"나비", 200, 60};
    int times[5] = {7, 11, 2, 15, 19};
    int fed = 0;

    for (int i = 0; i < 5; i++) {
        if (times[i] < 6) {
            printf("%d시: 새벽이라 건너뜀\n", times[i]);
            continue;
        }
        if (!feedOnce(&myFeeder)) {
            printf("%d시: 사료 부족! 보호자에게 알림\n", times[i]);
            break;
        }
        printf("%d시: %s에게 %dg 줬어요 (남은 사료 %dg)\n",
               times[i], myFeeder.petName, myFeeder.portion, myFeeder.food);
        fed++;
    }

    printf("오늘 급식 횟수: %d번\n", fed);
    return 0;
}
```

출력:
```
7시: 나비에게 60g 줬어요 (남은 사료 140g)
11시: 나비에게 60g 줬어요 (남은 사료 80g)
2시: 새벽이라 건너뜀
15시: 나비에게 60g 줬어요 (남은 사료 20g)
19시: 사료 부족! 보호자에게 알림
오늘 급식 횟수: 3번
```

**🧒 쉽게 설명하면**
급식기 로봇의 하루를 따라가 봐요.
1. 시간표를 하나씩 봐요 (`for` + 배열).
2. **새벽 2시**는 나비도 자는 시간이니까 패스 (`continue`).
3. 밥 줄 시간이면 **급식 기계(`feedOnce`)** 에 **급식기 주소(`&myFeeder`)** 를 넘겨요. 기계는 진짜 사료통에서 60g을 빼요.
4. 19시에 사료가 20g밖에 없어요 → 기계가 0(실패)을 돌려줘요 → **"보호자님, 사료 채워 주세요!"** 알림을 보내고 멈춰요 (`break`).
- **`!feedOnce(...)` 의 `!` 는?** "아니다(NOT)"라는 뜻이에요. "급식이 **실패했으면**"이라고 읽어요. 0 → `!0` → 참!
- **왜 함수가 직접 `printf`를 안 해요?** 함수는 **"줬다/못 줬다"만 보고**하고, 화면에 뭐라고 쓸지는 `main` 이 정해요. 이렇게 **일하는 부분**과 **보여 주는 부분**을 나누면, 나중에 화면 대신 **휴대폰 알림**으로 바꿀 때 `main` 만 고치면 돼요. 현업에서 아주 중요한 습관이에요!
- **왜 부족할 때 `break`?** 사료가 20g뿐이라 다음 시간에도 어차피 못 줘요. 계속 시도하면 보호자 휴대폰에 알림이 **여러 번** 울려서 귀찮겠죠? 한 번만 알리고 멈춰요.

## 📝 오늘의 핵심 정리

| 도구 | 한 줄 요약 | 오늘 쓴 곳 |
|---|---|---|
| `if / else if / else` | 위에서부터 처음 맞는 것 하나만 실행 | 온실 상태 판단, 사료통 알림 |
| `for` | 정해진 횟수만큼 반복 (배열과 짝꿍) | 온실 5동, 일주일 기록, 급식 시간표 |
| `while` | 조건이 참인 동안 반복 (값을 꼭 바꿔야 함) | 사료 몇 번 줄 수 있나 |
| `continue` | 이번 것만 건너뛰기 | 고장 센서, 안 먹은 급식, 새벽 시간 |
| `break` | 반복 즉시 멈추기 | 위험 온도, 정량 도달, 사료 부족 |
| 배열 | 번호 붙은 칸 (0번부터!) | 온도 목록, 일주일 사료 기록 |
| 포인터 `*` `&` `->` | 주소를 넘겨서 원본을 바꾸기 | 창문·히터, 사료 채우기, 급식기 |
| 구조체 `.` | 여러 정보를 카드 한 장으로 | 온실 카드, 펫 카드, 급식기 카드 |
| 함수 `return` | 규칙을 이름 붙인 기계로 | 적정 온도 판정, 하루 사료량, 급식 1회 |

**오늘의 버그 사냥 포인트 🐛**
1. **말이 안 되는 값(-100도, -5g)은 맨 먼저 거르기** — 안 그러면 히터를 마구 켜는 사고가 나요.
2. **0으로 나누기 조심** — 정상 센서가 0개면 평균을 구하면 안 돼요 (`if (count > 0)`).
3. **최솟값은 첫 칸 값으로 시작** — `0`으로 시작하면 영원히 0이 답이 돼요.
4. **`while`의 조건은 "충분히 남았나?"** — `food > 0` 이 아니라 `food >= portion`, 안 그러면 사료통이 마이너스!
5. **한도 검사는 `==` 말고 `>=`** — 한도를 훌쩍 넘는 순간을 놓치지 않게.
6. **원본을 바꾸려면 주소(`&`)** — 복사본만 바꾸면 "창문 열었는데 온도가 그대로예요" 버그!
