## 엔지니어가 직면한 가상의 문제 1

**[Apple Watch 헬스팀]** 시계가 1분마다 심박수(bpm, 1분 동안 심장이 뛴 횟수)를 6번 쟀어요. 각 기록은 몇 분째인지(`minute`), 심박수(`bpm`), 운동 중인지(`moving`, 1이면 운동 중), 센서가 제대로 쟀는지(`sensor_ok`, 1이면 정상)를 가져요. 규칙: 센서가 잘못 쟀으면 무조건 "다시 측정"이에요. 그 밖에는 40 **미만**이면 "너무 느림", 운동 중이 **아닌데** 120 **이상**이면 "경고", 나머지는 "정상"이에요. (운동 중에 심장이 빨리 뛰는 건 자연스러운 일이라 괜찮아요!)

```c
int bpm[6] = {72, 0, 130, 125, 38, 160};
// 기록 6개: {minute, bpm, moving, sensor_ok}
// {1,72,0,1} {2,0,0,0} {3,130,1,1} {4,125,0,1} {5,38,0,1} {6,160,0,1}
```

- **조건문 퀴즈 1:** 기록 하나의 `sensor_ok`, `bpm`, `moving`을 보고 "다시 측정", "너무 느림", "경고", "정상" 중 하나를 출력하는 코드를 작성하세요. (센서 검사를 먼저!)
- **반복문 퀴즈 1:** 구조체 배열 `beats[6]`을 처음부터 끝까지 돌면서 `"1분: 72bpm"` 모양으로 출력하는 코드를 작성하세요.
- **흐름제어 퀴즈 1:** 위 반복문에서 센서가 잘못 잰 기록(`sensor_ok == 0`)은 건너뛰고, "경고"에 해당하는 기록(운동 중이 아닌데 120 이상)을 처음 발견하면 `"첫 경고: N분"`을 출력하고 반복을 멈추는 코드를 작성하세요.
- **배열 퀴즈 1:** `bpm` 배열에서 0(측정 실패)인 칸은 빼고, 나머지 값들의 **평균**(정수)을 구해 출력하세요. (합계 `sum`과 개수 `cnt`를 따로 세요)
- **포인터 변수 퀴즈 1:** 측정 실패(0)인 칸을 **바로 앞 칸의 값**으로 채우려고 해요. 포인터 `p`를 `bpm`의 **두 번째 칸**에서 출발시켜 끝까지 `p++`로 이동하며, `*p`가 0이면 앞 칸 값 `*(p - 1)`로 바꾸는 코드를 작성하세요. (왜 첫 칸이 아니라 두 번째 칸에서 출발할까요?)
- **구조체 퀴즈 1:** 몇 분째(`minute`), 심박수(`bpm`), 운동 여부(`moving`), 센서 정상 여부(`sensor_ok`)를 가진 구조체 `struct Beat`를 정의하세요.
- **함수 퀴즈 1:** 기록 배열의 시작 주소 `b`와 개수 `n`을 받아서, 센서가 정상인 기록 중 "너무 느림" 또는 "경고"에 해당하는 기록의 수를 반환하는 함수 `count_alert`를 작성하세요.
- **흐름제어 퀴즈 2 (종합):** `main`에서 기록 6개짜리 구조체 배열과 `count_alert`를 사용해, 개수가 3 이상이면 `"의사 상담 권장 (N번)"`, 1 이상이면 `"주의 관찰: N번"`, 0이면 `"건강 양호"`를 출력하는 코드를 작성하세요.

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[CGV 예매 앱 팀]** 영화관 맨 앞줄 좌석 8개를 보여 주고 예매해 주는 프로그램을 만들어요. 각 좌석은 좌석 번호(`num`, 1~8), 예매 여부(`taken`, 1이면 이미 예매됨), VIP 여부(`vip`, 1이면 VIP석)를 가져요. 가격은 VIP석 15000원, 일반석 12000원이에요. 친구랑 같이 온 손님은 **바로 붙어 있는 빈자리 2개**가 필요해요.

```c
int taken[8] = {1, 1, 0, 0, 0, 1, 0, 0};
int vip[8]   = {0, 0, 0, 1, 1, 1, 0, 0};
// 좌석 8개: {num, taken, vip}
```

- **구조체 퀴즈 1:** 좌석 번호(`int num`), 예매 여부(`int taken`), VIP 여부(`int vip`)를 가진 구조체 `struct Seat`를 정의하고, 변수 `one`을 `7`, `0`, `1`로 만들어 `"7번: VIP석 15000원"`처럼 번호와 가격을 출력하는 코드를 작성하세요.
- **함수 퀴즈 1:** 좌석 배열 시작 주소 `s`와 개수 `n`을 받아, 나란히 붙은 빈자리 2개를 처음 찾으면 **두 자리를 모두 예매 처리(`taken = 1`)** 하고 앞자리 번호(`num`)를 반환하는 함수 `book_pair`를 작성하세요. 없으면 `-1`을 반환하세요.

## 문제 1: Apple Watch 심박수 이상 감지

### 조건문 정답
```c
if (sensor_ok == 0) {
    printf("다시 측정\n");
} else if (bpm < 40) {
    printf("너무 느림\n");
} else if (bpm >= 120 && moving == 0) {
    printf("경고\n");
} else {
    printf("정상\n");
}
```
**왜 이렇게?** 체온계가 고장 났는데 "열이 0도예요!"라고 믿으면 큰일이죠? 그래서 "기계가 제대로 쟀나?"를 **맨 먼저** 물어봐요. 그다음 "심장이 너무 느리게 뛰나?"를 묻고, 마지막으로 "가만히 앉아 있는데(`moving == 0`) **그리고**(`&&`) 심장이 쿵쾅쿵쾅 120 이상 뛰나?"를 물어요. 뛰어노는 중에 심장이 빠른 건 당연하니까, 두 조건이 **둘 다** 맞아야 경고예요. 결과: 1분 정상, 2분 다시 측정, 3분 정상(운동 중이라 괜찮아요), 4분 경고, 5분 너무 느림, 6분 경고.

### 반복문 정답
```c
for (int i = 0; i < 6; i++) {
    printf("%d분: %dbpm\n", beats[i].minute, beats[i].bpm);
}
```
**왜 이렇게?** 기록이 딱 6개라서 횟수가 정해진 `for`를 써요. 이번에는 카드 안에 `minute`이 이미 들어 있으니 `i + 1` 대신 그걸 바로 꺼내 쓰면 돼요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 6; i++) {
    if (beats[i].sensor_ok == 0) {
        continue;
    }
    if (beats[i].bpm >= 120 && beats[i].moving == 0) {
        printf("첫 경고: %d분\n", beats[i].minute);
        break;
    }
}
```
**왜 이렇게?** `continue`는 "이건 고장 난 기록이니까 무시하고 다음 거!", `break`는 "찾았다! 이제 그만!"이에요. 3분은 130이지만 운동 중이라 통과, 4분(125, 가만히)이 처음 걸려서 `첫 경고: 4분`이 나와요. 6분(160)도 경고지만 이미 `break`로 멈췄으니 안 봐요.

### 배열 정답
```c
int sum = 0, cnt = 0;
for (int i = 0; i < 6; i++) {
    if (bpm[i] == 0) {
        continue;
    }
    sum += bpm[i];
    cnt++;
}
printf("평균: %d\n", sum / cnt);   // 105
```
**왜 이렇게?** 평균은 "다 더하고 몇 개인지로 나누기"예요. 그런데 0은 진짜 심박수가 아니라 "못 쟀다"는 뜻이라서 같이 더하면 평균이 억울하게 낮아져요. 그래서 0은 건너뛰고 **더한 개수만** 세요. 72+130+125+38+160 = 525, 5개라서 525 / 5 = 105예요. (0까지 넣고 6으로 나누면 87이 돼서 틀린 답이에요!)

### 포인터 정답
```c
int *p = bpm + 1;          // 두 번째 칸에서 출발
for (int i = 1; i < 6; i++) {
    if (*p == 0) {
        *p = *(p - 1);     // 바로 앞 칸 값을 복사
    }
    p++;
}
// bpm은 {72, 72, 130, 125, 38, 160}이 돼요
```
**왜 이렇게?** `p`는 칸을 가리키는 손가락이고, `*p`는 그 칸 안의 값, `*(p - 1)`은 "손가락 바로 왼쪽 칸의 값"이에요. 첫 칸에서 출발하면 왼쪽 칸이 없어서(배열 밖!) 이상한 값을 읽게 돼요. 그래서 **두 번째 칸**(`bpm + 1`)부터 출발하고, 반복도 5번만(`i = 1`부터 `i < 6`) 해요. 2분의 0이 1분 값 72로 채워져요. `p++`는 `if` 밖에 둬야 모든 칸을 지나가요.

### 구조체 정답
```c
struct Beat {
    int minute;
    int bpm;
    int moving;
    int sensor_ok;
};
```
**왜 이렇게?** 한 번 잰 기록에는 "몇 분째, 심박수, 운동 중?, 센서 정상?"이 항상 한 세트로 다녀요. 배열 4개로 따로 들고 다니면 짝이 엇갈리기 쉬우니 "기록 카드" 한 장으로 묶어요.

### 함수 정답
```c
int count_alert(struct Beat *b, int n) {
    int cnt = 0;
    for (int i = 0; i < n; i++) {
        if (b[i].sensor_ok == 0) {
            continue;
        }
        if (b[i].bpm < 40 || (b[i].bpm >= 120 && b[i].moving == 0)) {
            cnt++;
        }
    }
    return cnt;
}
```
**왜 이렇게?** 함수는 "기록 묶음 주소(`b`)랑 몇 장인지(`n`) 줄게, 이상한 거 몇 개인지 세어 와!" 하는 심부름꾼이에요. "너무 느림 **또는**(`||`) 경고"라서 둘 중 하나만 맞아도 세요. 괄호 `( )`로 "경고 조건"을 한 덩어리로 묶어야 뜻이 헷갈리지 않아요. 4분, 5분, 6분이 걸려서 3을 돌려줘요. 함수는 배열이 몇 칸인지 혼자 알 수 없어서 `n`을 꼭 받아야 해요.

### 흐름제어 정답 (2, 종합)
```c
int main(void) {
    struct Beat beats[6] = {
        {1, 72, 0, 1}, {2, 0, 0, 0}, {3, 130, 1, 1},
        {4, 125, 0, 1}, {5, 38, 0, 1}, {6, 160, 0, 1}
    };
    int alerts = count_alert(beats, 6);
    if (alerts >= 3) {
        printf("의사 상담 권장 (%d번)\n", alerts);
    } else if (alerts >= 1) {
        printf("주의 관찰: %d번\n", alerts);
    } else {
        printf("건강 양호\n");
    }
    return 0;
}
```
**왜 이렇게?** 큰 숫자부터 검사하는 게 포인트예요! 만약 `alerts >= 1`을 먼저 물으면 3도 1 이상이라서 "주의 관찰"로 빠져 버리고, "의사 상담"에는 영영 못 가요. 결과는 `의사 상담 권장 (3번)`이에요.

## 문제 2: CGV 영화관 좌석 예매기

### 조건문 정답
```c
if (taken == 1) {
    printf("예매 불가\n");
} else if (vip == 1) {
    printf("VIP석 15000원\n");
} else {
    printf("일반석 12000원\n");
}
```
**왜 이렇게?** 누가 이미 앉은 자리는 VIP든 아니든 못 팔아요. 그래서 "이미 팔렸나?"를 먼저 묻고, 빈자리일 때만 "VIP석인가?"를 물어서 가격을 정해요.

### 반복문 정답
```c
for (int i = 0; i < 8; i++) {
    if (seats[i].taken == 1) {
        printf("%d번: X\n", seats[i].num);
    } else {
        printf("%d번: O\n", seats[i].num);
    }
}
```
**왜 이렇게?** 8자리를 하나씩 보면서, 반복문 **안에** 조건문을 넣어 O/X를 골라요. 이렇게 "반복 속 조건"이 흐름제어의 기본 모양이에요. 출력: 1 X, 2 X, 3 O, 4 O, 5 O, 6 X, 7 O, 8 O.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 8; i++) {
    if (seats[i].taken == 1) {
        continue;
    }
    if (seats[i].vip == 1) {
        printf("첫 빈 VIP 좌석: %d번\n", seats[i].num);
        break;
    }
}
```
**왜 이렇게?** 팔린 자리는 `continue`로 휙 넘기고, 빈자리 중 VIP석을 찾으면 `break`로 멈춰요. 3번은 빈자리지만 일반석이라 지나가고, 4번이 처음 만난 빈 VIP석이에요. 6번은 VIP지만 이미 팔렸어요. 출력은 `첫 빈 VIP 좌석: 4번`.

### 배열 정답
```c
for (int i = 0; i < 7; i++) {
    if (taken[i] == 0 && taken[i + 1] == 0) {
        printf("나란히 좌석: %d번, %d번\n", i + 1, i + 2);
        break;
    }
}
```
**왜 이렇게?** "나랑 내 오른쪽 친구 자리가 둘 다 비었나?"를 보는 거예요. 그런데 맨 끝자리(8번, `i = 7`)는 오른쪽 자리가 없어요! `i < 8`로 하면 `taken[8]`이라는 **없는 칸**을 들여다보는 사고가 나요. 그래서 `i < 7`까지만 돌아요. 3번·4번이 처음으로 둘 다 비어서 `나란히 좌석: 3번, 4번`이에요.

### 포인터 정답
```c
int *q = taken;
for (int i = 0; i < 8; i++) {
    if (*q == 0) {
        *q = 1;                     // 예매 처리!
        printf("예매: %d번\n", i + 1);
        break;
    }
    q++;
}
// taken은 {1, 1, 1, 0, 0, 1, 0, 0}이 돼요
```
**왜 이렇게?** 손가락 `q`가 한 칸씩 오른쪽으로 가다가, 빈자리(`*q == 0`)를 만나면 그 칸에 직접 1을 적어 넣어요(`*q = 1`). 포인터로 값을 바꾸면 **진짜 배열**이 바뀌어요. 1번, 2번은 차 있어서 지나가고 3번을 예매해요. 이번엔 찾자마자 `break`로 나가니까 `q++`가 `if` 다음에 와도 괜찮아요.

### 구조체 정답
```c
struct Seat {
    int num;
    int taken;
    int vip;
};

struct Seat one = {7, 0, 1};
if (one.taken == 1) {
    printf("%d번: 예매 불가\n", one.num);
} else if (one.vip == 1) {
    printf("%d번: VIP석 15000원\n", one.num);
} else {
    printf("%d번: 일반석 12000원\n", one.num);
}
```
**왜 이렇게?** 좌석 한 개의 정보를 "좌석 카드"로 묶었어요. 카드 안의 칸은 점(`.`)으로 꺼내요. `one.vip`는 "one 카드의 vip 칸"이에요. 빈자리이고 VIP라서 `7번: VIP석 15000원`이 나와요.

### 함수 정답
```c
int book_pair(struct Seat *s, int n) {
    for (int i = 0; i < n - 1; i++) {
        if (s[i].taken == 0 && s[i + 1].taken == 0) {
            s[i].taken = 1;
            s[i + 1].taken = 1;
            return s[i].num;
        }
    }
    return -1;
}
```
**왜 이렇게?** 이 심부름꾼은 두 가지 일을 해요. ① 나란히 빈자리를 찾고 ② 그 자리에 "예매됨" 스티커를 붙여요. 주소(`s`)를 받았기 때문에 함수 안에서 바꾼 `taken`이 **바깥(main)의 진짜 좌석표**에도 그대로 남아요. 이게 포인터를 넘기는 이유예요! `return`은 찾자마자 함수를 끝내니까 `break`가 따로 필요 없어요. 끝까지 못 찾으면 맨 아래 `return -1`에 도착해요. 끝 검사도 배열 퀴즈처럼 `n - 1`까지만 해요.

### 흐름제어 정답 (2, 종합)
```c
int main(void) {
    struct Seat seats[8] = {
        {1,1,0}, {2,1,0}, {3,0,0}, {4,0,1},
        {5,0,1}, {6,1,1}, {7,0,0}, {8,0,0}
    };
    for (int team = 0; team < 3; team++) {
        int r = book_pair(seats, 8);
        if (r == -1) {
            printf("나란히 앉을 자리 없음\n");
            break;
        }
        printf("예매 완료: %d번, %d번\n", r, r + 1);
    }
    return 0;
}
```
**왜 이렇게?** 출력은 이렇게 나와요.
```
예매 완료: 3번, 4번
예매 완료: 7번, 8번
나란히 앉을 자리 없음
```
첫 팀이 3·4번을 가져가면 좌석표가 진짜로 바뀌어요. 그래서 두 번째 팀이 찾을 때는 5번만 비어 있고 6번은 차 있으니 건너뛰고 7·8번을 가져가요. 세 번째 팀이 왔을 땐 5번 한 자리만 남아서 둘이 나란히 못 앉아요 → `-1` → "자리 없음" 출력 후 `break`. 함수가 좌석표를 **기억해서 바꿔 주기** 때문에 같은 자리를 두 번 파는 사고(이중 예매)가 안 생겨요. 이게 실제 예매 서버가 제일 조심하는 부분이에요!
