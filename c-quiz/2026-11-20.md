## 엔지니어가 직면한 가상의 문제 1

**[Visa 이상거래 탐지팀]** 한 고객이 "나는 서울에 있는데 파리에서 내 카드가 긁혔어요!"라고 신고했어요. 그 카드의 오늘 결제 기록 8건을 보니, 서울에서 커피를 산 지 **15분 만에** 파리에서 $900 결제가 있었어요. 비행기로 12시간 걸리는 거리인데요! 엔지니어는 거래마다 **수상한 점(깃발)**을 붙이고, **위험 점수**를 매겨서 **승인 / OTP 확인 / 차단**을 결정하는 엔진을 고쳐야 해요.

```c
#include <stdio.h>
#include <string.h>      // strcmp

#define N 8
#define F_BIG   1u       // 0001  고액
#define F_NIGHT 2u       // 0010  심야(0~5시)
#define F_CITY  4u       // 0100  180분 안에 도시가 바뀜
#define F_FAST  8u       // 1000  앞 거래와 2분 이내

typedef enum { FOOD, SHOP, TRAVEL, GAME, NCAT } Category;   // 0,1,2,3, 그리고 개수 4
const char *CN[NCAT] = {"식비", "쇼핑", "여행", "게임"};

typedef struct { int h, m; } Time;
typedef struct { int id; char city[8]; int amount; Category cat; Time t; } Tx;   // amount: 달러

Tx log_[N] = {
    {101, "Seoul",   12, FOOD,   { 3, 10}},
    {102, "Seoul",  450, SHOP,   { 9,  0}},
    {103, "Seoul",   30, GAME,   { 9,  5}},
    {104, "Paris",  900, TRAVEL, { 9, 20}},
    {105, "Paris",   60, GAME,   { 9, 22}},
    {106, "Paris",   75, GAME,   { 9, 23}},
    {107, "Seoul",    8, FOOD,   {13,  0}},
    {108, "Seoul", 1300, SHOP,   {13,  1}},
};
const int PTS[4] = {40, 10, 50, 20};   // 깃발 0번(BIG)~3번(FAST)의 위험 점수
```

(금액 ≥ 한도면 BIG, 시각 < 6시면 NIGHT, `prev`가 있고 도시가 다르고 간격 < 180분이면 CITY, `prev`가 있고 간격 ≤ 2분이면 FAST). 8건의 깃발 값(숫자)은?
  (① `case FOOD:` 뒤에 `return` 대신 `limit = 100;`만 쓰고 `break`를 빠뜨리면 식비 한도는 몇이 될까요? ② 깃발 검사를 `f && F_CITY`로 쓰면 왜 틀릴까요?)
- **반복문 퀴즈 1 (비트 돌기):** `int score_of(unsigned f)`를 `for (int b = 0; b < 4; b++)` 안에서 `if (f & (1u << b)) s += PTS[b];`로, `int bits(unsigned f)`(켜진 깃발 수)는 `while (f) { c += f & 1u; f >>= 1; }`로 만드세요. 8건의 `"104: 깃발 2개, 위험점수 90"`은?

  `void refund_bad(Tx t) { t.amount = 0; }` 와 `void refund(Tx *t) { t->amount = 0; }`
  중에서 `refund_bad(log_[3])`을 부른 뒤 `log_[3].amount`는 몇일까요? 왜?

- **흐름제어 퀴즈 2 (종합 엔진):** 거래를 차례로 처리해요. (`prev`는 바로 앞 거래, 첫 거래는 `NULL`)

  2. 20 ≤ 점수 < 80 → OTP 확인. `int ok_at[N] = {0,0,0,0,2,0,0,1};`(고객이 몇 번째 시도에 맞히는지, 0 = 못 맞힘). **`do-while`**로 최대 3번 시도하며 `"  105 OTP 1번째: 실패"` 출력. 맞히면 승인, 3번 다 틀리면 차단

  5. 마지막에 `"승인 A건 $합계, 차단 B건"`

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[Google Pixel 카메라팀]** 새 사진 편집 앱의 **흑백 필터 엔진**을 만들어요. 흑백 사진은 사실 **숫자 표(2차원 배열)**예요. 칸 하나(픽셀)마다 0(검정)~255(흰색) 밝기가 들어 있어요. 오늘은 5줄 × 6칸짜리 작은 사진으로 연습해요.

```c
#include <stdio.h>
#include <string.h>     // memcpy

#define R 5             // 줄(row)
#define C 6             // 칸(column)
typedef unsigned char u8;   // 0~255만 담는 1바이트 상자

const u8 ORIG[R][C] = {
    { 20,  20,  20, 200, 210, 255},
    { 20,  20, 180, 200, 255, 255},
    { 20, 100, 120, 130, 200, 210},
    { 60,  60,  60, 130,  20,  20},
    { 60,  60,  60, 130,  20,  20},
};
u8 img[R][C];
void reset(void) { memcpy(img, ORIG, sizeof img); }   // 원본으로 되돌리기

typedef struct { int top, left, bottom, right; } Rect;   // 잘라낼 네모(양끝 포함)
typedef struct { int min, max, avg, count; } Stats;
```

- **조건문 퀴즈 1:** `u8 clamp(int v)`를 만드세요. 0보다 작으면 0, 255보다 크면 255, 아니면 그대로. 그리고 `const char *label(int v)`는 64 미만 "어두움", 128 미만 "약간 어두움", 192 미만 "약간 밝음", 나머지 "밝음". `clamp(250+40)`, `clamp(-30)`, `clamp(130)`과 20, 100, 130, 200, 255의 label은?
  (`u8 v = 250; v += 40;` 처럼 clamp 없이 더하면 `v`는 몇이 될까요? 왜 사진에서 이게 큰 사고일까요?)
- **반복문 퀴즈 1 (2중 반복):** 줄마다 합과 평균을 `"row1 sum 930 avg 155"`처럼 출력하고, 전체 평균과 **가장 밝은 줄**을 찾으세요. 전체 평균이 80 미만이면 "야간 모드 추천", 170 초과면 "노출 과다", 아니면 "정상".
- **흐름제어 퀴즈 1 (깃발 변수로 두 층 탈출):** 줄 순서대로 보면서 **처음 나오는 255(하얗게 날아간 점)**를 찾아요. 칸을 볼 때마다 `checks++`. 찾으면 `found = 1; break;`, 바깥 반복은 `if (found) break;`. 위치와 검사 횟수는? 바깥의 `if (found) break;`를 빼먹으면 `checks`는 몇이 될까요?
- **배열 퀴즈 1 (히스토그램):** `int h[4] = {0};`에 `h[img[i][j] / 64]++`로 밝기 구간별 개수를 세고, `"  0~ 63 16 ################"`처럼 `#` 막대로 그리세요. 255 / 64는 몇이고, 왜 칸이 4개면 충분할까요?
- **포인터 변수 퀴즈 1 (2차원을 1차원처럼):** `const u8 *base = &img[0][0];`에서 `for (p = base; p < base + R*C; p++)`로 가장 어두운 점(`mn`)과 가장 밝은 점(`mx`)을 찾아요(같으면 먼저 나온 것). `p - base`를 **(줄, 칸)**으로 바꾸려면? 그리고 `*(*(img + 2) + 3)`, `base[15]`, `base[C*3 + 4]`의 값은?
- **구조체 퀴즈 1:** `int valid(Rect r)`(사진 안에 있고 `top <= bottom`, `left <= right`)와 `Stats rect_stats(u8 a[][C], Rect r)`를 만드세요. 잘못된 네모면 `count = -1`. `{1,1,3,3}`, `{0,3,1,5}`, `{2,4,1,6}`의 결과는? `sizeof(Rect)`는? 함수 매개변수를 `u8 a[][C]`처럼 **두 번째 크기만** 꼭 써야 하는 이유는?
- **함수 퀴즈 1 (재귀 영역 채우기):** "배경 지우기" 버튼은 누른 점과 **같은 밝기로 이어진 영역**을 한 번에 칠해요.
  `int fill(int r, int c, int from, int to)`: 사진 밖이면 0, `img[r][c] != from`이면 0, 아니면 `to`로 칠하고 `1 + 위 + 아래 + 왼쪽 + 오른쪽 fill`을 돌려줘요. 함수가 불린 횟수를 `calls++`로 세세요. `fill(0,0,20,0)`과 그다음 `fill(4,5,20,0)`의 결과(칠한 수, 호출 수)는? **칠하기를 재귀 호출보다 뒤로** 미루면 어떻게 될까요? `from == to`이면?
- **흐름제어 퀴즈 2 (종합 편집기):** 명령 문자열 `"BIXTFQB"`를 `for (const char *p = cmd; *p; p++)`와 `switch (*p)`로 처리해요. (원본에서 시작)

  - 그 밖: `"'X': 모르는 명령, 건너뜀"` 후 `continue`
  - 명령이 실행되면 `"B 후: 평균 140, 255 개수 3"`

# 정답 및 해설 (초등학교 5학년 눈높이)

## 문제 1: Visa 이상거래 탐지

### 조건문 정답
```c
int limit_of(Category c) {
    switch (c) {
        case FOOD:   return 100;
        case GAME:   return 50;
        case SHOP:                 // 아무것도 안 쓰고 아래로 '흘러가게'
        case TRAVEL: return 800;   // SHOP과 TRAVEL이 같은 답을 공유
        default:     return 0;
    }
}

int gap(Time a, Time b) { return (b.h * 60 + b.m) - (a.h * 60 + a.m); }

unsigned flags_of(const Tx *cur, const Tx *prev) {
    unsigned f = 0;
    if (cur->amount >= limit_of(cur->cat)) f |= F_BIG;
    if (cur->t.h < 6)                      f |= F_NIGHT;
    if (prev != NULL) {                    // 첫 거래는 '앞 거래'가 없어요
        int g = gap(prev->t, cur->t);
        if (strcmp(prev->city, cur->city) != 0 && g < 180) f |= F_CITY;
        if (g <= 2)                                       f |= F_FAST;
    }
    return f;
}
```
```
101: 2  (NIGHT)        102: 0          103: 0
104: 5  (BIG + CITY)   105: 9 (BIG + FAST)   106: 9 (BIG + FAST)
107: 0                 108: 9 (BIG + FAST)
```
**해설:**
- `switch`는 **엘리베이터 층 버튼**이에요. `c`가 몇 층인지 보고 그 층에서 내려요. `case SHOP:` 다음에 아무것도 없으면 문이 안 열리고 **아래층(TRAVEL)까지 흘러가서** 거기서 내려요. 그래서 두 분류가 한 답을 같이 써요.
- ① `case FOOD: limit = 100;` 다음에 `break`가 없으면 멈추지 않고 `case GAME: limit = 50;`까지 내려가요. **식비 한도가 50**이 돼서 $60 저녁밥도 "고액"이라고 의심받아요. `switch`에서 `break` 빠뜨리기는 현업에서도 정말 자주 나는 버그예요.
- 깃발은 **전등 스위치 4개가 달린 판**이에요. `f |= F_CITY`는 "3번째 스위치만 켜고 다른 건 그대로". 104번은 BIG(1) + CITY(4) = **5**(이진수 0101).
- ② `&&`는 "둘 다 0이 아니니?"만 물어봐요. `f && F_CITY`는 f에 **아무 깃발이나** 켜져 있으면 참이 돼요. 105번(BIG + FAST)도 "도시 바뀜!"이 돼 버려요. 특정 스위치만 보려면 비트 `&`로 `f & F_CITY`를 써야 해요.
- 107번은 파리→서울이지만 217분 차이라서 CITY가 아니에요(180분 기준). 규칙은 "기준선"이라서 완벽하지 않다는 것도 기억해요.

### 반복문 정답
```c
int score_of(unsigned f) {
    int s = 0;
    for (int b = 0; b < 4; b++)
        if (f & (1u << b)) s += PTS[b];     // b번째 스위치가 켜졌니?
    return s;
}
int bits(unsigned f) {
    int c = 0;
    while (f) { c += f & 1u; f >>= 1; }     // 맨 오른쪽 스위치를 보고, 한 칸씩 밀기
    return c;
}
```
```
101: 깃발 1개, 위험점수 10
102: 깃발 0개, 위험점수 0
103: 깃발 0개, 위험점수 0
104: 깃발 2개, 위험점수 90
105: 깃발 2개, 위험점수 60
106: 깃발 2개, 위험점수 60
107: 깃발 0개, 위험점수 0
108: 깃발 2개, 위험점수 60
```
**해설:** `1u << b`는 "b번째 스위치만 켜진 판"을 만들어요(1, 2, 4, 8). 그걸 `f`에 대 보고(`&`) 겹치면 그 스위치가 켜져 있는 거예요. 104번은 0번(40점) + 2번(50점) = **90점**.
`bits`의 `while`은 **줄 선 친구들을 오른쪽부터 한 명씩 내보내며** 세는 거예요. `f >>= 1`로 한 칸씩 밀다가 0이 되면(아무도 안 남으면) 멈춰요. 몇 번 돌지 미리 정하지 않아도 되니까 `while`이 어울려요.

### 흐름제어 퀴즈 1 정답
```c
int total = 0, checked = 0;
for (int i = 0; i < N; i++) {
    checked++;
    const Tx *prev = (i > 0) ? &log_[i - 1] : NULL;
    int s = score_of(flags_of(&log_[i], prev));
    if (s == 0) continue;                           // 깨끗한 거래는 조용히 넘김
    total += s;
```

### 흐름제어 퀴즈 2 정답
```c
int ok_at[N] = {0, 0, 0, 0, 2, 0, 0, 1};
int ap = 0, apsum = 0, bl = 0;
for (int i = 0; i < N; i++) {
    const Tx *prev = (i > 0) ? &log_[i - 1] : NULL;
    int s = score_of(flags_of(&log_[i], prev));
    int ok;
    if (s >= 80) {
        ok = 0;                                  // 너무 위험 → 묻지도 않고 차단
    } else if (s >= 20) {
        int tries = 0;
        ok = 0;
        do {
            tries++;
            printf("  %d OTP %d번째: %s\n", log_[i].id, tries, tries == ok_at[i] ? "성공" : "실패");
            if (tries == ok_at[i]) ok = 1;
        } while (!ok && tries < 3);
    } else {
        ok = 1;
    }

    if (ok) {
        ap++; apsum += log_[i].amount;
        printf("%d $%d 점수 %d -> 승인\n", log_[i].id, log_[i].amount, s);
        continue;
    }
    bl++;
    printf("%d $%d 점수 %d -> 차단 (누적 %d)\n", log_[i].id, log_[i].amount, s, bl);
    if (bl >= 2) {
        printf("차단 2건! 카드 잠금. 남은 %d건 처리 안 함\n", N - 1 - i);
        break;
    }
}
printf("승인 %d건 $%d, 차단 %d건\n", ap, apsum, bl);
```
```
101 $12 점수 10 -> 승인
102 $450 점수 0 -> 승인
103 $30 점수 0 -> 승인
104 $900 점수 90 -> 차단 (누적 1)
  105 OTP 1번째: 실패
  105 OTP 2번째: 성공
105 $60 점수 60 -> 승인
  106 OTP 1번째: 실패
  106 OTP 2번째: 실패
  106 OTP 3번째: 실패
106 $75 점수 60 -> 차단 (누적 2)
차단 2건! 카드 잠금. 남은 2건 처리 안 함
승인 4건 $552, 차단 2건
```
**해설:** 이 엔진은 **놀이공원 입구 직원 3명**이에요.
- 점수 낮음 → "들어가세요!"(승인)
- 점수 중간 → "표 다시 보여 주세요"(OTP)
- 점수 아주 높음 → "안 돼요!"(차단)

OTP는 **최소 한 번은 꼭 물어봐야** 해요. `while (!ok && tries < 3)`로 시작하면 처음엔 `ok = 0`이라 괜찮지만, "물어보기 전에 조건부터 따지는" 모양이라 실수로 `ok`를 1로 시작하면 한 번도 안 물어봐요. `do-while`은 **"일단 한 번 하고, 그다음에 또 할지 생각"**이라서 "적어도 한 번" 하는 일에 딱이에요(비밀번호 입력, 메뉴 선택 등).
"OTP 성공 → 승인", "점수 낮음 → 승인"처럼 **결과가 같은 길**을 `ok` 변수 하나로 모아서, 승인 코드와 차단 코드를 **한 번씩만** 썼어요. 이렇게 하면 나중에 "차단 시 문자 보내기"를 추가할 때 한 곳만 고치면 돼요.
카드가 잠기면 107(서울 커피 $8)도 처리 안 돼요. 진짜 주인이 불편하지만, 108번 $1300 결제를 막았어요. 보안에서는 이런 **"불편 vs 안전" 저울질**을 늘 해요.

**해설:** `u8`(= `unsigned char`)은 **0부터 255까지만 있는 자동차 계기판**이에요. 255에서 1이 더 오르면 0으로 **한 바퀴 돌아요**. 250 + 40 = 290, 290 − 256 = **34**. 사진에서 이러면 "제일 밝은 하늘"이 갑자기 "거의 검정"으로 변해서 하늘에 까만 점이 생겨요! 그래서 계산은 넉넉한 `int`로 하고, 담기 **직전에** `clamp`로 0~255 울타리 안에 넣어요. `clamp`의 매개변수가 `u8`이 아니라 `int`인 이유도 이거예요. `u8`로 받으면 들어오는 순간 이미 34가 돼 버려요.

```
130 130 20
```
**해설:** 2차원 배열은 사실 메모리에 **기차처럼 한 줄로** 붙어 있어요. 0번 줄 6칸 뒤에 바로 1번 줄 6칸이 이어져요. 그래서 `base`에서 `p++`만 하면 30칸을 쭉 지나갈 수 있어요. 반복문 하나로 끝나니 2중 반복보다 단순하죠.
기차 칸 번호를 다시 (줄, 칸)으로 바꾸려면: **줄 = 번호 ÷ 6**, **칸 = 번호 % 6**. 칸 15번 → 15 ÷ 6 = 2줄, 15 % 6 = 3칸 → `img[2][3]` = 130.
`*(*(img + 2) + 3)`도 같은 곳이에요. `img + 2`는 "2번 줄로 이동", `*`로 그 줄을 열고, `+ 3`으로 3칸 이동, 마지막 `*`로 값을 꺼내요. `img[2][3]`는 사실 이걸 **짧게 쓴 별명**이에요. `base[C*3 + 4]` = `img[3][4]` = 20.

### 구조체 정답
```c
int valid(Rect r) {
    return r.top >= 0 && r.left >= 0 && r.bottom < R && r.right < C
        && r.top <= r.bottom && r.left <= r.right;
}
Stats rect_stats(u8 a[][C], Rect r) {
    Stats s = {255, 0, 0, 0};          // min은 가장 큰 값, max는 가장 작은 값으로 시작
    if (!valid(r)) { s.count = -1; return s; }
    int sum = 0;
    for (int i = r.top; i <= r.bottom; i++)
        for (int j = r.left; j <= r.right; j++) {
            int v = a[i][j];
            if (v < s.min) s.min = v;
            if (v > s.max) s.max = v;
            sum += v; s.count++;
        }
    s.avg = sum / s.count;
    return s;
}
```
```
{1,1,3,3}: 9칸, 최소 20, 최대 200, 평균 111
{0,3,1,5}: 6칸, 최소 200, 최대 255, 평균 229
{2,4,1,6}: 잘못된 네모
sizeof(Rect) = 16
```
**해설:** `Rect`는 **네 귀퉁이 정보를 한 봉투에** 넣은 거예요. 함수에 숫자 4개를 따로 넘기면 순서를 헷갈리기 쉬운데(`top, left`였나 `left, top`이었나?), 봉투 하나면 `r.top`처럼 이름으로 꺼내니까 안전해요. 결과도 `Stats` 봉투 하나에 담아 돌려줘요.
세 번째 네모는 **두 가지**가 잘못됐어요: 위(2)가 아래(1)보다 크고, 오른쪽 6은 사진 밖(칸은 0~5)이에요. 검사 없이 돌리면 반복이 0번이라 `sum / count`에서 **0으로 나누기**가 일어나요. 그래서 계산 **전에** `valid`로 막아요(사용자가 손가락으로 사진 밖까지 끌 수 있으니까요!).
`min`을 255로 시작하는 이유: 처음 값을 0으로 두면 어떤 점도 0보다 작지 않아서 최솟값이 영원히 0이에요. "가장 작은 걸 찾을 땐 가장 큰 값에서 출발"!
`u8 a[][C]`: 기차를 줄로 나누려면 **한 줄이 몇 칸인지** 알아야 `a[i][j]` = "i × 6 + j번째 칸"을 계산할 수 있어요. 줄 수(5)는 몰라도 계산이 되지만, 칸 수(6)는 꼭 알아야 해요.

### 함수 정답
```c
int calls = 0;
int fill(int r, int c, int from, int to) {
    calls++;
    if (r < 0 || r >= R || c < 0 || c >= C) return 0;   // 사진 밖 → 멈춤
    if (img[r][c] != from)                    return 0;   // 다른 색 → 멈춤
    img[r][c] = (u8)to;                                   // 먼저 칠한다!
    return 1 + fill(r - 1, c, from, to) + fill(r + 1, c, from, to)
             + fill(r, c - 1, from, to) + fill(r, c + 1, from, to);
}
```
```
fill(0,0,20,0): 6픽셀, 호출 25번
fill(4,5,20,0): 4픽셀, 호출 17번
   0   0   0 200 210 255
   0   0 180 200 255 255
   0 100 120 130 200 210
  60  60  60 130   0   0
  60  60  60 130   0   0
```
**해설:** 재귀는 **물감이 번지는 것**이에요. 한 칸을 칠하고 "위, 아래, 왼쪽, 오른쪽 친구도 같은 색이면 칠해 줘!"라고 **똑같은 부탁**을 4번 해요. 부탁받은 칸도 또 4번 부탁하고요. 멈추는 규칙(사진 밖이면 멈춤, 다른 색이면 멈춤)이 있어서 영원히 번지지 않아요.
왼쪽 위 20 영역은 (0,0)(0,1)(0,2)(1,0)(1,1)(2,0) **6칸**이에요. 오른쪽 아래 20 영역 4칸은 **이어져 있지 않아서** 안 칠해졌어요. 그래서 두 번 따로 눌러야 해요.
호출이 25번인 이유: 칠한 6칸이 각각 4번씩 부탁(24번) + 처음 1번 = 25번. 대부분은 "이미 칠했음" 또는 "사진 밖"이라 바로 돌아와요.
**칠하기를 뒤로 미루면?** (0,0)이 (0,1)에게 부탁하고, (0,1)이 다시 (0,0)에게 부탁하는데 (0,0)은 아직 20이니까 또 부탁… **끝없이 서로 부탁**해서 프로그램이 스택 넘침(stack overflow)으로 죽어요. "칠했다"는 표시가 곧 "여기 왔었음" 표시예요.
**`from == to`이면?** 칠해도 색이 그대로라 같은 문제가 생겨요. 그래서 종합 문제에서는 "이미 128이면 건너뜀"으로 미리 막았어요.

### 흐름제어 퀴즈 2 정답
```c
reset();
const char *cmd = "BIXTFQB";
int done = 0, skip = 0, quit = 0;
for (const char *p = cmd; *p; p++) {
    switch (*p) {
        case 'B':
            for (int i = 0; i < R; i++) for (int j = 0; j < C; j++) img[i][j] = clamp(img[i][j] + 40);
            break;
        case 'I':
            for (int i = 0; i < R; i++) for (int j = 0; j < C; j++) img[i][j] = 255 - img[i][j];
            break;
        case 'T':
            for (int i = 0; i < R; i++) for (int j = 0; j < C; j++) img[i][j] = img[i][j] >= 128 ? 255 : 0;
            break;
        case 'F': {
            int from = img[0][0];
            if (from == 128) { printf("  이미 칠해짐\n"); break; }
            printf("  채운 픽셀 %d\n", fill(0, 0, from, 128));
            break;
        }
        case 'Q':
            printf("Q: 저장하고 종료\n");
            quit = 1;
            break;              // ← switch만 나감! 그래서 쪽지(quit)를 남겨요
        default:
            printf("'%c': 모르는 명령, 건너뜀\n", *p);
            skip++;
            continue;           // ← switch를 뚫고 for의 다음 바퀴로
    }
    if (quit) break;            // ← 여기서 진짜로 for를 나감
    done++;
    printf("%c 후: 평균 %d, 255 개수 %d\n", *p, avg_all(), count255());
}
printf("실행 %d, 무시 %d\n", done, skip);
show();
```
(`avg_all()`은 전체 평균, `count255()`는 255인 점의 개수를 돌려주는 2중 반복 함수예요.)
```
B 후: 평균 140, 255 개수 3
I 후: 평균 114, 255 개수 0
'X': 모르는 명령, 건너뜀
T 후: 평균 136, 255 개수 16
  채운 픽셀 12
F 후: 평균 85, 255 개수 4
Q: 저장하고 종료
실행 4, 무시 1
 128 128 128   0   0   0
 128 128   0   0   0   0
 128   0   0   0   0   0
 128 128 128   0 255 255
 128 128 128   0 255 255
```
**해설:**
- **B**: 모두 +40. 이미 255인 3칸은 `clamp` 덕분에 255로 그대로(없었으면 39가 됐을 거예요!). 210 → 250은 255가 아니라서 개수는 3.
- **I**: 밝은 건 어둡게, 어두운 건 밝게. 255였던 3칸은 0이 돼서 개수 0.
- **X**: 모르는 명령. `continue`는 `switch`를 **뚫고 나가서** `for`의 다음 바퀴로 가요. 그래서 아래의 `done++`와 출력이 실행되지 않아요.
- **T**: 128 이상은 하양(255), 아니면 검정(0). 하양 16칸.
- **F**: `img[0][0]`이 255라서 왼쪽 위로 이어진 **하얀 영역 12칸**을 128(회색)로 칠해요. 오른쪽 아래 하얀 4칸은 검정(0)으로 막혀 있어서 안 번졌어요. 그래서 255가 4개 남아요.
- **Q**: 여기가 오늘의 핵심 함정이에요! `switch` 안의 `break`는 **`switch`라는 작은 방에서만** 나가요. `for`는 계속 돌아서 마지막 `B`까지 실행돼 버려요. 그래서 흐름제어 퀴즈 1처럼 **`quit` 쪽지**를 남기고 `switch` 밖에서 `if (quit) break;`로 진짜 반복을 끝내요. 마지막 `B`는 실행되지 않았어요.

정리하면 `switch` 안에서는
- `break` → `switch`만 나감 (반복은 계속)
- `continue` → `switch`는 상관없이 **반복의 다음 바퀴**로 감 (`switch`에는 `continue`가 없어서 바깥 반복의 것이 쓰여요)

사진 앱의 "되돌리기 / 필터 순서대로 적용" 기능도 이렇게 **명령 목록 + `switch` 엔진**으로 돼 있어요. 버튼을 누를 때마다 명령 글자가 목록에 쌓이고, 엔진이 하나씩 꺼내 실행해요.

## 오늘의 한 줄 정리
- `switch`에서 `case`를 묶으면 같은 답을 공유하고, `break`를 빠뜨리면 **아래 층으로 흘러가요**.
- 비트 깃발: 켜기 `f |= X`, 확인 `f & X` (`&&` 아님!)
- `do-while`은 "**적어도 한 번**" 하는 일(OTP, 비밀번호 입력)에 써요.
- 함수 포인터 배열 = 리모컨 버튼 판. 규칙을 추가해도 엔진 반복은 그대로예요.
- 구조체를 그냥 넘기면 **복사본**, 주소로 넘겨야 **원본**이 바뀌어요.
- `u8`는 255 다음이 0! 계산은 `int`, 담기 전에 `clamp`.
- 2차원 배열은 메모리에선 한 줄 기차: 줄 = 번호 / 칸수, 칸 = 번호 % 칸수.
- 재귀는 "먼저 표시(칠하기), 그다음 부탁". 멈추는 규칙이 꼭 있어야 해요.
- `switch` 안의 `break`는 `switch`만, `continue`는 반복의 다음 바퀴로!
