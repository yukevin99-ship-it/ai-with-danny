## 엔지니어가 직면한 가상의 문제 1

**[Riot Games 매치메이킹팀]** "실력 차이가 너무 나는 사람이랑 붙었어요!", "30분째 매칭이 안 잡혀요!" 두 가지 불만이 동시에 쏟아져요. 매치메이킹 서버는 **실력 점수(MMR)가 비슷한 사람끼리** 붙여야 하지만, 너무 오래 기다린 사람은 **조금 더 넓은 범위**에서라도 찾아 줘야 해요. 오늘 대기열에 8명이 있어요.

```c
#include <stdio.h>
#include <stdlib.h>     // abs

#define MAXP 8

typedef struct { int wins, losses; } Record;                         // 전적
typedef struct { char name[8]; int mmr; int wait; Record rec; } Player;  // wait = 기다린 시간(초)
typedef struct { int id; const char *a, *b; int diff; } Match;

Player q[MAXP] = {
    {"Ari", 1480,  30, {12,  8}}, {"Bo",  2210,   5, {40, 10}},
    {"Cy",  1525,  90, { 7, 13}}, {"Dan",  980, 200, { 3, 17}},
    {"Eve", 2150,  60, {33, 17}}, {"Fin", 1300,  10, {15, 15}},
    {"Gus", 1600, 150, {20, 20}}, {"Hye", 1010,  45, { 9, 11}},
};
const char *TN[5] = {"브론즈", "실버", "골드", "플래티넘", "다이아"};
```

- **조건문 퀴즈 1:** `int tier_index(int mmr)`를 `if - else if - else`로 만드세요. 1000 미만 브론즈(0), 1400 미만 실버(1), 1800 미만 골드(2), 2200 미만 플래티넘(3), 나머지 다이아(4). 그리고 `int winrate(Record r)`는 판수가 0이면 `-1`, 아니면 승률(%)을 정수로 돌려줘요. 8명을 `"Ari: 골드, 승률 60%"`처럼 출력하세요.
  (① `if (mmr >= 1000)`을 **맨 먼저** 검사하면 Bo(2210)는 뭐가 될까요? ② 승률을 `r.wins / (r.wins + r.losses) * 100`으로 쓰면 결과가 어떻게 될까요? ③ 판수 0 검사를 왜 꼭 해야 할까요?)
- **반복문 퀴즈 1 (상한이 있는 누적):** 허용 MMR 차이는 처음 **50**이고, **30초 기다릴 때마다 +50**, 단 **최대 300**이에요. 공식 대신 `for (int s = 30; s <= wait; s += 30)` 반복으로 `int tol(int wait)`를 만들고, 300에 닿으면 `t = 300;` 후 `break`하세요. 8명의 허용 범위는? (Dan은 반복을 몇 번 돌고 멈출까요?)
- **흐름제어 퀴즈 1 (`goto`로 탈출):** "차이가 **40 이하**인 첫 번째 짝"을 찾아요. `for (i...) for (j = i + 1...)` 이중 반복으로 비교할 때마다 `checks++`, 찾으면 `"찾음: 이름-이름 (차이 N), 비교 K번"`을 출력하고 `goto found;`. 끝까지 못 찾으면 `"매칭 없음"`. 비교는 몇 번 할까요? `break` 하나만 썼다면 어떻게 됐을까요?
- **배열 퀴즈 1 (개수 세기 + 누적 합):** `int cnt[5] = {0};`에 `cnt[tier_index(q[i].mmr)]++`로 티어별 인원을 세요. 그리고 `below`(나보다 낮은 티어 인원의 **누적 합**)를 함께 출력하세요: `"골드 3명 (아래 티어 3명)"`. 플래티넘인 Eve보다 아래 티어는 몇 명일까요?

  4. 모두 매칭되면 `break`. 아니면 **남은 사람만** `wait += 30` 하고 다음 라운드
  5. 끝나고 남은 사람은 `"대기 계속: 이름 (N초)"`

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[삼성 갤럭시 키보드팀]** 스마트폰 키보드는 내가 "he"까지만 쳐도 "hello / help / her"를 추천해 주고, "wurk"라고 잘못 치면 "work"로 고쳐 줘요. 그리고 내가 자주 쓰는 단어는 **점점 더 앞에** 추천해요. 오늘은 이 **자동완성·자동수정 엔진**을 새로 만들어요.

```c
#include <stdio.h>
#include <string.h>     // strlen, strcmp, strcpy, memcpy

#define MAXW 10
#define WLEN 12

typedef struct { char text[WLEN]; int freq; } Word;   // freq = 얼마나 자주 썼나

Word dict[MAXW] = {
    {"world", 40}, {"hello", 50}, {"work", 90}, {"help", 80},
    {"word", 70}, {"hero", 35}, {"her", 60}, {"helmet", 10},
};
int n = 8;    // 지금 사전에 든 단어 수
```

- **조건문 퀴즈 1:** `char normalize(char c)`를 만드세요. 대문자면 소문자로(`c - 'A' + 'a'`), 소문자나 공백(`' '`)이면 그대로, 나머지(숫자, 문장부호)는 `0`을 돌려줘서 "무시"하게 해요. `"HeL1o, Wo!"`의 글자마다 결과는?
  (① 대문자 검사를 `if ('A' <= c <= 'Z')`로 쓰면 `'!'`는 어떻게 될까요? 왜 그럴까요? ② `'H' - 'A' + 'a'`가 왜 `'h'`일까요?)
- **반복문 퀴즈 1:** `"HeL1o, Wo!"`를 `for (i = 0; t[i] != '\0'; i++)`로 돌면서 `normalize`가 0이면 `continue`, 아니면 `out[k++]`에 담아요. 마지막에 `out[k] = '\0';`. 결과 문자열과 길이는?
- **흐름제어 퀴즈 1:** 접두사 `"he"`로 시작하는 단어를 **사전 순서대로 최대 3개** 보여줘요. 단어마다 `checked++`, 접두사가 아니면 `continue`, 맞으면 출력하고 3개가 되면 `break`. 무엇이 나오고, 몇 단어를 검사했나요? 안 보인 `he` 단어 중에 아까운 것은?

- **포인터 변수 퀴즈 1:** `int is_prefix(const char *pre, const char *w)`를 `while (*pre)` 안에서 `*pre != *w`면 `return 0`, 아니면 `pre++; w++;`로 만드세요. 다음 결과는?
  `("he","hello")`, `("hel","her")`, `("hello","hel")`, `("","work")`, `("wor","world")`
  (③번은 `w`가 더 짧은데 왜 사고가 안 날까요? `const char *pre`의 `const`는 무엇을 막을까요? `char *const pre`와는 무엇이 다를까요?)
- **구조체 퀴즈 1 (출력 매개변수):** `int learn(Word *d, int *n, const char *w)`를 만드세요. 사전에 있으면(`strcmp`) `freq += 10` 후 새 빈도를 돌려주고, 없으면 사전이 꽉 찼을 때(`*n >= MAXW`) `-1`, 아니면 `strcpy`로 맨 뒤에 넣고 `freq = 10`, `(*n)++`, `10`을 돌려줘요. `"work"`, `"zap"`, `"zip"`, `"zoo"`를 차례로 `learn`한 결과와 마지막 `n`은? `sizeof(Word)`는? (`*n++`이라고 쓰면 무슨 일이 생길까요?)
- **함수 퀴즈 1 (자동수정 판단):** `int one_typo(const char *a, const char *b)`는 **길이가 같고 딱 한 글자만** 다르면 1이에요. 길이가 다르면 바로 0, 다른 글자가 2개째 나오면 바로 `return 0`. 결과는?
  `("wurk","work")`, `("wrok","work")`, `("helo","help")`, `("helo","hero")`, `("helo","hello")`, `("work","work")`
  "helo"는 고칠 후보가 2개예요. 어느 것으로 고쳐야 할까요?
- **흐름제어 퀴즈 2 (종합):** 키 입력 줄 `"HeLx<p wurk helo zap wo#"`을 한 글자씩 처리해요. (`'<'` = 지우기, `' '` = 단어 확정, `'#'` = 입력 끝)
  1. `'<'`: 버퍼가 비어 있지 않으면 한 글자 지우고 `"  ⌫ -> [hel]"` 출력 후 `continue`
  2. `' '`: 버퍼 단어가 사전에 있으면 `"확정: help -> 빈도 90"`. 없으면 `one_typo`인 단어 중 **빈도가 가장 큰 것**으로 `"자동 수정: wurk -> work, 빈도 100"`. 그것도 없으면 `learn`으로 `"새 단어: zap (빈도 10)"`. 버퍼를 비우고 `continue`
  3. `'#'`: `"끝. 입력 중인 [wo]"`를 출력하고, 지금 버퍼를 접두사로 **빈도 높은 순 3개** 추천(`"추천(wo): ..."`) 후 `break`
  4. 그 밖의 글자는 `normalize`해서 0이면 무시, 아니면 버퍼에 추가 (버퍼가 꽉 차면 무시)
  5. 마지막에 `"자동수정 N번, 새 단어 M개, 사전 K개"`
  실제 출력은? 흐름제어 퀴즈 1과 달리 왜 이번 추천은 "사전 순서"가 아니라 "빈도 순서"일까요?

# 정답 및 해설 (초등학교 5학년 눈높이)

## 문제 1: Riot Games 매치메이킹

### 조건문 정답
```c
int tier_index(int mmr) {
    if (mmr < 1000)      return 0;   // 브론즈
    else if (mmr < 1400) return 1;   // 실버
    else if (mmr < 1800) return 2;   // 골드
    else if (mmr < 2200) return 3;   // 플래티넘
    else                 return 4;   // 다이아
}

int winrate(Record r) {
    int games = r.wins + r.losses;
    if (games == 0) return -1;            // 0으로 나누기 금지!
    return r.wins * 100 / games;          // 먼저 곱하고, 나중에 나눠요
}

// main
for (int i = 0; i < MAXP; i++)
    printf("%s: %s, 승률 %d%%\n", q[i].name, TN[tier_index(q[i].mmr)], winrate(q[i].rec));
```
```
Ari: 골드, 승률 60%
Bo: 다이아, 승률 80%
Cy: 골드, 승률 35%
Dan: 브론즈, 승률 15%
Eve: 플래티넘, 승률 66%
Fin: 실버, 승률 50%
Gus: 골드, 승률 50%
Hye: 실버, 승률 45%
```
**해설:**
- `else if`는 **위에서부터 차례로 물어보는 문지기 줄**이에요. 첫 문지기가 "1000 미만이니?"라고 물어서 아니면 다음 문지기에게 보내요. 두 번째 문지기는 "1400 미만이니?"만 물어봐도 돼요. 이미 "1000 이상"이라는 건 앞 문지기가 확인해 줬으니까요.
- ① `if (mmr >= 1000)`을 맨 앞에 두면 Bo(2210)도 1000 이상이니까 **첫 문을 통과해서 실버**가 돼 버려요! `else if`에서는 **좁은 조건부터** 물어야 해요(작은 수부터 `<`로 올라가거나, 큰 수부터 `>=`로 내려가거나).
- ② `12 / 20 * 100`은 **0**이에요. C에서 정수끼리 나누면 소수점을 버려요. 12 ÷ 20 = 0.6 → 0, 그다음 × 100 = 0. 그래서 8명 모두 승률 0%가 돼요. **곱하기를 먼저** 해서 `1200 / 20 = 60`으로 계산해야 해요.
- ③ 처음 온 신규 유저는 0승 0패예요. 0으로 나누면 프로그램이 **죽어요**(정수 0 나누기는 C에서 정의되지 않은 동작이고, 보통 서버가 멈춰요). 그래서 "판수가 0이면 계산하지 말고 -1"이라고 먼저 막아요.

### 반복문 정답
```c
int tol(int wait) {
    int t = 50;
    for (int s = 30; s <= wait; s += 30) {
        t += 50;
        if (t >= 300) { t = 300; break; }   // 상한(뚜껑)
    }
    return t;
}
```
```
Ari 30초 -> 100   Bo 5초 -> 50    Cy 90초 -> 200   Dan 200초 -> 300
Eve 60초 -> 150   Fin 10초 -> 50  Gus 150초 -> 300 Hye 45초 -> 100
```
**해설:** `s`는 "30초, 60초, 90초…" 하고 **알람 시계**처럼 울려요. 기다린 시간이 그 알람을 지날 때마다 범위가 50씩 넓어져요. Dan은 30, 60, 90, 120, 150초 — **5번** 돌고 300에 닿아서 `break`해요. 180초 알람은 울릴 필요가 없죠. 뚜껑(300)을 안 두면 1시간 기다린 사람은 범위가 6000이 돼서 브론즈와 다이아가 붙게 돼요. 그게 바로 "실력 차이가 너무 나요!" 불만의 원인이에요.

### 흐름제어 퀴즈 1 정답
```c
int checks = 0;
for (int i = 0; i < MAXP; i++) {
    for (int j = i + 1; j < MAXP; j++) {
        checks++;
        int d = abs(q[i].mmr - q[j].mmr);
        if (d <= 40) {
            printf("찾음: %s-%s (차이 %d), 비교 %d번\n", q[i].name, q[j].name, d, checks);
            goto found;
        }
    }
}
printf("매칭 없음\n");
found:
    ;   // 라벨 뒤에는 문장이 있어야 해서 빈 문장
```
```

```

### 포인터 변수 정답
```c
int m[8] = {980, 1010, 1300, 1480, 1525, 1600, 2150, 2210};
int T = 3100, best = -1, bl = 0, bh = 0, step = 0;
int *lo = m, *hi = m + 7;
while (lo < hi) {
    int s = *lo + *hi, d = abs(s - T);
    printf("%d단계: %d+%d=%d (차이 %d), hi-lo=%ld\n", ++step, *lo, *hi, s, d, (long)(hi - lo));

    if (s == T) break;
    else if (s < T) lo++;     // 합이 작다 → 작은 쪽을 키운다
    else            hi--;     // 합이 크다 → 큰 쪽을 줄인다
}

```

### 구조체 정답
```c
void swap(Player *a, Player *b) { Player t = *a; *a = *b; *b = t; }

int sel_sort(Player *a, int n) {
    int sw = 0;
    for (int i = 0; i < n - 1; i++) {
        int mi = i;                                   // 가장 작은 사람 자리
        for (int j = i + 1; j < n; j++)
            if (a[j].mmr < a[mi].mmr) mi = j;
        if (mi != i) { swap(&a[i], &a[mi]); sw++; }   // 이미 제자리면 안 바꿈
    }
    return sw;
}
```
```
Dan(980) Hye(1010) Fin(1300) Ari(1480) Cy(1525) Gus(1600) Eve(2150) Bo(2210)
swap 5번, sizeof(Player) = 24
```
**해설:** 선택 정렬은 "**남은 사람 중 가장 작은 사람을 골라 맨 앞으로**"를 반복해요. `swap`은 Player 한 명을 **이름, 점수, 대기 시간, 전적까지 가방째로** 바꿔요. 점수만 바꾸면 Dan의 점수가 Ari 이름에 붙는 대참사가 나요! `mi != i`일 때만 바꿔서 쓸데없는 일을 줄였어요(7번 중 5번만 실제로 바꿈).
`sizeof(Player)` = 이름 8 + mmr 4 + wait 4 + Record(4 + 4) 8 = **24바이트**.
전적은 **상자 안의 상자**예요. 변수 이름으로 가지고 있으면 `q[i].rec.wins`(점 두 번), 포인터(주소)로 가지고 있으면 `p->rec.wins`(화살표 한 번 + 점 한 번). `rec`은 포인터가 아니라 Player 안에 **진짜로 들어 있는** 구조체라서 두 번째는 점이에요.

**해설:** 보통 함수 안의 변수는 함수가 끝나면 **지워지는 칠판**이에요. `static`을 붙이면 **지워지지 않는 칠판**이 돼서 지난번 숫자를 기억해요. 그래서 번호표 기계처럼 1001, 1002, 1003… 이 나와요. `static`을 지우면 매번 새 칠판에 1001을 쓰니까 **모든 매치가 #1001** → 서버 기록에서 매치끼리 구별이 안 돼요!
`make_match`는 결과를 Match 가방 하나에 담아서 **통째로** 돌려줘요. 돌려줄 값이 4개여도 `return` 하나면 끝이에요. 매개변수가 `const Player *`인 건 "이 함수는 선수 정보를 **읽기만** 하고 안 고쳐요"라는 약속이에요.

## 프로그램 1: 삼성 갤럭시 키보드 자동완성·자동수정

### 조건문 정답
```c
char normalize(char c) {
    if ('A' <= c && c <= 'Z')                      return c - 'A' + 'a';
    else if (('a' <= c && c <= 'z') || c == ' ')   return c;
    else                                           return 0;   // 무시
}
```
```
'H'->'h'  'e'->'e'  'L'->'l'  '1'->무시  'o'->'o'  ','->무시
' '->' '  'W'->'w'  'o'->'o'  '!'->무시
```
**해설:**
- ① `'A' <= c <= 'Z'`는 수학처럼 보이지만 C는 **왼쪽부터 두 번에 나눠** 계산해요. 먼저 `'A' <= '!'` → 거짓 → **0**. 그다음 `0 <= 'Z'`(0 ≤ 90) → 참 → **1**! 그래서 `'!'`도, `'a'`도, 무슨 글자든 "대문자"가 돼 버려요. 반드시 `'A' <= c && c <= 'Z'`처럼 **두 조건을 `&&`로** 묶어야 해요.
- ② 컴퓨터 속 글자는 사실 **번호**예요. `'A'`=65, `'H'`=72, `'a'`=97. `'H' - 'A'`는 "A에서 몇 칸 떨어졌나" = 7. 거기에 `'a'`(97)를 더하면 104 = `'h'`. 대문자 줄과 소문자 줄이 **똑같은 순서로 32칸 떨어져** 있어서 가능한 마법이에요.

### 반복문 정답
```c
const char *t = "HeL1o, Wo!";
char out[32];
int k = 0;
for (int i = 0; t[i] != '\0'; i++) {
    char c = normalize(t[i]);
    if (c == 0) continue;      // 숫자·문장부호는 건너뛰기
    out[k++] = c;
}
out[k] = '\0';
printf("[%s] 길이 %d\n", out, k);
```
```

```
**해설:** `i`는 원래 글자를 읽는 손가락, `k`는 새 종이에 쓰는 손가락이에요. 버릴 글자가 나오면 `i`만 앞으로 가고 `k`는 가만히 있어요. 그래서 `"HeL1o"`의 `1`이 빠져서 **"helo"**가 됐어요. 사용자는 "hello"를 치려다 실수한 거죠. 이 "helo"는 흐름제어 퀴즈 2에서 다시 나와요! 마지막 `'\0'`은 "문자열 여기서 끝"이라는 **마침표**예요. 빼먹으면 `printf`가 쓰레기 글자까지 계속 읽어요.

### 포인터 변수 정답
```c
int is_prefix(const char *pre, const char *w) {
    while (*pre) {                    // 접두사 글자가 남아 있는 동안
        if (*pre != *w) return 0;
        pre++; w++;
    }
    return 1;                         // 접두사를 다 통과!
}
```
```
("he","hello") = 1
("hel","her")  = 0
("hello","hel")= 0
("","work")    = 1
("wor","world")= 1
```
**해설:**
- 두 손가락을 각 단어 첫 글자에 올리고 **동시에 한 칸씩** 옮기면서 같은지 봐요. 접두사 손가락이 끝(`'\0'`)에 닿으면 성공!
- ③ `"hello"`와 `"hel"`: 4번째에서 `w`는 이미 마침표 `'\0'`(0번 글자)를 가리켜요. `'l' != '\0'` → **다르니까 바로 0**. 그래서 짧은 단어 밖으로 넘어가기 전에 멈춰요. 마침표가 안전장치예요.
- ④ 빈 접두사 `""`는 아무것도 안 쳤다는 뜻이라 모든 단어가 후보예요(1).
- `const char *pre`: "**가리키는 글자**를 못 고쳐요"(`*pre = 'x'` 금지), 하지만 손가락은 옮길 수 있어요(`pre++` OK).
  `char *const pre`: 정반대예요. "**손가락**이 못 움직여요"(`pre++` 금지), 글자는 고칠 수 있어요. 이 함수는 손가락을 움직여야 하니까 앞의 것을 써요.

```c
int learn(Word *d, int *n, const char *w) {
    int k = find(d, *n, w);
    if (k >= 0) { d[k].freq += 10; return d[k].freq; }
    if (*n >= MAXW) return -1;                     // 사전 꽉 참
    strcpy(d[*n].text, w);
    d[*n].freq = 10;
    (*n)++;
    return 10;
}
```
```
learn("work") = 100
learn("zap")  = 10
learn("zip")  = 10
learn("zoo")  = -1     (n = 10, 꽉 참)
sizeof(Word) = 16
```
**해설:**
- `strcmp`는 두 단어를 비교해서 **같으면 0**을 돌려줘요. "같으면 1"이 아니라서 처음엔 헷갈려요! `if (strcmp(a, b))`라고만 쓰면 오히려 **다를 때** 참이 돼요.
- `d[k].text = w;`처럼 배열에 `=`를 쓸 수는 없어요. 글자를 **한 칸씩 베껴 쓰는** `strcpy`를 써야 해요.
- `int *n`은 main에 있는 **단어 개수 상자의 주소**예요. 함수 안에서 `(*n)++` 하면 main의 `n`이 진짜로 8 → 9 → 10이 돼요. `*n++`이라고 쓰면 `++`가 먼저 붙어서 "**주소를 한 칸 옮기고** 그 자리를 읽기"가 돼요. 개수는 그대로고 엉뚱한 메모리를 건드려요. 그래서 괄호가 꼭 필요해요.
- `sizeof(Word)` = 글자 12 + int 4 = **16바이트**.

### 함수 정답
```c
int one_typo(const char *a, const char *b) {
    if (strlen(a) != strlen(b)) return 0;
    int diff = 0;
    for (; *a; a++, b++)
        if (*a != *b && ++diff > 1) return 0;     // 2개째 다르면 즉시 포기
    return diff == 1;
}
```
```
("wurk","work")  = 1
("wrok","work")  = 0   (r↔o 자리 바꿈 = 2글자 다름)
("helo","help")  = 1
("helo","hero")  = 1
("helo","hello") = 0   (길이가 다름)
("work","work")  = 0   (똑같으면 오타가 아님)
```
**해설:** 받아쓰기 채점처럼 한 글자씩 맞춰 보다가 **두 번째 틀린 글자**가 나오면 더 볼 필요 없이 "이건 오타 1개가 아니야" 하고 끝내요. `*a != *b && ++diff > 1`에서 글자가 같으면 `&&` 뒤는 아예 계산 안 해요(단락 평가). 그래서 diff는 **다를 때만** 올라가요.
"helo"는 help로도 hero로도 고칠 수 있어요. 이럴 때 키보드는 **빈도가 더 큰 쪽**(help 80 > hero 35)으로 고쳐요. 사람들이 더 많이 쓰는 단어일수록 "원래 치려던 단어"일 가능성이 높으니까요.

### 흐름제어 퀴즈 2 정답 (종합)
```c
void suggest(const Word *d, int n, const char *pre) {
    int shown[MAXW] = {0};
    printf("추천(%s):", pre);
    for (int k = 0; k < 3; k++) {                  // 1등, 2등, 3등을 차례로
        int best = -1;
        for (int i = 0; i < n; i++) {
            if (shown[i] || !is_prefix(pre, d[i].text)) continue;
            if (best < 0 || d[i].freq > d[best].freq) best = i;
        }
        if (best < 0) break;                       // 후보가 더 없음
        shown[best] = 1;
        printf(" %s(%d)", d[best].text, d[best].freq);
    }
    printf("\n");
}

int main(void) {
    const char *keys = "HeLx<p wurk helo zap wo#";
    char buf[WLEN] = "";
    int len = 0, corrected = 0, added = 0;

    for (const char *p = keys; ; p++) {
        char c = *p;
        if (c == '<') {                                    // 지우기
            if (len > 0) len--;
            buf[len] = '\0';
            printf("  ⌫ -> [%s]\n", buf);
            continue;
        }
        if (c == '#' || c == '\0') {                       // 입력 끝
            buf[len] = '\0';
            printf("끝. 입력 중인 [%s]\n", buf);
            suggest(dict, n, buf);
            break;
        }
        if (c == ' ') {                                    // 단어 확정
            buf[len] = '\0';
            if (len == 0) continue;
            if (find(dict, n, buf) >= 0) {
                printf("확정: %s -> 빈도 %d\n", buf, learn(dict, &n, buf));
            } else {
                int best = -1;
                for (int i = 0; i < n; i++)
                    if (one_typo(buf, dict[i].text) && (best < 0 || dict[i].freq > dict[best].freq))
                        best = i;
                if (best >= 0) {
                    printf("자동 수정: %s -> %s, 빈도 %d\n", buf, dict[best].text,
                           learn(dict, &n, dict[best].text));
                    corrected++;
                } else {
                    int r = learn(dict, &n, buf);
                    if (r < 0) printf("사전 꽉 참: %s 버림\n", buf);
                    else { printf("새 단어: %s (빈도 %d)\n", buf, r); added++; }
                }
            }
            len = 0; buf[0] = '\0';
            continue;
        }
        char nc = normalize(c);
        if (nc == 0 || len >= WLEN - 1) continue;          // 무시할 글자 / 버퍼 꽉 참
        buf[len++] = nc;
        buf[len] = '\0';
    }
    printf("자동수정 %d번, 새 단어 %d개, 사전 %d개\n", corrected, added, n);
    return 0;
}
```
```
  ⌫ -> [hel]
확정: help -> 빈도 90
자동 수정: wurk -> work, 빈도 100
자동 수정: helo -> help, 빈도 100
새 단어: zap (빈도 10)
끝. 입력 중인 [wo]
추천(wo): work(100) word(70) world(40)
자동수정 2번, 새 단어 1개, 사전 9개
```
**해설:**
- **한 글자씩 보고 "이 글자는 어떤 종류야?"를 묻는 게** 키보드 프로그램의 심장이에요. `'<'`면 지우기, `' '`면 확정, `'#'`면 끝, 나머지는 쓰기. 종류마다 할 일을 하고 `continue`로 다음 글자로 가요.
- `"HeLx<p"`: h, e, l, x까지 쓰고 `<`로 x를 지운 다음 p → **help**. 사전에 있어서 빈도 80 → 90.
- `"wurk"`: 사전에 없지만 work와 한 글자만 달라서 **자동 수정**, work 90 → 100.
- `"helo"`: help(90)와 hero(35) 둘 다 후보예요. 빈도가 큰 **help**로 고쳐서 90 → 100. 쓸수록 더 잘 맞히는 키보드가 됐어요!
- `"zap"`: 아무것도 안 닮아서 **새 단어**로 배워요. 다음에 "za"만 쳐도 추천돼요.
- `"wo"` 다음에 `'#'`: 추천은 **빈도 순**이에요. 흐름제어 퀴즈 1처럼 사전 순서로 고르면 world가 맨 앞에 왔겠지만, 사람들은 work를 훨씬 많이 쓰니까 **work가 1등**이에요. "제일 큰 것 찾기"를 3번 반복하고 `shown[]`으로 이미 뽑은 것을 빼면 정렬 없이도 1·2·3등을 뽑을 수 있어요.
- `len >= WLEN - 1` 검사: 버퍼는 12칸인데 마지막 한 칸은 마침표 `'\0'` 자리예요. 누가 글자를 100개 연속으로 쳐도 **11글자까지만** 받아서 메모리가 넘치지 않게 해요. 해커들이 노리는 "버퍼 오버플로"를 막는 습관이에요.
