## 엔지니어가 직면한 가상의 문제 1

**[업비트(Upbit) 매칭 엔진팀]** 새로 상장한 가상의 코인 **"DANNY 코인"**(기준가 50,000원)에서 이상한 신고가 들어왔어요. "50,020원에 사겠다고 했는데 주문이 들어갔다", "시장가로 샀는데 갑자기 가격이 확 뛰었다"… 엔지니어인 너는 **주문 검사 → 가장 좋은 상대 찾기 → 체결 → 호가창 정리 → 급등하면 거래 정지(VI)**를 하는 매칭 엔진을 다시 짜야 해요!

### 반복문 퀴즈1 정답

```c
int best_index(Order b[], int n) {
    int bi = -1;
    for (int i = 0; i < n; i++) {
        if (b[i].qty == 0) continue;                 // 빈 주문은 무시
        if (bi == -1) { bi = i; continue; }          // 첫 후보
        int better = (b[i].side == SELL) ? (b[i].price < b[bi].price)
                                         : (b[i].price > b[bi].price);
        if (better || (b[i].price == b[bi].price && b[i].time < b[bi].time))
            bi = i;
    }
    return bi;
}
```

- `bids`의 1등: **202** (49,990원). 사는 쪽은 비싸게 사겠다는 사람이 1등이에요.

**🧒 쉽게 설명하면:** 반에서 "제일 키 큰 사람"을 찾을 때, 첫 번째 친구를 일단 1등 자리에 세우고 한 명씩 비교해서 더 크면 바꾸잖아요. 여기선 규칙이 두 개예요. ① 값이 더 좋으면 바꾼다 ② 값이 똑같으면 **줄을 먼저 선 사람**이 이긴다. 줄 서기는 공평해야 하니까요! `bi == -1`로 시작하는 건 "아직 1등 자리가 비어 있음"이라는 표시예요.

### 배열 퀴즈1 정답

```c
void compact(Order b[], int *n) {
    int w = 0;                          // 쓰는 손가락
    for (int r = 0; r < *n; r++)        // 읽는 손가락
        if (b[r].qty > 0)
            b[w++] = b[r];              // 살아 있는 주문만 앞으로
    *n = w;
}
```
301 뒤: `asks` = `101(50100 x2) 104(50200 x5)`, `na = 2`

**🧒 쉽게 설명하면:** 줄에서 빠진 친구가 있으면 뒤 친구들이 앞으로 한 칸씩 당겨 서죠. 오른손가락(`r`)은 모든 친구를 하나씩 보고, 왼손가락(`w`)은 "다음에 설 자리"를 가리켜요. 남을 친구만 `w` 자리에 세우고 `w`를 한 칸 옮겨요. 마지막에 `w`가 곧 남은 친구 수예요.
`int *n`인 이유: 함수에 `int n`을 주면 **숫자를 적은 쪽지의 복사본**을 주는 거라서, 함수 안에서 고쳐도 바깥 `na`는 그대로 4예요. 그러면 바깥에서는 아직 4명이 있는 줄 알고 쓰레기 칸을 읽어요. `&na`(진짜 `na`의 주소)를 줘야 진짜를 고칠 수 있어요.

### 포인터 변수 퀴즈1 정답

```c
Order *best(Order *b, int n) {
    Order *bp = NULL;
    for (Order *p = b; p < b + n; p++) {
        if (p->qty == 0) continue;
        if (bp == NULL) { bp = p; continue; }
        int better = (p->side == SELL) ? (p->price < bp->price)
                                       : (p->price > bp->price);
        if (better || (p->price == bp->price && p->time < bp->time))
            bp = p;
    }
    return bp;                          // 없으면 NULL
}

int fill(Order *t, Order *m) {
    int f = t->qty < m->qty ? t->qty : m->qty;
    t->qty -= f;
    m->qty -= f;                        // 진짜 호가창 주문이 줄어요
    return f;
}
```
③ **함정의 답:** `Order m = asks[...]`는 **복사본**을 만든 거예요. `fill(&in, &m)`은 복사본의 수량만 줄이고, 진짜 `asks[1]`(102)은 여전히 2개 그대로예요. 다음 반복에서 `best`가 또 102를 1등으로 뽑아요. 결과: 301이 102한테서 2+2+2+1 = **7개**를 사요. 102는 2개밖에 안 팔겠다고 했는데! 없는 코인을 파는 **유령 체결**이에요. (만약 `in`까지 복사본이었다면 아무것도 안 줄어서 **무한 루프**가 돼요.) 반드시 `Order *m = best(asks, na);`처럼 **진짜를 가리켜야** 해요.

**🧒 쉽게 설명하면:** 친구 공책을 **복사기로 복사해서** 지우개로 지우면, 친구 진짜 공책은 그대로죠? 포인터는 "친구 공책이 있는 책상 위치"를 알려 주는 것이라서, 그 위치로 가서 지우면 진짜 공책이 지워져요. `p < b + n`은 "책상 줄 끝까지 걸어가라"는 뜻이에요. `b + n`은 마지막 책상 **바로 다음 자리**라서 `<`를 써요(`<=`면 없는 책상까지 가요!).

### 함수 퀴즈1 정답

```c
int halted = 0;

int crosses(const Order *in, const Order *m) {
    if (in->type == MARKET) return 1;
    if (in->side == BUY)    return in->price >= m->price;
    return in->price <= m->price;
}

int vi_hit(int price) { return abs(price - BASE) * 1000 >= 3 * BASE; }

int match(Order *in, Order book[], int *n) {
    while (in->qty > 0) {
        Order *m = best(book, *n);
        if (m == NULL)        break;
        if (!crosses(in, m))  break;
        if (vi_hit(m->price)) {
            printf("  VI 발동! %d원 체결 직전 거래 정지\n", m->price);
            halted = 1;
            break;
        }
        int f = fill(in, m);
        logt[nt++] = (Trade){ in->id, m->id, m->price, f };
        printf("  체결: %d <- %d  %d원 x %d\n", in->id, m->id, m->price, f);
    }
    compact(book, n);
    return in->qty;
}
```
VI 검사: 50,100 → 차이 100 → 100,000 < 150,000 ❌ / **50,200 → 차이 200 → 200,000 ≥ 150,000 ✅** / 49,950 ❌ / **49,850 → 차이 150 → 150,000 ≥ 150,000 ✅**

**🧒 쉽게 설명하면:** 함수는 "한 가지 일만 하는 로봇"이에요. 체결 가능 로봇, 급등 감시 로봇, 매칭 로봇이 따로 있으면 어디가 고장 났는지 금방 찾아요.
`× 1000`인 이유: 컴퓨터는 0.003 같은 소수를 정확히 못 적어요(0.1+0.2가 0.30000000000000004가 되는 것처럼). 돈 계산에서 1원 오차는 큰일! 그래서 양쪽에 1000을 곱해서 **정수끼리만** 비교해요. `abs`는 "위로 벗어났든 아래로 벗어났든 거리만 봐"라는 뜻이고요.

**🧒 쉽게 설명하면:** 지구가 태양을 한 바퀴 도는 데 365일보다 **약 6시간** 더 걸려요. 4년 모으면 하루가 되니까 4년마다 2월 29일을 넣어요. 그런데 사실 6시간보다 살짝 짧아서, 100년마다 한 번은 빼고, 400년마다 한 번은 다시 넣어요. "4 → 100 → 400" 세 단계 규칙이에요.
**달을 먼저 검사**하는 이유: 달이 13이면 `mdays[13]`을 읽게 되는데, 그런 칸은 없어서 컴퓨터가 엉뚱한 값을 읽어요. 위험한 검사 전에 안전 검사를 먼저 하는 게 조건문 순서의 비밀이에요.

### 반복문 퀴즈1 정답

```c
long day_number(Date d) {
    long n = 0;
    for (int y = 2000; y < d.y; y++) n += is_leap(y) ? 366 : 365;
    for (int m = 1;    m < d.m; m++) n += dim(d.y, m);
    return n + d.d;
}
int days_between(Date a, Date b) { return (int)(day_number(b) - day_number(a)); }
```
- 오늘의 `day_number` = **9824** (2000년 1월 1일이 1번째 날)
- 원래 유통기한 D값: 우유 **7**, 계란 **12**, 두부 **0**, 냉동만두 **97**, 시금치 **-1**, 요거트 **2**, 상추 **2**, 케첩 **159**

**🧒 쉽게 설명하면:** "11월 23일부터 2월 28일까지 며칠?"은 달마다 날 수가 달라서 머리가 아파요. 그래서 모든 날짜에 **번호표**를 붙여요. "2000년 1월 1일 = 1번, 1월 2일 = 2번…" 그러면 두 번호를 빼기만 하면 끝! 지난 해들을 하나씩 더하는 반복, 지난 달들을 하나씩 더하는 반복, 두 개를 차례로 써요. 반복이 `<`인 이유는 **이번 해·이번 달은 아직 다 안 지났기** 때문이에요.

### 흐름제어 퀴즈1 정답

```c
int status(int d) {
    if (d < 0)  return 0;   // 지남
    if (d == 0) return 1;   // 오늘
    if (d <= 3) return 2;   // 임박
    return 3;               // 여유
}
const char *SN[] = {"지남", "오늘", "임박", "여유"};

for (int i = 0; i < NF; i++) {
    Food *f = &foods[i];
    f->ok = parse_date(f->exp_s, &f->exp) && valid_date(f->exp);
    if (!f->ok) { printf("%s: 날짜 오류\n", f->name); continue; }
    int d = days_between(TODAY, f->exp);
    printf("%s: %s\n", f->name, SN[status(d)]);
}
```
```
우유: 여유
계란: 여유
두부: 오늘
냉동만두: 여유
시금치: 지남
요거트: 임박
아이스크림: 날짜 오류
상추: 임박

```
**함정의 답:** 우유는 11월 21일에 뜯었고 3일 안에 먹어야 하니 **24일까지**, 케첩은 10월 1일에 뜯었고 30일 안에 먹어야 하니 **이미 10월 31일에 끝났어요!** 원래 유통기한만 보면 큰일 나요 → 구조체 퀴즈에서 고쳐요.

**🧒 쉽게 설명하면:** `if`를 위에서부터 차례로 물어보는 "체로 거르기"예요. 첫 체(`d < 0`)를 통과 못 한 것만 다음 체로 가니까, `d <= 3`까지 왔다면 이미 "0보다 크다"는 걸 알아요. 그래서 `d >= 1 && d <= 3`처럼 길게 안 써도 돼요. `&&`의 비밀도 있어요: `parse_date`가 실패(0)하면 `valid_date`는 **아예 불리지 않아요**(이미 답이 0이니까). 쓰레기 날짜로 검사하지 않게 막아 주는 거예요.

### 배열 퀴즈1 정답

① 달 번호(1~12)를 **그대로 칸 번호로** 쓰려고요. `mdays[11]`이 바로 11월(30일)이에요. 0번 칸은 안 쓰는 "빈 의자"예요. 12칸으로 만들면 매번 `mdays[m - 1]`이라고 써야 하고, 깜빡하면 한 달씩 밀려요.

② 
```c
int cnt[3][4] = {{0}};
for (int i = 0; i < NF; i++)
    if (foods[i].ok)
        cnt[foods[i].zone][status(foods[i].dday)]++;
```
```
        지남 오늘 임박 여유
냉장칸   1    1    2    1      ← 케첩 / 두부 / 우유·요거트 / 계란
냉동칸   0    0    0    1      ← 냉동만두 (아이스크림은 날짜 오류라 빠짐)
야채칸   1    0    1    0      ← 시금치 / 상추
```
**🧒 쉽게 설명하면:** 2차원 배열은 **엑셀 표**예요. `cnt[줄][칸]`. 음식이 어느 줄(냉장/냉동/야채)·어느 칸(지남/오늘/임박/여유)에 속하는지 알면 그 자리에 바둑돌 하나(`++`)를 올리면 돼요. `enum`이 0, 1, 2 숫자라서 바로 칸 번호로 쓸 수 있어요.

### 포인터 변수 퀴즈1 정답

```c
int read_num(const char **pp, int maxdig) {
    const char *p = *pp;
    int v = 0, n = 0;
    while (*p >= '0' && *p <= '9' && n < maxdig) {
        v = v * 10 + (*p - '0');
        p++; n++;
    }
    if (n == 0) return -1;
    *pp = p;                        // 바깥 손가락을 옮겨 줌
    return v;
}

int parse_date(const char *s, Date *out) {
    const char *p = s;
    int y, m, d;
    if ((y = read_num(&p, 4)) < 0 || *p++ != '-') return 0;
    if ((m = read_num(&p, 2)) < 0 || *p++ != '-') return 0;
    if ((d = read_num(&p, 2)) < 0 || *p != '\0')  return 0;
    out->y = y; out->m = m; out->d = d;     // 다 성공했을 때만 씀
    return 1;
}
```
| 글자 | 결과 | 이유 |
|---|---|---|
| `"2026-11-25"` | 1 (2026, 11, 25) | 완벽 |
| `"2026/11/25"` | 0 | `-` 자리에 `/` |
| `"2026-1-5"` | 1 (2026, 1, 5) | 최대 2자리니까 1자리도 OK |
| `"20261125"` | 0 | 4자리 읽고 나니 `-`가 아니라 `1` |
| `"2026-11-"` | 0 | 일 숫자가 없음 |
| `"2026-11-25x"` | 0 | 끝에 `x`가 남음 |

**🧒 쉽게 설명하면:** 책을 손가락으로 짚으며 읽는다고 생각해요. `read_num`에게 "여기서부터 숫자 읽어 줘"라고 할 때 **손가락 자체**(`p`)를 주면, 친구는 자기 손가락으로 읽고 돌려줘요. 내 손가락은 여전히 처음 자리! 그래서 "**내 손가락이 어디 있는지 적힌 쪽지**"(`&p`, 즉 `const char **`)를 줘야 친구가 내 손가락을 숫자 뒤로 옮겨 줄 수 있어요.
`*p - '0'`은 글자 `'7'`을 숫자 7로 바꾸는 마법이에요(글자들은 '0', '1', '2'…가 순서대로 붙어 있어서 빼면 거리가 나와요). `*out`을 **맨 마지막에** 쓰는 건, 실패했을 때 반쯤 고쳐진 날짜가 남지 않게 하려는 거예요.

### 구조체 퀴즈1 정답

```c
Date add_days(Date d, int n) {          // d는 복사본이라 마음껏 바꿔도 OK
    while (n > 0) {
        d.d++;
        if (d.d > dim(d.y, d.m)) {
            d.d = 1; d.m++;
            if (d.m > 12) { d.m = 1; d.y++; }
        }
        n--;
    }
    return d;                            // 구조체 통째로 돌려줌
}

int date_cmp(Date a, Date b) {
    if (a.y != b.y) return a.y < b.y ? -1 : 1;
    if (a.m != b.m) return a.m < b.m ? -1 : 1;
    if (a.d != b.d) return a.d < b.d ? -1 : 1;
    return 0;
}

Date effective(const Food *f) {
    if (!f->opened) return f->exp;
    Date lim = add_days(f->open_day, f->open_limit);
    return date_cmp(lim, f->exp) < 0 ? lim : f->exp;
}
```
| 음식 | 진짜 기한 | D | 상태 |
|---|---|---|---|
| 우유 | 2026-11-24 (11/21 + 3일) | **1** | 임박 |
| 계란 | 2026-12-05 | 12 | 여유 |
| 두부 | 2026-11-23 | 0 | 오늘 |
| 냉동만두 | 2027-02-28 | 97 | 여유 |
| 시금치 | 2026-11-22 | -1 | 지남 |
| 요거트 | 2026-11-25 | 2 | 임박 |
| 상추 | 2026-11-25 | 2 | 임박 |
| 케첩 | 2026-10-31 (10/1 + 30일) | **-23** | 지남 |

**🧒 쉽게 설명하면:** `Date`는 "년·월·일" 세 칸짜리 도시락통이에요. 함수에 도시락통을 주면 **똑같은 새 도시락통**을 받아서 안에서 마음껏 바꾸고, 바뀐 도시락통을 통째로 돌려줘요. 원래 도시락(우유의 `open_day`)은 그대로라서 안전해요. `Food` 안에 `Date`가 들어 있는 건 **큰 가방 안의 작은 필통**이에요: `f->open_day.d`처럼 점을 두 번 찍어서 꺼내요.

### 함수 퀴즈1 정답

```c
Food *list[NF];
int n = 0;
for (int i = 0; i < NF; i++)
    if (foods[i].ok) {
        foods[i].dday = days_between(TODAY, effective(&foods[i]));
        list[n++] = &foods[i];
    }

for (int i = 1; i < n; i++) {               // 삽입 정렬
    Food *key = list[i];
    int j = i - 1;
    while (j >= 0 && list[j]->dday > key->dday) {   // > 라서 같으면 안 넘어감
        list[j + 1] = list[j];
        j--;
    }
    list[j + 1] = key;
}
```
```
케첩(-23) 시금치(-1) 두부(0) 우유(1) 요거트(2) 상추(2) 계란(12) 냉동만두(97)
```
**🧒 쉽게 설명하면:** 카드놀이할 때 카드를 한 장씩 집어서 **알맞은 자리에 끼워 넣는** 것이 삽입 정렬이에요. 같은 숫자 카드(요거트 2, 상추 2)는 `>`를 쓰면 원래 순서대로 남고, `>=`를 쓰면 자리가 뒤집혀요.
포인터만 옮기는 이유: `Food`는 이름 16칸 + 날짜 여러 개라서 **무거운 짐가방**이에요. 짐가방을 들고 줄을 바꾸는 대신 "**짐가방 번호표**"(포인터, 8바이트)만 바꾸면 훨씬 빠르고, 진짜 `foods` 배열은 원래 순서 그대로 남아요. 그리고 `list[i]->used = 1`처럼 고치면 진짜 음식에 표시가 돼요!

### 흐름제어 퀴즈2 정답

```c
for (int day = 0; day < 7; day++) {
    Date dt = add_days(TODAY, day);
    printf("[%d/%d]\n", dt.m, dt.d);

    for (int i = 0; i < n; i++)                         // ① 상한 것 버리기
        if (!list[i]->used && list[i]->dday < day) {
            printf("  버림: %s\n", list[i]->name);
            list[i]->used = 2;
        }

    Food *pick = NULL;                                  // ② 가장 급한 것 고르기
    for (int i = 0; i < n; i++)
        if (!list[i]->used) { pick = list[i]; break; }

    if (pick == NULL) { puts("  장보기!"); break; }
    if (pick->dday - day > 7) {
        printf("  급한 재료 없음 (%s D-%d) 추천 종료\n", pick->name, pick->dday - day);
        break;
    }
    pick->used = 1;
    printf("  오늘의 재료: %s (D-%d)\n", pick->name, pick->dday - day);
}
```
```
[11/23]
  버림: 케첩
  버림: 시금치
  오늘의 재료: 두부 (D-0)
[11/24]
  오늘의 재료: 우유 (D-0)
[11/25]
  오늘의 재료: 요거트 (D-0)
[11/26]
  버림: 상추
  급한 재료 없음 (계란 D-9) 추천 종료
```
- **상추가 버려진 이유:** 요거트와 상추 둘 다 11월 25일까지인데, 하루에 하나만 쓰니까 25일에 요거트를 쓰고 나면 26일엔 상추가 이미 상했어요. (실제 냉장고라면 "25일에 두 개 다 써야 해요!" 경고를 띄우면 좋겠죠? 이게 다음 버전 아이디어예요.)
- **요거트가 먼저인 이유:** 정렬할 때 `>`를 써서 같은 D값이면 원래 순서(요거트가 상추보다 앞)를 지켰기 때문이에요.
- 11/26에 계란은 아직 9일이나 남아서 급하지 않으니 추천을 끝내요.

**🧒 쉽게 설명하면:** 매일 아침 냉장고 문을 열고 ① 상한 음식은 먼저 쓰레기통에(버림 표시 `used = 2`), ② 남은 것 중 **제일 급한 것 하나**를 꺼내요. 이미 급한 순서로 줄 세워 놨으니(정렬) 앞에서부터 보다가 첫 번째로 안 쓴 음식을 만나면 바로 `break` — 더 볼 필요가 없어요! 그리고 바깥의 `break` 두 개는 "냉장고가 비었으면 장보러 가요", "급한 게 없으면 오늘 추천은 끝"이라는 **멈춤 조건**이에요. 무엇을 할지(`if`), 몇 번 할지(`for`), 언제 그만둘지(`break`, `continue`)를 섞는 것, 이게 바로 흐름제어예요!
