## 엔지니어가 직면한 가상의 문제 1

**[Meta WhatsApp 메시지 전송팀]** "엄마한테 보낸 메시지가 이상하게 도착했어요!"라는 신고가 들어왔어요. 메시지는 인터넷을 지날 때 **4글자짜리 조각(패킷) 6개**로 잘려서 따로따로 가요. 그런데 길에서 **순서가 뒤섞이고**, 어떤 조각은 **두 번** 오고, 어떤 조각은 **글자가 망가져서** 와요. 받은 쪽은 망가진 조각을 골라내고, 순서대로 맞추고, 빠진 조각은 다시 보내 달라고 해야 해요.

조각마다 **체크섬**(`sum`)이 붙어 있어요. 보내는 쪽이 글자들을 모두 **XOR(`^`)** 해서 적어 둔 "지문"이에요. 받은 쪽이 다시 계산해서 지문이 다르면 → 망가진 조각!

```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>     // qsort

#define TOTAL     6     // 원래 조각 수 (번호 0~5)
#define PAY       4     // 조각 하나에 글자 4개
#define MAX_PKT   10
#define MAX_RETRY 3

typedef struct { int seq; char data[PAY + 1]; unsigned char sum; } Packet;   // seq = 조각 번호

Packet rx[MAX_PKT] = {                 // 도착한 순서 그대로
    {2, "S_TO", 0x17}, {0, "SEND", 0x1C}, {7, "OOPS", 0x00}, {5, "9PM!", 0x05},
    {2, "S_TO", 0x17}, {4, "_AX_", 0x15}, {1, "_PIC", 0x05}, {3, "_MOM", 0x10},
    {-1, "", 0x00},                    // seq == -1 : "이제 끝!" 신호 (END)
    {4, "_AT_", 0x15},                 // END 뒤에 늦게 온 조각
};
Packet re[MAX_RETRY] = { {4, "_AX_", 0x15}, {4, "_AT_", 0x15}, {4, "_AT_", 0x15} };   // 다시 보내 달라고 했을 때 오는 조각들
```

- **조건문 퀴즈 1 (단락 평가):** `const char *classify(const Packet *p, const int *seen)`을 `if - else if - else`로 만드세요. 번호가 `0 ~ TOTAL-1` 밖이면 `"번호 오류"`, 이미 받은 번호(`seen[p->seq] == 1`)면 `"중복"`, 체크섬이 안 맞으면(`xsum(p->data) != p->sum`) `"손상"`, 나머지는 `"정상"`이에요. (`xsum`은 반복문 퀴즈에서 만들어요.) `int seen[TOTAL] = {0};`으로 시작해서 `rx[0]~rx[7]`을 차례로 분류하고, `"정상"`이면 `seen`에 1을 적으세요. 결과는?
  (① 번호 검사를 `if (p->seq < 0 || p->seq >= TOTAL)` **한 줄**로 쓰면, `seq`가 -1일 때 `p->seq >= TOTAL`은 계산될까요? ② `seen[p->seq]` 검사를 **맨 앞**으로 옮기면 `rx[2]`에서 무슨 일이 생길까요?)
- **반복문 퀴즈 1 (`'\0'`까지 도는 `while`):** `unsigned char xsum(const char *s)`를 만드세요. `x = 0`에서 시작해 `while (s[i] != '\0')`로 글자마다 `x ^= s[i];`를 해요. `"SEND"`, `"_PIC"`, `"S_TO"`, `"_AT_"`, `"_TA_"`, `"_AX_"`의 체크섬을 `0x1C`처럼 16진수로 출력하세요(`%02X`). `"_AT_"`와 `"_TA_"`를 비교해 보세요. 무엇이 이상한가요? (왜 `i < 4` 대신 `'\0'`을 볼까요?)
- **흐름제어 퀴즈 1:** `rx`를 `for (i = 0; i < MAX_PKT; i++)`로 읽어요. `seq == -1`이면 `"rx[8]: END 신호 -> 수신 종료"` 후 `break`. `classify`가 `"정상"`이 아니면 `"rx[2]: 번호 오류 -> 버림"` 후 `continue`. 정상이면 `seen`에 적고 `"rx[0]: 조각 2 받음"`. 마지막에 `"정상 N개, 버림 M개"`. `rx[9]`의 `"_AT_"`는 읽힐까요?
- **배열 퀴즈 1 (빈칸 채우기 배열):** 흐름제어 퀴즈가 끝난 뒤의 `seen`을 보고 **빠진 조각 번호**를 모두 출력하세요. 그리고 `char out[TOTAL * PAY + 1];`을 전부 `'?'`로 채운 뒤, 정상 조각의 글자를 **자기 자리**(`out[seq * PAY + k]`)에 넣으세요(이중 `for`). 마지막 칸은 `'\0'`! 결과 문자열은? (왜 `out` 크기가 `+ 1`일까요?)
- **포인터 변수 퀴즈 1 (읽는 손가락, 쓰는 손가락):** `rx`의 앞 8개를 복사한 `Packet buf[MAX_PKT]`에서 **정상 조각만 남기고 앞으로 당겨** 주세요. 새 배열을 만들지 말고, `Packet *r = a, *w = a;` 두 손가락으로 `while (r < a + n)`을 돌아요. `r`은 매번 한 칸씩, `w`는 정상 조각을 `*w = *r;`로 적었을 때만 한 칸 가요. `int compact(Packet *a, int n)`은 남은 개수 `w - a`를 돌려줘요. 남은 조각 번호 순서는? (왜 `w`는 절대 `r`을 앞지르지 못할까요?)
- **구조체 퀴즈 1 (삽입 정렬):** 압축된 5개 조각(번호 `2 0 5 1 3`)을 **삽입 정렬**로 번호 순서대로 줄 세우세요. `Packet key = a[i];`로 조각을 **통째로 손에 들고**, 왼쪽에 더 큰 번호가 있으면 `a[j + 1] = a[j];`로 한 칸씩 오른쪽으로 밀어요. 빈 자리에 `key`를 내려놓아요. `i`마다 배열을 출력하고, 모두 몇 번 밀었는지 세세요. `sizeof(Packet)`은 몇 바이트일까요?
- **함수 퀴즈 1 (`qsort` + 비교 함수):** 이번엔 정렬을 직접 짜지 말고 C 라이브러리의 `qsort`를 써요. `int by_seq(const void *a, const void *b)`를 만들어 `qsort(buf, 5, sizeof(Packet), by_seq);`로 오름차순 정렬하세요. 그리고 `by_seq`를 **한 번만 써서** 내림차순 비교 함수 `by_seq_desc`도 만드세요. (① 왜 매개변수가 `const void *`일까요? ② `return x->seq - y->seq;`는 보통은 되지만 어떤 숫자에서 위험할까요?)
- **흐름제어 퀴즈 2 (종합):** 진짜 수신 프로그램을 만들어요.
  1. `rx`를 받아서(흐름제어 퀴즈 1처럼) 정상 조각을 `Packet good[MAX_PKT]`에 모아요
  2. `qsort`로 정렬해요
  3. `memset(out, '?', TOTAL * PAY);`로 채우고, `for (Packet *p = good; p < good + g; p++)` 안에서 `memcpy(out + p->seq * PAY, p->data, PAY);`로 조립한 뒤 `"1차 조립: ..."`을 출력해요
  4. 빠진 번호마다 `"재요청: 4번 조각"`을 출력하고, `re[]`를 **최대 `MAX_RETRY`번** 받아 보면서 정상이면 `"  2번째 재전송: 성공"` 후 `break`, 아니면 `"  1번째 재전송: 손상"`. 끝까지 못 받으면 `"전송 실패"` 후 `return 1`
  5. `"완성: ..."`, `"정상 N개, 버림 M개, 재전송 K번"`
  실제 출력은? 이 조립 방식에서 `qsort`를 빼도 결과가 같을까요? 그럼 정렬은 왜 할까요?

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[한국항공우주연구원 누리호 발사 시퀀서팀]** 로켓 발사는 "버튼 하나 누르면 끝"이 아니에요. **대기 → 연료주입 → 최종점검 → 카운트다운 → 발사**를 **정해진 순서대로만** 지나가야 하고, 문제가 생기면 언제든 **발사중단**으로 가서 했던 일을 **거꾸로** 되돌려야 해요. 이걸 **상태 머신**이라고 불러요. 오늘은 발사 시퀀서 프로그램을 새로 만들어요.

```c
#include <stdio.h>

#define WIN       3     // 이동 평균에 쓰는 칸 수
#define P_MAX     70    // 탱크 압력 한계 (bar)
#define STACK_MAX 8

typedef enum { S_IDLE, S_FUEL, S_CHECK, S_COUNT, S_LIFTOFF, S_ABORT } State;
typedef enum { E_START, E_FUEL_DONE, E_ALL_GO, E_ZERO, E_FAULT } Event;
typedef struct { int wind; int lightning_km; int temp; int humid; } Weather;   // 풍속(m/s), 낙뢰 거리(km), 기온(℃), 습도(%)
typedef struct { const char *name; int critical; int ok; } Item;               // 점검 항목 (critical = 1이면 꼭 통과해야 함)
typedef struct { const char *undo[STACK_MAX]; int top; } Stack;                // 되돌리기 목록

const char *sname[] = {"대기", "연료주입", "최종점검", "카운트다운", "발사", "발사중단"};
const char *ename[] = {"START", "FUEL_DONE", "ALL_GO", "ZERO", "FAULT"};
```

- **조건문 퀴즈 1:** `const char *weather_go(Weather w)`를 만드세요. 풍속이 15 **초과**면 `"NO-GO: 강풍"`, 낙뢰가 10km **미만**이면 `"NO-GO: 낙뢰"`, 기온이 0℃ **이하이면서** 습도가 80% **이상**이면 `"NO-GO: 결빙"`, 나머지는 `"GO"`. 예보 5개의 결과는?
  `{8, 30, 12, 60}`, `{18, 40, 5, 50}`, `{10, 6, 20, 90}`, `{5, 25, -2, 85}`, `{15, 10, 0, 79}`
  (① 결빙 조건을 `&&` 대신 `||`로 쓰면 어느 예보가 바뀔까요? ② 5번 예보는 숫자가 모두 기준에 **딱 붙어** 있어요. 왜 GO일까요?)
- **반복문 퀴즈 1 (HOLD가 있는 카운트다운):** `int glitch[11] = {0}; glitch[6] = 1; glitch[2] = 1;`이에요(T-6, T-2에 센서 값이 한 번 튐). `int t = 10, elapsed = 0;`으로 `while (t >= 0)`을 돌면서 매번 `elapsed++`. 튄 초에는 `"T-6 센서 값 튐! HOLD (이 초를 다시)"`를 출력하고 `glitch[t] = 0;` 후 `continue`(이때 `t--`를 **안 해요**). T-3에는 `"T-3 엔진 점화!"`, T-0에는 `"T-0 LIFTOFF!"`, 나머지는 `"T-10"`처럼 출력하고 `t--`. 실제 걸린 시간은? (`glitch[t] = 0;`을 빼먹으면 무슨 일이 생길까요?)
- **흐름제어 퀴즈 1:** 점검 항목 7개예요.
  `Item it[7] = {{"전원",1,1}, {"통신",1,1}, {"온보드 카메라",0,0}, {"텔레메트리",1,1}, {"발사대 조명",0,0}, {"관성항법장치",1,0}, {"추적 레이더",1,1}};`
  통과(`ok`)면 `"전원: GO"` 후 `continue`, 실패했는데 선택 항목이면 `"온보드 카메라: 경고 (선택 항목, 계속)"` 후 `continue`, 실패했는데 꼭 필요한 항목이면 `"관성항법장치: 치명적 고장! 점검 중단"` 후 `break`. 마지막에 `"GO N개, 경고 M개, 결과: NO-GO"` (반복이 끝까지 돌았으면 `"ALL GO"`). 추적 레이더는 점검받을까요? 반복이 끝까지 돌았는지는 **무엇으로** 알 수 있을까요?
- **배열 퀴즈 1 (이동 평균):** 1초마다 잰 연료탱크 압력이 `int p[10] = {50, 52, 55, 61, 66, 72, 75, 69, 64, 60};`예요. 순간 값 하나만 보면 센서가 잠깐 튄 것에도 발사를 멈추게 돼요. 그래서 **최근 3개의 평균**을 봐요. `sum += p[i];` 하고, `i >= WIN`이면 `sum -= p[i - WIN];`(창 밖으로 나간 값 빼기). `i >= WIN - 1`부터 평균을 소수 1자리로 출력하고, 평균이 `P_MAX`를 넘으면 `"  <- 경보!"`를 붙이세요. 경보는 몇 번, 처음은 몇 초일까요? 5초의 72는 왜 경보가 아닐까요? (왜 매초 3개를 다시 다 더하지 않을까요?)
- **포인터 변수 퀴즈 1 (`int (*e)[3]`):** 1단 엔진 4개마다 온도 센서가 3개(터보펌프, 연소실, 노즐) 있어요.
  `int eng[4][3] = {{610, 2900, 1450}, {605, 3010, 1400}, {640, 2950, 1500}, {600, 2880, 1390}};`
  `int hottest(int (*e)[3], int rows)`를 만드세요. 엔진마다 3개 온도의 합을 `*(*(e + r) + c)`로 구해 `"1번 엔진 합 4960"`처럼 출력하고, 합이 가장 큰 엔진의 인덱스를 돌려줘요. 그리고 ① `(*(eng + 2))[1]`의 값 ② `main`에서 `sizeof(eng)`, `sizeof(eng[0])` ③ 함수 안에서 `sizeof(e)` ④ `eng + 1`은 `eng`보다 몇 바이트 뒤일까요? (`int (*e)[3]`과 `int *e[3]`은 뭐가 다를까요?)
- **구조체 퀴즈 1 (스택으로 되돌리기):** `int push(Stack *s, const char *u)`(꽉 차면 0을 돌려줌)와 `const char *pop(Stack *s)`(비었으면 `NULL`)를 만드세요. `"연료 배출"`, `"산화제 배출"`, `"외부전원 복귀"`, `"발사대 팔 재결합"`을 차례로 `push`한 뒤 `top`을 출력하고, `while ((u = pop(&st)) != NULL)`로 `"되돌리기 1: ..."`을 출력하세요. 한 번 더 `pop`하면? (왜 **거꾸로** 되돌려야 할까요? `s->undo[s->top++]`과 `s->undo[--s->top]`에서 `++`, `--`의 위치는 왜 다를까요?)
- **함수 퀴즈 1 (상태 전이 함수):** `State next_state(State s, Event e)`를 만드세요. 규칙은
  - `FAULT`가 오면 **발사·발사중단이 아닌 모든 상태**에서 → 발사중단
  - 대기 + `START` → 연료주입, 연료주입 + `FUEL_DONE` → 최종점검, 최종점검 + `ALL_GO` → 카운트다운, 카운트다운 + `ZERO` → 발사
  - 그 밖의 이벤트는 **무시**하고 지금 상태 그대로
  `switch (s)` 안에서 `if`로 이벤트를 보고, 맞지 않으면 `break` 후 마지막 `return s;`로 떨어지게 하세요. 아래 6개의 결과는?
  (대기, `START`) (대기, `ZERO`) (최종점검, `FUEL_DONE`) (카운트다운, `FAULT`) (발사, `FAULT`) (카운트다운, `ZERO`)
- **흐름제어 퀴즈 2 (종합):** `State run(const char *label, const int *p)`를 만들어 두 번 시도해요.
  1. `Event script[4] = {E_ZERO, E_START, E_FUEL_DONE, E_ALL_GO};`를 하나씩 `next_state`에 넣어요. 상태가 안 바뀌면 `"무시: ZERO (지금 대기)"` 후 `continue`. 바뀌면 `"대기 -> 연료주입"`을 출력하고 `switch`로 **새 상태에 들어갈 때** 되돌리기를 `push`해요(연료주입: `"연료 배출"`, `"산화제 배출"` / 최종점검: `"외부전원 복귀"` / 카운트다운: `"발사대 팔 재결합"`)
  2. 카운트다운 상태인 동안(`while (s == S_COUNT)`) T-10부터 1초마다 `p[i]`를 읽어 이동 평균을 내요. 평균이 `P_MAX`를 넘으면 `"T-4 압력 평균 71.0bar > 70! FAULT"` → `next_state(s, E_FAULT)` 후 `break`. `t == 0`이 되면 `"T-0 LIFTOFF! (발사)"`
     (힌트: 소수 없이 비교하려면 `sum > P_MAX * WIN`)

## 문제 1: WhatsApp 메시지 조각 재조립

### 조건문 정답 (단락 평가)
```c
const char *classify(const Packet *p, const int *seen) {
    if (p->seq < 0 || p->seq >= TOTAL) return "번호 오류";
    else if (seen[p->seq])             return "중복";
    else if (xsum(p->data) != p->sum)  return "손상";
    else                               return "정상";
}

// main 안에서
int seen[TOTAL] = {0};
for (int i = 0; i < 8; i++) {
    const char *r = classify(&rx[i], seen);
    printf("rx[%d] 조각 %d \"%s\": %s\n", i, rx[i].seq, rx[i].data, r);
    if (strcmp(r, "정상") == 0) seen[rx[i].seq] = 1;
}
```
출력:
```
rx[0] 조각 2 "S_TO": 정상
rx[1] 조각 0 "SEND": 정상
rx[2] 조각 7 "OOPS": 번호 오류
rx[3] 조각 5 "9PM!": 정상
rx[4] 조각 2 "S_TO": 중복
rx[5] 조각 4 "_AX_": 손상
rx[6] 조각 1 "_PIC": 정상
rx[7] 조각 3 "_MOM": 정상
```
**왜 이렇게?** 학교 앞 경비 아저씨가 택배를 받는다고 생각해요. ① 먼저 "우리 학교 주소가 맞나?"(번호 검사) ② "이거 아까 받은 거 아닌가?"(중복) ③ "상자가 찢어졌나?"(체크섬). 순서대로 물어보고, 처음 "문제 있음"이 나오면 거기서 끝이에요.
① `||`는 **앞이 참이면 뒤를 아예 안 봐요**(단락 평가). "둘 중 하나만 맞으면 되는데 이미 하나 맞았으니 더 볼 필요 없지!" 그래서 `seq`가 -1이면 `p->seq >= TOTAL`은 계산되지 않아요. `&&`는 반대로 **앞이 거짓이면** 뒤를 안 봐요.
② `seen[p->seq]`를 맨 앞에 두면 `rx[2]`는 `seen[7]`을 보게 돼요. 그런데 `seen`은 0~5번 칸밖에 없어요! **배열 밖**을 읽으면 C는 경고도 없이 아무 값이나 읽거나 프로그램이 죽어요. 그래서 "번호가 맞는지"를 **반드시 먼저** 검사해요. 이게 현업에서 보안 구멍을 막는 가장 기본 규칙이에요.
③ 체크섬은 글자를 하나하나 계산해야 해서 가장 **비싼** 검사예요. 싼 검사로 먼저 걸러 내고 비싼 검사는 마지막에 해요.

### 반복문 정답 (`'\0'`까지 도는 `while`)
```c
unsigned char xsum(const char *s) {
    unsigned char x = 0;
    int i = 0;
    while (s[i] != '\0') {
        x ^= (unsigned char)s[i];
        i++;
    }
    return x;
}

// main 안에서
const char *w[6] = {"SEND", "_PIC", "S_TO", "_AT_", "_TA_", "_AX_"};
for (int i = 0; i < 6; i++)
    printf("%s -> 0x%02X\n", w[i], xsum(w[i]));
```
출력:
```
SEND -> 0x1C
_PIC -> 0x05
S_TO -> 0x17
_AT_ -> 0x15
_TA_ -> 0x15
_AX_ -> 0x19
```
**왜 이렇게?** XOR(`^`)은 "**두 비트가 다르면 1, 같으면 0**"인 계산이에요. 글자를 하나씩 XOR로 섞으면 그 단어만의 "지문"이 생겨요. `_AX_`는 `T`가 `X`로 바뀌어서 지문이 `0x15` → `0x19`로 달라졌어요. 그래서 `rx[5]`가 "손상"으로 잡혔죠.
**이상한 점:** `_AT_`와 `_TA_`는 **다른 단어인데 지문이 똑같아요!** XOR은 순서를 신경 쓰지 않아서(`A^T`와 `T^A`가 같음) 글자 **자리가 바뀐** 건 못 잡아요. 그래서 진짜 WhatsApp 같은 곳은 순서까지 섞어서 계산하는 **CRC32** 같은 더 똑똑한 지문을 써요. "체크섬이 맞다 = 100% 정답"은 아니라는 걸 꼭 기억해요.
`i < 4` 대신 `'\0'`을 보는 이유: C의 문자열은 끝에 **보이지 않는 마침표 `'\0'`** 이 붙어 있어요. `'\0'`을 보면 글자 수가 3개든 100개든 같은 함수로 계산할 수 있어요. 숫자 4를 박아 두면 조각 크기가 바뀔 때 함수도 고쳐야 해요.

### 포인터 변수 정답 (읽는 손가락, 쓰는 손가락)
```c
int compact(Packet *a, int n) {
    int seen[TOTAL] = {0};
    Packet *r = a, *w = a;
    while (r < a + n) {
        if (strcmp(classify(r, seen), "정상") == 0) {
            seen[r->seq] = 1;
            *w = *r;                 // 좋은 조각을 쓰는 자리로 복사
            w++;
        }
        r++;                         // 읽는 손가락은 무조건 한 칸
    }
    return (int)(w - a);             // 포인터 빼기 = 몇 칸 썼는지
}

// main 안에서
Packet buf[MAX_PKT];
memcpy(buf, rx, sizeof rx);
int m = compact(buf, 8);
printf("남은 조각 %d개:", m);
for (int i = 0; i < m; i++) printf(" %d", buf[i].seq);
printf("\n");
```
출력:
```
남은 조각 5개: 2 0 5 1 3
```
**왜 이렇게?** 책상 위 카드 줄에서 나쁜 카드를 빼는 방법이에요. 왼손(`r`)은 카드를 **하나씩 다 읽고**, 오른손(`w`)은 **좋은 카드를 놓을 자리**를 가리켜요. 좋은 카드면 오른손 자리에 놓고 오른손도 한 칸 가요. 나쁜 카드면 오른손은 가만히 있어요.
`w`가 `r`을 못 앞지르는 이유: `r`은 **매번** 가고 `w`는 **가끔** 가니까요. 그래서 `w`가 덮어쓰는 자리는 이미 `r`이 읽고 지나간 자리라서, 아직 안 읽은 카드를 망가뜨릴 일이 없어요. 새 배열이 필요 없으니 메모리를 아껴요. 서버가 1초에 패킷 백만 개를 다룰 때 이런 절약이 아주 중요해요.

### 구조체 정답 (삽입 정렬)
```c
void isort(Packet *a, int n) {
    int shifts = 0;
    for (int i = 1; i < n; i++) {
        Packet key = a[i];                         // 조각을 통째로 손에 들기
        int j = i - 1;
        while (j >= 0 && a[j].seq > key.seq) {
            a[j + 1] = a[j];                       // 큰 조각을 오른쪽으로 밀기
            j--;
            shifts++;
        }
        a[j + 1] = key;                            // 빈 자리에 내려놓기
        printf("i=%d (조각 %d 끼우기):", i, key.seq);
        for (int k = 0; k < n; k++) printf(" %d", a[k].seq);
        printf("\n");
    }
    printf("밀어낸 횟수 %d\n", shifts);
}
```
출력:
```
i=1 (조각 0 끼우기): 0 2 5 1 3
i=2 (조각 5 끼우기): 0 2 5 1 3
i=3 (조각 1 끼우기): 0 1 2 5 3
i=4 (조각 3 끼우기): 0 1 2 3 5
밀어낸 횟수 4
```
`sizeof(Packet)` = **12바이트** (`int` 4 + 글자 5 + `sum` 1 = 10인데, 컴퓨터가 `int` 자리를 4의 배수로 맞추려고 빈칸 2바이트를 붙여요.)
**왜 이렇게?** 카드 게임에서 카드를 한 장씩 받아서 **손에 든 카드 사이에 끼워 넣는** 방법이에요. 새 카드를 들고, 왼쪽에 더 큰 카드가 있으면 하나씩 오른쪽으로 밀고, 빈 자리에 쏙!
- `Packet key = a[i];`는 구조체를 **통째로 복사**해요. 안에 있는 `data` 배열까지 같이 복사돼요. 먼저 들어 두지 않으면 밀어내는 동안 `a[i]` 자리가 덮여서 그 조각을 잃어버려요.
- 네트워크 조각은 보통 **거의 순서대로** 와요(조금만 뒤섞임). 삽입 정렬은 "거의 정렬된" 줄에서 아주 조금만 밀면 돼서 빨라요. `i=2`처럼 이미 제자리면 한 번도 안 밀어요.
- `while` 조건에서 `j >= 0`을 **앞에** 쓴 것도 단락 평가예요. `j`가 -1이 되면 `a[-1]`을 보기 전에 멈춰요.

### 함수 정답 (`qsort` + 비교 함수)
```c
int by_seq(const void *a, const void *b) {
    const Packet *x = a, *y = b;                       // "사실 이건 Packet이야"
    return (x->seq > y->seq) - (x->seq < y->seq);      // 크면 1, 같으면 0, 작으면 -1
}
int by_seq_desc(const void *a, const void *b) {
    return by_seq(b, a);                               // 순서만 뒤집어서 부르기
}

// main 안에서 (buf에는 2 0 5 1 3 조각이 들어 있어요)
qsort(buf, 5, sizeof(Packet), by_seq);
for (int i = 0; i < 5; i++) printf("%d:%s ", buf[i].seq, buf[i].data);
printf("\n");
qsort(buf, 5, sizeof(Packet), by_seq_desc);
for (int i = 0; i < 5; i++) printf("%d ", buf[i].seq);
printf("\n");
```
출력:
```
0:SEND 1:_PIC 2:S_TO 3:_MOM 5:9PM! 
5 3 2 1 0 
```
**왜 이렇게?** `qsort`는 "정렬 로봇"이에요. 로봇은 정렬은 잘하는데 **뭐가 더 큰지는 몰라요.** 그래서 우리가 "두 개를 비교하는 방법"을 **함수로 만들어서** 로봇에게 건네줘요.
① 로봇은 숫자든, 학생 카드든, 패킷이든 **아무거나** 정렬할 수 있어야 해요. 그래서 "뭔지 모르는 것의 주소"라는 뜻의 `const void *`로 받아요. 우리 함수 안에서 "이건 사실 `Packet`이야"라고 `const Packet *`로 바꿔서 써요. `const`는 "비교만 하고 **고치지는 않을게**"라는 약속이에요.
② `x - y`는 숫자가 아주 크면 위험해요. 예를 들어 `x = 2000000000`, `y = -2000000000`이면 빼기 결과가 `int`에 다 안 들어가서 **음수로 뒤집혀요(오버플로)**. 그럼 큰 게 작다고 나와요! `(x > y) - (x < y)`는 결과가 1, 0, -1뿐이라 절대 넘치지 않아요.
`by_seq_desc`는 `a`와 `b`를 **바꿔서** 부르기만 했어요. 같은 코드를 두 번 쓰지 않는 것, 이게 함수를 쓰는 이유예요.

```
  2번째 재전송: 성공
완성: SEND_PICS_TO_MOM_AT_9PM!
정상 5개, 버림 3개, 재전송 2번
```
**왜 이렇게?** 오늘 만든 부품이 모두 모였어요! `classify`(조건문 + 단락 평가) → `xsum`(반복문) → `continue`/`break`(흐름제어) → 출석부 `seen`(배열) → `qsort`(함수 넘기기) → `memcpy`(포인터 + 자리 계산) → 재요청 `while`(재시도 제한).
- `memset(out, '?', 24)`는 "24칸을 모두 `?`로 칠해", `memcpy(목적지, 출발지, 4)`는 "4바이트를 그대로 옮겨 적어"예요. 반복문으로 한 글자씩 하던 일을 한 줄로 해요.
- `out + p->seq * PAY`는 "out에서 **번호 × 4칸** 뒤"라는 주소예요. 4번 조각은 16번째 칸부터 들어가요.
- 재전송도 **무한히 기다리지 않아요.** `MAX_RETRY`번까지만 받고, 그래도 안 되면 `return 1`로 "실패"를 알려요. 첫 재전송 `_AX_`는 또 망가져서 버렸고, 두 번째 `_AT_`로 완성됐어요.
- **`qsort`를 빼도 결과는 같아요!** 조각을 번호 자리에 직접 넣기 때문이에요. 그럼 정렬은 왜 할까요? 큰 동영상처럼 **전체를 한꺼번에 담을 판이 없을 때**는 조각을 0번부터 순서대로 화면에 흘려보내야 해요(스트리밍). 그때는 정렬된 줄이 꼭 필요해요. 오늘 코드는 "둘 다 할 줄 아는" 연습이에요.

### 조건문 정답
```c
const char *weather_go(Weather w) {
    if (w.wind > 15)                        return "NO-GO: 강풍";
    else if (w.lightning_km < 10)           return "NO-GO: 낙뢰";

}

// main 안에서
Weather ws[5] = {{8, 30, 12, 60}, {18, 40, 5, 50}, {10, 6, 20, 90}, {5, 25, -2, 85}, {15, 10, 0, 79}};
for (int i = 0; i < 5; i++)
    printf("%d번 예보: %s\n", i + 1, weather_go(ws[i]));
```
출력:
```
1번 예보: GO
2번 예보: NO-GO: 강풍
3번 예보: NO-GO: 낙뢰
4번 예보: NO-GO: 결빙
5번 예보: GO
```
**왜 이렇게?** 로켓은 바람이 세면 휘청이고, 번개가 가까우면 맞을 수 있고, **추운데 축축하면** 몸에 얼음이 생겨요. 얼음은 "추움" **그리고** "축축함"이 **둘 다** 있어야 생기니까 `&&`예요.
① `||`로 쓰면 "추운 날이거나 축축한 날이면 무조건 금지"가 돼요. 5번 예보(0℃, 습도 79%)가 **결빙으로 바뀌어요.** 하늘이 맑아도 0℃라는 이유만으로 발사를 못 해요. 조건 하나 잘못 쓰면 수천억 원짜리 발사가 이유 없이 미뤄져요.
② 5번은 풍속 15(초과가 아님), 낙뢰 10km(미만이 아님), 기온 0(이하라서 참) **그리고** 습도 79(80 이상이 아님 → 거짓) → 결빙도 아님 → GO. `>`와 `>=`, `<`와 `<=`의 차이가 **경계값**에서 결과를 바꿔요. 그래서 엔지니어는 꼭 "딱 기준인 값"으로 테스트해요.

### 반복문 정답 (HOLD가 있는 카운트다운)
```c
int glitch[11] = {0};
glitch[6] = 1;
glitch[2] = 1;
int t = 10, elapsed = 0;

while (t >= 0) {
    elapsed++;
    if (glitch[t]) {
        printf("T-%d 센서 값 튐! HOLD (이 초를 다시)\n", t);
        glitch[t] = 0;
        continue;                    // t-- 를 건너뜀 → 같은 초를 다시
    }
    if (t == 0)      printf("T-0 LIFTOFF!\n");
    else if (t == 3) printf("T-3 엔진 점화!\n");
    else             printf("T-%d\n", t);
    t--;
}
printf("실제 걸린 시간 %d초\n", elapsed);
```
출력:
```
T-10
T-9
T-8
T-7
T-6 센서 값 튐! HOLD (이 초를 다시)
T-6
T-5
T-4
T-3 엔진 점화!
T-2 센서 값 튐! HOLD (이 초를 다시)
T-2
T-1
T-0 LIFTOFF!
실제 걸린 시간 13초
```
**왜 이렇게?** 숨바꼭질 술래가 "10, 9, 8…" 세다가 재채기가 나면 그 숫자를 **다시** 세는 것과 같아요. 카운트다운 숫자는 11개(10~0)지만 HOLD가 2번 있어서 실제로는 **13초**가 걸렸어요.
`continue`를 만나면 아래의 `t--`를 **건너뛰고** 바로 `while` 조건으로 돌아가요. 그래서 같은 `t`를 한 번 더 봐요.
`glitch[t] = 0;`을 빼먹으면? 다시 T-6을 봤을 때 또 "튐!"이 되고, 또 `continue`… **영원히 T-6에 갇혀요(무한 루프).** `continue`로 숫자를 안 바꿀 때는 "**다음 번엔 다르게 될 이유**"가 꼭 있어야 해요. 그래서 `for`보다 `while`을 썼어요. `for (t = 10; t >= 0; t--)`에서 `continue`하면 `t--`가 **자동으로** 실행돼서 HOLD가 안 돼요.

### 흐름제어 정답 (1)
```c
Item it[7] = {{"전원",1,1}, {"통신",1,1}, {"온보드 카메라",0,0}, {"텔레메트리",1,1},
              {"발사대 조명",0,0}, {"관성항법장치",1,0}, {"추적 레이더",1,1}};
int go = 0, warn = 0, i;

for (i = 0; i < 7; i++) {
    if (it[i].ok) {
        printf("%s: GO\n", it[i].name);
        go++;
        continue;
    }
    if (!it[i].critical) {
        printf("%s: 경고 (선택 항목, 계속)\n", it[i].name);
        warn++;
        continue;
    }
    printf("%s: 치명적 고장! 점검 중단\n", it[i].name);
    break;
}
printf("GO %d개, 경고 %d개, 결과: %s\n", go, warn, i < 7 ? "NO-GO" : "ALL GO");
```
출력:
```
전원: GO
통신: GO
온보드 카메라: 경고 (선택 항목, 계속)
텔레메트리: GO
발사대 조명: 경고 (선택 항목, 계속)
관성항법장치: 치명적 고장! 점검 중단
GO 3개, 경고 2개, 결과: NO-GO
```
**왜 이렇게?** 소풍 가기 전 가방 검사예요. 손수건이 없으면 "아쉽지만 괜찮아"(선택 항목 → `continue`), 하지만 **도시락**이 없으면 "오늘 소풍 취소!"(필수 항목 → `break`). 관성항법장치는 로켓이 어디로 가는지 아는 "눈"이라서 고장 나면 절대 못 떠요.
- **추적 레이더는 점검받지 못해요.** 이미 `break`로 나왔으니까요. 어차피 발사를 못 하니 더 볼 필요가 없죠.
- `i`를 `for` **바깥에** 만든 이유: 반복이 끝난 뒤에도 `i`를 보고 싶어서예요. 끝까지 돌았으면 `i == 7`, 중간에 `break`했으면 `i < 7`이에요. 이렇게 "**어떻게 끝났는지**"를 반복 변수로 알아내는 건 현업에서 아주 많이 쓰는 기술이에요.
- 조건을 "통과면 `continue`, 선택이면 `continue`, 남은 건 치명"처럼 **빨리 빠져나가는 순서**로 써서 `else`가 겹겹이 쌓이지 않았어요.

### 배열 정답 (이동 평균)
```c
int p[10] = {50, 52, 55, 61, 66, 72, 75, 69, 64, 60};
int sum = 0, alarms = 0, first = -1;

for (int i = 0; i < 10; i++) {
    sum += p[i];                              // 새 값 들어오기
    if (i >= WIN) sum -= p[i - WIN];          // 창 밖으로 나간 값 빼기
    if (i < WIN - 1) {
        printf("%d초: %d (평균 준비 중)\n", i, p[i]);
        continue;
    }
    double avg = (double)sum / WIN;
    printf("%d초: %d 평균 %.1f%s\n", i, p[i], avg, avg > P_MAX ? "  <- 경보!" : "");
    if (avg > P_MAX) {
        alarms++;
        if (first < 0) first = i;
    }
}
printf("경보 %d번, 처음 경보 %d초\n", alarms, first);
```
출력:
```
0초: 50 (평균 준비 중)
1초: 52 (평균 준비 중)
2초: 55 평균 52.3
3초: 61 평균 56.0
4초: 66 평균 60.7
5초: 72 평균 66.3
6초: 75 평균 71.0  <- 경보!
7초: 69 평균 72.0  <- 경보!
8초: 64 평균 69.3
9초: 60 평균 64.3
경보 2번, 처음 경보 6초
```
**왜 이렇게?** 기차 창문을 생각해요. 창문으로는 **풍경 3칸**만 보여요. 기차가 한 칸 가면 새 풍경 하나가 들어오고, 맨 뒤 풍경 하나가 나가요. 그래서 "새 값 더하기, 나간 값 빼기" 딱 두 번만 계산하면 돼요. 창이 3칸이든 1000칸이든 매초 계산은 **2번**이에요. 매번 3개를 다시 더하면 창이 1000칸일 때 1000번씩 더해야 해서 느려요.
5초의 72는 순간 값은 70을 넘었지만 평균(66.3)은 안 넘었어요. 센서가 **잠깐 튄 값** 하나 때문에 발사를 멈추면 안 되니까, "**계속** 높은지"를 평균으로 봐요. 6초, 7초에는 정말로 계속 높아서 경보가 울렸어요.
`(double)sum / WIN`: `int / int`는 소수점을 버려요(157 / 3 = 52). 하나를 `double`로 바꿔야 52.3이 나와요.

### 포인터 변수 정답 (`int (*e)[3]`)
```c
int hottest(int (*e)[3], int rows) {
    int best = 0, bsum = -1;
    for (int r = 0; r < rows; r++) {
        int s = 0;
        for (int c = 0; c < 3; c++)
            s += *(*(e + r) + c);             // e[r][c] 와 똑같아요
        printf("%d번 엔진 합 %d\n", r + 1, s);
        if (s > bsum) { bsum = s; best = r; }
    }
    printf("함수 안 sizeof(e)=%zu\n", sizeof(e));
    return best;
}

// main 안에서
int eng[4][3] = {{610, 2900, 1450}, {605, 3010, 1400}, {640, 2950, 1500}, {600, 2880, 1390}};
int b = hottest(eng, 4);
printf("가장 뜨거운: %d번 엔진\n", b + 1);
printf("(*(eng + 2))[1] = %d\n", (*(eng + 2))[1]);
printf("sizeof(eng)=%zu, sizeof(eng[0])=%zu\n", sizeof(eng), sizeof(eng[0]));
printf("eng+1 은 %ld바이트 뒤\n", (long)((char *)(eng + 1) - (char *)eng));
```
출력 (`int` 4바이트, 64비트 컴퓨터 기준):
```
1번 엔진 합 4960
2번 엔진 합 5015
3번 엔진 합 5090
4번 엔진 합 4870
함수 안 sizeof(e)=8
가장 뜨거운: 3번 엔진
(*(eng + 2))[1] = 2950
sizeof(eng)=48, sizeof(eng[0])=12
eng+1 은 12바이트 뒤
```
**왜 이렇게?** `eng`는 아파트예요. 한 **층**(줄)에 방이 3개 있어요. `int (*e)[3]`은 "**방 3개짜리 층**을 가리키는 손가락"이에요. 그래서 `e + 1`은 방 하나가 아니라 **한 층 위**(방 3개 = 12바이트)로 가요.
- `*(e + r)` = r층 전체 → `*(e + r) + c` = 그 층의 c번 방 주소 → `*(...)` = 그 방의 값. 이게 바로 `e[r][c]`의 정체예요. `(*(eng + 2))[1]`은 3층 2번 방 = **2950**.
- `main`에서 `sizeof(eng)`는 아파트 전체 48바이트, 한 층은 12바이트. 그런데 함수로 넘기면 **손가락(주소)만** 넘어가서 `sizeof(e)`는 8바이트(주소 크기)예요. 그래서 함수에는 `rows`(층 수)를 **따로** 알려줘야 해요.
- 2번 엔진은 연소실이 3010℃로 가장 뜨겁지만 **합계**로는 3번 엔진(5090)이 1등이에요. "무엇으로 비교하는지"를 정확히 정해야 해요.
- `int (*e)[3]`은 "방 3개 층을 가리키는 손가락 **1개**", `int *e[3]`은 괄호가 없어서 "int 손가락 **3개짜리 배열**"이에요. 괄호 하나로 뜻이 완전히 바뀌어요!

### 구조체 정답 (스택으로 되돌리기)
```c
int push(Stack *s, const char *u) {
    if (s->top == STACK_MAX) return 0;       // 꽉 참
    s->undo[s->top++] = u;                   // 지금 칸에 넣고 → top 올리기
    return 1;
}
const char *pop(Stack *s) {
    if (s->top == 0) return NULL;            // 비었음
    return s->undo[--s->top];                // top 내리고 → 그 칸 꺼내기
}

// main 안에서
Stack st = { .top = 0 };
push(&st, "연료 배출");
push(&st, "산화제 배출");
push(&st, "외부전원 복귀");
push(&st, "발사대 팔 재결합");
printf("top=%d\n", st.top);
const char *u;
int n = 0;
while ((u = pop(&st)) != NULL) printf("되돌리기 %d: %s\n", ++n, u);
printf("빈 스택 pop: %s\n", pop(&st) ? "뭔가 나옴" : "NULL");
```
출력:
```
top=4
되돌리기 1: 발사대 팔 재결합
되돌리기 2: 외부전원 복귀
되돌리기 3: 산화제 배출
되돌리기 4: 연료 배출
빈 스택 pop: NULL
```
**왜 이렇게?** 스택은 **접시 쌓기**예요. 접시는 맨 위에 올리고, 꺼낼 때도 맨 위부터 꺼내요(LIFO: 나중에 들어온 게 먼저 나감).
**거꾸로 되돌리는 이유:** 아침에 양말 → 신발 순서로 신었다면, 벗을 때는 신발 → 양말 순서죠? 양말부터 벗을 수는 없어요! 로켓도 연료를 채운 뒤 발사대 팔을 뗐으니까, 되돌릴 때는 팔부터 다시 붙이고 그 다음 연료를 빼야 안전해요.
`top`은 "**다음 접시가 놓일 자리**"예요. 넣을 때는 지금 자리에 놓고 **그 다음** 올리니까 `top++`(뒤에 `++`). 꺼낼 때는 **먼저** 내려서 마지막 접시 자리로 가야 하니까 `--top`(앞에 `--`). 위치 하나 틀리면 빈 칸을 꺼내거나 접시를 덮어써요.
`push`가 꽉 찼을 때 0, `pop`이 비었을 때 `NULL`을 돌려주는 건 "**안 되는 상황을 알려 주는 문지기**"예요. 이게 없으면 배열 밖에 쓰거나 읽어요.

### 함수 정답 (상태 전이 함수)
```c
State next_state(State s, Event e) {
    if (e == E_FAULT && s != S_LIFTOFF && s != S_ABORT) return S_ABORT;
    switch (s) {
        case S_IDLE:  if (e == E_START)     return S_FUEL;    break;
        case S_FUEL:  if (e == E_FUEL_DONE) return S_CHECK;   break;
        case S_CHECK: if (e == E_ALL_GO)    return S_COUNT;   break;
        case S_COUNT: if (e == E_ZERO)      return S_LIFTOFF; break;
        default: break;
    }
    return s;                                 // 맞는 규칙이 없으면 그대로
}

// main 안에서
State ts[6] = {S_IDLE, S_IDLE, S_CHECK, S_COUNT, S_LIFTOFF, S_COUNT};
Event es[6] = {E_START, E_ZERO, E_FUEL_DONE, E_FAULT, E_FAULT, E_ZERO};
for (int i = 0; i < 6; i++)
    printf("%s + %s -> %s\n", sname[ts[i]], ename[es[i]], sname[next_state(ts[i], es[i])]);
```
출력:
```
대기 + START -> 연료주입
대기 + ZERO -> 대기
최종점검 + FUEL_DONE -> 최종점검
카운트다운 + FAULT -> 발사중단
발사 + FAULT -> 발사
카운트다운 + ZERO -> 발사
```
**왜 이렇게?** 보드게임 말판이에요. 말은 **정해진 길로만** 갈 수 있어요. "대기"에서 갑자기 "ZERO(발사!)" 카드가 나와도 연료도 안 넣었는데 쏠 수는 없죠. 그래서 **무시**하고 제자리예요.
- `FAULT`는 **비상벨**이라 어느 칸에서든 바로 "발사중단"으로 가요. 그래서 `switch` 전에 맨 먼저 검사해요. 단, 이미 하늘로 날아간 로켓(발사)은 되돌릴 수 없으니 예외예요.
- 이 함수는 `printf`도 안 하고 전역 변수도 안 바꿔요. "지금 칸 + 카드 → 다음 칸"만 알려줘요. 이런 함수는 **테스트하기 정말 쉬워요.** 위처럼 6줄로 모든 규칙을 확인할 수 있죠. 실제 우주 프로그램에서도 상태 전이는 이렇게 따로 떼어서 수천 번 테스트해요.
- `case` 안에서 `if`가 거짓이면 `break`로 `switch`를 빠져나와 마지막 `return s;`에 도착해요. `break`가 없으면 다음 `case`로 **줄줄이 흘러내려가서** 엉뚱한 규칙이 적용될 수 있어요.

### 흐름제어 정답 (2, 종합)
```c
// push, pop, next_state 는 위와 같아요
State run(const char *label, const int *p) {
    printf("===== %s =====\n", label);
    State s = S_IDLE;
    Stack st = { .top = 0 };
    Event script[4] = {E_ZERO, E_START, E_FUEL_DONE, E_ALL_GO};

    for (int k = 0; k < 4; k++) {                        // ① 발사 준비
        State n = next_state(s, script[k]);
        if (n == s) { printf("무시: %s (지금 %s)\n", ename[script[k]], sname[s]); continue; }
        printf("%s -> %s\n", sname[s], sname[n]);
        s = n;
        switch (s) {                                     // 새 상태에 들어갈 때 할 일
            case S_FUEL:  push(&st, "연료 배출"); push(&st, "산화제 배출"); break;
            case S_CHECK: push(&st, "외부전원 복귀"); break;
            case S_COUNT: push(&st, "발사대 팔 재결합"); break;
            default: break;
        }
    }

    int sum = 0, t = 10, i = 0;                          // ② 카운트다운 + 이동 평균
    while (s == S_COUNT) {
        if (t == 0) { s = next_state(s, E_ZERO); printf("T-0 LIFTOFF! (%s)\n", sname[s]); break; }
        sum += p[i];
        if (i >= WIN) sum -= p[i - WIN];
        if (i >= WIN - 1 && sum > P_MAX * WIN) {
            printf("T-%d 압력 평균 %.1fbar > %d! FAULT\n", t, (double)sum / WIN, P_MAX);
            s = next_state(s, E_FAULT);
            break;
        }
        t--;
        i++;
    }

    if (s == S_ABORT) {                                  // ③ 되돌리기
        const char *u;
        int n = 0;
        while ((u = pop(&st)) != NULL) printf("  되돌리기 %d: %s\n", ++n, u);
        printf("결과: %s (되돌린 작업 %d개)\n", sname[s], n);
    } else {
        printf("결과: %s (남은 되돌리기 %d개는 필요 없음)\n", sname[s], st.top);
    }
    return s;
}

int main(void) {
    int p_bad[10]  = {50, 52, 55, 61, 66, 72, 75, 69, 64, 60};
    int p_good[10] = {50, 51, 53, 72, 58, 60, 62, 63, 64, 65};
    int ok = 0;
    ok += run("1차 시도", p_bad)  == S_LIFTOFF;
    ok += run("2차 시도", p_good) == S_LIFTOFF;
    printf("발사 성공 %d번 / 시도 2번\n", ok);
    return 0;
}
```
출력:
```
===== 1차 시도 =====
무시: ZERO (지금 대기)
대기 -> 연료주입
연료주입 -> 최종점검
최종점검 -> 카운트다운
T-4 압력 평균 71.0bar > 70! FAULT
  되돌리기 1: 발사대 팔 재결합
  되돌리기 2: 외부전원 복귀
  되돌리기 3: 산화제 배출
  되돌리기 4: 연료 배출
결과: 발사중단 (되돌린 작업 4개)
===== 2차 시도 =====
무시: ZERO (지금 대기)
대기 -> 연료주입
연료주입 -> 최종점검
최종점검 -> 카운트다운
T-0 LIFTOFF! (발사)
결과: 발사 (남은 되돌리기 4개는 필요 없음)
발사 성공 1번 / 시도 2번
```
**왜 이렇게?** 오늘 만든 부품이 모두 모였어요! `next_state`(함수 + `switch`) → `push`/`pop`(구조체 스택) → 이동 평균(배열 창) → `while (s == S_COUNT)`(상태가 반복을 조종) → `break`/`continue`.
- 맨 처음 `ZERO`는 대기 상태에서 와서 **무시**됐어요. 누가 실수로 "발사!" 버튼을 먼저 눌러도 상태 머신이 막아 줘요. 이게 상태 머신을 쓰는 가장 큰 이유예요.
- 되돌리기는 "**그 상태에 들어갈 때**" 미리 쌓아 둬요. 그래야 어디서 멈추든 **딱 거기까지 한 일만** 거꾸로 되돌릴 수 있어요.
- 1차: 6번째 값(i=6, T-4)에서 평균 213 / 3 = 71.0 → FAULT → 발사중단 → 접시 4개를 위에서부터 되돌렸어요.
- 2차: `p_good`에도 72(i=3)가 있지만 평균은 (51+53+72)/3 = 58.7이라 괜찮아요. **한 번 튄 값**은 평균이 걸러 줘요. 그래서 T-0까지 가서 발사!
- `sum > P_MAX * WIN`(213 > 210)처럼 **양쪽에 3을 곱해서** 비교하면 소수를 안 써도 돼요. 소수는 0.1 같은 수를 정확히 못 담을 때가 있어서, 로켓·은행 프로그램은 될 수 있으면 정수로 비교해요.
- `run`을 **함수로** 만들었기 때문에 데이터만 바꿔서 두 번 시도할 수 있었어요. `== S_LIFTOFF`는 참이면 1, 거짓이면 0이라서 그대로 `ok`에 더해 성공 횟수를 셌어요.

💡 **오늘의 핵심 한 줄:** `||`와 `&&`는 **답이 정해지면 뒤를 안 봐요** — 그래서 "배열 범위 검사"는 항상 **앞에** 써요. 상태가 많은 프로그램은 **상태 머신**(`enum` + `switch` + 전이 함수)으로 정해진 길만 걷게 하고, 했던 일은 **스택**에 쌓아 두었다가 **거꾸로** 되돌려요!
