## 엔지니어가 직면한 가상의 문제 1

**[네이버 웹툰 업로드 시스템팀 — 가상]** 토요일 밤 11시, 인기 웹툰 새 회차가 올라가야 하는데 독자들이 "그림이 안 보여요!", "로딩이 너무 느려요!"라고 난리가 났어요. 조사해 보니 옛날 업로드 프로그램은 **깨진 파일(0KB)** 도 그대로 올리고, **엄청 큰 그림**도 줄이지 않고 올리고 있었어요. 엔지니어인 너는 **회차의 그림 컷을 하나씩 검사해서, 알맞게 처리하는 프로그램**을 새로 만들어야 해요.

**오늘의 규칙**

| 컷 크기(`size`, KB) | 상태 | 할 일 |
|---|---|---|
| `0` 이하 | 깨진 파일 | 올리지 않음 (건너뛰기) |
| `1` ~ `999` | 정상 | 그대로 업로드 |
| `1000` ~ `2999` | 큼 | 반으로 압축(÷2) 후 업로드 |
| `3000` 이상 | 너무 커요! | 작가에게 알리고 **업로드 중단** |

**오늘의 데이터**

```c
// 이번 회차 그림 6컷의 크기(KB). 0은 깨진 파일
int sizes[6] = {450, 1200, 0, 800, 2400, 3500};
```

### 조건문 퀴즈1

**📘 개념 설명 — 조건문 (`if / else if / else`)**
- **정의**: "만약 ~라면 이걸 하고, 아니면 저걸 해"라고 컴퓨터에게 **갈림길**을 알려 주는 문법이에요.
- **적용 논리**: 위에서부터 차례로 검사하다가 **처음으로 참인 곳 하나만** 실행해요. 그래서 범위를 **작은 수부터 차례로** 검사하면, 뒤쪽 조건에는 "몇 이상"을 다시 쓸 필요가 없어요.
- **응용 가능성**: 사진 앱의 "용량이 너무 커요" 경고, 이메일 첨부파일 크기 제한, 게임 다운로드 전 저장 공간 검사 등 **파일을 다루는 모든 곳**에서 쓰여요.

**문제**: `size` 값을 보고 규칙표대로 상태(`깨진 파일`, `정상`, `압축 필요`, `너무 커요!`)를 출력하세요.

```c
#include <stdio.h>

int main(void) {
    int size = 1200;   // 0, 450, 1200, 2999, 3000 으로 바꿔 가며 테스트해 보세요

    /* 여기에 코드를 작성하세요 */
    // 출력 예: size = 1200 이면 "압축 필요"

    return 0;
}
```

### 반복문 퀴즈1

- **응용 가능성**: 웹툰 60컷 차례로 보여 주기, 사진 앨범 100장 미리보기 만들기, 노래 재생목록 하나씩 틀기 등 **"여러 개를 하나씩 다 보기"** 에 항상 써요.

**문제**: `for` 문으로 6컷의 크기를 `"1컷: 450KB"` 처럼 한 줄씩 출력하세요. (컷 번호는 **1컷부터**예요!)

```c
#include <stdio.h>

int main(void) {

}
```

### 흐름제어 퀴즈1

**📘 개념 설명 — 흐름제어 (`continue`, `break`)**
- **정의**: 반복문 안에서 **이번 것만 건너뛰기(`continue`)**, **반복을 아예 멈추기(`break`)** 를 하는 명령이에요.
- **적용 논리**: `continue`를 만나면 아래 코드를 무시하고 **다음 차례**로 가요. `break`를 만나면 반복문을 **즉시 탈출**해요.
- **응용 가능성**: 깨진 파일은 건너뛰고, 규칙을 크게 어긴 파일이 나오면 업로드 전체를 멈추고 사람에게 알리기 — 파일 업로드·백업 프로그램의 기본 동작이에요.

**문제**: 1컷부터 차례로 검사하세요.
1. 크기가 **0 이하**이면 `"3컷: 깨진 파일, 건너뜀"` 출력 후 **건너뛰기**(`continue`)
2. 크기가 **3000 이상**이면 `"6컷: 너무 커요! 업로드 중단"` 출력 후 **멈추기**(`break`)
3. 그 밖에는 `"1컷: 업로드 준비"` 출력

```c
#include <stdio.h>

int main(void) {
    int sizes[6] = {450, 1200, 0, 800, 2400, 3500};

    for (int i = 0; i < 6; i++) {
        /* 여기에 코드를 작성하세요 */
    }
    printf("검사 끝\n");
    return 0;
}
```

### 배열 퀴즈1

- **적용 논리**: `sizes[i]` 처럼 번호로 칸을 꺼내요. 반복문과 함께 쓰면 "모두 더하기", "개수 세기", "제일 큰 것 찾기"를 할 수 있어요.
- **응용 가능성**: 서버 저장 공간 계산(파일 크기 합계), 가장 무거운 파일 찾기, 실패한 파일 개수 세기 — **통계와 보고서**의 기본이에요.

### 함수 퀴즈1

**📘 개념 설명 — 함수 (`return`)**
- **정의**: 자주 쓰는 일을 **이름 붙은 기계**로 만들어 두는 거예요. 재료(매개변수)를 넣으면 결과(`return`)가 나와요.
- **적용 논리**: 규칙을 함수 **한 곳**에 적어 두면, 규칙이 바뀌어도(예: 3000KB → 5000KB) 그 함수만 고치면 돼요.
- **응용 가능성**: 업로드 서버, 앱, 관리자 화면이 모두 **같은 검사 함수**를 불러 쓰면, 어디서 검사해도 결과가 똑같아요.

**문제**: 두 함수를 완성하세요.

2. `sumSizes(int arr[], int n)`: 배열의 값 중 **0보다 큰 것만** 더해서 돌려줘요.

```c
#include <stdio.h>

int getStatus(int size) {
    /* 여기에 코드를 작성하세요 */
}

int sumSizes(int arr[], int n) {
    /* 여기에 코드를 작성하세요 */
}

int main(void) {
    int sizes[6] = {450, 1200, 0, 800, 2400, 3500};
```

**[러닝 앱 스타트업 "달려라" 개발팀 — 가상]** 회사가 새 달리기 앱을 만들기로 했어요. 사람들이 매일 달린 거리를 기록하면, 앱이 **칭찬 배지**를 주고, **주간 목표**를 달성했는지 알려 주고, 친구들과 **별점**으로 비교해 줘요. 엔지니어인 너는 이 앱의 핵심인 **"주간 달리기 기록" 프로그램**을 처음부터 만들어야 해요!

## 문제 1 — 웹툰 회차 이미지 업로드 검사

### 조건문 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    int size = 1200;

    if (size <= 0) {
        printf("깨진 파일\n");
    } else if (size < 1000) {
        printf("정상\n");
    } else if (size < 3000) {
        printf("압축 필요\n");
    } else {
        printf("너무 커요!\n");
    }
    return 0;
}
```

출력: `압축 필요`

**🧒 쉽게 설명하면**
택배 상자를 보내는 우체국 아저씨를 생각해 봐요. "상자가 비었네? → 안 보냄", "작네? → 그냥 보냄", "크네? → 접어서 보냄", "너무 크네? → 못 보냄!"
- **왜 `size <= 0` 이 맨 앞?** 빈 상자(0KB)는 보낼 필요가 없어요. **말이 안 되는 것부터** 걸러야 아래 검사가 편해져요. `== 0` 대신 `<= 0` 으로 쓰면 혹시 이상한 음수가 와도 같이 걸러져서 더 안전해요.
- **왜 `size < 3000` 에 "1000 이상"을 안 쓸까?** `else if`는 "앞의 것이 다 아닐 때만" 검사해요. 여기까지 왔다면 이미 1000 이상이라는 뜻이에요.
- **경계값 조심!** 2999는 "압축 필요", 3000은 "너무 커요!"예요. `size <= 3000` 이라고 쓰면 3000KB가 통과돼 버려요.

**🧒 쉽게 설명하면**
- `continue` = **"이 사진은 찢어졌으니 패스!"** 3컷은 아래 `"업로드 준비"`를 건너뛰고 바로 4컷으로 가요.
- `break` = **"잠깐! 다 멈춰!"** 너무 큰 그림이 있으면 독자 화면이 멈출 수 있어요. 그래서 **작가에게 먼저 알려야** 해서 반복을 끝내요.
- **순서가 중요해요.** `continue`/`break` 검사를 `printf("업로드 준비")` **보다 위에** 둬야 해요. 아래에 두면 깨진 파일도 "업로드 준비"라고 먼저 출력돼 버려요.
- `break`는 **반복문만** 빠져나가요. 그래서 `"검사 끝"`은 꼭 출력돼요.

### 배열 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    int sizes[6] = {450, 1200, 0, 800, 2400, 3500};
    int broken = 0, total = 0, count = 0;
    int biggest = 0;
    int biggestCut = 0;

    for (int i = 0; i < 6; i++) {
        if (sizes[i] <= 0) {
            broken++;
            continue;          // 깨진 파일은 합계·평균에서 빼기
        }
        total += sizes[i];
        count++;
        if (sizes[i] > biggest) {
            biggest = sizes[i];
            biggestCut = i;    // 값뿐 아니라 "몇 번 칸인지"도 기억!
        }
    }

    if (count > 0) {
        printf("깨진 파일 %d개, 합계 %dKB, 평균 %dKB, 가장 큰 컷 %d컷(%dKB)\n",
               broken, total, total / count, biggestCut + 1, biggest);
    } else {
        printf("올릴 수 있는 컷이 하나도 없어요!\n");
    }
    return 0;
}
```

출력: `깨진 파일 1개, 합계 8350KB, 평균 1670KB, 가장 큰 컷 6컷(3500KB)`
(450 + 1200 + 800 + 2400 + 3500 = 8350, 8350 ÷ 5 = 1670)

**🧒 쉽게 설명하면**
가방에 든 책 무게를 재는 것과 같아요. 빈 책 표지(0KB)는 세지 않고, "고장 난 책 1권"이라고만 적어 둬요.
- **왜 `biggestCut`을 따로 기억할까?** "제일 큰 게 3500KB야"만 알면 작가에게 "**몇 컷**이 커요"라고 말해 줄 수 없어요. **번호(인덱스)** 도 같이 기억해야 해요.
- **`biggest`는 왜 0에서 시작해도 될까?** 깨지지 않은 컷은 모두 1KB 이상이라, 첫 정상 컷을 만나면 바로 바뀌어요.
- **`if (count > 0)` 은 왜?** 컷이 전부 깨졌으면 `count`가 0이에요. **0으로 나누면 프로그램이 멈춰요!**

### 포인터 변수 퀴즈1 정답

```c
#include <stdio.h>

void compress(int *size) {
    *size = *size / 2;
}

void swapCuts(int *a, int *b) {
    int temp = *a;   // a의 값을 잠깐 다른 그릇에 옮겨 두기
    *a = *b;
    *b = temp;
}

int main(void) {
    int cut2 = 1200, cut4 = 800;

    compress(&cut2);
    printf("압축 후 2컷: %dKB\n", cut2);

    swapCuts(&cut2, &cut4);
    printf("바꾼 후 2컷: %dKB, 4컷: %dKB\n", cut2, cut4);
    return 0;
}
```

출력:
```
압축 후 2컷: 600KB
바꾼 후 2컷: 800KB, 4컷: 600KB
```

**🧒 쉽게 설명하면**
- **왜 `&cut2` 로 넘길까?** 친구에게 "우리 집 화분 물 줘"라고 할 때 **화분 사진**(복사본)을 주면 사진에만 물이 묻어요. **집 주소**(`&`)를 줘야 진짜 화분에 물을 줄 수 있어요.
- **`*size` 는?** "그 주소에 있는 진짜 값"이라는 뜻이에요. `*size = *size / 2` 는 "진짜 값을 반으로 줄여!"
- **`swapCuts`에 왜 `temp`가 필요할까?** 오렌지 주스 컵과 우유 컵을 바꾸려면 **빈 컵 하나**가 더 있어야 해요. 바로 `*a = *b` 를 하면 a에 있던 값이 사라져 버려요!

### 구조체 퀴즈1 정답

```c
#include <stdio.h>

struct Cut {
    int number;
    int size;
    int ok;
};

int main(void) {
    struct Cut cuts[3] = {
        {1, 450, 1},
        {2, 0, 0},
        {3, 800, 1}
    };

    // 1. 카드 3장 출력
    for (int i = 0; i < 3; i++) {
        if (cuts[i].ok == 1) {
            printf("%d컷: %dKB 업로드 가능\n", cuts[i].number, cuts[i].size);
        } else {
            printf("%d컷: %dKB 업로드 불가\n", cuts[i].number, cuts[i].size);
        }
    }

    // 2. 포인터로 2컷 카드 고치기
    struct Cut *p = &cuts[1];
    p->size = 700;
    p->ok = 1;
    printf("다시 받은 %d컷: %dKB 업로드 가능\n", p->number, p->size);
    return 0;
}
```

출력:
```
1컷: 450KB 업로드 가능
2컷: 0KB 업로드 불가
3컷: 800KB 업로드 가능
다시 받은 2컷: 700KB 업로드 가능
```

**🧒 쉽게 설명하면**
구조체는 **학생증**처럼 번호·크기·가능 여부가 한 장에 적힌 카드예요.
- **`cuts[i].size`** = "i번 카드의 크기 칸"이에요. 점(`.`)은 "~의"라는 뜻!
- **왜 `&cuts[1]` 일까?** 2컷은 **1번 칸**에 있어요(0번부터 세니까요). 컷 번호와 칸 번호가 1 차이 나는 걸 꼭 기억해요.
- **`p->size` 는?** `p`는 카드의 **주소**를 가진 포인터라서 점 대신 화살표(`->`)를 써요. 화살표로 "그 카드에 가서 크기 칸을 바꿔!"라고 하면 **진짜 카드**가 바뀌어요.

### 함수 퀴즈1 정답

```c
#include <stdio.h>

int getStatus(int size) {
    if (size <= 0) return 0;
    else if (size < 1000) return 1;
    else if (size < 3000) return 2;
    else return 3;
}

int sumSizes(int arr[], int n) {
    int sum = 0;
    for (int i = 0; i < n; i++) {
        if (arr[i] > 0) {
            sum += arr[i];
        }
    }
    return sum;
}

int main(void) {
    int sizes[6] = {450, 1200, 0, 800, 2400, 3500};

    for (int i = 0; i < 6; i++) {
        printf("%d컷 상태 번호: %d\n", i + 1, getStatus(sizes[i]));
    }
    printf("합계: %dKB\n", sumSizes(sizes, 6));
    return 0;
}
```

출력:
```
1컷 상태 번호: 1
2컷 상태 번호: 2
3컷 상태 번호: 0
4컷 상태 번호: 1
5컷 상태 번호: 2
6컷 상태 번호: 3

```

**🧒 쉽게 설명하면**
함수는 **자판기**예요. 동전(크기)을 넣으면 음료(상태 번호)가 나와요.
- **왜 번호로 돌려줄까?** 글자보다 숫자가 비교하기 쉬워요. 받는 쪽에서 `if (getStatus(s) == 2)` 처럼 바로 판단할 수 있어요.
- **`return` 을 만나면?** 그 자리에서 **함수가 끝나요.** 그래서 첫 조건이 맞으면 아래 조건은 아예 안 봐요.
- **`sumSizes(sizes, 6)` 에서 왜 6을 같이 줄까?** 함수는 배열을 받으면 **칸이 몇 개인지 몰라요.** 그래서 칸 수를 따로 알려 줘야 해요.

### 흐름제어 퀴즈1 (종합) 정답

```c
#include <stdio.h>

#define SKIP   0
#define UPLOAD 1
#define STOP   2

struct Cut {
    int number;
    int size;
};

int checkCut(struct Cut *c) {
    if (c->size <= 0) {
        return SKIP;
    }
    if (c->size >= 3000) {
        return STOP;
    }
    if (c->size >= 1000) {
        printf("%d컷: %dKB → %dKB로 압축\n", c->number, c->size, c->size / 2);
        c->size = c->size / 2;     // 포인터라서 진짜 카드의 크기가 바뀌어요
    }
    return UPLOAD;
}

int main(void) {
    struct Cut episode[6] = {
        {1, 450}, {2, 1200}, {3, 0}, {4, 800}, {5, 2400}, {6, 3500}
    };
    int uploaded = 0, total = 0;

    for (int i = 0; i < 6; i++) {
        int result = checkCut(&episode[i]);

        if (result == SKIP) {
            printf("%d컷: 깨진 파일, 건너뜀\n", episode[i].number);
            continue;
        }
        if (result == STOP) {
            printf("%d컷: %dKB 너무 커요! 업로드 중단\n", episode[i].number, episode[i].size);
            break;
        }
        printf("%d컷: %dKB 업로드\n", episode[i].number, episode[i].size);
        uploaded++;
        total += episode[i].size;
    }

    printf("결과: %d컷 업로드, 총 %dKB\n", uploaded, total);
    return 0;
}
```

출력:
```
1컷: 450KB 업로드
2컷: 1200KB → 600KB로 압축
2컷: 600KB 업로드
3컷: 깨진 파일, 건너뜀
4컷: 800KB 업로드
5컷: 2400KB → 1200KB로 압축
5컷: 1200KB 업로드
6컷: 3500KB 너무 커요! 업로드 중단
결과: 4컷 업로드, 총 3050KB
```
(450 + 600 + 800 + 1200 = 3050)

**🧒 쉽게 설명하면**
학교 게시판에 그림을 붙이는 **도우미(함수)** 와 **반장(main)** 을 떠올려 봐요.
- 반장이 그림을 한 장씩 도우미에게 건네요(`&episode[i]`, 그림 **자체**를 건네는 거예요).
- 도우미는 그림을 보고 "찢어졌어(SKIP)", "괜찮아, 너무 크면 접어 줄게(UPLOAD)", "이건 너무 커서 안 돼(STOP)" 중 하나를 말해 줘요.
- 반장은 그 말을 듣고 **다음 그림으로 넘어가거나(`continue`)**, **붙이고 개수를 세거나**, **멈추고 선생님을 불러요(`break`)**.
- **왜 함수는 `continue`/`break`를 안 쓰고 신호만 돌려줄까?** `continue`와 `break`는 **반복문 안에서만** 쓸 수 있어요. 함수는 "판단"만, 반복 제어는 `main`이 맡는 거예요. 이렇게 **역할을 나누면** 코드가 훨씬 읽기 쉬워요.
- **`#define SKIP 0`은 왜?** `if (result == 0)` 보다 `if (result == SKIP)` 이 뜻을 바로 알 수 있어요. 숫자에 **이름표**를 붙인 거예요.

### 조건문 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    int todayKm = 5;

    if (todayKm < 0) {
        printf("기록 오류\n");
    } else if (todayKm == 0) {
        printf("쉬는 날\n");
    } else if (todayKm <= 2) {
        printf("가볍게 달렸어요\n");
    } else if (todayKm <= 5) {
        printf("잘 달렸어요\n");
    } else {
        printf("대단해요!\n");
    }
    return 0;
}
```

출력: `잘 달렸어요`

**🧒 쉽게 설명하면**
선생님이 숙제 검사 후 스티커를 주는 것과 같아요. "이름이 거꾸로 적혔네(오류)", "안 했네(쉬는 날)", "조금 했네", "잘했네", "와, 대단해!"
- **왜 `todayKm < 0` 이 맨 앞?** 사람이 -1km를 달릴 수는 없죠! GPS가 실수한 거예요. 이런 값에 "가볍게 달렸어요"라고 칭찬하면 이상하니까 **제일 먼저** 걸러요.
- **왜 `== 0` 을 따로?** 0km는 "가볍게"가 아니라 **아예 안 달린 날**이에요. 딱 한 값만 특별하면 `==` 로 콕 집어요. (`=` 하나만 쓰면 비교가 아니라 "넣기"가 되니 조심!)
- **`<= 2` 와 `<= 5`**: 규칙이 "1~2", "3~5"처럼 **끝 숫자를 포함**하니까 `<=` 를 써요.

### 반복문 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    const char *days[7] = {"월", "화", "수", "목", "금", "토", "일"};

    int total = 0;
    int i = 0;
```

출력:
```
월: 누적 3km

```

**🧒 쉽게 설명하면**

- **조건이 왜 두 개(`&&`)일까?** `total < goal` 만 쓰면, 일주일 내내 달려도 목표를 못 채운 사람은 **8일째, 9일째… 없는 날**까지 계속 돌아요. `i < 7` 은 "일주일이 끝나면 무조건 그만"이라는 **안전장치**예요. `&&`는 "둘 다 참일 때만 계속"이라는 뜻이에요.

- **왜 여기선 `for` 말고 `while`?** "며칠 걸릴지 **미리 모를 때**"는 `while`이 더 자연스러워요.

### 배열 퀴즈1 정답

```c
#include <stdio.h>

int main(void) {
    const char *days[7] = {"월", "화", "수", "목", "금", "토", "일"};
    int km[7] = {3, 0, 5, 0, 8, 4, 6};
    int runDays = 0, total = 0;
    int best = 0;

    for (int i = 0; i < 7; i++) {
        if (km[i] > 0) {
            runDays++;
            total += km[i];
        }
        if (km[i] > km[best]) {
            best = i;
        }
    }

    printf("달린 날 %d일, 총 %dkm, 최고 기록 %s요일 %dkm\n",
           runDays, total, days[best], km[best]);
    return 0;
}
```

출력: `달린 날 5일, 총 26km, 최고 기록 금요일 8km`
(3 + 5 + 8 + 4 + 6 = 26)

**🧒 쉽게 설명하면**
**요일 이름표 줄**과 **거리 줄**이 나란히 서 있다고 생각해 봐요. 같은 자리(번호)에 선 친구끼리 짝꿍이에요. `days[4]`는 "금", `km[4]`는 8 → "금요일에 8km"!
- **왜 `best`에 값이 아니라 번호를 저장할까?** 번호만 알면 `km[best]`로 거리도, `days[best]`로 요일도 **둘 다** 꺼낼 수 있어요. 값(8)만 기억하면 "몇 요일이었지?"를 알 수 없어요.
- **왜 `best = 0` 으로 시작해도 될까?** "일단 월요일이 최고라고 치고, 더 많이 달린 날이 나오면 바꾸자"는 뜻이에요. 실제 배열의 첫 칸에서 출발하니 안전해요.
- **왜 `>` 이고 `>=` 가 아닐까?** 똑같은 기록이 또 나오면 **먼저 나온 날**을 최고 기록으로 남기려고요. (`>=` 면 나중 날로 바뀌어요. 정하기 나름!)

### 포인터 변수 퀴즈1 정답

```c
#include <stdio.h>

void addRun(int *total, int km) {
    *total = *total + km;     // *total += km; 라고 써도 같아요
}

void updateBest(int *best, int km) {
    if (km > *best) {
        *best = km;
    }
}

int main(void) {
    int total = 0, best = 0;
    int runs[3] = {3, 8, 5};

    for (int i = 0; i < 3; i++) {
        addRun(&total, runs[i]);
        updateBest(&best, runs[i]);
    }
    printf("누적 %dkm, 최고 기록 %dkm\n", total, best);
    return 0;
}
```

출력: `누적 16km, 최고 기록 8km`

**🧒 쉽게 설명하면**
- **`total` 은 주소로, `km` 는 그냥 값으로 줄까?** `total`은 **바꿔야 하는 원본**(내 기록장)이라 주소를 줘요. `km`는 **읽기만** 하면 되니까 값만 줘도 돼요. "바꿀 것은 주소, 읽을 것은 값"!
- **`updateBest` 는 어떻게 움직여요?** 3km → "0보다 크네, 최고 3!", 8km → "3보다 크네, 최고 8!", 5km → "8보다 작네, 그대로". 마치 **키 재기 왕 뽑기**처럼 더 큰 친구가 나올 때만 왕관을 넘겨줘요.
- **포인터 없이 `int total` 로 받으면?** 함수 안의 **복사본**만 커지고, 밖의 `total`은 계속 0이에요. 앱 화면에 "누적 0km"가 뜨는 버그!

### 구조체 퀴즈1 정답

```c
#include <stdio.h>

struct Runner {
    char name[20];
    int totalKm;
    int goalKm;
};

void printRunner(struct Runner *r) {
    int percent = 0;
    if (r->goalKm > 0) {
        percent = r->totalKm * 100 / r->goalKm;
    }

    if (r->totalKm >= r->goalKm) {
        printf("%s: %d/%dkm (%d%%) 달성!\n", r->name, r->totalKm, r->goalKm, percent);
    } else {
        printf("%s: %d/%dkm (%d%%) 조금 더!\n", r->name, r->totalKm, r->goalKm, percent);
    }
}

int main(void) {
    struct Runner runners[3] = {
        {"민지", 26, 20},
        {"준호", 12, 20},
        {"서연", 20, 20}
    };

    for (int i = 0; i < 3; i++) {
        printRunner(&runners[i]);
    }
    return 0;
}
```

출력:
```
민지: 26/20km (130%) 달성!
준호: 12/20km (60%) 조금 더!
서연: 20/20km (100%) 달성!
```

**🧒 쉽게 설명하면**
친구마다 **운동 카드**가 한 장씩 있고, 카드에는 이름·이번 주 거리·목표가 적혀 있어요.
- **왜 `r->name` 일까?** `r`은 카드의 **주소**예요. 주소로 카드를 찾아가서 이름 칸을 읽으려면 화살표(`->`)를 써요.
- **왜 `* 100` 을 먼저 할까?** 정수 나눗셈은 소수점을 버려요. `12 / 20` 은 **0** 이 돼서 0%가 나와요! 먼저 `12 * 100 = 1200` 을 만들고 `÷ 20` 해야 **60%** 가 나와요.
- **`%%` 는?** `printf`에서 `%`는 특별한 기호라서, 진짜 퍼센트 글자를 찍으려면 **두 번** 써야 해요.

### 함수 퀴즈1 정답

```c
#include <stdio.h>

int calcPercent(int total, int goal) {
    if (goal <= 0) {
        return 0;
    }
    return total * 100 / goal;
}

int getStars(int percent) {
    if (percent >= 100) return 3;
    else if (percent >= 50) return 2;
    else if (percent >= 1) return 1;
    else return 0;
}

int main(void) {
    int totals[4] = {26, 12, 0, 5};
    int goal = 20;

    for (int i = 0; i < 4; i++) {
        int stars = getStars(calcPercent(totals[i], goal));
        printf("%dkm: ", totals[i]);
        if (stars == 0) {
            printf("별 없음");
        }
        for (int s = 0; s < stars; s++) {
            printf("★");
        }
        printf("\n");
    }
    return 0;
}
```

출력:
```
26km: ★★★
12km: ★★
0km: 별 없음
5km: ★
```
(26 → 130% → 별 3개, 12 → 60% → 별 2개, 0 → 0% → 별 없음, 5 → 25% → 별 1개)

**🧒 쉽게 설명하면**
**기계 두 대를 줄 세운 공장**이에요. 첫 번째 기계(`calcPercent`)가 거리를 "몇 %"로 바꾸면, 그 결과가 바로 두 번째 기계(`getStars`)에 들어가서 "별 몇 개"가 나와요.
- **`getStars(calcPercent(...))` 는 안쪽부터!** 수학에서 괄호 안을 먼저 계산하듯, **안쪽 함수가 먼저** 실행돼요.
- **`goal <= 0` 검사는 왜?** 목표를 0으로 잘못 설정한 사람이 있으면 0으로 나누게 돼서 **앱이 꺼져요.** 함수 안에서 미리 막아 두면, 이 함수를 쓰는 **모든 곳이 안전**해져요.
- **별 찍기 `for (s = 0; s < stars; s++)`**: 별이 3개면 0, 1, 2 → 세 번 찍어요. 별이 0개면 `0 < 0`이 거짓이라 **한 번도 안 돌아요.** 그래서 "별 없음"을 따로 출력해 줬어요.

### 흐름제어 퀴즈1 (종합) 정답

```c
#include <stdio.h>

const char *days[7] = {"월", "화", "수", "목", "금", "토", "일"};

struct Runner {
    char name[20];
    int km[7];
    int goalKm;
    int totalKm;
    int goalDay;
};

int calcPercent(int total, int goal) {
    if (goal <= 0) return 0;
    return total * 100 / goal;
}

int getStars(int percent) {
    if (percent >= 100) return 3;
    else if (percent >= 50) return 2;
    else if (percent >= 1) return 1;
    else return 0;
}

void runWeek(struct Runner *r) {
    for (int i = 0; i < 7; i++) {
        if (r->km[i] == 0) {
            continue;                       // 쉬는 날
        }
        if (r->km[i] < 0) {
            printf("%s: %s요일 GPS 오류! 기록 중단\n", r->name, days[i]);
            break;                          // 믿을 수 없는 기록
        }
        r->totalKm += r->km[i];
        if (r->goalDay == -1 && r->totalKm >= r->goalKm) {
            r->goalDay = i;                 // 처음 목표를 넘은 날만 기억
        }
    }
}

int main(void) {
    struct Runner friends[3] = {
        {"민지", {3, 0, 5, 0, 8, 4, 6},  15, 0, -1},
        {"준호", {2, 2, 0, -1, 5, 0, 3}, 20, 0, -1},
        {"서연", {0, 4, 4, 4, 0, 4, 4},  20, 0, -1}
    };

    for (int i = 0; i < 3; i++) {
        struct Runner *r = &friends[i];
        runWeek(r);
        int stars = getStars(calcPercent(r->totalKm, r->goalKm));

        if (r->goalDay != -1) {
            printf("%s: %dkm, %s요일에 목표 달성, 별 %d개\n",
                   r->name, r->totalKm, days[r->goalDay], stars);
        } else {
            printf("%s: %dkm, 목표 미달성, 별 %d개\n",
                   r->name, r->totalKm, stars);
        }
    }
    return 0;
}
```

출력:
```
민지: 26km, 금요일에 목표 달성, 별 3개
준호: 목요일 GPS 오류! 기록 중단
준호: 4km, 목표 미달성, 별 1개
서연: 20km, 일요일에 목표 달성, 별 3개
```

계산 확인:
- 민지: 3+5+8+4+6 = 26km, 금요일에 16km로 목표 15km 처음 넘음, 173% → 별 3개
- 준호: 2+2 = 4km 후 목요일 -1 → 중단, 4×100÷20 = 20% → 별 1개
- 서연: 4×5 = 20km, 일요일에 딱 20km 도달, 100% → 별 3개

**🧒 쉽게 설명하면**
반 친구들 **줄넘기 기록장**을 선생님이 검사하는 모습이에요.
- **바깥 반복(`main`)** 은 "다음 친구 기록장 주세요", **안쪽 반복(`runWeek`)** 은 "월요일부터 일요일까지 한 칸씩 볼게요"예요. 반복 안에 반복이 들어 있어요!
- **쉬는 날 → `continue`**: 빈칸은 그냥 넘겨요.
- **GPS 오류 → `break`**: "-1km?" 이상한 기록이 나오면 그 뒤도 믿을 수 없으니, **그 친구의 검사만** 멈춰요. `break`는 **자기가 들어 있는 반복 하나**만 빠져나가요. 그래서 준호 다음 서연이 검사는 그대로 계속돼요!
- **`r->goalDay == -1 &&` 는 왜?** 민지는 금요일에 목표를 넘고, 토·일에도 계속 "목표 이상"이에요. 이 검사가 없으면 달성 요일이 **일요일로 덮어써져요.** "아직 기록 안 했을 때만" 적으라는 뜻이에요.
- **`-1` 은 왜 시작값?** 요일 번호는 0~6이에요. 그래서 **절대 나올 수 없는 -1**을 "아직 없음"이라는 표시로 써요. 현업에서도 자주 쓰는 방법이에요.
- **함수에 카드 주소(`r`)를 넘긴 이유**: `runWeek`가 `totalKm`과 `goalDay`를 **진짜 카드에 직접** 적어야, `main`에서 결과를 읽을 수 있어요.

## 📝 오늘의 핵심 정리

| 도구 | 한 줄 요약 | 오늘 쓴 곳 |
|---|---|---|
| `if / else if / else` | 위에서부터 처음 맞는 것 하나만 실행 | 컷 크기 판정, 달리기 칭찬 배지 |
| `for` | 정해진 횟수만큼 반복 (배열과 짝꿍) | 6컷 검사, 일주일 기록, 별 찍기 |
| `while` | 조건이 참인 동안 반복 (값을 꼭 바꿔야 함) | 목표까지 며칠 걸렸나 |
| `&&` | 두 조건이 **모두** 참일 때만 참 | `i < 7 && total < goal`, 처음 달성일 기억 |
| `continue` | 이번 것만 건너뛰기 | 깨진 파일, 쉬는 날 |
| `break` | 자기가 든 반복 하나만 즉시 멈추기 | 너무 큰 그림, 목표 달성, GPS 오류 |
| 배열 | 번호 붙은 칸 (0번부터!) | 컷 크기 목록, 요일·거리 짝꿍 배열 |
| 포인터 `*` `&` `->` | 주소를 넘겨서 원본을 바꾸기 | 압축, 순서 바꾸기(swap), 누적·최고 기록 |
| 구조체 `.` `->` | 여러 정보를 카드 한 장으로 | 컷 카드, 러너 카드(안에 배열까지!) |
| 함수 `return` | 규칙을 이름 붙인 기계로 | 상태 번호, 합계, 달성률 → 별점 |

**오늘의 버그 사냥 포인트 🐛**
1. **`continue`/`break` 검사는 "처리"보다 위에** — 아래에 두면 깨진 파일도 "업로드 준비"가 먼저 찍혀요.
2. **최고값을 찾을 땐 "번호"를 기억** — 값만 기억하면 "몇 컷이었지? 무슨 요일이었지?"를 몰라요.
3. **바꾸기(swap)에는 빈 컵(`temp`) 하나** — 없으면 한쪽 값이 사라져요.
4. **`while` 조건엔 안전장치 `i < 7`** — 목표를 못 채운 사람 때문에 없는 8일째를 읽는 사고 방지.
5. **퍼센트는 `* 100` 먼저, `÷` 나중** — 반대로 하면 정수 나눗셈 때문에 0%가 돼요.
6. **"처음 한 번만" 기록하려면 `-1` 표시 + `&&`** — 안 그러면 달성 요일이 계속 덮어써져요.
7. **`break`는 반복 하나만 탈출** — 안쪽 반복에서 `break`해도 바깥 반복은 계속 돌아요.
