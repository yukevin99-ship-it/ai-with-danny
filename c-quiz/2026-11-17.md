## 엔지니어가 직면한 가상의 문제 1

**[Google 검색 서버팀]** 오늘 아침부터 검색 결과가 늦게 뜬다는 신고가 쏟아졌어요! 서버는 자주 찾는 단어의 결과를 **캐시**(책상 위 작은 메모장)에 적어 둬요. 메모장에 있으면 2ms 만에 답하지만(적중, hit), 없으면 멀리 있는 **DB**(도서관 큰 책장)까지 가야 해서 60ms가 걸려요(놓침, miss). 메모장은 **3칸**뿐이라 꽉 차면 **가장 오래 안 쓴 것(LRU, Least Recently Used)** 을 지우고 새 것을 적어요.

```c
#include <stdio.h>
#include <string.h>

#define CAP    3        // 캐시 칸 수
#define HIT_MS 2        // 캐시 적중 때 걸리는 시간 (ms)
#define DB_MS  60       // DB까지 다녀올 때 걸리는 시간 (ms)
#define SLA_MS 320      // 약속한 최대 누적 시간 (넘으면 경보!)

typedef struct { char key[8]; int last; int valid; } Entry;   // last = 마지막으로 쓴 시각
typedef struct { Entry slot[CAP]; int clock; int hits; int misses; } Cache;

const char *reqs[10] = {"cat", "dog", "cat", "sun", "map", "dog", "cat", "art", "map", "cat"};
```

- **조건문 퀴즈 1:** 응답 시간 기록 `int ms[8] = {2, 61, 0, 140, 2, 260, 100, 5};`가 있어요. `const char *grade(int ms)`를 `if - else if - else`로 만드세요. 0이면 `"측정 실패"`, 5 이하 `"캐시 적중"`, 100 이하 `"DB 조회"`, 200 이하 `"느림"`, 그보다 크면 `"타임아웃 위험"`이에요. `"3번 요청: 0ms -> 측정 실패"`처럼 8개를 출력하세요.
  (① 왜 `ms == 0`을 **맨 먼저** 검사할까요? ② `ms <= 100`을 `ms <= 5`보다 먼저 쓰면 1번 요청(2ms)은 어떻게 나올까요?)
- **반복문 퀴즈 1 (`do-while`):** DB가 잠깐 쓰러졌어요. 다시 연결을 시도하는데, `int up[6] = {0, 0, 0, 1, 1, 1};`(i번째 시도에 1이면 성공)이에요. 실패하면 `wait`ms를 기다리고 `wait`를 **2배**로 늘려요(100 → 200 → 400…, "지수 백오프"). **최대 5번**까지만 시도해요. `do { ... } while (!ok && t < 5);`로 만들고 `"2번째 시도 실패 -> 200ms 기다림"`, `"4번째 시도: 연결 성공!"`, `"총 기다린 시간 Nms"`를 출력하세요. (왜 `while`이 아니라 `do-while`이 어울릴까요?)
- **흐름제어 퀴즈 1 (중첩 반복문):** 지금 캐시 안에는 `const char *snap[3] = {"cat", "sun", "dog"};`가 있어요. 검색어 `const char *q[6] = {"sun", "", "art", "dog", "STOP", "cat"};`를 하나씩 보면서, 안쪽 `for`로 `snap`을 뒤져요. 찾으면 안쪽 반복만 `break`해요. 빈 문자열이면 `"빈 요청 무시"` 후 `continue`, `"STOP"`이면 `"STOP 신호! 검사 끝"` 후 **바깥 반복을** `break`해요. 적중은 몇 개일까요? `"cat"`은 검사될까요? (안쪽 `for` 안의 `break`는 어디까지 빠져나갈까요?)
- **배열 퀴즈 1 (2차원 배열):** 서버 3대가 하루를 6시간씩 4구간으로 나눠 기록한 캐시 적중 수예요:

  이중 `for`로 ① 서버별 합계 ② 구간별 합계(`col[4]`) ③ 가장 큰 칸의 위치(`h[?][?]`)를 구하세요. 가장 바쁜 서버와 가장 바쁜 시간 구간은요?
- **포인터 변수 퀴즈 1 (포인터를 돌려주는 함수):** `Cache c = {{{"cat", 5, 1}, {"sun", 2, 1}, {"dog", 7, 1}}, 7, 0, 0};`이에요. `Entry *pick_victim(Cache *c)`를 만드세요. 빈 칸(`valid == 0`)이 있으면 그 칸 주소를, 없으면 `last`가 가장 작은 칸의 주소를 돌려줘요. 돌려받은 포인터 `v`로 `strcpy(v->key, "art"); v->last = ++c.clock;`을 하면 3칸은 어떻게 바뀔까요? `v - c.slot`은 얼마일까요? (함수 안의 지역 변수 `Entry tmp;`의 주소 `&tmp`를 돌려주면 왜 안 될까요?)

  을 한 뒤 `backup.slot[0].key`, `backup.hits`, `alias->slot[0].key`, `alias->hits`를 출력하면? 구조체 안의 **배열까지** 복사될까요? `sizeof(Cache)`는 몇 바이트일까요? (그래서 함수에 `Cache`를 넘길 때 왜 `Cache *`로 넘길까요?)
- **함수 퀴즈 1 (재귀 + 메모이제이션):** 캐시의 원리는 "**한 번 계산한 건 적어 두기**"예요. 피보나치 `fib(n) = fib(n-1) + fib(n-2)`(fib(0)=0, fib(1)=1)를 **재귀**로 만들고 전역 변수 `calls`로 함수가 몇 번 불렸는지 세세요. 그 다음 `long long memo[50];`에 답을 적어 두는 `fib_memo`를 만들어 비교하세요. `fib(20)`의 값과 두 방식의 호출 횟수는? `fib(30)`을 그냥 재귀로 하면 몇 번 불릴까요?
- **흐름제어 퀴즈 2 (종합):** 진짜 LRU 캐시를 돌려요. 빈 캐시 `Cache k = {0};`로 시작해서 `reqs` 10개를 순서대로 처리해요:
  - `int find(const Cache *c, const char *key)`로 찾고, 매 요청마다 `k.clock++`
  - 있으면 → `last`를 지금 시각으로 바꾸고 `"3) cat: 적중 +2ms (누적 122ms)"`
  - 없으면 → `pick_victim`이 고른 칸에 새 단어를 적고 `"5) map: 놓침 +60ms (누적 242ms) / 쫓아냄: dog"` (빈 칸에 적었으면 "쫓아냄"은 안 써요)
  - 누적 시간이 `SLA_MS`를 넘으면 `"SLA 경보! ..."` 후 `break`
  - 마지막에 `"처리 N건, 적중 H, 놓침 M, 적중률 R%"`. 실제 출력은? 왜 적중률이 이렇게 낮을까요? 캐시를 4칸으로 늘리면 어떻게 될까요?

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[스마트 주차장 정산 시스템팀]** 대형 쇼핑몰 지하 주차장(B1~B3, 층마다 4칸)의 프로그램을 새로 만들어요. 들어오는 차에게 빈 칸을 찾아 주고, 꽉 차면 줄을 세우고, 나가는 차는 요금을 계산해요. 각 층의 **4번째 칸(인덱스 3)은 전기차(EV) 충전 칸**이라서 전기차만 쓸 수 있고, 전기차도 충전 칸에만 세워요.

```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>     // malloc, free

#define FLOORS   3
#define SLOTS    4
#define FREE_MIN 30     // 30분까지 무료
#define DAY_MAX  15000  // 하루 최대 요금 (원)

typedef enum { SMALL, NORMAL, EV } CarType;      // 경차, 일반, 전기차
typedef struct { char plate[16]; CarType type; int member; int floor, slot; int in_min; int used; } Car;
typedef struct Node { char plate[16]; CarType type; int member; struct Node *next; } Node;   // 대기 줄
typedef struct { char kind; char plate[16]; CarType type; int member; char time[8]; } Event;  // 'I' 입차, 'O' 출차, 'X' 고장

int lot[FLOORS][SLOTS] = {      // 0 = 빈칸, 1 = 차 있음, -1 = 고장
    {1,  1, 0, 1},              // B1
    {1, -1, 1, 0},              // B2
    {0,  1, 1, 1}               // B3
};
const char *fl[3] = {"B1", "B2", "B3"};
```
요금 규칙: 30분까지 무료. 넘으면 넘은 시간을 **10분 단위로 올림**해서, 단위당 경차 500원 / 전기차 600원 / 일반 1000원. 회원은 **20% 할인**, 그리고 하루 최대 15000원.

## 문제 1: Google 검색 서버의 LRU 캐시

### 조건문 정답
```c
const char *grade(int ms) {
    if (ms == 0)          return "측정 실패";
    else if (ms <= 5)     return "캐시 적중";
    else if (ms <= 100)   return "DB 조회";
    else if (ms <= 200)   return "느림";
    else                  return "타임아웃 위험";
}

// main 안에서
int ms[8] = {2, 61, 0, 140, 2, 260, 100, 5};
for (int i = 0; i < 8; i++)
    printf("%d번 요청: %dms -> %s\n", i + 1, ms[i], grade(ms[i]));
```
출력:
```
1번 요청: 2ms -> 캐시 적중
2번 요청: 61ms -> DB 조회
3번 요청: 0ms -> 측정 실패
4번 요청: 140ms -> 느림
5번 요청: 2ms -> 캐시 적중
6번 요청: 260ms -> 타임아웃 위험
7번 요청: 100ms -> DB 조회
8번 요청: 5ms -> 캐시 적중
```
**왜 이렇게?** `if - else if`는 **위에서부터 차례로 물어보다가 처음 "네!"가 나오면 거기서 멈추는** 줄서기예요.
① 0ms는 "엄청 빠르다"가 아니라 "**재는 기계가 고장 났다**"는 뜻이에요. 0도 5보다 작으니까 `ms <= 5`가 먼저 있으면 "캐시 적중"으로 착각해요. 그래서 **이상한 값부터 먼저** 걸러내요.
② `ms <= 100`이 먼저 있으면 2ms도 "100 이하네!" 하고 "DB 조회"가 돼 버려요. 범위를 검사할 때는 **좁은 것(작은 기준)부터** 써야 해요. 7번(100ms)과 8번(5ms)처럼 **경계에 딱 맞는 값**은 `<=`라서 포함된다는 것도 꼭 확인해요.

### 반복문 정답 (`do-while`)
```c
int up[6] = {0, 0, 0, 1, 1, 1};
int t = 0, wait = 100, total = 0, ok;

do {
    ok = up[t];
    t++;
    if (ok) {
        printf("%d번째 시도: 연결 성공!\n", t);
    } else {
        printf("%d번째 시도 실패 -> %dms 기다림\n", t, wait);
        total += wait;
        wait *= 2;                      // 기다리는 시간 2배
    }
} while (!ok && t < 5);

if (!ok) printf("5번 다 실패: 포기하고 관리자 호출\n");
printf("총 기다린 시간 %dms\n", total);
```
출력:
```
1번째 시도 실패 -> 100ms 기다림
2번째 시도 실패 -> 200ms 기다림
3번째 시도 실패 -> 400ms 기다림
4번째 시도: 연결 성공!
총 기다린 시간 700ms
```
**왜 이렇게?** 친구 집 초인종을 눌렀는데 대답이 없으면, 바로 또 누르지 않고 조금 기다렸다가, 또 없으면 **더 오래** 기다렸다 누르죠? 친구가 화장실에 있을 수도 있으니까요. 서버도 똑같아요. 쓰러진 DB에 1초에 1000번씩 문을 두드리면 일어나지도 못해요. 그래서 100 → 200 → 400ms로 기다림을 늘려요.
`do-while`은 "**일단 한 번 해 보고, 그 다음에 또 할지 물어봐**"예요. 연결은 **최소 한 번은 꼭** 시도해야 하니까 딱 맞아요. 그냥 `while (!ok ...)`로 쓰면 처음에 `ok`에 아무 값도 안 들어 있어서 이상하게 동작할 수 있어요.
`t < 5`는 "**영원히 매달리지 않기**"예요. 이 조건이 없으면 DB가 영영 안 살아날 때 프로그램도 영영 멈춰요.

### 흐름제어 정답 (1, 중첩 반복문)
```c
const char *snap[3] = {"cat", "sun", "dog"};
const char *q[6] = {"sun", "", "art", "dog", "STOP", "cat"};
int hits = 0;

for (int i = 0; i < 6; i++) {
    if (q[i][0] == '\0') {                       // 빈 문자열
        printf("%d: 빈 요청 무시\n", i + 1);
        continue;
    }
    if (strcmp(q[i], "STOP") == 0) {
        printf("%d: STOP 신호! 검사 끝\n", i + 1);
        break;                                   // 바깥 for 끝
    }
    int found = -1;
    for (int j = 0; j < 3; j++) {
        if (strcmp(snap[j], q[i]) == 0) {
            found = j;
            break;                               // 안쪽 for만 끝
        }
    }
    if (found >= 0) { hits++; printf("%d: %s 적중 (%d번 칸)\n", i + 1, q[i], found); }
    else            printf("%d: %s 없음\n", i + 1, q[i]);
}
printf("적중 %d개\n", hits);
```
출력:
```
1: sun 적중 (1번 칸)
2: 빈 요청 무시
3: art 없음
4: dog 적중 (2번 칸)
5: STOP 신호! 검사 끝
적중 2개
```
**왜 이렇게?** 반복문 두 개가 겹쳐 있으면 **양파 껍질**처럼 생각하세요. `break`는 **자기를 감싼 가장 가까운 껍질 하나만** 벗기고 나가요.
- 안쪽 `for`의 `break`는 "칸 찾았다! 남은 칸은 안 봐도 돼"예요. 바깥 `for`는 계속 다음 검색어로 가요.
- `STOP`의 `break`는 바깥 `for` 안에 바로 있으니까 바깥 반복 전체를 끝내요. 그래서 6번째 `"cat"`은 **검사되지 않아요.** 캐시에 있었는데도요!
- 글자를 비교할 때 `q[i] == "STOP"`이라고 쓰면 안 돼요. 그건 "글자가 같니?"가 아니라 "**같은 주소에 있니?**"를 묻는 거예요. 글자 비교는 꼭 `strcmp(...) == 0`이에요.
- 빈 문자열 `""`은 첫 글자가 바로 끝 표시 `'\0'`이라서 `q[i][0] == '\0'`으로 알아내요.

### 배열 정답 (2차원 배열)
```c
int h[3][4] = {{120, 95, 130, 80}, {60, 70, 40, 30}, {150, 160, 90, 200}};
int col[4] = {0};
int bi = 0, bj = 0;                       // 가장 큰 칸의 위치

for (int i = 0; i < 3; i++) {
    int sum = 0;
    for (int j = 0; j < 4; j++) {
        sum += h[i][j];                   // 가로(서버) 합
        col[j] += h[i][j];                // 세로(구간) 합
        if (h[i][j] > h[bi][bj]) { bi = i; bj = j; }
    }
    printf("서버%d 합계 %d\n", i, sum);
}
for (int j = 0; j < 4; j++) printf("구간%d 합계 %d\n", j, col[j]);
printf("가장 큰 칸: h[%d][%d] = %d\n", bi, bj, h[bi][bj]);
```
출력:
```
서버0 합계 425
서버1 합계 200
서버2 합계 600
구간0 합계 330
구간1 합계 325
구간2 합계 260
구간3 합계 310
가장 큰 칸: h[2][3] = 200
```
**왜 이렇게?** 2차원 배열은 **교실 자리표**예요. `h[줄][번호]`처럼 두 숫자로 자리를 찾아요.
- **가로로 더하면** 서버 한 대의 하루 합계 → 가장 바쁜 서버는 **서버2(600)**.
- **세로로 더하면** 같은 시간대 세 서버의 합계 → 가장 바쁜 시간은 **구간0(330)**. `col[j] += ...` 한 줄로 이중 `for` **한 번에** 가로와 세로를 같이 구했어요. 같은 표를 두 번 돌 필요가 없죠.
- 서버1은 다른 서버의 1/3밖에 일을 안 해요. 엔지니어라면 "서버1에 일을 더 나눠 주자!"라고 생각할 수 있어요.

### 포인터 변수 정답 (포인터를 돌려주는 함수)
```c
Entry *pick_victim(Cache *c) {
    Entry *v = &c->slot[0];
    for (int i = 0; i < CAP; i++) {
        if (!c->slot[i].valid) return &c->slot[i];   // 빈 칸이 최고!
        if (c->slot[i].last < v->last) v = &c->slot[i];
    }
    return v;
}

// main 안에서
Cache c = {{{"cat", 5, 1}, {"sun", 2, 1}, {"dog", 7, 1}}, 7, 0, 0};
Entry *v = pick_victim(&c);
printf("쫓아낼 칸: %s (%ld번)\n", v->key, (long)(v - c.slot));
strcpy(v->key, "art");
v->last = ++c.clock;
for (int i = 0; i < CAP; i++) printf("%d: %s last=%d\n", i, c.slot[i].key, c.slot[i].last);
```
출력:
```
쫓아낼 칸: sun (1번)
0: cat last=5
1: art last=8
2: dog last=7
```
**왜 이렇게?** `pick_victim`은 "**이 사물함이야!**" 하고 사물함 **번호표(주소)** 를 건네줘요. 번호표를 받았으니 `v->key`로 **진짜 그 사물함**을 열고 내용물을 바꿀 수 있어요. 복사본을 받았다면 진짜 캐시는 그대로였을 거예요.
- `sun`은 `last = 2`로 가장 오래전에 쓰여서 쫓겨났어요. "오래 안 본 장난감부터 상자에 넣는" 것과 같아요.
- `v - c.slot`은 **포인터끼리 빼기**예요. "배열 시작에서 몇 칸 떨어져 있니?"를 알려줘서 **1**이 나와요.
- `++c.clock`은 시계를 먼저 1 올리고(8) 그 값을 써요.
- 함수 안의 `Entry tmp;`는 함수가 끝나면 **사라지는 임시 사물함**이에요. 그 주소를 돌려주면 "없어진 사물함의 번호표"를 들고 있는 셈이라, 열어 보면 엉뚱한 물건이 들어 있거나 프로그램이 죽어요. 그래서 꼭 **함수가 끝나도 남아 있는 곳**(여기서는 `c` 안의 칸)의 주소만 돌려줘요.

### 구조체 정답 (구조체 복사 vs 포인터)
```c
Cache backup = c;          // 통째로 복사 (복사본)
Cache *alias = &c;         // 주소만 기억 (같은 물건)
strcpy(c.slot[0].key, "owl");
c.hits = 10;

printf("backup: %s, hits=%d\n", backup.slot[0].key, backup.hits);
printf("alias : %s, hits=%d\n", alias->slot[0].key, alias->hits);
printf("sizeof(Cache) = %zu\n", sizeof(Cache));
```
출력:
```
backup: cat, hits=0
alias : owl, hits=10
sizeof(Cache) = 60
```
**왜 이렇게?** `backup = c`는 공책을 **복사기로 통째로 복사**한 거예요. 그 뒤에 원본 공책에 낙서해도 복사본은 깨끗해요. 구조체 안에 있는 배열(`slot[3]`, 그 안의 `key[8]`)까지 **전부** 복사돼요. (배열끼리는 `a = b;`가 안 되는데, 구조체로 감싸면 되는 게 재미있죠!)
`alias = &c`는 공책이 **어디 있는지 메모**만 한 거예요. 그래서 `alias`로 보면 바뀐 내용이 그대로 보여요.
`Entry`는 `key` 8바이트 + `int` 2개(8바이트) = 16바이트, `Cache`는 16×3 + `int` 3개(12바이트) = **60바이트**예요. 함수에 `Cache`를 그냥 넘기면 부를 때마다 60바이트를 복사하고, 함수가 바꾼 것도 원본에 반영이 안 돼요. 주소(`Cache *`)는 8바이트뿐이고 원본을 직접 바꿀 수 있어서, 현업에서는 큰 구조체는 거의 항상 **포인터로** 넘겨요. 바꾸면 안 될 때는 `const Cache *`로 "읽기만 할게요" 약속을 붙여요.

### 함수 정답 (재귀 + 메모이제이션)
```c
long long calls = 0;
long long memo[50];                 // 전역 배열은 처음에 모두 0

long long fib(int n) {
    calls++;
    if (n <= 1) return n;           // 멈추는 조건 (꼭 필요!)
    return fib(n - 1) + fib(n - 2);
}

long long fib_memo(int n) {
    calls++;
    if (n <= 1) return n;
    if (memo[n] != 0) return memo[n];          // 적어 둔 답이 있으면 바로!
    return memo[n] = fib_memo(n - 1) + fib_memo(n - 2);
}

// main 안에서
calls = 0; printf("fib(20) = %lld, 호출 %lld번\n", fib(20), calls);
calls = 0; printf("fib_memo(20) = %lld, 호출 %lld번\n", fib_memo(20), calls);
calls = 0; fib(30); printf("fib(30) 호출 %lld번\n", calls);
```
출력:
```
fib(20) = 6765, 호출 21891번
fib_memo(20) = 6765, 호출 39번
fib(30) 호출 2692537번
```
**왜 이렇게?** **재귀**는 함수가 **자기 자신을 다시 부르는** 거예요. 마트료시카 인형을 열면 더 작은 인형이 나오고, 가장 작은 인형(`n <= 1`)에서 멈추죠. 멈추는 조건이 없으면 인형이 끝없이 나와서 프로그램이 터져요.
그런데 그냥 재귀는 `fib(18)`을 여기서도 구하고 저기서도 구하고… **같은 숙제를 수천 번** 다시 해요. 그래서 2만 번 넘게 불려요. `fib(30)`은 **269만 번**이에요!
`memo`는 "**한 번 푼 답은 공책에 적어 두기**"예요. 두 번째부터는 계산 없이 공책만 보면 되니까 **39번**이면 끝나요. 이게 바로 오늘 문제의 **캐시**와 똑같은 생각이에요. 느린 일(DB, 복잡한 계산)의 결과를 빠른 곳에 적어 두는 거죠.
(`printf` 안에서 `fib(20)`과 `calls`를 같이 쓰면 어느 쪽을 먼저 계산할지 C가 정해 두지 않았어요. 진짜 코드에서는 `long long r = fib(20);`로 먼저 계산한 다음 출력하는 게 안전해요.)

### 흐름제어 정답 (2, 종합)
```c
int find(const Cache *c, const char *key) {
    for (int i = 0; i < CAP; i++)
        if (c->slot[i].valid && strcmp(c->slot[i].key, key) == 0) return i;
    return -1;
}

int main(void) {
    Cache k = {0};
    int total = 0, done = 0;

    for (int i = 0; i < 10; i++) {
        int idx = find(&k, reqs[i]);
        k.clock++;
        done++;
        if (idx >= 0) {                                   // 적중
            k.slot[idx].last = k.clock;                   // "방금 썼어!" 표시
            k.hits++;
            total += HIT_MS;
            printf("%2d) %s: 적중 +%dms (누적 %dms)\n", i + 1, reqs[i], HIT_MS, total);
        } else {                                          // 놓침
            Entry *e = pick_victim(&k);
            char old[8] = "";
            if (e->valid) strcpy(old, e->key);            // 쫓겨날 이름 기억
            strcpy(e->key, reqs[i]);
            e->last = k.clock;
            e->valid = 1;
            k.misses++;
            total += DB_MS;
            printf("%2d) %s: 놓침 +%dms (누적 %dms)", i + 1, reqs[i], DB_MS, total);
            if (old[0]) printf(" / 쫓아냄: %s", old);
            printf("\n");
        }
        if (total > SLA_MS) {
            printf("SLA 경보! %d번째 요청에서 누적 %dms > %dms\n", i + 1, total, SLA_MS);
            break;
        }
    }
    printf("처리 %d건, 적중 %d, 놓침 %d, 적중률 %.1f%%\n",
           done, k.hits, k.misses, 100.0 * k.hits / done);
    return 0;
}
```
출력:
```
 1) cat: 놓침 +60ms (누적 60ms)
 2) dog: 놓침 +60ms (누적 120ms)
 3) cat: 적중 +2ms (누적 122ms)
 4) sun: 놓침 +60ms (누적 182ms)
 5) map: 놓침 +60ms (누적 242ms) / 쫓아냄: dog
 6) dog: 놓침 +60ms (누적 302ms) / 쫓아냄: cat
 7) cat: 놓침 +60ms (누적 362ms) / 쫓아냄: sun
SLA 경보! 7번째 요청에서 누적 362ms > 320ms
처리 7건, 적중 1, 놓침 6, 적중률 14.3%
```
**왜 이렇게?** 오늘 만든 부품이 다 모였어요: `find`(반복문으로 찾기) → `pick_victim`(포인터 돌려받기) → `strcpy`로 진짜 칸 바꾸기 → `break`(경보).
- 6번째에 `dog`가 다시 왔는데, **바로 앞(5번째)에** 쫓겨났어요! 7번째 `cat`도 6번째에 쫓겨난 직후에 왔고요. 사용하는 단어는 cat, dog, sun, map **4개**인데 캐시는 **3칸**이라서, 계속 "방금 지운 걸 다시 찾는" 일이 생겼어요. 이걸 현업에서는 **캐시 스래싱(thrashing)** 이라고 불러요. 신고가 쏟아진 진짜 원인이에요!
- **4칸으로 늘리면** 5번째까지 아무것도 안 쫓겨나서 6·7번째가 적중(+2ms)이 돼요. 8번째 `art`가 올 때 한 번(`sun`) 쫓아내지만, 10개를 다 처리해도 누적 310ms라서 경보가 안 울리고 적중률은 **50%** 가 돼요. 해결책은 "코드를 고친다"가 아니라 "`#define CAP 4` **한 줄**을 바꾼다"예요. 이게 `#define`을 쓰는 이유예요.
- `k.clock++`을 **찾기 전에 하든 후에 하든** 매 요청마다 딱 한 번 해야 해요. 시계가 안 가면 누가 오래됐는지 알 수 없어요.
- 적중률은 `100.0 * k.hits / done`처럼 **`100.0`(소수)를 먼저 곱해야** 해요. `k.hits / done`을 먼저 하면 정수 나눗셈이라 `1 / 7 = 0`이 되어 0%가 나와요.

## 프로그램 1: 스마트 주차장 정산 시스템

### 조건문 정답 (`switch`)
```c
int fee(CarType t, int minutes, int member) {
    if (minutes <= FREE_MIN) return 0;                 // 무료 시간
    int units = (minutes - FREE_MIN + 9) / 10;         // 10분 단위 올림
    int rate;
    switch (t) {
        case SMALL: rate = 500;  break;
        case EV:    rate = 600;  break;
        default:    rate = 1000; break;                // NORMAL
    }
    int f = units * rate;
    if (member) f = f * 8 / 10;                        // 회원 20% 할인
    return f > DAY_MAX ? DAY_MAX : f;                  // 하루 상한
}
```
출력:
```
12가3456 95분 -> 7000원
34나5678 30분 -> 0원
56다7890 200분 -> 8160원
78라1234 600분 -> 15000원
90마5678 31분 -> 500원
```
**왜 이렇게?** `switch`는 **엘리베이터 버튼**이에요. `t`가 몇 층인지 보고 그 층(`case`)에서 문이 열려요. `break`는 "**여기서 내려!**"예요.
① `break`를 빼먹으면 SMALL 층에서 내리지 않고 다음 층(EV)까지 계속 내려가요. 이걸 **fall-through**라고 해요. 그래서 `rate = 500` 다음에 `rate = 600`이 실행돼서 경차가 전기차 요금(31분이면 600원)을 내게 돼요. 컴파일 오류도 안 나서 찾기 정말 어려운 버그예요!
- 95분: 넘은 시간 65분 → 10분 단위로 **올림**하면 7단위 → 7000원. `+ 9`를 하면 1분만 넘어도 1단위가 돼요(31분 경차 → 500원).
- 30분은 `<=`라서 딱 무료예요.
② 78라1234는 57단위 × 1000원 = 57000원 → 할인 45600원 → 상한 **15000원**. 만약 상한을 먼저 하면 15000원 → 할인 **12000원**이 돼요. 규칙에 "하루 **최대** 15000원"이라고 했으니 **할인 먼저, 상한 나중**이 맞아요. 순서 하나에 3000원이 왔다 갔다 해요. 돈 계산 코드는 이런 순서를 꼭 기획자와 확인해요.

### 반복문 정답 (2차원 배열 + 이중 `for`)
```c
int total = 0, broken = 0;
for (int f = 0; f < FLOORS; f++) {
    int empty = 0;
    printf("%s:", fl[f]);
    for (int s = 0; s < SLOTS; s++) {
        if (lot[f][s] == 0)      { printf(" □"); empty++; }
        else if (lot[f][s] == 1) { printf(" ■"); }
        else                     { printf(" X"); broken++; }
    }
    printf("  (빈칸 %d)\n", empty);
    total += empty;
}
printf("빈칸 %d, 고장 %d\n", total, broken);
```
출력:
```
B1: ■ ■ □ ■  (빈칸 1)
B2: ■ X ■ □  (빈칸 1)
B3: □ ■ ■ ■  (빈칸 1)
빈칸 3, 고장 1
```
**왜 이렇게?** 바깥 `for`는 "**층마다 엘리베이터 타기**", 안쪽 `for`는 "**그 층에서 한 칸씩 걸어가기**"예요. 안쪽 반복이 다 끝나야 다음 층으로 가요.
`empty`는 **바깥 `for` 안에서** `0`으로 만들어요. 층이 바뀔 때마다 새로 세야 하니까요. 반대로 `total`은 반복 **밖**에 있어서 모든 층을 계속 더해요. 변수를 **어디에 만드느냐**가 "어디까지 셀 거냐"를 정해요.

### 흐름제어 정답 (1, 중첩 반복문 탈출)
```c
int find_spot(CarType t, int *pf, int *ps) {
    for (int f = 0; f < FLOORS; f++) {
        for (int s = 0; s < SLOTS; s++) {
            if (lot[f][s] != 0)      continue;    // 빈칸 아님
            if (t == EV && s != 3)   continue;    // 전기차는 충전 칸만
            if (t != EV && s == 3)   continue;    // 충전 칸은 전기차만
            *pf = f; *ps = s;
            return 1;                             // 두 반복 모두 한 번에 탈출!
        }
    }
    return 0;                                     // 자리 없음
}
```
결과: 일반차 → **B1-3**, 전기차 → **B2-4**.
친구 코드의 결과: 일반차 → **B3-1** (틀림!)

**왜 이렇게?** 친구 코드의 `break`는 **안쪽 반복(칸 걷기)만** 끝내요. B1에서 3번 칸을 찾았는데, 바깥 반복은 "아직 층이 남았네?" 하고 B2, B3로 계속 내려가요. 그러다 B3-1에서 또 빈칸을 찾아서 **답을 덮어써요.** 손님은 1층 위 빈자리를 두고 지하 3층까지 내려가야 해요!
고치는 방법은 세 가지예요.
1. **함수로 만들고 `return`** (위 정답): `return`은 함수를 통째로 끝내니까 두 반복을 한 번에 빠져나가요. 가장 깔끔해요.
2. **깃발 변수**: `int found = 0;`을 두고 `for (f = 0; f < FLOORS && !found; f++)`처럼 바깥 조건에도 확인해요.
3. `goto done;`: C에는 있지만 코드가 거미줄처럼 꼬이기 쉬워서 회사마다 조심해서 써요.
그리고 `continue` 세 줄은 "**이 칸은 안 돼요**" 하는 문지기 셋이에요. 문지기를 다 통과한 칸만 아래로 내려가요. `if` 안에 `if` 안에 `if`… 처럼 깊게 들어가지 않아서 읽기 쉬워요.

### 배열 정답 (버블 정렬)
```c
int stay[7] = {95, 30, 200, 45, 600, 31, 120};
int swaps = 0, pass = 0;

for (int i = 0; i < 6; i++) {
    int s = 0;
    pass++;
    for (int j = 0; j < 6 - i; j++) {
        if (stay[j] > stay[j + 1]) {              // 앞이 더 크면 자리 바꾸기
            int tmp = stay[j];
            stay[j] = stay[j + 1];
            stay[j + 1] = tmp;
            s++;
        }
    }
    swaps += s;
    printf("%d바퀴 (바꿈 %d):", pass, s);
    for (int k = 0; k < 7; k++) printf(" %d", stay[k]);
    printf("\n");
    if (s == 0) break;                            // 이미 정렬 끝!
}
printf("총 %d번 바꿈, %d바퀴, 중앙값 %d분\n", swaps, pass, stay[3]);
```
출력:
```
1바퀴 (바꿈 4): 30 95 45 200 31 120 600
2바퀴 (바꿈 3): 30 45 95 31 120 200 600
3바퀴 (바꿈 1): 30 45 31 95 120 200 600
4바퀴 (바꿈 1): 30 31 45 95 120 200 600
5바퀴 (바꿈 0): 30 31 45 95 120 200 600
총 9번 바꿈, 5바퀴, 중앙값 95분
```
**왜 이렇게?** 키 순서로 줄 설 때, **옆 친구와 키를 비교해서** 내가 더 크면 자리를 바꾸는 걸 끝까지 반복하는 거예요. 한 바퀴 돌면 **가장 큰 값(600)이 맨 뒤로** 거품(bubble)처럼 올라가요.
- `j < 6 - i`: 한 바퀴마다 맨 뒤에 큰 값이 하나씩 자리를 잡으니까, 거기는 다시 볼 필요가 없어요.
- 자리를 바꿀 때 `tmp`가 꼭 필요해요. 두 컵의 물을 바꾸려면 **빈 컵 하나**가 더 있어야 하잖아요.
- 5바퀴째에 한 번도 안 바꿨다는 건 "**이미 다 줄을 섰어**"라는 뜻이라 6바퀴째는 안 해도 돼요. 이게 `break` 한 줄의 힘이에요.
- 정렬을 하면 **중앙값**(가운데 값, 95분)을 바로 알 수 있어요. 평균은 600분짜리 한 대 때문에 160분 정도로 부풀지만, 중앙값은 "보통 손님"을 더 잘 보여줘요.

### 포인터 변수 정답 (포인터 산술)
```c
int *p = &lot[0][0];
int *end = p + FLOORS * SLOTS;          // 12칸 다음 자리
int empty = 0;

for (; p < end; p++) {
    if (*p == 0) {
        long idx = p - &lot[0][0];
        printf("빈칸: %s-%ld (idx %ld)\n", fl[idx / SLOTS], idx % SLOTS + 1, idx);
        empty++;
    }
}
printf("빈칸 %d개, *(&lot[0][0] + 5) = %d\n", empty, *(&lot[0][0] + 5));
```
출력:
```
빈칸: B1-3 (idx 2)
빈칸: B2-4 (idx 7)
빈칸: B3-1 (idx 8)
빈칸 3개, *(&lot[0][0] + 5) = -1
```
**왜 이렇게?** 주차장은 3층짜리 건물처럼 보이지만, 컴퓨터 메모리 안에서는 **기차 12칸이 한 줄로** 붙어 있어요: B1의 4칸 → B2의 4칸 → B3의 4칸.
- `p++`는 "**다음 칸으로 한 칸 이동**"이에요. `int`가 4바이트라도 `p++`는 알아서 4바이트를 건너뛰어요.
- `p - &lot[0][0]`은 "**맨 앞 칸에서 몇 칸 왔니?**"예요. 7번째 칸이면, 한 층이 4칸이니까 `7 / 4 = 1`층(B2), `7 % 4 = 3`번 칸 → 사람 말로 **B2-4**예요.
- `*(&lot[0][0] + 5)`는 5칸 앞 = `lot[1][1]` = 고장 칸 **-1**이에요.
- `end`는 마지막 칸 **바로 다음** 자리예요. `p < end`일 때까지만 보니까 배열 밖으로 안 나가요. `p <= end`라고 쓰면 주차장 밖 남의 땅을 들여다보게 돼요!

### 구조체 정답 (연결 리스트)
```c
Node *head = NULL, *tail = NULL;
int qn = 0;

void push_back(const char *p, CarType t, int m) {
    Node *n = malloc(sizeof(Node));      // 새 칸 하나 빌리기
    if (n == NULL) return;               // 메모리 부족 대비
    strcpy(n->plate, p);
    n->type = t; n->member = m;
    n->next = NULL;                      // 맨 끝이니까 뒤는 없음
    if (tail) tail->next = n;            // 지금 꼴찌 뒤에 붙이기
    else      head = n;                  // 줄이 비어 있었으면 첫 번째
    tail = n;
    qn++;
}

void pop_front(void) {
    if (head == NULL) return;
    Node *n = head;
    head = head->next;                   // 두 번째 차가 맨 앞으로
    if (head == NULL) tail = NULL;       // 줄이 텅 비면 tail도 비우기!
    free(n);                             // 빌린 칸 돌려주기
    qn--;
}

// main 안에서
push_back("A", NORMAL, 0); push_back("B", SMALL, 0); push_back("C", EV, 1);
pop_front();
push_back("D", NORMAL, 0);
for (Node *n = head; n; n = n->next) printf("%s -> ", n->plate);
printf("끝 (대기 %d대)\n", qn);
while (head) pop_front();                // 다 쓰면 전부 돌려주기
```
출력:
```
B -> C -> D -> 끝 (대기 3대)
```
**왜 이렇게?** 연결 리스트는 **기차놀이**예요. 각 친구가 **앞 친구의 어깨**가 아니라 **뒤 친구의 이름(주소)** 을 알고 있어요. `head`는 맨 앞 친구, `tail`은 맨 뒤 친구예요.
- 배열은 처음에 칸 수를 정해야 하지만, 연결 리스트는 차가 올 때마다 `malloc`으로 칸을 **하나씩 빌려서** 붙여요. 대기 차가 몇 대일지 모를 때 딱이에요.
- A를 빼면 `head`가 B로 바뀌기만 하면 돼요. 배열이었다면 B, C를 한 칸씩 앞으로 **모두 옮겨야** 했어요.
- `tail`이 없으면 끝에 붙일 때마다 `head`부터 `next`를 따라 **맨 뒤까지 걸어가야** 해요. 줄이 1000대면 1000걸음! `tail`을 기억하면 한 걸음이에요.
- 마지막 차를 뺐는데 `tail`을 그대로 두면, `tail`이 이미 `free`된(돌려준) 칸을 가리켜요. 다음에 `tail->next = n`을 하면 **남의 물건에 손대는** 큰 사고가 나요.
- `free`를 안 하면 빌린 메모리를 영영 안 돌려주는 **메모리 누수**예요. 주차장 프로그램은 1년 내내 켜져 있으니까, 조금씩 새던 메모리가 쌓여서 결국 멈춰요.

### 함수 정답 (출력 매개변수로 입력 검사)
```c
int parse_time(const char *s, int *out) {
    if (strlen(s) != 5 || s[2] != ':') return 0;
    for (int i = 0; i < 5; i++) {
        if (i == 2) continue;                         // ':' 자리는 건너뛰기
        if (s[i] < '0' || s[i] > '9') return 0;       // 숫자가 아니면 탈락
    }
    int hh = (s[0] - '0') * 10 + (s[1] - '0');
    int mm = (s[3] - '0') * 10 + (s[4] - '0');
    if (hh > 23 || mm > 59) return 0;
    *out = hh * 60 + mm;                              // 진짜 답은 여기에!
    return 1;
}
```
출력:
```
"09:30" -> OK 570
"23:59" -> OK 1439
"24:00" -> 형식 오류
"9:30" -> 형식 오류
"12:7a" -> 형식 오류
"18:45" -> OK 1125
```
**왜 이렇게?** 이 함수는 **두 가지**를 알려줘야 해요. "제대로 된 시각이야?(예/아니오)"와 "몇 분이야?". 그런데 `return`은 하나만 돌려줄 수 있어요.
그래서 `return`으로는 **성공/실패**만 알려주고, 진짜 답은 **주소를 받아서(`int *out`) 그 자리에 직접 적어 줘요.** 친구가 "답은 내 공책 3쪽에 적어 줘"라고 공책을 건네준 것과 같아요.
만약 실패를 `-1`로 돌려주기로 하면, 나중에 누군가 `-1`을 진짜 시간처럼 계산에 써 버릴 수 있어요. 성공 여부와 답을 **나눠 두면** 그런 실수가 줄어요.
- `s[i] - '0'`은 글자 `'7'`을 숫자 `7`로 바꾸는 마법이에요. 글자 `'0'`~`'9'`는 컴퓨터 안에서 번호가 차례로 붙어 있거든요.
- `"9:30"`은 사람 눈엔 멀쩡하지만 길이가 4라서 탈락이에요. 기계에서 들어오는 값은 **형식을 딱 하나로** 정하고 엄격하게 검사해야, 이상한 값이 요금 계산까지 흘러가지 않아요.

```c

Car *park(const char *p, CarType t, int m, int f, int s, int in) {
    for (int i = 0; i < FLOORS * SLOTS; i++) {
        if (cars[i].used) continue;
        Car *c = &cars[i];
        strcpy(c->plate, p);
        c->type = t; c->member = m; c->floor = f; c->slot = s;
        c->in_min = in; c->used = 1;

        return c;
    }
    return NULL;
}

Car *find_car(const char *p) {
    for (int i = 0; i < FLOORS * SLOTS; i++)
        if (cars[i].used && strcmp(cars[i].plate, p) == 0) return &cars[i];

}

    while (head) pop_front();                                         // 메모리 정리
    return 0;

입차 4대, 출차 2대, 매출 18640원, 대기 1대
```
**왜 이렇게?** 오늘 만든 부품이 모두 모였어요!
`parse_time`(입력 검사) → `find_spot`(2차원 배열 + 중첩 반복 탈출) → `push_back`/`pop_front`(연결 리스트) → `fee`(`switch`) → `Car *`(포인터로 진짜 차 정보 바꾸기) → `break`(고장).
- **검사 순서**가 중요해요. 고장(`'X'`)은 시각과 상관없이 바로 멈춰야 하니까 맨 먼저, 그 다음 시각 검사예요. 시각이 이상한데 계산을 하면 `now`에 아무 값이나 들어 있어서 요금이 엉망이 돼요.
- 33다3333은 `"9:20"`(앞에 0이 없음)이라 무시됐어요. 그래서 B3-1 자리가 44라4444에게 갔어요. 앞 사건이 뒤 사건에 영향을 주는 거예요.
- 11가1111: 125분 → 넘은 95분 → 10단위 → 10000원. 22나2222: 210분, 전기차, 회원 → 18단위 × 600 = 10800 → 20% 할인 **8640원**.
- 66바6666이 못 들어간 이유: 비워진 B2-4는 **전기차 충전 칸**이고 66바6666은 일반차예요. `find_spot`의 문지기가 막았어요. 대기 줄은 "**맨 앞 차부터**" 들어가는 공정한 규칙이라, 맨 앞 차가 못 들어가면 계속 기다려요.
- 각 갈래 끝에 `continue`를 둬서 "입차 처리 끝났으면 출차 코드는 보지 마"를 분명히 했어요. 그래서 아래쪽 출차 코드에는 `else`가 필요 없어요.
- 영업이 끝나면 `while (head) pop_front();`로 빌린 메모리를 **모두 돌려줘요.** `malloc`이 있으면 짝꿍 `free`도 꼭 있어야 해요.

---

💡 **오늘의 핵심 한 줄:** `break`는 **가장 가까운 반복 하나만** 빠져나가요. 두 겹을 한 번에 빠져나가려면 **함수로 만들고 `return`** 하세요. 그리고 느린 일은 **적어 두고(캐시·메모이제이션)**, 큰 구조체는 **주소로** 넘기고, `malloc`에는 꼭 짝꿍 **`free`** 를 붙여요!
