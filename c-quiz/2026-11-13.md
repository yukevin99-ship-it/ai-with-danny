## 엔지니어가 직면한 가상의 문제 1

**[NVIDIA 데이터센터 운영팀]** AI 학습 작업을 GPU(그래픽 카드) 6대에 나눠 줘야 해요. 각 GPU는 번호(`id`), 온도(`temp`, ℃), 남은 메모리(`free_mem`, GB), 살아 있는지(`alive`, 1이면 켜져 있음)를 가져요. 규칙: 꺼져 있으면 무조건 "고장"이에요. 그 밖에는 온도가 90도 **이상**이면 "과열 대기", 남은 메모리가 작업 크기(`need` = 40GB) **이상**이면 "배정 가능", 나머지는 "메모리 부족"이에요.

```c
int temp[6]     = {65, 0, 92, 70, 55, 88};   // 0 = 꺼져서 못 잼
int free_mem[6] = {50, 0, 70, 20, 60, 45};
// GPU 6대: {id, temp, free_mem, alive}
// {1,65,50,1} {2,0,0,0} {3,92,70,1} {4,70,20,1} {5,55,60,1} {6,88,45,1}
```

- **조건문 퀴즈 1:** GPU 하나의 `alive`, `temp`, `free_mem`과 `need`를 보고 "고장", "과열 대기", "배정 가능", "메모리 부족" 중 하나를 출력하세요. (GPU 3은 메모리가 70GB나 남았는데 왜 "배정 가능"이 아닐까요?)
- **반복문 퀴즈 1:** 구조체 배열 `gpus[6]`을 돌면서 `"GPU 1: 65도, 남은 메모리 50GB"` 모양으로 출력하세요.
- **흐름제어 퀴즈 1:** 꺼진 GPU는 건너뛰고(`continue`), 켜진 GPU는 `"GPU N 확인"`을 출력해요. 그런데 90도 이상인 GPU를 처음 만나면 `"긴급: GPU N 과열!"`을 출력하고 멈추세요(`break`). 실제로 몇 줄이 나올까요?
- **배열 퀴즈 1:** `temp` 배열에서 0(꺼짐)은 빼고 **평균 온도**를 구한 뒤, **평균보다 뜨거운 GPU 수**를 세어 `"평균 74도, 평균보다 뜨거운 GPU 2개"`처럼 출력하세요. (왜 반복문이 2번 필요할까요?)
- **포인터 변수 퀴즈 1:** 작업 3개(`40, 30, 25`GB)가 순서대로 들어와요. 작업마다 포인터 `p`를 `free_mem` 맨 앞에 두고, 메모리가 충분한 **첫 번째 칸**을 찾으면 `*p -= 작업크기`를 하고 멈춰요 (이걸 "First-Fit" 배정이라고 해요). 다 끝난 뒤 `free_mem` 배열은 어떻게 될까요?
- **구조체 퀴즈 1:** `struct Gpu`를 정의하고 `g`를 `{7, 85, 64, 1}`로 만드세요. 그다음 `struct Gpu backup = g;`로 백업을 만들고, `g.free_mem`에서 40을 뺀 뒤 `"원본 GPU 7: 24GB / 백업: 64GB"`를 출력하세요. (백업도 같이 줄어들까요?)
- **함수 퀴즈 1:** GPU 배열 `g`, 개수 `n`, 작업 크기 `need`, 그리고 **답을 적어 줄 칸의 주소** `int *best_idx`를 받는 함수 `pick_gpu`를 작성하세요. 배정 가능한 GPU(켜짐, 90도 미만, 메모리 충분)의 **개수**를 `return`하고, 그중 **메모리가 가장 많이 남은 GPU의 칸 번호**는 `*best_idx`에 적어 주세요. 하나도 없으면 `*best_idx`는 `-1`이에요. (함수는 값을 1개만 돌려줄 수 있는데, 답 2개를 어떻게 돌려줄까요?)
- **흐름제어 퀴즈 2 (종합):** `main`에서 작업 `int jobs[4] = {40, 50, 30, 70};`를 차례로 `pick_gpu`에 넣어요. 후보가 0개면 `"작업 N(XGB) 배정 실패: 대기열로"`를 출력하고 멈추고, 아니면 고른 GPU의 메모리를 줄이고 `"작업 N(XGB) -> GPU K (후보 C개)"`를 출력하세요. 마지막에 `"배정 완료: M개"`를 출력해요. 실제 출력은?

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[Tesla 슈퍼차저 운영팀]** 충전소에 온 전기차 5대를 충전해 주는 스케줄러를 만들어요. 각 차는 번호(`id`), 배터리(`battery`, %), 아직 기다리는지(`waiting`, 0이면 **떠난 차**)를 가져요. 목표는 **80%**까지 충전이고, 1분에 **10%**씩 차요. (80%를 넘으면 안 돼요!)

- **배열 퀴즈 1:** 5분마다 기록한 "사용 중인 충전기 수" `int usage[8] = {2, 3, 4, 4, 4, 3, 4, 1};`가 있어요. 충전기는 모두 4대예요. 충전소가 **가장 오래 연속으로 꽉 찼던(4대)** 기록이 몇 번인지 구해 `"최장 만석: 3번 연속 (15분)"`처럼 출력하세요.

# 정답 및 해설 (초등학교 5학년 눈높이)

## 문제 1: NVIDIA GPU 작업 배정

### 조건문 정답
```c
if (alive == 0) {
    printf("고장\n");
} else if (temp >= 90) {
    printf("과열 대기\n");
} else if (free_mem >= need) {
    printf("배정 가능\n");
} else {
    printf("메모리 부족\n");
}
```
**왜 이렇게?** 꺼진 컴퓨터한테 "메모리 얼마 남았어?" 물어봐야 대답을 못 하죠? 그래서 "켜져 있니?"를 **맨 먼저** 물어요. 다음은 "너무 뜨겁니?"예요. 열이 39도인 친구한테 운동을 시키면 안 되는 것처럼, 뜨거운 GPU한테 일을 더 주면 고장 나요. 그래서 GPU 3은 메모리가 70GB나 있어도 "과열 대기"예요. 결과: 1 배정 가능, 2 고장, 3 과열 대기, 4 메모리 부족, 5 배정 가능, 6 배정 가능.

### 반복문 정답
```c
for (int i = 0; i < 6; i++) {
    printf("GPU %d: %d도, 남은 메모리 %dGB\n",
           gpus[i].id, gpus[i].temp, gpus[i].free_mem);
}
```
**왜 이렇게?** GPU가 딱 6대니까 "6번 돌아!"가 정해진 `for`가 딱이에요. `gpus[i]`는 "i번째 GPU 카드", `.temp`는 "그 카드의 온도 칸"이에요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 6; i++) {
    if (gpus[i].alive == 0) {
        continue;                      // 꺼진 GPU는 패스
    }
    if (gpus[i].temp >= 90) {
        printf("긴급: GPU %d 과열!\n", gpus[i].id);
        break;                         // 불났다! 바로 보고하러 가요
    }
    printf("GPU %d 확인\n", gpus[i].id);
}
```
**왜 이렇게?** `continue`는 "이 친구는 결석이니 다음 친구로!", `break`는 "큰일 났다! 점검 멈추고 선생님께 달려가!"예요. 과열 검사를 `printf("확인")`보다 **위에** 둬야 뜨거운 GPU를 "확인"이라고 잘못 말하지 않아요. 출력은 딱 2줄: `GPU 1 확인`, `긴급: GPU 3 과열!`

### 배열 정답
```c
int sum = 0, cnt = 0;
for (int i = 0; i < 6; i++) {          // 1번째 반복: 평균 구하기
    if (temp[i] == 0) continue;
    sum += temp[i];
    cnt++;
}
int avg = sum / cnt;                   // 370 / 5 = 74

int hot = 0;
for (int i = 0; i < 6; i++) {          // 2번째 반복: 평균과 비교하기
    if (temp[i] > avg) hot++;
}
printf("평균 %d도, 평균보다 뜨거운 GPU %d개\n", avg, hot);
```
**왜 이렇게?** 반 평균 점수를 모르면 "평균보다 잘 본 친구"를 셀 수 없죠? 그래서 **먼저 한 바퀴** 돌아서 평균을 알아내고, **한 바퀴 더** 돌면서 비교해요. 0은 "꺼져서 못 잰 값"이라 평균에 넣으면 평균이 엉터리로 낮아지니까 빼요. 92도와 88도가 74도보다 높아서 2개예요. (꺼진 GPU의 0은 어차피 74보다 작아서 두 번째 반복에선 저절로 안 세져요.)

### 포인터 정답
```c
int jobs3[3] = {40, 30, 25};
for (int j = 0; j < 3; j++) {
    int *p = free_mem;                 // 작업마다 손가락을 맨 앞으로!
    while (p < free_mem + 6) {
        if (*p >= jobs3[j]) {
            *p -= jobs3[j];            // 그 칸의 메모리를 진짜로 줄여요
            break;
        }
        p++;
    }
}
// free_mem: {10, 0, 15, 20, 60, 45}
```
**왜 이렇게?** 주차장에서 "입구에서 가장 가까운 빈자리"에 차를 세우는 거랑 같아요. 차(작업)가 올 때마다 **입구부터 다시** 살펴야 하니까 `p = free_mem`을 반복문 **안에서** 해요. 40GB → 1번 칸(50→10). 30GB → 1번 칸은 10이라 부족, 2번은 0, 3번 칸(70→40). 25GB → 3번 칸(40→15). `*p -= ...`는 손가락이 가리키는 **진짜 칸**을 바꾸니까 배열이 실제로 변해요.

### 구조체 정답
```c
struct Gpu {
    int id;
    int temp;
    int free_mem;
    int alive;
};

struct Gpu g = {7, 85, 64, 1};
struct Gpu backup = g;                 // 통째로 복사!
g.free_mem -= 40;
printf("원본 GPU %d: %dGB / 백업: %dGB\n", g.id, g.free_mem, backup.free_mem);
// 원본 GPU 7: 24GB / 백업: 64GB
```
**왜 이렇게?** `backup = g`는 성적표를 **복사기로 한 장 더 뽑는 것**이에요. 원본에 낙서해도 복사본은 그대로죠? 그래서 백업은 64GB 그대로예요. 현업에서도 "바꾸기 전 상태"를 이렇게 저장해 두고, 문제가 생기면 되돌려요. (포인터로 가리키는 것과 다르다는 게 핵심!)

### 함수 정답
```c
int pick_gpu(struct Gpu *g, int n, int need, int *best_idx) {
    int count = 0;
    *best_idx = -1;                    // 아직 못 찾음
    for (int i = 0; i < n; i++) {
        if (g[i].alive == 0) continue;
        if (g[i].temp >= 90) continue;
        if (g[i].free_mem < need) continue;
        count++;
        if (*best_idx == -1 || g[i].free_mem > g[*best_idx].free_mem) {
            *best_idx = i;
        }
    }
    return count;
}
// 사용: int idx; int c = pick_gpu(gpus, 6, 40, &idx);  → c = 3, idx = 4 (GPU 5)
```
**왜 이렇게?** 함수의 `return`은 "대답 한 개"만 할 수 있어요. 그런데 우리는 "몇 개야?"와 "누가 제일 좋아?" 두 개가 궁금해요. 그래서 친구한테 **빈 쪽지 칸의 주소**(`&idx`)를 건네주고 "여기에 적어 줘!"라고 하는 거예요. 함수는 `*best_idx = i`로 그 쪽지에 직접 적어요. `*best_idx == -1`을 먼저 묻는 건 "아직 아무도 안 골랐으면 첫 후보를 일단 골라!"라는 뜻이에요. 이렇게 안 되는 조건을 `continue`로 하나씩 걸러 내는 방식을 현업에선 "가드(guard)"라고 불러요.

### 흐름제어 정답 (2, 종합)
```c
int jobs[4] = {40, 50, 30, 70};
int ok = 0;
for (int j = 0; j < 4; j++) {
    int idx;
    int n = pick_gpu(gpus, 6, jobs[j], &idx);
    if (n == 0) {
        printf("작업 %d(%dGB) 배정 실패: 대기열로\n", j + 1, jobs[j]);
        break;
    }
    gpus[idx].free_mem -= jobs[j];
    ok++;
    printf("작업 %d(%dGB) -> GPU %d (후보 %d개)\n", j + 1, jobs[j], gpus[idx].id, n);
}
printf("배정 완료: %d개\n", ok);
```
실제 출력:
```
작업 1(40GB) -> GPU 5 (후보 3개)
작업 2(50GB) -> GPU 1 (후보 1개)
작업 3(30GB) -> GPU 6 (후보 1개)
작업 4(70GB) 배정 실패: 대기열로
배정 완료: 3개
```
**왜 이렇게?** 작업 1은 후보 GPU 1(50)·5(60)·6(45) 중 제일 넉넉한 5번으로 가요(60→20). 작업 2(50GB)는 이제 50 이상 남은 게 GPU 1뿐이에요(50→0). 작업 3(30GB)은 GPU 6만 45로 충분해요(45→15). 작업 4(70GB)는 GPU 3이 딱 70GB 있지만 **92도라 과열**이라 못 써요 → 실패! 고른 GPU 메모리를 꼭 줄여 줘야(`-=`) 다음 작업이 "이미 찬 GPU"를 또 고르지 않아요.

## 프로그램 1: Tesla 슈퍼차저 충전 스케줄러

### 조건문 정답
```c
if (waiting == 0) {
    printf("떠난 차\n");
} else if (battery >= 80) {
    printf("충전 불필요\n");
} else if (battery < 10) {
    printf("긴급 충전\n");
} else if (battery < 30) {
    printf("우선 충전\n");
} else {
    printf("일반 충전\n");
}
```
**왜 이렇게?** 5%는 30보다도 작아요. 만약 `< 30`을 먼저 물으면 5%짜리 차가 "우선 충전"으로 끝나 버려서 "긴급"을 못 받아요! 그래서 **더 좁은 조건(10 미만)을 먼저** 물어요. 결과: 차1 우선, 차2 긴급, 차3 떠난 차, 차4 충전 불필요, 차5 일반.

### 반복문 정답
```c
int b = 15, m = 0;
while (b < 80) {
    b += 10;
    if (b > 80) b = 80;     // 넘치지 않게 뚜껑 닫기
    m++;
    printf("%d분: %d%%\n", m, b);
}
printf("완료: %d분\n", m);
```
**왜 이렇게?** "몇 분 걸릴지"를 처음엔 모르니까 "80이 될 때까지 계속!"이라는 `while`이 딱 맞아요. 25, 35, 45, 55, 65, 75 다음엔 85가 되는데, 컵에 물을 80까지만 따르듯 80으로 맞춰요. 그래서 `7분: 80%`, `완료: 7분`. (`%%`는 화면에 `%` 글자를 찍는 방법이에요.)

### 흐름제어 정답 (1)
```c
int power = 100;
for (int i = 0; i < 5; i++) {
    if (waiting[i] == 0 || battery[i] >= 80) {
        continue;
    }
    int need = 80 - battery[i];
    if (need > power) {
        printf("전력 부족: 차 %d는 다음 차례\n", i + 1);
        break;
    }
    power -= need;
    printf("차 %d 충전 %d%% (남은 전력 %d)\n", i + 1, need, power);
}
```
**왜 이렇게?** 용돈 100원으로 과자를 순서대로 사는데, 다음 과자가 남은 돈보다 비싸면 "오늘은 여기까지!" 하고 멈추는 거예요. 차1은 65 필요 → 남은 35. 차2는 75가 필요한데 35밖에 없어서 멈춰요. 출력: `차 1 충전 65% (남은 전력 35)`, `전력 부족: 차 2는 다음 차례`. 돈을 쓰기(`power -= need`) **전에** 먼저 확인해야 전력이 마이너스가 안 돼요.

### 배열 정답
```c
int usage[8] = {2, 3, 4, 4, 4, 3, 4, 1};
int run = 0, best = 0;
for (int i = 0; i < 8; i++) {
    if (usage[i] == 4) {
        run++;                       // 연속 기록 +1
        if (run > best) best = run;  // 최고 기록 갱신
    } else {
        run = 0;                     // 끊겼으니 처음부터
    }
}
printf("최장 만석: %d번 연속 (%d분)\n", best, best * 5);
```
**왜 이렇게?** 줄넘기 "연속 몇 번"을 세는 것과 같아요. 성공하면 `run`을 1 올리고, 걸리면 0으로 돌아가요. 그리고 지금까지의 **최고 기록**은 `best`에 따로 적어 둬야 해요. 3·4·5번째 칸이 4,4,4라서 3번 연속 → 3 × 5분 = 15분. 마지막 4(7번째)는 1번뿐이라 최고 기록을 못 넘어요.

### 포인터 정답
```c
int battery[5] = {15, 5, 40, 90, 72};
for (int r = 0; r < 4; r++) {
    for (int *p = battery; p < battery + 4 - r; p++) {
        if (*p > *(p + 1)) {
            int t = *p;
            *p = *(p + 1);
            *(p + 1) = t;
        }
    }
}
// battery: {5, 15, 40, 72, 90}
```
**왜 이렇게?** 키 순서로 줄 설 때, 옆 친구랑 비교해서 내가 더 크면 자리를 바꾸는 거예요. `*(p + 1)`은 "손가락 바로 오른쪽 칸"이에요. 한 바퀴 돌면 제일 큰 90이 거품처럼 맨 뒤로 올라가요(그래서 "버블" 정렬). 이미 맨 뒤로 간 칸은 다시 볼 필요가 없어서 `- r`만큼 덜 돌아요. 또 `p < battery + 4 - r`처럼 **4**까지만 가는 이유: 마지막 칸에서 `p + 1`을 보면 배열 밖으로 나가 버리거든요! 바꿀 땐 컵 두 개의 물을 바꾸듯 빈 컵 `t`가 꼭 필요해요.

### 구조체 정답
```c
struct Car {
    int id;
    int battery;
    int waiting;
};

struct Charger {
    int no;
    struct Car car;          // 충전기 안에 차 카드가 쏙!
    int busy;
};

struct Charger st = {3, {7, 25, 1}, 1};
printf("충전기 %d번: 차 %d (%d%%)\n", st.no, st.car.id, st.car.battery);
st.car.battery += 30;
printf("충전기 %d번: 차 %d (%d%%)\n", st.no, st.car.id, st.car.battery);
// 충전기 3번: 차 7 (25%) → 충전기 3번: 차 7 (55%)
```
**왜 이렇게?** 필통(충전기) 안에 지우개(차)가 들어 있는 모습이에요. 지우개 크기를 알고 싶으면 "필통 **안의** 지우개 **의** 크기" → `st.car.battery`처럼 점을 두 번 찍어요. 초기값도 `{7, 25, 1}`을 중괄호로 한 번 더 감싸서 "이건 안쪽 차 카드야"라고 알려 줘요.

### 함수 정답
```c
int charge(struct Car *c, int minutes) {
    int used = 0;
    while (used < minutes && c->battery < 80) {
        c->battery += 10;
        if (c->battery > 80) c->battery = 80;
        used++;
    }
    return used;
}
// 72%인 차에 5분 → 1분 만에 80%, return 1
// 15%인 차에 3분 → 45%, return 3
```
**왜 이렇게?** `while`에 조건이 **두 개**(`&&`)예요. "시간이 남았고, **그리고** 아직 덜 찼으면" 계속 충전해요. 둘 중 하나라도 아니면 멈춰요. 그래서 72% 차는 1분 만에 80%가 되어 남은 4분을 안 쓰고 돌려줘요 — 그 4분을 다음 차한테 줄 수 있어요! 차를 주소(`*c`)로 받았으니 `c->battery`를 바꾸면 **진짜 차**의 배터리가 바뀌어요.

### 흐름제어 정답 (2, 종합)
```c
struct Car cars[5] = {{1,15,1}, {2,5,1}, {3,40,0}, {4,90,1}, {5,72,1}};
int left = 8;
for (int i = 0; i < 5; i++) {
    if (left == 0) {                                   // ① 문 닫을 시간?
        printf("영업 종료!\n");
        break;
    }
    if (cars[i].waiting == 0 || cars[i].battery >= 80) // ② 충전할 필요 없는 차?
        continue;
    int give = 4;
    if (give > left) give = left;                      // ③ 남은 시간보다 많이 못 줘요
    int used = charge(&cars[i], give);
    left -= used;
    printf("차 %d: %d분 충전 -> %d%% (남은 시간 %d분)\n",
           cars[i].id, used, cars[i].battery, left);
}
int un = 0;
for (int i = 0; i < 5; i++) {
    if (cars[i].waiting == 1 && cars[i].battery < 80) un++;
}
printf("80%% 못 채운 차: %d대\n", un);
```
실제 출력:
```
차 1: 4분 충전 -> 55% (남은 시간 4분)
차 2: 4분 충전 -> 45% (남은 시간 0분)
영업 종료!
80% 못 채운 차: 3대
```
**왜 이렇게?** 차 1은 15→55%(4분), 차 2는 5→45%(4분)를 쓰고 나니 남은 시간이 0이에요. 다음 차례(차 3)에서 **맨 먼저** "문 닫을 시간이야?"를 물으니 바로 `영업 종료!`. 차 5(72%)는 1분이면 끝났을 텐데 아쉽게 못 받았어요. 마지막에 다시 한 바퀴 돌면서 "기다리는데 80% 못 채운 차"를 세면 차 1(55), 차 2(45), 차 5(72) → 3대예요. 떠난 차 3과 이미 90%인 차 4는 안 세요. `charge(&cars[i], ...)`에서 `&`로 **주소**를 넘겨야 함수가 진짜 차의 배터리를 바꿀 수 있어요!
