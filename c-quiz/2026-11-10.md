## 엔지니어가 직면한 가상의 문제 1

**[GitHub Actions CI 팀]** 개발자가 코드를 올리면 테스트 6개가 자동으로 돌아요. 각 테스트는 번호(`id`), 걸린 시간(`ms`, 밀리초), 통과 여부(`passed`, 1이면 통과), 가끔 제멋대로 실패하는 불안정 테스트 여부(`flaky`, 1이면 불안정)를 가져요. 규칙: 불안정한 테스트는 결과와 상관없이 "재시도"예요. 그 밖에는 통과하지 못했으면 "실패", 통과했어도 5000 **이상** 걸렸으면 "느림", 나머지는 "통과"예요.

```c
int ms[6] = {1200, 300, 6000, 800, 5000, 90};
// 테스트 6개: {id, ms, passed, flaky}
// {1,1200,1,0} {2,300,0,1} {3,6000,1,0} {4,800,0,0} {5,5000,1,0} {6,90,1,0}
```

- **조건문 퀴즈 1:** 테스트 하나의 `flaky`, `passed`, `ms`를 보고 "재시도", "실패", "느림", "통과" 중 하나를 출력하는 코드를 작성하세요. (불안정 검사를 먼저!)
- **반복문 퀴즈 1:** 구조체 배열 `tests[6]`을 처음부터 끝까지 돌면서 `"1번 테스트: 1200ms"` 모양으로 출력하는 코드를 작성하세요. (번호는 1부터)
- **흐름제어 퀴즈 1:** 위 반복문에서 불안정한 테스트(`flaky == 1`)는 건너뛰고, 통과하지 못한 테스트를 처음 발견하면 "실패 발견: (id)"를 출력하고 반복을 멈추는 코드를 작성하세요.
- **배열 퀴즈 1:** `ms` 배열에서 5000 **이상**인 값이 몇 개인지 세어 `cnt`에 저장하고 출력하세요.
- **포인터 변수 퀴즈 1:** 포인터 `p`가 `ms` 배열의 처음부터 끝까지 한 칸씩 이동하며(`p++`), 가리키는 값이 5000보다 **큰 칸만** 5000으로 줄이는(시간 제한 보정) 코드를 작성하세요. (`ms[i]`가 아니라 `*p`를 사용)
- **구조체 퀴즈 1:** 번호(`id`), 걸린 시간(`ms`), 통과 여부(`passed`), 불안정 여부(`flaky`)를 가진 구조체 `struct Test`를 정의하세요.
- **함수 퀴즈 1:** 테스트 배열의 시작 주소 `t`와 개수 `n`을 받아서, 불안정하지 않으면서 통과하지 못한 테스트의 수를 반환하는 함수 `count_fail`을 작성하세요.
- **흐름제어 퀴즈 2 (종합):** `main`에서 테스트 6개짜리 구조체 배열과 `count_fail`을 사용해, 개수가 0이면 "모든 테스트 통과", 아니면 "실패 테스트: N개"를 출력하는 코드를 작성하세요.

# 정답 및 해설 (초등학교 5학년 눈높이)

## 문제 1: GitHub Actions 테스트 결과 판정

### 조건문 정답
```c
if (flaky == 1) {
    printf("재시도\n");
} else if (passed == 0) {
    printf("실패\n");
} else if (ms >= 5000) {
    printf("느림\n");
} else {
    printf("통과\n");
}
```
**왜 이렇게?** 장난꾸러기 친구가 "나 오늘 시험 망쳤어~" 해도 그 친구는 원래 자주 장난치니까 한 번 더 시켜 보죠? 불안정 테스트가 바로 그런 친구라서 **맨 먼저** 물어봐요. 그다음엔 "통과 못 했나?"를 물어보고, 통과했을 때만 "너무 오래 걸렸나?"를 물어봐요. 딱 5000도 느린 거라서 `>=`예요.

### 반복문 정답
```c
for (int i = 0; i < 6; i++) {
    printf("%d번 테스트: %dms\n", i + 1, tests[i].ms);
}
```
**왜 이렇게?** 테스트가 6개로 정해져 있으니 `for`가 딱이에요. 컴퓨터는 0부터 세지만 사람은 1번부터 부르니까 보여줄 때만 `i + 1`을 써요. `i < 6`이라야 0~5, 딱 6칸만 열어요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 6; i++) {
    if (tests[i].flaky == 1) {
        continue;
    }
    if (tests[i].passed == 0) {
        printf("실패 발견: %d\n", tests[i].id);
        break;
    }
}
```
**왜 이렇게?** `continue`는 "이 친구는 원래 불안정하니 패스, 다음!", `break`는 "찾았다! 이제 그만 찾아도 돼!"예요. 2번은 실패했지만 불안정해서 건너뛰고, 4번이 처음으로 진짜 실패예요. 출력은 `실패 발견: 4`예요.

### 배열 정답
```c
int cnt = 0;
for (int i = 0; i < 6; i++) {
    if (ms[i] >= 5000) {
        cnt++;
    }
}
printf("%d\n", cnt);   // 2
```
**왜 이렇게?** 조건에 맞는 칸을 만날 때마다 막대기를 하나씩 긋는(`cnt++`) 거예요. 6000과 5000 두 칸이 5000 이상이라 답은 2예요. 딱 5000도 세는 게 포인트예요!

### 포인터 정답
```c
int *p = ms;
for (int i = 0; i < 6; i++) {
    if (*p > 5000) {
        *p = 5000;
    }
    p++;
}
// ms는 {1200, 300, 5000, 800, 5000, 90}이 돼요
```
**왜 이렇게?** 배열 이름 `ms`는 "첫 칸의 주소"예요. `p`는 손가락, `*p`는 손가락이 가리키는 칸 안의 값이에요. 5000보다 큰 칸(6000)만 5000으로 줄이고, 손가락은 `p++`로 한 칸씩 옮겨요. `p++`는 `if` 바깥에 둬야 해요. 안에 두면 작은 값 칸에서 손가락이 못 움직여서 같은 칸만 계속 보게 돼요. 그리고 딱 5000인 칸은 "큰" 게 아니니 그대로예요.

### 구조체 정답
```c
struct Test {
    int id;
    int ms;
    int passed;
    int flaky;
};
```
**왜 이렇게?** 테스트 하나에는 번호, 시간, 통과 여부, 불안정 여부가 항상 같이 다녀요. 배열 4개로 따로 두면 짝이 어긋나기 쉬우니 하나의 "테스트 카드"로 묶어요.

### 함수 정답
```c
int count_fail(struct Test *t, int n) {
    int cnt = 0;
    for (int i = 0; i < n; i++) {
        if (t[i].flaky == 1) {
            continue;
        }
        if (t[i].passed == 0) {
            cnt++;
        }
    }
    return cnt;
}
```
**왜 이렇게?** 함수는 "일을 대신해 주는 심부름꾼"이에요. 카드 묶음의 시작 주소 `t`와 몇 장인지 `n`을 받아서 세어 온 숫자를 `return`으로 돌려줘요. 2번은 불안정해서 빠지고 4번만 해당되므로 반환값은 1이에요. `n`을 받는 이유는 함수가 배열이 몇 칸인지 스스로 알 수 없기 때문이에요.

### 흐름제어 정답 (2, 종합)
```c
int main(void) {
    struct Test tests[6] = {
        {1, 1200, 1, 0}, {2, 300, 0, 1}, {3, 6000, 1, 0},
        {4, 800, 0, 0}, {5, 5000, 1, 0}, {6, 90, 1, 0}
    };
    int failed = count_fail(tests, 6);
    if (failed == 0) {
        printf("모든 테스트 통과\n");
    } else {
        printf("실패 테스트: %d개\n", failed);
    }
    return 0;
}
```
**왜 이렇게?** 심부름꾼이 가져온 숫자를 변수에 담아 두고 `if`로 갈림길을 만들어요. 결과는 `실패 테스트: 1개`예요.

## 문제 2: 당근마켓 이웃 추천 도우미

### 조건문 정답
```c
if (temp >= 40 && deals >= 10) {
    printf("우수 이웃\n");
} else {
    printf("일반 이웃\n");
}
```
**왜 이렇게?** "따뜻하기도 **하고**(and) 거래 경험도 많아야" 우수 이웃이에요. 둘 다 맞아야 하니 `&&`를 써요. 하나라도 틀리면 `else`로 가요. "이상"은 같은 값도 포함이라 `>=`예요.

### 반복문 정답
```c
for (int i = 0; i < 5; i++) {
    printf("%d번 이웃: %s (%d도)\n", i + 1, ppl[i].name, ppl[i].temp);
}
```
**왜 이렇게?** 5명을 차례로 보는 일이라 `for`예요. 이름은 글자 묶음이라 `%s`, 숫자는 `%d`를 써요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 5; i++) {
    if (ppl[i].reported == 1) {
        continue;
    }
    if (ppl[i].temp >= 40 && ppl[i].deals >= 10) {
        printf("첫 우수 이웃: %s\n", ppl[i].name);
        break;
    }
}
```
**왜 이렇게?** 신고당한 이웃은 `continue`로 패스해요. Joon은 온도가 38이라 탈락, Mina(45도, 20번)가 처음 통과해서 `첫 우수 이웃: Mina`를 출력하고 `break`로 끝내요.

### 배열 정답
```c
int good = 0;
for (int i = 0; i < 5; i++) {
    if (reported[i] == 0 && temps[i] >= 40 && deals[i] >= 10) {
        good++;
    }
}
printf("%d\n", good);   // 2
```
**왜 이렇게?** 세 배열의 같은 번호 칸은 같은 이웃 이야기예요. Mina(1번 인덱스)와 Dong(4번 인덱스)이 통과해서 2예요. Sora는 온도 52로 조건은 맞지만 신고당했기 때문에 빠지고, Hana는 거래가 5번뿐이라 빠져요.

### 포인터 정답
```c
int *p = temps;
for (int i = 0; i < 5; i++) {
    if (*p > 50) {
        *p = 50;
    }
    p++;
}
// temps는 {38, 45, 50, 41, 42}가 돼요
```
**왜 이렇게?** 손가락 `p`가 가리키는 값이 50보다 클 때만 50으로 바꿔요. 52였던 Sora의 온도만 50이 돼요. 손가락 이동 `p++`는 매번 해야 하니 `if` 밖에 둬요.

### 구조체 정답
```c
struct Neighbor {
    char name[20];
    int temp;
    int deals;
    int reported;
};

struct Neighbor one = {"Tae", 40, 10, 0};
if (one.temp >= 40 && one.deals >= 10) {
    printf("%s: 우수 이웃\n", one.name);
} else {
    printf("%s: 일반 이웃\n", one.name);
}
```
**왜 이렇게?** 이웃 한 명의 정보를 한 카드로 묶었어요. 카드 안의 칸은 `.`(점)으로 꺼내요. `one.temp`는 "one 카드의 temp 칸"이에요. Tae는 딱 40도, 딱 10번이라 `>=` 덕분에 간신히 통과해서 `Tae: 우수 이웃`이에요. `>`를 썼다면 억울하게 탈락했을 거예요!

### 함수 정답
```c
int find_best(struct Neighbor *s, int n) {
    int best = -1;
    for (int i = 0; i < n; i++) {
        if (s[i].reported == 1) {
            continue;
        }
        if (s[i].temp >= 40 && s[i].deals >= 10) {
            if (best == -1 || s[i].temp > s[best].temp) {
                best = i;
            }
        }
    }
    return best;
}
```
**왜 이렇게?** `best`는 "지금까지 1등 후보의 번호표"예요. 처음엔 후보가 없어서 `-1`이에요. 후보가 처음 나타나면 무조건 1등이 되고(`best == -1`), 그다음부터는 온도가 더 높을 때만 자리를 바꿔요. `best == -1`을 **먼저** 검사해야 `s[-1]`이라는 없는 칸을 읽는 사고를 막아요(`||`는 앞이 참이면 뒤를 보지 않아요). Mina(45)와 Dong(42) 중 Mina가 더 따뜻해서 반환값은 `1`이에요.

### 흐름제어 정답 (2, 종합)
```c
int idx = find_best(ppl, 5);
if (idx == -1) {
    printf("추천할 이웃 없음\n");
} else {
    printf("추천 이웃: %s (%d도)\n", ppl[idx].name, ppl[idx].temp);
}
```
**왜 이렇게?** 출력은 `추천 이웃: Mina (45도)`예요. 반환값이 `-1`이면 아무도 없다는 신호라서 `ppl[idx]`를 쓰기 **전에** 꼭 먼저 확인해야 해요.
