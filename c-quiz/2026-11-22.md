## 엔지니어가 직면한 가상의 문제 1

**[삼성 SmartThings 펌웨어 OTA 배포팀]** 지난달 새 펌웨어를 집집마다 있는 TV·냉장고·에어컨·세탁기에 **한꺼번에** 보냈다가, 일부 세탁기가 업데이트 중에 멈춰 버렸어요! 그래서 이번 `2.10.1` 펌웨어는 **1차 → 2차 → 3차**로 나눠서 조금씩 보내기로 했어요(이걸 **단계적 배포, 카나리 배포**라고 해요). 그리고 어떤 차수에서 **실패율이 30%를 넘으면**, 이번에 업데이트한 기기들을 **모두 원래 버전으로 되돌려야(롤백)** 해요.

```c

#include <stdlib.h>      // qsort

#define MAX_TRY 3        // 설치는 최대 3번까지 시도
#define MIN_BAT 20       // 배터리 20% 미만이면 업데이트 금지 (중간에 꺼지면 고장!)

typedef struct { int major, minor, patch; } Ver;      // 2.10.1 → {2, 10, 1}

typedef struct {
    char id[8];
    Ver  cur;            // 지금 버전
    int  battery;        // %
    int  online;         // 1 = 인터넷 연결됨
    int  wave;           // 몇 차 배포 대상인지 (1, 2, 3)
    int  sim_fail;       // (테스트용) 설치가 몇 번 연속 실패하는 기기인지
} Device;

Device devs[] = {
    {"TV-01", {2, 9,14}, 80, 1, 1, 0},
    {"TV-02", {2,10, 0}, 95, 1, 1, 1},
    {"FR-03", {2, 9, 3}, 15, 1, 1, 0},
    {"AC-04", {1,12, 7}, 60, 0, 2, 0},
    {"WM-05", {2, 9,14}, 70, 1, 2, 3},
    {"TV-06", {2,10, 1}, 88, 1, 2, 0},
    {"WM-07", {2, 8,30}, 50, 1, 2, 2},
    {"FR-08", {1, 9, 0}, 55, 1, 3, 0},
    {"AC-09", {2, 9, 9}, 40, 1, 3, 5},
};
#define ND (int)(sizeof devs / sizeof devs[0])
const Ver TARGET = {2, 10, 1};

void pv(Ver v) { printf("%d.%d.%d", v.major, v.minor, v.patch); }   // 버전 출력 도우미
```

  ② `const char *eligible(const Device *d)`를 만드세요. 순서대로: 오프라인이면 `"오프라인"`, 배터리 < 20이면 `"배터리 부족"`, 이미 `TARGET` 이상이면 `"이미 최신"`, major가 `TARGET`보다 낮으면 `"메이저 차이: 수동"`, 나머지는 `"대상"`.
  9대의 결과는? (함정: 버전을 `double`로 바꿔 `2.9 < 2.10`처럼 비교하면 결과가 어떻게 나올까요?)
- **반복문 퀴즈 1 (`do-while` 재시도):** `int install(Device *d)`를 만드세요. 시도 번호 `t`를 1씩 늘리며, `t > d->sim_fail`이면 `"  시도t 성공"`을 찍고 `t`를 돌려줘요. 아니면 `"  시도t 실패"`. **최대 3번**까지 해 보고 다 실패하면 `0`을 돌려줘요. `"대상"`인 기기 5대에 대해 출력은? 왜 `while`보다 `do-while`이 어울릴까요?
- **흐름제어 퀴즈 1 (안전 모드):** 차수 상관없이 기기를 순서대로 보며 `"대상"`이 아니면 `"FR-03: 배터리 부족, 건너뜀"` 후 `continue`. 대상이면 설치하고, 시도 1번에 **7분**이 걸려요(실패해서 포기한 기기는 3번 시도한 셈). 성공하면 `"TV-01: 완료 (누적 1대, 7분)"`. **한 대라도 설치에 실패하면** `"WM-05 실패! 안전 모드로 배포 중단 (본 기기 K/9, 걸린 시간 M분)"` 후 `break`. 출력은?

## 엔지니어가 창작해야 하는 가상의 프로그램 1

**[한글과컴퓨터 워드프로세서팀]** 글을 쓰다가 실수하면 누구나 **Ctrl+Z(실행 취소)**를 누르고, 너무 많이 취소했으면 **Ctrl+Y(다시 실행)**를 눌러요. 이번에 **가벼운 모바일 메모 앱**에 이 기능을 처음부터 만들어요. 휴대폰 메모리가 작아서 문서는 **23글자**까지, 되돌리기 기록은 **최근 4개**까지만 기억해요.

```c
#include <stdio.h>
#include <string.h>

#define MAXT 24          // 문서 최대 글자 수 23 + '\0'
#define MAXH 4           // 되돌리기 기록 최대 개수

typedef enum { INS, DEL } Kind;                                // 0 = 넣기, 1 = 지우기
typedef struct { Kind kind; int pos; char text[12]; } Action;  // 실제로 일어난 일 기록
typedef struct { char op; int pos; char arg[12]; } Cmd;        // 사용자가 누른 명령
// op: 'i' 넣기(arg = 넣을 글자), 'd' 지우기(arg = 지울 개수 "2"), 'u' 실행 취소, 'r' 다시 실행, 'q' 끝내기

char doc[MAXT] = "";
Action undo_st[MAXH]; int undo_top = 0;    // 되돌리기 스택
Action redo_st[MAXH]; int redo_top = 0;    // 다시 실행 스택

int to_int(const char *s) { int n = 0; while (*s >= '0' && *s <= '9') n = n*10 + (*s++ - '0'); return n; }
```

- **조건문 퀴즈 1:** `const char *check(const Cmd *c)`를 만드세요(`len = strlen(doc)`).
  - `'i'`: 위치가 0보다 작거나 `len`보다 크면 `"위치 오류"`, `len + 넣을 글자 수 > 23`이면 `"용량 초과"`, 아니면 `"OK"`
  - `'d'`: 지울 개수 ≤ 0이면 `"지울 게 없음"`, 위치 < 0 이거나 `pos + 개수 > len`이면 `"범위 오류"`, 아니면 `"OK"`
  - `'u'`: 되돌리기 스택이 비었으면 `"되돌릴 것 없음"`, `'r'`: 다시 실행 스택이 비었으면 `"다시 할 것 없음"`, `'q'`: `"OK"`, 그 밖: `"모르는 명령"`

  `doc = "Hello C World!"`(14글자, 스택은 비어 있음)일 때 다음 10개의 결과는?
  `{'i',14,"!"} {'i',15,"x"} {'i',0,"ABCDEFGHI"} {'i',0,"ABCDEFGHIJ"} {'i',-1,"a"} {'d',12,"2"} {'d',13,"2"} {'d',2,"0"} {'u'} {'z'}`
  (왜 넣기는 `pos == len`이 괜찮은데 지우기는 `pos + n == len`까지만 괜찮을까요?)
- **반복문 퀴즈 1 (끼워넣기):** `void ins_text(char *s, int pos, const char *t)`를 만드세요. 글자들을 `strlen(t)`칸만큼 **오른쪽으로 민 다음** 빈자리에 `t`를 복사해요. `"Hlo"`의 1번 자리에 `"el"`, `"C"`의 0번 자리에 `"I love "`, `"abc"`의 3번 자리에 `"de"`를 넣은 결과는? (함정: 미는 반복문을 **앞에서부터**(`for (i = pos; i <= len; i++)`) 돌리면 `"Hlo"` + `"el"`은 무엇이 될까요?)
- **흐름제어 퀴즈 1:** 빈 문서에서 다음 명령을 차례로 처리하세요.
  `{'i',0,"Hi"} {'i',9,"!"} {'i',2," Kim"} {'x'} {'d',2,"9"} {'i',6,"!"} {'q'} {'i',0,"never"}`
  `check`가 `"OK"`가 아니면 `"2번 i: 위치 오류, 건너뜀"` 후 `continue`, `'q'`면 `"7번 q: 저장 후 종료 (남은 명령 1개 무시)"` 후 `break`, 나머지는 실행하고 `"1번 i: \"Hi\""`. 마지막에 `"성공 A, 건너뜀 B, 최종 \"...\""`. 출력은?

(`"I really love C"`에서 `"really "`를 지운 뒤 그 포인터로 7글자를 읽어 보세요)
- **함수 퀴즈 1 (Undo/Redo 엔진):** 함수 4개를 만드세요.
  - `apply(const Action *a)`: `INS`면 `ins_text`, `DEL`이면 `del_text`
  - `do_action(Action a)`: 실행 → 되돌리기 스택에 `push` → **다시 실행 스택 비우기(`redo_top = 0`)**
  - `undo()`: 되돌리기 스택에서 꺼내 `inverse`를 실행 → 원래 기록을 다시 실행 스택에 `push`
  - `redo()`: 다시 실행 스택에서 꺼내 그대로 실행 → 되돌리기 스택에 `push`

  빈 문서에서 `{'i',0,"cat"} {'i',3,"s"} {'i',0,"my "} {'u'} {'u'} {'r'} {'i',0,"a "} {'r'}`을 하면 단계마다 문서와 두 스택은? 마지막 `'r'`은 왜 안 될까요?
- **흐름제어 퀴즈 2 (종합: 메모 앱 하루):** 빈 문서에서 아래 18개 명령을 처리하세요.
  ```c
  {'i',0,"Hello"}, {'i',5," World"}, {'d',0,"6"}, {'u'}, {'i',5,","},
  {'r'}, {'d',6,"1"}, {'i',11,"!!"}, {'u'}, {'u'}, {'u'}, {'u'}, {'u'},
  {'r'}, {'p'}, {'i',0,">> "}, {'q'}, {'i',0,"X"}
  ```
  1. `check`가 `"OK"`가 아니면 `"13 u: 되돌릴 것 없음, 건너뜀"` 후 `continue`
  2. `switch (op)`: `'i'`/`'d'` → `do_action(make(c))`, 편집 횟수 +1 / `'u'` → `undo()` / `'r'` → `redo()` / `'q'` → `" 17 q: 종료"` 후 `goto end;`
  3. `" 1 i: \"Hello\"  (undo 1, redo 0)"` 출력
  4. 편집(`i`/`d`)이 **3번째, 6번째…**가 될 때마다 `"   [자동저장 #1] \"...\""`

# 정답 및 해설 (초등학교 5학년 눈높이)

> 모든 정답 출력은 실제로 `gcc -Wall -Wextra -fsanitize=address,undefined`로 컴파일해서 돌려 본 결과예요.

## 문제 1: 삼성 SmartThings 펌웨어 단계적 배포

### 조건문 정답
```c
int ver_cmp(Ver a, Ver b) {
    if (a.major != b.major)      return a.major < b.major ? -1 : 1;
    else if (a.minor != b.minor) return a.minor < b.minor ? -1 : 1;
    else if (a.patch != b.patch) return a.patch < b.patch ? -1 : 1;
    else                         return 0;
}

const char *eligible(const Device *d) {
    if (!d->online)                         return "오프라인";
    else if (d->battery < MIN_BAT)          return "배터리 부족";
    else if (ver_cmp(d->cur, TARGET) >= 0)  return "이미 최신";
    else if (d->cur.major < TARGET.major)   return "메이저 차이: 수동";
    else                                    return "대상";
}
```
```
TV-01 2.9.14 -> 대상
TV-02 2.10.0 -> 대상
FR-03 2.9.3 -> 배터리 부족
AC-04 1.12.7 -> 오프라인
WM-05 2.9.14 -> 대상
TV-06 2.10.1 -> 이미 최신
WM-07 2.8.30 -> 대상
FR-08 1.9.0 -> 메이저 차이: 수동
AC-09 2.9.9 -> 대상
```
**해설:**
- 버전 비교는 **사전에서 단어 찾기**랑 같아요. 첫 글자(major)가 다르면 거기서 끝! 같을 때만 둘째 글자(minor)를 보고, 그것도 같을 때만 셋째(patch)를 봐요. 그래서 `else if`로 차례차례 내려가요.
- **함정:** `2.9`와 `2.10`을 **소수**로 보면 `2.9 > 2.1`이라서 `2.9 < 2.10`은 **거짓(0)**이 나와요. 하지만 버전에서 `.`은 소수점이 아니라 **칸막이**예요. 9번째 판보다 10번째 판이 더 새것이죠! 실제로 소수/문자열로 비교하다가 "새 버전을 옛날 버전이라고 착각"하는 사고가 자주 나요. 그래서 숫자 3개를 **따로따로** 비교해요.
- 순서도 중요해요. 오프라인(AC-04)은 연락이 안 되니 다른 걸 물어볼 수도 없어요. 그래서 맨 먼저 물어요. AC-04는 버전도 낮지만(1.x) "오프라인"이 먼저 걸려요.

### 반복문 정답
```c

        t++;

        printf("  시도%d 실패\n", t);

    return 0;                      // 3번 다 실패
}
```

```
TV-02:
  시도1 실패
  시도2 성공
WM-05:

  시도2 실패
```

**해설:**
- `do-while`은 "**일단 한 번 해 보고**, 그다음에 또 할지 물어보기"예요. 설치는 **적어도 한 번은 꼭** 해 봐야 하니까 딱 맞아요. `while`은 "먼저 물어보고 하기"라서 한 번도 안 할 수도 있어요.
- `return t;`는 성공하자마자 함수를 **바로 빠져나가요**. 반복문을 끝낼 때 `break`만 있는 게 아니에요.
- AC-09는 5번이나 실패하는 기기지만, 우리는 3번까지만 해 봐요. 끝없이 다시 시도하면 기기도 서버도 지쳐요. 그래서 **횟수 상한**이 꼭 있어야 해요.

### 배열 정답
```c
int st[4][3] = {{0}};                    // [차수][0=대상, 1=성공, 2=실패]
for (int i = 0; i < ND; i++) {

```
```
1차 | 대상 2 성공 2 실패 0 | 실패율   0%
2차 | 대상 2 성공 1 실패 1 | 실패율  50% #####
3차 | 대상 1 성공 0 실패 1 | 실패율 100% ##########
```

가장 위험한 차수: **3차 (100%)**

**해설:**
- 2차원 배열은 **표(엑셀)**예요. 줄 번호 = 차수, 칸 번호 = 대상/성공/실패.
- 차수가 1, 2, 3이라서 **줄 번호를 그대로 쓰려고** 0번 줄은 비워 두고 4줄을 만들었어요. `st[3][3]`이면 줄 번호가 0~2뿐이라 `st[3]`은 **없는 줄**이에요. 배열 밖을 쓰면 다른 변수가 망가져요!
- `st[w][0] ? ... : 0`은 "대상이 0대면 나누지 마"예요. 0으로 나누면 프로그램이 죽어요.
- 3차는 대상이 1대뿐이라 한 대만 실패해도 100%예요. 숫자가 작을 땐 비율이 크게 흔들린다는 것도 현업에서 꼭 생각해야 해요.

### 포인터 변수 정답
```c
const char *find_key(const char *s, const char *key) {
    size_t k = strlen(key);
    const char *p = s;
    while (*p) {
        if (strncmp(p, key, k) == 0 && p[k] == '=') return p + k + 1;  // 칸 맨 앞에서만 비교
        while (*p && *p != ';') p++;      // 이 칸 끝까지 걷기
        if (*p == ';') p++;               // 다음 칸 첫 글자로
    }
    return NULL;
}

int read_num(const char **pp) {
    int n = 0;
    while (**pp >= '0' && **pp <= '9') {
        n = n * 10 + (**pp - '0');
        (*pp)++;                          // 커서를 한 글자 앞으로
    }
    return n;
}

const char *p = find_key(m, "fw");
Ver v;
v.major = read_num(&p); if (*p == '.') p++;
v.minor = read_num(&p); if (*p == '.') p++;
v.patch = read_num(&p);
```
```
fw    -> 2.10.1,  읽은 뒤 p = ";minsize=512;size=4096;crc=77"
size  -> 4096
crc   -> "77"
hash  -> NULL (못 찾음)
strstr(m, "size=") -> 512   ← 틀린 값!
```
**해설:**
- `read_num`은 **책갈피(커서)를 옮기는** 함수예요. 친구한테 책을 주면서 "읽은 데까지 책갈피 옮겨 줘"라고 하려면, 책갈피가 **어디 꽂혀 있는지(주소)**를 알려 줘야 해요. 그래서 "포인터의 주소" = `const char **`를 받아요. `const char *`만 받으면 함수 안에서 옮긴 책갈피가 밖으로 안 나와서, `2`를 읽고 또 `2`를 읽고 또 `2`를 읽게 돼요.
- `'7' - '0'`은 글자 '7'을 숫자 7로 바꾸는 마법이에요. 글자도 컴퓨터 안에서는 번호라서 빼면 돼요.
- **함정:** `strstr`은 "글자 어디든" 찾아요. 그래서 `minsize=512` **안에 숨어 있는** `size=`를 먼저 찾아 **512KB**라고 말해요. 진짜 크기는 4096KB인데요! 펌웨어를 반만 받고 "다 받았다"고 착각하면 기기가 고장 나요. 그래서 `find_key`는 **`;` 다음, 칸의 맨 앞**에서만 비교해요.
- `hash`는 없으니 `NULL`이에요. `NULL`을 받으면 **꼭 확인하고** 써야 해요. 확인 없이 `read_num(&p)`를 하면 0번지를 읽다가 프로그램이 죽어요.

### 구조체 정답
```c
Ver bump(Ver v, char part) {        // v는 '복사본'
    switch (part) {
        case 'M': v.major++; v.minor = 0; v.patch = 0; break;
        case 'm': v.minor++; v.patch = 0; break;
        case 'p': v.patch++; break;
    }
    return v;                       // 고친 복사본을 통째로 돌려줌
}
```
```
bump(v,'p')            = 2.9.15
bump(v,'m')            = 2.10.0
bump(v,'M')            = 3.0.0
bump(bump(v,'m'),'p')  = 2.10.1   (안쪽 먼저: 2.10.0 → 2.10.1)
v                      = 2.9.14   (그대로!)
sizeof(Ver) = 12, sizeof(Device) = 36
```
**해설:**
- 구조체를 함수에 넘기면 **복사본**이 가요. 시험지를 복사해서 친구에게 주면, 친구가 낙서해도 내 원본은 깨끗하죠. 그래서 `v`는 끝까지 `2.9.14`예요.
- minor를 올리면 patch를 0으로 돌려요. 10월이 되면 날짜가 1일부터 다시 시작하는 것과 같아요.
- `sizeof(Ver)` = int 3개 = 4×3 = **12**. `Device` = id 8 + Ver 12 + int 4개 16 = **36**.
- `if (v == TARGET)`은 **컴파일 에러**예요. C는 구조체를 `==`로 통째로 비교할 줄 몰라요. 그래서 `ver_cmp`처럼 칸마다 비교하는 함수를 직접 만들어요.

### 함수 정답
```c
int cmp_dev(const void *x, const void *y) {
    const Device *a = x, *b = y;           // "아무 주소"를 Device 주소로 바꿔 읽기
    if (a->wave != b->wave) return a->wave - b->wave;   // 차수: 작은 게 앞
    return b->battery - a->battery;                     // 배터리: 큰 게 앞 (b - a!)
}
qsort(tmp, ND, sizeof tmp[0], cmp_dev);
```
```
1차: TV-02(95) TV-01(80) FR-03(15)
2차: TV-06(88) WM-05(70) AC-04(60) WM-07(50)
3차: FR-08(55) AC-09(40)
```
**해설:**
- `qsort`는 **정렬 로봇**이에요. 로봇은 "어떤 게 앞이야?"를 모르니까, 우리가 **판정하는 함수(`cmp_dev`)를 통째로 건네줘요**. 함수 이름만 쓰면 그게 함수의 주소(함수 포인터)가 돼요.
- 판정 규칙: **음수**면 a가 앞, **양수**면 b가 앞, 0이면 같아요.
- `qsort`는 어떤 배열이든 정렬해야 해서 `const void *`(종류 모를 주소)로 줘요. 우리가 "이건 Device야" 하고 바꿔 읽는 거예요.
- **함정:** `a->battery - b->battery`로 쓰면 배터리가 **적은 순**이 돼서 1차가 `FR-03(15) TV-01(80) TV-02(95)`가 돼요. 빼는 순서 하나로 방향이 뒤집혀요.

- 3차는 **시작도 안 해요**. 2차에서 이미 "이 펌웨어 위험해!"라는 신호가 왔으니까요. 결국 처음부터 최신이었던 TV-06만 2.10.1로 남아요.
- **왜 거꾸로 롤백?** 블록을 쌓았다가 치울 때 **맨 위부터** 내리잖아요. 실제 업데이트는 앞 기기의 결과가 뒤 기기에 영향을 줄 때가 많아서(예: 허브가 먼저, 기기가 나중), 되돌릴 때는 **나중에 한 것부터** 되돌려야 안전해요. 그래서 스택(`stack[--top]`)을 써요.
- **왜 `goto`?** `break`는 **한 겹**만 빠져나와요. 여기서는 안쪽 `for`(기기)가 아니라 바깥 `for`(차수)까지 한 번에 나가서 **정리 코드로 점프**해야 해요. "문제가 생기면 무조건 한곳(`rollback:`)에서 정리한다"는 규칙은 리눅스 커널 같은 진짜 C 코드에서 많이 쓰는 방식이에요. 단, `goto`는 **아래쪽 정리 장소로만** 쓰고 위로 되돌아가는 데는 쓰지 않아요.
- `goto done;`이 없으면 성공했을 때도 `rollback:` 줄로 **그냥 흘러 들어가요**. 라벨은 "문"이 아니라 "표지판"일 뿐이라서요. (여기서는 스택에 든 게 있으면 성공한 기기를 되돌려 버려요!)

### 조건문 정답
```c
const char *check(const Cmd *c) {
    int len = (int)strlen(doc);
    if (c->op == 'i') {
        if (c->pos < 0 || c->pos > len)                       return "위치 오류";
        else if (len + (int)strlen(c->arg) > MAXT - 1)        return "용량 초과";
        else                                                  return "OK";
    } else if (c->op == 'd') {
        int n = to_int(c->arg);
        if (n <= 0)                                           return "지울 게 없음";
        else if (c->pos < 0 || c->pos + n > len)              return "범위 오류";
        else                                                  return "OK";
    } else if (c->op == 'u') return undo_top == 0 ? "되돌릴 것 없음" : "OK";
    else if (c->op == 'r')   return redo_top == 0 ? "다시 할 것 없음" : "OK";
    else if (c->op == 'q')   return "OK";
    else                     return "모르는 명령";
}
```
```
i 14 '!'          -> OK          (맨 끝에 붙이기)
i 15 'x'          -> 위치 오류    (15번 자리는 없음)
i 0 'ABCDEFGHI'   -> OK          (14 + 9 = 23, 딱 맞음)
i 0 'ABCDEFGHIJ'  -> 용량 초과    (14 + 10 = 24 > 23)
i -1 'a'          -> 위치 오류
d 12 '2'          -> OK          ("d!" 지우기, 12 + 2 = 14)
d 13 '2'          -> 범위 오류    (13 + 2 = 15 > 14)
d 2 '0'           -> 지울 게 없음
u                 -> 되돌릴 것 없음
z                 -> 모르는 명령
```
**해설:**
- 글자 사이 **틈**을 생각해 보세요. `"abc"`에는 틈이 `|a|b|c|` 4개(0~3)라서 **맨 끝 틈(3)**에 넣는 것도 괜찮아요. 하지만 지우기는 **실제 글자**를 지워야 하니까 `pos + n`이 글자 수(3)를 넘으면 안 돼요.
- `MAXT - 1`인 이유: 배열 24칸 중 1칸은 문자열 끝 표시 `'\0'`의 자리예요. 이 칸을 빼먹으면 `'\0'`이 배열 밖에 써져서 옆 변수가 망가져요.
- 위치 검사를 **용량 검사보다 먼저** 해요. 이상한 위치(-1)라면 용량은 물어볼 필요도 없으니까요.

### 반복문 정답
```c
void ins_text(char *s, int pos, const char *t) {
    int len = (int)strlen(s), k = (int)strlen(t);
    for (int i = len; i >= pos; i--)       // 뒤에서부터! ('\0'도 같이 밀어요)
        s[i + k] = s[i];
    for (int j = 0; j < k; j++)            // 빈자리에 복사
        s[pos + j] = t[j];
}
```
```
"Hlo" + (1, "el")      -> "Hello"
"C"   + (0, "I love ") -> "I love C"
"abc" + (3, "de")      -> "abcde"
앞에서부터 미는 틀린 버전: "Hlo" + (1, "el") -> "Hellol"
```
**해설:**
- 줄 선 친구들을 2칸씩 뒤로 보내려면 **맨 뒤 친구부터** 움직여야 해요. 앞 친구부터 움직이면 뒤 친구 자리에 올라타서 뒤 친구가 **사라져요**.
- 틀린 버전을 따라가 볼게요. `H l o \0`에서 `s[3] = s[1]('l')` → `\0`이 덮여서 사라짐! `s[4] = s[2]('o')`, `s[5] = s[3]`인데 `s[3]`은 이미 `'l'`로 바뀐 뒤예요. 그래서 `"Hellol"`처럼 이상한 글자가 생겨요. (이번엔 배열 뒤쪽이 우연히 0이라 멈췄지만, 아니었다면 쓰레기 글자가 줄줄 나왔을 거예요.)
- `i = len`부터 시작하는 이유: 맨 끝의 `'\0'`도 같이 밀어야 새 문자열의 끝이 표시돼요.

### 배열 정답
```c
void push(Action *st, int *top, Action a) {
    if (*top == MAXH) {                          // 꽉 참
        for (int i = 1; i < MAXH; i++)           // 한 칸씩 앞으로 당기기
            st[i - 1] = st[i];                   // (맨 앞 = 가장 오래된 기록은 덮여서 사라짐)
        (*top)--;
    }
    st[(*top)++] = a;
}
```
```
push a: undo[+0'a']
push b: undo[+0'a' +1'b']
push c: undo[+0'a' +1'b' +2'c']
push d: undo[+0'a' +1'b' +2'c' +3'd']
push e: undo[+1'b' +2'c' +3'd' +4'e']      ← 'a' 기록이 밀려남
push f: undo[+2'c' +3'd' +4'e' +5'f']      ← 'b' 기록이 밀려남
undo -> "abcde"
undo -> "abcd"
undo -> "abc"
undo -> "ab"
undo 4번, 최종 "ab"
```
(`+3'd'`는 "3번 자리에 d를 넣었음"이라는 뜻이에요.)

**해설:**
- 사진첩이 4장짜리라서 새 사진을 넣을 때마다 **가장 오래된 사진을 빼요**. 그래서 실행 취소는 4번까지만 되고 `"ab"`는 되돌릴 수 없어요. 진짜 워드프로세서도 메모리 때문에 "최근 몇 개까지만" 기억해요.
- `*top`처럼 별표를 붙이는 건 "함수 밖에 있는 진짜 `undo_top`을 바꿔야 해서"예요. 그냥 `int top`을 받으면 복사본만 바뀌어요.
- `st[(*top)++] = a;`는 "지금 칸에 넣고, 그다음 칸 번호로 하나 올리기"를 한 줄로 쓴 거예요.

### 포인터 변수 정답
```c
void del_text(char *s, int pos, int n) {
    char *dst = s + pos, *src = s + pos + n;
    while ((*dst++ = *src++))
        ;
}
```
```
"I really love C" (2, 7) -> "I love C"   (길이 8)
"abcdef"          (4, 2) -> "abcd"
"abcdef"          (0, 6) -> ""           (길이 0)
```
**해설:**
- 손가락 두 개를 생각해요. `src`(읽는 손가락)는 지울 부분 **바로 뒤**, `dst`(쓰는 손가락)는 지울 부분 **처음**에 둬요. 그리고 "읽은 글자를 쓰고, 둘 다 한 칸 앞으로"를 반복해요. 뒤 글자들이 앞으로 당겨지면서 지운 부분을 덮어요.
- **언제 멈추나요?** `*dst = *src`는 "옮겨 쓴 글자"가 값이 돼요. 마지막에 `'\0'`(값이 0)을 옮겨 쓰는 순간 `while(0)` → 멈춰요. 끝 표시까지 **옮기고 나서** 멈추니까 새 문자열도 제대로 끝나요.
- 괄호를 두 겹 쓰는 건 "`==` 쓰려다 `=` 잘못 쓴 거 아니에요, **일부러 대입한 거예요**"라고 컴파일러에게 알려 주는 약속이에요. 한 겹이면 `-Wall`이 경고를 내요.
- 넣기와 반대로 지우기는 **앞에서부터** 당겨야 안전해요. 앞으로 당길 땐 아직 안 읽은 글자를 덮지 않거든요.

### 구조체 정답
```c
Action inverse(Action a) {
    a.kind = (a.kind == INS) ? DEL : INS;
    return a;
}
```
```
a          = {DEL(1), 2, "really "}
inverse(a) = {INS(0), 2, "really "}
a는 그대로 DEL!  sizeof(Action) = 20  (kind 4 + pos 4 + text 12)
포인터로 저장했다면 지운 뒤 읽은 7글자: "love C"   ← "really "가 아님!
```
**해설:**
- "2번 자리에서 `really `를 지웠다"의 반대는 "2번 자리에 `really `를 넣는다"예요. 그래서 **기록만 있으면 언제든 되돌릴 수 있어요**. 이게 Undo의 핵심 아이디어예요.
- 그런데 지운 글자를 **기록장에 직접 베껴 써 둬야** 해요(`char text[12]`). "문서 2번 자리를 봐"라고 **주소만** 적어 두면(`const char *`), 지운 뒤 그 자리에는 이미 `"love C"`가 당겨져 와 있어요. 친구 집 주소만 적어 뒀는데 친구가 이사 가면, 그 주소엔 다른 사람이 살고 있는 것과 같아요.
- 구조체는 값으로 넘겨져서 `a`는 안 바뀌어요(문제 1의 `bump`와 같아요).

### 함수 정답
```c
void apply(const Action *a) {
    if (a->kind == INS) ins_text(doc, a->pos, a->text);
    else                del_text(doc, a->pos, (int)strlen(a->text));
}
void do_action(Action a) { apply(&a); push(undo_st, &undo_top, a); redo_top = 0; }
void undo(void) {
    Action a = undo_st[--undo_top];
    Action b = inverse(a);
    apply(&b);
    push(redo_st, &redo_top, a);          // '원래 기록'을 넣어야 나중에 그대로 다시 실행 가능
}
void redo(void) {
    Action a = redo_st[--redo_top];
    apply(&a);
    push(undo_st, &undo_top, a);
}
```
```
1) i: "cat"     undo[+0'cat']                    redo[]
2) i: "cats"    undo[+0'cat' +3's']              redo[]
3) i: "my cats" undo[+0'cat' +3's' +0'my ']      redo[]
4) u: "cats"    undo[+0'cat' +3's']              redo[+0'my ']
5) u: "cat"     undo[+0'cat']                    redo[+0'my ' +3's']
6) r: "cats"    undo[+0'cat' +3's']              redo[+0'my ']
7) i: "a cats"  undo[+0'cat' +3's' +0'a ']       redo[]           ← redo가 사라짐!
8) r: 다시 할 것 없음  "a cats"
```
**해설:**
- 스택 두 개는 **접시 두 더미**예요. Ctrl+Z를 누르면 왼쪽 더미 맨 위 접시를 꺼내 반대로 하고, 오른쪽 더미에 올려요. Ctrl+Y는 그 반대예요.
- 6번에서 redo는 **가장 최근에 취소한 `s`**부터 다시 해요(`my `가 아니라). 접시 더미는 맨 위부터 꺼내니까요.
- **7번이 핵심:** 새로 입력하면 `redo_top = 0`으로 다시 실행 더미를 버려요. 왜냐면 `"my "`는 "`cats`가 있던 문서의 0번 자리"를 기준으로 기록된 거라서, 문서가 `"a cats"`로 바뀐 뒤에 실행하면 엉뚱한 곳에 들어갈 수 있거든요. 그래서 한글, 워드, VS Code 모두 "새로 입력하면 Redo는 사라진다" 규칙을 써요.

### 흐름제어 퀴즈 2 정답
```c
int n = sizeof s / sizeof s[0], edits = 0, skipped = 0, saves = 0;
for (int i = 0; i < n; i++) {
    const char *e = check(&s[i]);
    if (strcmp(e, "OK")) { printf("%2d %c: %s, 건너뜀\n", i + 1, s[i].op, e); skipped++; continue; }
    switch (s[i].op) {
        case 'i': case 'd': do_action(make(&s[i])); edits++; break;
        case 'u': undo(); break;
        case 'r': redo(); break;
        case 'q': printf("%2d q: 종료\n", i + 1); goto end;
    }
    printf("%2d %c: \"%s\"  (undo %d, redo %d)\n", i + 1, s[i].op, doc, undo_top, redo_top);
    if ((s[i].op == 'i' || s[i].op == 'd') && edits % 3 == 0) {
        saves++;
        printf("   [자동저장 #%d] \"%s\"\n", saves, doc);
    }
}
end:
printf("편집 %d번, 건너뜀 %d번, 자동저장 %d번, 최종 \"%s\"\n", edits, skipped, saves, doc);
```
```
 1 i: "Hello"  (undo 1, redo 0)
 2 i: "Hello World"  (undo 2, redo 0)
 3 d: "World"  (undo 3, redo 0)
   [자동저장 #1] "World"
 4 u: "Hello World"  (undo 2, redo 1)
 5 i: "Hello, World"  (undo 3, redo 0)
 6 r: 다시 할 것 없음, 건너뜀
 7 d: "Hello,World"  (undo 4, redo 0)
 8 i: "Hello,World!!"  (undo 4, redo 0)
   [자동저장 #2] "Hello,World!!"
 9 u: "Hello,World"  (undo 3, redo 1)
10 u: "Hello, World"  (undo 2, redo 2)
11 u: "Hello World"  (undo 1, redo 3)
12 u: "Hello"  (undo 0, redo 4)
13 u: 되돌릴 것 없음, 건너뜀
14 r: "Hello World"  (undo 1, redo 3)
15 p: 모르는 명령, 건너뜀
16 i: ">> Hello World"  (undo 2, redo 0)
17 q: 종료
편집 7번, 건너뜀 3번, 자동저장 2번, 최종 ">> Hello World"
```
**해설:**
- **6번:** 4번에서 취소한 "Hello 지우기"를 다시 하고 싶었지만, 5번에서 `,`를 새로 입력해서 redo 더미가 비었어요. (함수 퀴즈의 규칙!)
- **8번:** 되돌리기 더미가 이미 4장으로 꽉 차 있어서, 가장 오래된 기록 **"0번에 Hello 넣기"가 밀려나요**. 그래서 9~12번에 실행 취소를 4번 하면 `"Hello"`까지만 돌아가고, 13번에선 "되돌릴 것 없음"이에요. 사진첩이 4장짜리라 첫 사진은 이미 버린 거예요.
- **자동저장:** 편집이 3번째(3번 줄), 6번째(8번 줄)일 때만 저장해요. 실행 취소/다시 실행은 편집 횟수에 안 들어가요. `edits % 3 == 0`은 "3으로 나눠 떨어지면" = 3, 6, 9…번째예요.
- **왜 `goto end`?** `switch` 안에서 `break`를 쓰면 **`switch`만** 빠져나오고 `for`는 계속 돌아요! 그러면 18번 `"X"`까지 문서에 들어가 버려요. (어제 쿠버네티스 퀴즈의 `OOM` 함정과 같은 이야기예요.) 반대로 `continue`는 `switch`에 반응하지 않고 바로 `for`의 다음 바퀴로 가요. 그래서 "`switch` 안에서 반복문을 끝내고 싶다"면 `goto end;`나 "끝내기 깃발(`int quit = 1;` 후 `break` → `for` 조건에서 검사)"을 써야 해요.

- **포인터:** 커서를 옮기려면 `**`, 지운 글자는 주소가 아니라 **내용을 베껴** 저장해요.
- **구조체:** 값으로 넘기면 복사본, `==`로는 비교 못 해요.
- **함수:** `qsort`엔 판정 함수를 건네주고, Undo/Redo는 스택 두 개로.
- **흐름제어:** `continue`는 패스, `break`는 한 겹 탈출, 여러 겹 탈출·정리는 `goto` 한곳으로!
