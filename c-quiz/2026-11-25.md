## 엔지니어가 직면한 가상의 문제 1

**[Meta 인스타그램 스토리팀]** 새벽에 신고가 쏟아졌어요. "친한 친구만 보라고 올린 스토리를 다른 애가 봤대요!", "어제 올린 스토리가 아직도 떠 있어요!", "제가 **차단한** 사람이 제 스토리를 봤어요!!" 엔지니어인 너는 **스토리 공개 규칙을 다시 짜고 → 옛 서버가 잘못 보여준 기록을 감사(검사)하고 → 사람마다 스토리 줄을 최신순으로** 다시 만들어야 해요.

**스토리 공개 규칙** (위에서부터 차례로 검사, 걸리면 바로 끝)
1. 삭제된 스토리 → 안 보임
2. 올린 시각이 **지금보다 미래** → 안 보임 (서버 시계 오류)
3. 올린 지 **24시간(1440분) 이상** → 안 보임
4. **내 스토리**면 → 보임 (위 1~3만 통과하면 돼요)
5. 둘 중 **누구라도 상대를 차단**했으면 → 안 보임
6. 공개 범위 검사
   - `PUBLIC`: 누구나. 단, 주인이 **비공개 계정**이면 팔로워만
   - `FOLLOWERS`: 주인을 팔로우하는 사람만
   - `CLOSE`: 주인의 **친한 친구 목록**에 있는 사람만

## 엔지니어가 창작해야되는 가상의 프로그램 1

**[교육청 "급식 알리미" 앱 개발팀 — 가상]** 학생마다 알레르기가 달라요. 이번 주 급식 메뉴를 보고 **학생별·요일별로 "먹어도 되는지"** 알려주고, 위험하면 **보호자에게 문자**를 보내는 프로그램을 새로 만들어야 해요.

**비트 마스크 아이디어**: 알레르기 8가지를 **스위치 8개**처럼 숫자 하나에 담아요. `난류 = 1(00000001)`, `우유 = 2(00000010)`, `메밀 = 4` … 이렇게 각자 자기 자리(비트) 하나만 켜요.

**판정 규칙**
- 메뉴에 `UNKNOWN`(재료 정보가 안 들어옴) 표시가 있으면 → **심한 알레르기 학생은 `HOLD`**(그날 급식 판정을 **즉시 멈추고** 보호자 확인), 아니면 `WARN`
- 메뉴 알레르기와 학생 알레르기가 겹치는 게 없으면 → `SAFE`
- 겹치면 → 심한 알레르기 학생(`severe == 1`)은 `DANGER`, 아니면 `WARN`
- `SAFE` 반찬만 열량(kcal)에 더해요. (`WARN`/`DANGER` 반찬은 빼요)
- 하루 판정 우선순위: `보류 > 대체식+담임 알림(DANGER) > 반찬 빼기(WARN) > 열량 부족(500kcal 미만) > OK`

### 흐름제어 퀴즈1
학생 한 명의 하루를 검사하는 `DayReport checkDay(const Student *s, int day)`를 만드세요. 그날 칸 4개를 돌면서:
- `EMPTY(-1)` → 그날 메뉴 끝, **`break`**
- 메뉴판에 없는 번호(오타) → `typo` +1, **`continue`**
- `HOLD` → `hold = 1`, 문제 반찬 기록 후 **즉시 `break`** (나머지 반찬은 보지도 않아요!)

## 문제 1 — 인스타그램 스토리 공개 범위

### 조건문 퀴즈1 정답
```c
Reason whyHidden(int viewer, const Story *s, int nowMin) {
    if (s->deleted) return H_DELETED;                   // 1
    int t = timeState(s, nowMin);                       // 2, 3
    if (t != OK_VISIBLE) return t;
    if (s->owner == viewer) return OK_VISIBLE;          // 4 내 스토리
    if (isBlockedEither(viewer, s->owner)) return H_BLOCKED;  // 5
    if (!audienceOK(viewer, s)) return H_AUDIENCE;      // 6
    return OK_VISIBLE;
}

int canView(int viewer, const Story *s, int nowMin) {
    return whyHidden(viewer, s, nowMin) == OK_VISIBLE;
}
```
**🧒 쉽게 설명하면**
공항 보안 검색대를 생각해 봐요. 여권이 없나?(삭제) → 날짜가 이상한가?(미래/만료) → 승무원 본인인가?(내 스토리, 바로 통과) → 블랙리스트인가?(차단) → 표가 맞나?(공개 범위). 하나라도 걸리면 **그 자리에서 "안 돼요!" 하고 이유를 말해줘요.** 그냥 "안 돼요"(0)가 아니라 **이유 번호**를 돌려주니까, 나중에 감사할 때 "왜 유출됐는지"까지 알 수 있어요.

③ 1500 − 60 = **1440분 = 정확히 24시간**. 24시간이 "다 됐으면" 사라져야 하니까 `>=`가 맞아요. `>`로 쓰면 **딱 1440분일 때 1분 동안 더 보이는 버그**가 생겨요. 실제로 태민이 그 1분 사이에 "새벽 러닝"을 봤다는 기록이 감사에 나와요! (흐름제어 퀴즈1의 #1)

④ "내 스토리면 통과"를 먼저 하면, **삭제한 스토리나 24시간 지난 스토리도 나한테는 계속 보여요.** 순서가 바뀌면 결과가 바뀌는 게 조건문의 무서운 점이에요. 그래서 "누구에게나 적용되는 규칙(삭제·시간)"을 맨 앞에 둬요.

### 배열 퀴즈1 정답
```c
char grid[NU][NS + 1];
for (int v = 0; v < NU; v++) {
    for (int k = 0; k < NS; k++) {
        const Story *s = &stories[k];
        Reason r = whyHidden(v, s, now);
        if (s->owner == v && r == OK_VISIBLE) grid[v][k] = '*';
        else if (r == OK_VISIBLE)             grid[v][k] = 'O';
        else if (r == H_BLOCKED)              grid[v][k] = 'X';
        else                                  grid[v][k] = '.';
    }
    grid[v][NS] = '\0';
    printf("%s %s\n", users[v].name, grid[v]);
}
int best = -1, bestK = -1;
for (int k = 0; k < NS; k++) {          // 이번엔 세로로
    int c = 0;
    for (int v = 0; v < NU; v++)
        if (grid[v][k] == 'O') c++;
    if (c > best) { best = c; bestK = k; }
}
```
출력:
```
      01234567
지우 .OOO*.O.
태민 .*.OO...
수아 ..**O.X.
현우 ..OO....
예린 .OXXO.*.
세로 'O' 개수: 0 2 2 3 3 0 1 0
가장 많이 퍼지는 스토리: 3번 "어제 바다" (3명)
```
**🧒 쉽게 설명하면** `follows`, `blocked`, `grid` 전부 **"가로줄 = 나, 세로줄 = 상대"** 모눈종이예요. `follows[2][1]`은 "2번(수아) 줄의 1번(태민) 칸" → 0이니까 수아는 태민을 팔로우 안 해요. ⚠️ `follows[a][b]`와 `follows[b][a]`는 **다른 칸**이에요! 지우가 예린을 팔로우해도(`[0][4] = 1`) 예린이 지우를 팔로우하는지는(`[4][0]`) 따로 봐야 해요. 그래서 차단 검사도 `blocked[a][b] || blocked[b][a]` 두 칸을 다 봐요. 3번과 4번이 3명으로 같지만 `>`라서 먼저 나온 3번이 이겨요.

### 포인터 변수 퀴즈1 정답
```c
const Story *findStory(const Story *arr, int n, int id) {
    for (int i = 0; i < n; i++)
        if (arr[i].id == id) return &arr[i];
    return NULL;
}

void swapStoryPtr(const Story **a, const Story **b) {
    const Story *t = *a;   // a가 가리키는 "칸"에 들어 있던 주소를 꺼내 둠
    *a = *b;
    *b = t;
}
// 부르는 쪽: swapStoryPtr(&f->items[i], &f->items[best]);
```
③ **버그**: 함수에 들어온 `a`, `b`는 주소를 **복사한 쪽지**예요. 쪽지끼리 바꿔 봤자 `f->items[]` 배열 칸에 적힌 원래 주소는 그대로예요. 함수가 끝나면 쪽지는 버려지니 **아무 일도 안 일어난 것**과 같아요.

**🧒 쉽게 설명하면**
사물함 두 칸(`items[i]`, `items[best]`)에 각각 **"보물 위치 쪽지"**(스토리 주소)가 들어 있어요. 쪽지 내용을 바꾸고 싶으면 **사물함 번호**(`&items[i]`, 즉 `Story **`)를 알려줘야 거기 가서 쪽지를 바꿔 넣을 수 있어요. 쪽지 **복사본**만 받아서 내 손에서 바꿔 봤자, 사물함 안 쪽지는 그대로예요. "주소를 바꾸려면 주소의 주소가 필요하다" — 이게 `**`(포인터의 포인터)예요.

### 구조체 퀴즈1 정답
① `users[f->items[0]->owner].name`
`f->items[0]` → 첫 번째 스토리 주소 → `->owner` → 올린 사람 번호 → `users[...]` → `.name`. 화살표(`->`)는 "주소를 따라가서 그 안의 칸", 점(`.`)은 "내 손에 있는 구조체의 칸"이에요.

② 포인터 배열로 만든 이유
1. **빠르고 가벼워요.** `Story` 하나는 50바이트쯤이지만 주소는 8바이트예요. 정렬할 때 큰 상자를 옮기지 않고 **이름표만** 옮겨요.
2. **원본이 하나뿐이에요.** 주인이 스토리를 삭제하면(`stories[k].deleted = 1`) 모든 사람의 줄이 같은 원본을 보고 있으니 다시 만들 때 바로 반영돼요. 복사본이면 사람마다 낡은 복사본이 남을 수 있어요.

**🧒 쉽게 설명하면** 도서관 책(원본)을 친구 수만큼 복사하는 대신, "3층 7번 책장"이라는 **위치 카드**만 나눠 주는 거예요.

### 함수 퀴즈1 정답
```c
int isBlockedEither(int a, int b) { return blocked[a][b] || blocked[b][a]; }

int timeState(const Story *s, int nowMin) {
    if (s->postedMin > nowMin)          return H_FUTURE;
    if (nowMin - s->postedMin >= DAY)   return H_EXPIRED;
    return OK_VISIBLE;
}

int audienceOK(int viewer, const Story *s) {
    switch (s->aud) {
    case PUBLIC:
        if (users[s->owner].isPrivate) return follows[viewer][s->owner];
        return 1;
    case FOLLOWERS: return follows[viewer][s->owner];
    case CLOSE:     return closeF[s->owner][viewer];   // ⚠️ 주인의 목록에 내가 있나!
    }
    return 0;    // 모르는 공개 범위면 안전하게 "안 보임"
}

void buildFeed(Feed *f, int viewer, int nowMin) {
    f->viewerId = viewer;
    f->count = 0;
    for (int k = 0; k < NS; k++)
        if (canView(viewer, &stories[k], nowMin))
            f->items[f->count++] = &stories[k];
    for (int i = 0; i < f->count - 1; i++) {          // 선택 정렬 (최신순)
        int best = i;
        for (int j = i + 1; j < f->count; j++)
            if (f->items[j]->postedMin > f->items[best]->postedMin) best = j;
        if (best != i) swapStoryPtr(&f->items[i], &f->items[best]);
    }
}

void printFeed(const Feed *f, int nowMin) {
    printf("%s의 스토리 줄(%d개):", users[f->viewerId].name, f->count);
    for (int i = 0; i < f->count; i++) {
        const Story *s = f->items[i];
        int left = DAY - (nowMin - s->postedMin);
        if (left < 60) printf(" [%s·%s·%d분 남음]",   users[s->owner].name, s->caption, left);
        else           printf(" [%s·%s·%d시간 남음]", users[s->owner].name, s->caption, left / 60);
    }
    printf("\n");
}
```
**🧒 쉽게 설명하면** 큰 레고 작품을 만들 때 "바퀴 만들기", "지붕 만들기"를 따로 해 두면, 바퀴가 이상할 때 **바퀴만** 고치면 돼요. 오늘 버그 중 "24시간"은 `timeState`만, "비공개 계정"은 `audienceOK`만 고치면 돼요.
⚠️ `CLOSE`에서 `closeF[viewer][s->owner]`로 **거꾸로** 쓰면 "**내** 친친 목록에 주인이 있나?"를 보게 돼요. 그러면 수아의 친친인 현우가 "비밀 일기"를 **못 보게** 돼요(현우 목록에는 수아가 없거든요). 반대로, 주인이 친친으로 고르지도 않았는데 혼자 주인을 친친으로 넣어 둔 사람은 **보게** 되고요. 2차원 배열은 **줄·칸 순서가 곧 뜻**이에요!
⚠️ `audienceOK`의 `return 0;`: 나중에 누가 공개 범위를 새로 추가했는데 `case`를 깜빡해도, **"모르면 안 보여준다"** 쪽으로 실패해서 안전해요.

### 흐름제어 퀴즈2 (종합) 정답
```c
int main(void) {
```

## 프로그램 1 — 급식 알레르기 알리미

### 조건문 퀴즈1 정답
```c
Level classify(const Student *s, const Dish *d) {
    if (d->mask & UNKNOWN)            return s->severe ? HOLD : WARN;  // 모르면 가장 조심
    if ((d->mask & s->mask) == 0)     return SAFE;                     // 겹치는 스위치 없음
    return s->severe ? DANGER : WARN;
}
```
② 판정표 (메뉴 1~12 순서)
```
하준: SAFE SAFE DANGER DANGER SAFE SAFE SAFE SAFE SAFE HOLD SAFE SAFE
시우: SAFE WARN SAFE WARN SAFE WARN WARN SAFE SAFE WARN SAFE WARN
```
③ C에서는 `==`가 `&`보다 **먼저** 계산돼요. 그래서 `d->mask & (s->mask == 0)`이 돼 버려요. 하준은 `s->mask == 0`이 거짓(0)이니까 `d->mask & 0` = 항상 0 → **모든 반찬이 "겹침 없음 아님"으로 뒤집혀요.** 비트 연산에는 **괄호를 꼭** 쳐요!

**🧒 쉽게 설명하면**
알레르기를 **전등 스위치 8개**라고 생각해요. 하준은 1번 스위치(난류)만 켜져 있고, 계란말이는 1번(난류)·2번(우유)이 켜져 있어요. `&`(그리고)는 "**둘 다 켜진 스위치만** 남겨!"라는 뜻이에요. 1번이 둘 다 켜져 있으니 결과가 0이 아니고 → 위험! 쌀밥은 스위치가 하나도 안 켜져 있으니 `&` 결과가 0 → 안전!
`UNKNOWN`을 먼저 보는 이유: 재료를 모르면 "겹치는 게 없다"가 아니라 **"모른다"**예요. 모르는 걸 안전하다고 하면 안 되니까, 가장 먼저 걸러내요.

### 반복문 퀴즈1 정답
```c
int countBits(unsigned m) {
    int c = 0;
    for (int b = 0; b < NA; b++)
        if (m & (1u << b)) c++;      // b번 스위치가 켜졌나?
    return c;
}

void printAllergens(unsigned m) {
    int first = 1;
    for (int b = 0; b < NA; b++)
        if (m & (1u << b)) {
            printf(first ? "%s" : ",%s", allergenName[b]);
            first = 0;
        }
    if (m & UNKNOWN) { printf(first ? "%s" : ",%s", "재료 미확인"); first = 0; }
    if (first) printf("없음");
}

unsigned all = 0;
for (int i = 0; i < NSTU; i++) all |= students[i].mask;
printf("반 전체: "); printAllergens(all); printf(" (%d종)\n", countBits(all));
```
출력:
```
하준(1개): 난류
서윤(2개): 우유,복숭아
도현(2개): 땅콩,새우
지아(0개): 없음
시우(2개): 대두,밀
반 전체: 난류,우유,땅콩,대두,밀,새우,복숭아 (7종)
```
**🧒 쉽게 설명하면** `1u << b`는 "1을 왼쪽으로 b칸 밀기" = **b번 스위치만 켜진 숫자**예요. 0번부터 7번까지 하나씩 "이거 켜졌어?" 물어보는 게 반복문이에요. `|`(또는)는 "**하나라도 켜졌으면 켜!**"라서, 다섯 명 걸 다 `|` 하면 반 전체에서 조심할 스위치가 모여요. 메밀은 아무도 없으니 7종. `first`는 "첫 번째엔 쉼표를 안 붙이기" 위한 깃발이에요.

### 흐름제어 퀴즈1 정답
```c
typedef struct {
    int day, kcal, warn, danger, typo, hold;
    const Dish *bad[SLOTS];
    int nbad;
} DayReport;

DayReport checkDay(const Student *s, int day) {
    DayReport r = {day, 0, 0, 0, 0, 0, {0}, 0};
    for (int k = 0; k < SLOTS; k++) {
        int id = week[day][k];
        if (id == EMPTY) break;                               // 빈칸 = 그날 끝
        const Dish *d = findDish(menu, NMENU, id);
        if (d == NULL) { r.typo++; continue; }                // 오타는 건너뛰기
        Level lv = classify(s, d);
        if (lv == HOLD) { r.hold = 1; r.bad[r.nbad++] = d; break; }  // 즉시 멈춤
        switch (lv) {
        case SAFE:   r.kcal += d->kcal;                  break;
        case WARN:   r.warn++;   r.bad[r.nbad++] = d;    break;
        case DANGER: r.danger++; r.bad[r.nbad++] = d;    break;
        default: break;
        }
    }
    return r;
}

const char *verdict(const DayReport *r) {
    if (r->hold)       return "⛔ 보류(보호자 확인)";
    if (r->danger > 0) return "🚨 대체식 + 담임 알림";
    if (r->warn > 0)   return "⚠️ 반찬 빼기";
    if (r->kcal < 500) return "🍙 열량 부족";
    return "✅ OK";
}
```
결과:
```
하준 목: kcal 310, hold 1 → ⛔ 보류(보호자 확인)
서윤 목: kcal 370, warn 2 → ⚠️ 반찬 빼기  (수제쿠키, 복숭아)
```
**🧒 쉽게 설명하면**
목요일 메뉴는 `잡곡밥 → 수제쿠키 → 미역국 → 복숭아` 순서예요.
- **하준**(심함): 잡곡밥 OK(310) → 수제쿠키 "재료 모름!" → **그 자리에서 멈춰요(`break`).** 미역국·복숭아는 보지도 않아서 열량이 310에서 끝나요. "엄마한테 물어보기 전엔 오늘 급식 판단 안 할래!"
- **서윤**(심하지 않음): 수제쿠키는 `WARN`이라 **멈추지 않고** 계속 가요. 미역국(60) 더하고, 복숭아는 서윤 알레르기라 빼요 → 310 + 60 = **370**.
- `if (lv == HOLD) ... break;`를 `switch` **밖**에 둔 이유: `switch` 안에서 `break`를 쓰면 **`switch`만** 빠져나가고 `for`는 계속 돌아요! 반복문을 멈추려면 `switch` 밖에서 `break`해야 해요.
- 판정 순서(`verdict`)도 조건문 순서가 곧 **중요도 순서**예요. 위험한 것부터 물어봐요.

### 포인터 변수 퀴즈1 정답
```c
const Dish *findDish(const Dish *arr, int n, int id) {
    for (int i = 0; i < n; i++)
        if (arr[i].id == id) return &arr[i];
    return NULL;
}

void addAllergy(Student *s, unsigned a) { s->mask |= a; }

Student *p = &students[3];
addAllergy(p, MILK);
DayReport r = checkDay(p, 1);      // 화요일
// 지아: 우유 / 화: ⚠️ 반찬 빼기, kcal 710 (잡곡밥 310 + 불고기 280 + 땅콩조림 120, 우유 130은 빠짐)

p->mask &= ~MILK;                  // ③ 우유 스위치만 끄기
```
④ 버그 두 개
1. `Student s`는 **복사본**이에요. 복사본의 스위치를 켜 봤자 진짜 `students[3]`은 그대로예요. → `Student *s`로 받아야 해요.
2. `s.mask | a;`는 계산만 하고 **결과를 어디에도 저장하지 않아요.** → `s->mask |= a;` (`=`가 붙어야 저장돼요)

**🧒 쉽게 설명하면**
- `|=` 는 "이 스위치 **켜!**" (다른 스위치는 그대로)
- `&= ~MILK` 는 "`~`로 우유만 꺼진 마스크(11111101)를 만들어서, `&`로 **우유 스위치만 끄기**" (다른 스위치는 그대로)
- 그냥 `p->mask = MILK;`라고 쓰면 원래 있던 다른 알레르기가 **전부 지워져요.** 그래서 꼭 `|=`, `&= ~`을 써요.
- 지아의 진짜 주소(`&students[3]`)를 줬으니 함수가 **진짜 지아의 카드**를 고쳐요. 복사본을 주면 복사한 종이에만 적고 버리는 거예요.

### 구조체 퀴즈1 정답
① 위 흐름제어 퀴즈1의 `DayReport` 참고.
② `s->parent.phone` — `s`는 주소라서 `->`, `parent`는 주소가 아니라 **안에 통째로 들어 있는** 구조체라서 `.`
③ `DayReport`는 작은 상자(숫자 몇 개 + 주소 4개)라서 통째로 복사해서 돌려줘도 금방이에요. 그리고 함수 안 지역 변수의 **주소**를 돌려주면 함수가 끝날 때 사라져서 위험하지만(유령 포인터), **값**을 돌려주면 받는 쪽에 안전하게 복사돼요.

**🧒 쉽게 설명하면** 학생증(`Student`) 뒷면에 **보호자 카드**(`Guardian`)가 붙어 있는 거예요. 학생증을 찾아가서(`->`) 뒷면의 보호자 카드(`.parent`)에서 전화번호(`.phone`)를 읽어요. `bad[]`에 반찬 **이름을 복사하지 않고 주소만** 담은 것도 문제 1의 `Feed`와 같은 아이디어예요.

① 문자: **하준 엄마 3건**(월·수·목), **도현 엄마 4건**(월·화·수·목). 서윤·시우는 심한 알레르기가 아니라서 `WARN`만 있고 문자는 안 가요.
② 영양사 상담: **시우** (대두·밀이 들어간 반찬이 많아서 하루 평균 382kcal)
③ `break`로 바꾸면 금요일은 `쌀밥(1) → 99(오타)`에서 멈춰서 **불고기(6)를 아예 검사하지 않아요.** 그러면 시우의 금요일이 `W`가 아니라 `O`(괜찮음)로 나오고, 열량은 쌀밥 300뿐이라 `🍙 열량 부족`이 돼요. 무엇보다 **위험한 반찬을 못 보고 지나치는 것**이 가장 큰 문제예요!

**🧒 쉽게 설명하면**
- **오타(`continue`)**: "이 칸은 글씨를 못 알아보겠네. 이 칸만 넘기고 다음 칸 볼게."
- **빈칸(`break`)**: "여기부터는 아무것도 없어. 오늘 메뉴 끝!"
- **재료 모름 + 심한 알레르기(`break` + 보류)**: "위험할 수도 있어! 더 보지 말고 어른한테 물어보자!"
세 경우 모두 "멈춘다"처럼 보이지만, **무엇을 멈추는지**(이 칸만? 오늘 전부?)가 달라요. 이걸 헷갈리면 알레르기 반찬을 놓치는 진짜 사고가 나요. 그래서 현업 엔지니어들은 `break`와 `continue`를 쓸 때마다 "이걸로 **어디까지** 멈추지?"를 꼭 확인해요.
