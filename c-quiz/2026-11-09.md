## 엔지니어가 직면한 가상의 문제 1

**[Cloudflare 보안팀]** 웹사이트에 접속자 5명(IP)이 1분 동안 보낸 요청 수가 있어요. 각 접속자는 번호(`id`), 요청 수(`count`), 실패 횟수(`fails`), 믿을 수 있는 접속자 여부(`trusted`, 1이면 신뢰)를 가져요. 규칙: 신뢰하는 접속자는 요청이 아무리 많아도 "허용"이에요. 그 밖에는 요청이 1000 **이상**이면 "차단", 300 이상 1000 미만이면 "주의", 그보다 작으면 "정상"이에요.

```c
int counts[5] = {50, 320, 1500, 80, 1000};
// 접속자 5명: {id, count, fails, trusted}
// {1,50,0,0} {2,320,4,0} {3,1500,9,1} {4,80,0,0} {5,1000,7,0}
```

- **조건문 퀴즈 1:** 접속자 하나의 `trusted`, `count`를 보고 "허용", "차단", "주의", "정상" 중 하나를 출력하는 코드를 작성하세요. (신뢰 검사를 먼저!)
- **반복문 퀴즈 1:** 구조체 배열 `users[5]`를 처음부터 끝까지 돌면서 `"1번 접속자: 요청 50"` 모양으로 출력하는 코드를 작성하세요. (번호는 1부터)
- **흐름제어 퀴즈 1:** 위 반복문에서 신뢰하는 접속자(`trusted == 1`)는 건너뛰고, 요청이 1000 이상인 접속자를 처음 발견하면 "차단 대상: (id)"를 출력하고 반복을 멈추는 코드를 작성하세요.
- **배열 퀴즈 1:** `counts` 배열에서 300 **이상**인 값이 몇 개인지 세어 `cnt`에 저장하고 출력하세요.
- **포인터 변수 퀴즈 1:** 포인터 `p`가 `counts` 배열의 처음부터 끝까지 한 칸씩 이동하며(`p++`), 가리키는 값이 1000보다 **큰 칸만** 1000으로 줄이는 코드를 작성하세요. (`counts[i]`가 아니라 `*p`를 사용)
- **구조체 퀴즈 1:** 번호(`id`), 요청 수(`count`), 실패 횟수(`fails`), 신뢰 여부(`trusted`)를 가진 구조체 `struct User`를 정의하세요.
- **함수 퀴즈 1:** 접속자 배열의 시작 주소 `u`와 개수 `n`을 받아서, 신뢰하지 않고 요청이 1000 이상인 접속자의 수를 반환하는 함수 `count_block`을 작성하세요.
- **흐름제어 퀴즈 2 (종합):** `main`에서 접속자 5명짜리 구조체 배열과 `count_block`을 사용해, 개수가 0이면 "차단 대상 없음", 아니면 "차단 대상: N명"을 출력하는 코드를 작성하세요.

int cps[5]   = {1500, 400, 900, 300, 1200};
int dists[5] = {20, 45, 30, 10, 40};

- **구조체 퀴즈 1:** 이름(`char name[20]`), 전투력(`int cp`), 거리(`int dist`), 도망 여부(`int fled`)를 가진 구조체 `struct Pokemon`을 정의하고, 변수 `one`을 `"Mew"`, `800`, `25`, `0`으로 만들어 이름과 "포획 가능" 또는 "포획 불가"를 출력하는 코드를 작성하세요.

# 정답 및 해설 (초등학교 5학년 눈높이)

## 문제 1: Cloudflare 접속 폭주 방어

### 조건문 정답
```c
if (trusted == 1) {
    printf("허용\n");
} else if (count >= 1000) {
    printf("차단\n");
} else if (count >= 300) {
    printf("주의\n");
} else {
    printf("정상\n");
}
```
**왜 이렇게?** 학교 정문에서 "저는 이 학교 선생님이에요!" 하는 사람은 몇 번을 드나들어도 막지 않죠? 신뢰하는 접속자가 바로 그래서 **맨 먼저** 물어봐요. 그다음엔 **큰 기준부터** 물어봐요. 300 이상을 먼저 물으면 1500도 "주의"에서 걸려 버려요. 딱 1000도 차단이라서 `>=`예요.

### 반복문 정답
```c
for (int i = 0; i < 5; i++) {
    printf("%d번 접속자: 요청 %d\n", i + 1, users[i].count);
}
```
**왜 이렇게?** 접속자가 5명으로 정해져 있으니 `for`가 딱이에요. 컴퓨터는 0부터 세지만 사람은 1번부터 부르니까 보여줄 때만 `i + 1`을 써요. `i < 5`라야 0~4, 딱 5칸만 열어요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 5; i++) {
    if (users[i].trusted == 1) {
        continue;
    }
    if (users[i].count >= 1000) {
        printf("차단 대상: %d\n", users[i].id);
        break;
    }
}
```
**왜 이렇게?** `continue`는 "이분은 믿는 사람이니 패스, 다음!", `break`는 "찾았다! 이제 그만 찾아도 돼!"예요. 3번(1500)은 많이 보냈지만 신뢰해서 건너뛰고, 5번(1000)이 처음으로 걸려요. 출력은 `차단 대상: 5`예요.

### 배열 정답
```c
int cnt = 0;
for (int i = 0; i < 5; i++) {
    if (counts[i] >= 300) {
        cnt++;
    }
}
printf("%d\n", cnt);   // 3
```
**왜 이렇게?** 조건에 맞는 칸을 만날 때마다 막대기를 하나씩 긋는(`cnt++`) 거예요. 320, 1500, 1000 세 칸이 300 이상이라 답은 3이에요. 이 문제는 신뢰 여부를 묻지 않았으니 1500도 센다는 게 포인트예요!

### 포인터 정답
```c
int *p = counts;
for (int i = 0; i < 5; i++) {
    if (*p > 1000) {
        *p = 1000;
    }
    p++;
}
// counts는 {50, 320, 1000, 80, 1000}이 돼요
```
**왜 이렇게?** 배열 이름 `counts`는 "첫 칸의 주소"예요. `p`는 손가락, `*p`는 손가락이 가리키는 칸 안의 값이에요. 1000보다 큰 칸(1500)만 1000으로 줄이고, 손가락은 `p++`로 한 칸씩 옮겨요. `p++`는 `if` 바깥에 둬야 해요. 안에 두면 작은 값 칸에서 손가락이 못 움직여서 같은 칸만 계속 보게 돼요. 그리고 딱 1000인 칸은 "큰" 게 아니니 그대로예요.

### 구조체 정답
```c
struct User {
    int id;
    int count;
    int fails;
    int trusted;
};
```
**왜 이렇게?** 접속자 한 명에게는 번호, 요청 수, 실패 횟수, 신뢰 여부가 항상 같이 다녀요. 배열 4개로 따로 두면 짝이 어긋나기 쉬우니 하나의 "접속자 카드"로 묶어요.

### 함수 정답
```c
int count_block(struct User *u, int n) {
    int cnt = 0;
    for (int i = 0; i < n; i++) {
        if (u[i].trusted == 1) {
            continue;
        }
        if (u[i].count >= 1000) {
            cnt++;
        }
    }
    return cnt;
}
```
**왜 이렇게?** 함수는 "일을 대신해 주는 심부름꾼"이에요. 카드 묶음의 시작 주소 `u`와 몇 장인지 `n`을 받아서 세어 온 숫자를 `return`으로 돌려줘요. 5번만 해당되므로 반환값은 1이에요. `n`을 받는 이유는 함수가 배열이 몇 칸인지 스스로 알 수 없기 때문이에요.

### 흐름제어 정답 (2, 종합)
```c
int main(void) {
    struct User users[5] = {
        {1, 50, 0, 0}, {2, 320, 4, 0}, {3, 1500, 9, 1},
        {4, 80, 0, 0}, {5, 1000, 7, 0}
    };
    int blocked = count_block(users, 5);
    if (blocked == 0) {
        printf("차단 대상 없음\n");
    } else {
        printf("차단 대상: %d명\n", blocked);
    }
    return 0;
}
```
**왜 이렇게?** 심부름꾼이 가져온 숫자를 변수에 담아 두고 `if`로 갈림길을 만들어요. 결과는 `차단 대상: 1명`이에요.

## 문제 2: Niantic 포켓몬 포획 도우미

### 조건문 정답
```c
if (cp <= 1000 && dist <= 50) {
    printf("포획 가능\n");
} else {
    printf("포획 불가\n");
}
```
**왜 이렇게?** "힘도 약해야 **하고**(and) 가까이도 있어야" 잡을 수 있어요. 둘 다 맞아야 하니 `&&`를 써요. 하나라도 틀리면 `else`로 가요. "이하"는 같은 값도 포함이라 `<=`예요.

### 반복문 정답
```c
for (int i = 0; i < 5; i++) {
    printf("%d번 포켓몬: %s (CP %d)\n", i + 1, mons[i].name, mons[i].cp);
}
```
**왜 이렇게?** 5마리를 차례로 보는 일이라 `for`예요. 이름은 글자 묶음이라 `%s`, 숫자는 `%d`를 써요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 5; i++) {
    if (mons[i].fled == 1) {
        continue;
    }
    if (mons[i].cp <= 1000 && mons[i].dist <= 50) {
        printf("첫 포획: %s\n", mons[i].name);
        break;
    }
}
```
**왜 이렇게?** 도망간 포켓몬은 이미 없으니 `continue`로 패스해요. Dragonite는 CP가 1500이라 탈락, Pikachu(400, 45m)가 처음 통과해서 `첫 포획: Pikachu`를 출력하고 `break`로 끝내요.

### 배열 정답
```c
int ok = 0;
for (int i = 0; i < 5; i++) {
    if (fled[i] == 0 && cps[i] <= 1000 && dists[i] <= 50) {
        ok++;
    }
}
printf("%d\n", ok);   // 2
```
**왜 이렇게?** 세 배열의 같은 번호 칸은 같은 포켓몬 이야기예요. Pikachu(1번 인덱스)와 Eevee(3번 인덱스)가 통과해서 2예요. Gengar는 조건은 맞지만 도망갔기 때문에 빠져요.

### 포인터 정답
```c
int *p = dists;
for (int i = 0; i < 5; i++) {
    if (*p < 15) {
        *p = 15;
    }
    p++;
}
// dists는 {20, 45, 30, 15, 40}이 돼요
```
**왜 이렇게?** 손가락 `p`가 가리키는 값이 15보다 작을 때만 15로 바꿔요. 10이던 Eevee 거리만 15가 돼요. 손가락 이동 `p++`는 매번 해야 하니 `if` 밖에 둬요.

### 구조체 정답
```c
struct Pokemon {
    char name[20];
    int cp;
    int dist;
    int fled;
};

struct Pokemon one = {"Mew", 800, 25, 0};
if (one.cp <= 1000 && one.dist <= 50) {
    printf("%s: 포획 가능\n", one.name);
} else {
    printf("%s: 포획 불가\n", one.name);
}
```
**왜 이렇게?** 포켓몬 한 마리의 정보를 한 카드로 묶었어요. 카드 안의 칸은 `.`(점)으로 꺼내요. `one.cp`는 "one 카드의 cp 칸"이에요. Mew는 800, 25m라서 `Mew: 포획 가능`이에요.

### 함수 정답
```c
int find_easiest(struct Pokemon *m, int n) {
    int best = -1;
    for (int i = 0; i < n; i++) {
        if (m[i].fled == 1) {
            continue;
        }
        if (m[i].cp <= 1000 && m[i].dist <= 50) {
            if (best == -1 || m[i].cp < m[best].cp) {
                best = i;
            }
        }
    }
    return best;
}
```
**왜 이렇게?** `best`는 "지금까지 1등 후보의 번호표"예요. 처음엔 후보가 없어서 `-1`이에요. 후보가 처음 나타나면 무조건 1등이 되고(`best == -1`), 그다음부터는 CP가 더 낮을 때만 자리를 바꿔요. `best == -1`을 **먼저** 검사해야 `m[-1]`이라는 없는 칸을 읽는 사고를 막아요(`||`는 앞이 참이면 뒤를 보지 않아요). Pikachu(400)와 Eevee(300) 중 Eevee가 더 약해서 반환값은 `3`이에요.

### 흐름제어 정답 (2, 종합)
```c
int idx = find_easiest(mons, 5);
if (idx == -1) {
    printf("잡을 수 있는 포켓몬 없음\n");
} else {
    printf("추천: %s (CP %d)\n", mons[idx].name, mons[idx].cp);
}
```
**왜 이렇게?** 출력은 `추천: Eevee (CP 300)`이에요. 반환값이 `-1`이면 아무도 없다는 신호라서 `mons[idx]`를 쓰기 **전에** 꼭 먼저 확인해야 해요.
