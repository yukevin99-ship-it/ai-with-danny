## 엔지니어가 직면한 가상의 문제 1

**[SpaceX 스타링크 팀]** 하늘에 떠 있는 위성 5개의 상태를 점검해요. 각 위성은 번호(`id`), 신호 세기(`signal`, 0~100), 작동 여부(`active`, 1이면 작동 중, 0이면 꺼짐)를 가지고 있어요. 작동 중인데 신호가 50 미만인 위성은 "위험 위성"이에요. 위험 위성이 3개 이상이면 지상 관제센터에 "긴급!" 알림을 보내야 해요.

```c
int signals[5] = {90, 45, 70, 0, 30};   // 신호 세기만 모은 배열
```

- **조건문 퀴즈 1:** 신호 세기 `signal`이 80 이상이면 "양호", 50 이상이면 "주의", 그 외에는 "위험"을 출력하는 코드를 작성하세요.
- **반복문 퀴즈 1:** 위성 5개가 들어 있는 구조체 배열 `sats[5]`를 처음부터 끝까지 돌면서 각 위성의 번호를 `"3번 위성"` 같은 모양으로 출력하는 코드를 작성하세요.
- **흐름제어 퀴즈 1:** 위 반복문에서 꺼진 위성(`active == 0`)은 건너뛰고, 신호가 50 미만인 위성을 처음 발견하면 "위험 위성: (번호)"를 출력하고 반복을 멈추는 코드를 작성하세요.
- **배열 퀴즈 1:** `signals` 배열에서 가장 큰 신호 세기를 찾아 `max`에 저장하고 출력하는 코드를 작성하세요.
- **포인터 변수 퀴즈 1:** 포인터 `p`가 `signals` 배열의 처음부터 끝까지 한 칸씩 이동하면서(`p++`), 가리키는 값에 5를 더해 신호를 보정하는 코드를 작성하세요. (`signals[i]`처럼 번호로 접근하지 말고 `*p`를 사용하세요.)
- **구조체 퀴즈 1:** 번호(`id`), 신호 세기(`signal`), 작동 여부(`active`)를 가진 구조체 `struct Satellite`를 정의하세요.
- **함수 퀴즈 1:** 위성 배열의 시작 주소 `s`와 개수 `n`을 받아서, "작동 중이면서 신호가 50 미만인" 위성의 개수를 반환하는 함수 `count_danger`를 작성하세요.
- **흐름제어 퀴즈 2 (종합):** `main`에서 위성 5개짜리 구조체 배열과 `count_danger` 함수를 사용해, 위험 위성이 3개 이상이면 "긴급!"을, 아니면 "정상 (개수)"를 출력하는 코드를 작성하세요.

# 정답 및 해설 (초등학교 5학년 눈높이)

## 문제 1: SpaceX 스타링크 위성 신호 점검

### 조건문 정답
```c
if (signal >= 80) {
    printf("양호\n");
} else if (signal >= 50) {
    printf("주의\n");
} else {
    printf("위험\n");
}
```
**왜 이렇게?** 학교 성적표를 떠올려 보세요. 먼저 "80점 이상이야?" 맞으면 거기서 끝! 아니면 "그럼 50점 이상이야?" 하고 차례대로 물어요. `else if`는 "앞 질문이 아니었을 때만" 다음 질문을 하는 장치예요. 큰 기준부터 물어야 90점이 "주의"로 잘못 분류되지 않아요.

### 반복문 정답
```c
for (int i = 0; i < 5; i++) {
    printf("%d번 위성\n", sats[i].id);
}
```
**왜 이렇게?** 출석을 부르는 선생님과 같아요. 위성이 5개로 정해져 있으니 횟수가 정해진 `for`가 딱이에요. 컴퓨터는 0번 칸부터 세니까 `i`는 0, 1, 2, 3, 4가 되어야 하고, 그래서 `i < 5`예요(`i <= 5`면 없는 6번째 칸을 열어 버려서 사고가 나요!). `sats[i].id`는 "i번 칸에 있는 위성 카드에서 id 적힌 부분을 읽어라"라는 뜻이에요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 5; i++) {
    if (sats[i].active == 0) {
        continue;
    }
    if (sats[i].signal < 50) {
        printf("위험 위성: %d\n", sats[i].id);
        break;
    }
}
```
**왜 이렇게?**
- `continue`는 "이 위성은 꺼져 있으니 패스! 다음 친구 보자"예요. 꺼진 위성의 신호가 0이라고 해서 "위험"이라고 놀라면 안 되거든요.
- `break`는 "처음 하나를 찾았으니 그만 찾을래!"예요. 숨바꼭질에서 한 명 찾으면 끝나는 규칙이라면 더 찾을 필요가 없죠.
- 순서가 중요해요. 꺼진 위성을 먼저 걸러 내고(continue), 그다음에 신호를 검사해야 해요.
- 예시 값 `{1번:90, 2번:45, ...}`에서는 1번은 양호하니 지나가고, 2번(신호 45)에서 "위험 위성: 2"를 출력하고 멈춰요.

### 배열 정답
```c
int max = signals[0];
for (int i = 1; i < 5; i++) {
    if (signals[i] > max) {
        max = signals[i];
    }
}
printf("가장 큰 신호: %d\n", max);
```
**왜 이렇게?** 반 친구들 중 키가 제일 큰 친구를 찾는 방법이에요. 먼저 첫 번째 친구를 "지금까지의 1등"이라고 해요. 그다음 친구들이 한 명씩 나와서 "나 더 커!" 하면 1등을 바꿔요. 처음에 `max`를 0으로 두면 점수가 모두 음수일 때 틀릴 수 있어서, 실제 값 하나(`signals[0]`)로 시작하는 게 안전해요. 첫 칸은 이미 1등으로 뽑았으니 `i`는 1부터 시작해요. 정답은 90이에요.

### 포인터 변수 정답
```c
int *p;
for (p = signals; p < signals + 5; p++) {
    *p += 5;
}
```
**왜 이렇게?**
- 배열 이름 `signals`는 "첫 번째 칸의 주소"예요. 주소는 집 주소처럼 "그 칸이 어디 있는지"를 알려 주는 숫자예요.
- `int *p`는 "주소를 적어 두는 쪽지"예요. `p = signals;`는 쪽지에 첫 칸의 주소를 적는 거예요.
- `p++`는 쪽지의 주소를 **다음 칸**으로 옮겨요. (int 한 칸만큼 정확히 옮겨 줘요.)
- `*p`는 "쪽지에 적힌 집에 가서 안에 있는 값"이에요. 그래서 `*p += 5`는 그 집 안의 값에 5를 더해요.
- `signals + 5`는 "배열 바로 다음 칸 주소"예요. 거기에 닿기 직전까지만 움직이므로 `p < signals + 5`예요. 이 칸의 값은 절대 읽거나 쓰면 안 돼요!

### 구조체 정답
```c
struct Satellite {
    int id;
    int signal;
    int active;
};
```
**왜 이렇게?** 위성마다 번호, 신호, 작동 여부가 따로따로 흩어져 있으면 정리하기 힘들어요. 구조체는 이것들을 한 장의 **학생증 카드**에 모아 놓는 거예요. 카드 한 장이 위성 한 대이고, 그 카드를 5장 모아 놓은 것이 `sats[5]`예요. 카드에 칸(멤버)을 `id`, `signal`, `active`로 만들고, 마지막의 `;`(세미콜론)을 잊지 마세요!

### 함수 정답
```c
int count_danger(struct Satellite *s, int n) {
    int count = 0;
    for (int i = 0; i < n; i++) {
        if (s[i].active == 1 && s[i].signal < 50) {
            count++;
        }
    }
    return count;
}
```
**왜 이렇게?**
- 함수는 **심부름꾼**이에요. "위성들 줄게, 위험한 게 몇 개인지 세서 알려줘!" 하면 세어서 숫자 하나를 `return`으로 돌려줘요.
- 배열을 함수에 넘기면 통째로 복사하지 않고 **첫 칸의 주소**만 넘어가요. 그래서 `struct Satellite *s`로 받아요. 개수 `n`은 함수가 배열 길이를 알 수 없으니 따로 알려줘야 해요.
- `&&`는 "그리고"예요. "작동 중이고 **그리고** 신호가 약할 때"만 위험이에요. 둘 중 하나만 맞으면 세면 안 돼요.
- 세기 시작 전에 `count`를 0으로 두는 것을 잊지 마세요. 안 그러면 쓰레기 값에서 출발해요.

### 흐름제어 정답 (2, 종합)
```c
#include <stdio.h>

struct Satellite {
    int id;
    int signal;
    int active;
};

int count_danger(struct Satellite *s, int n) {
    int count = 0;
    for (int i = 0; i < n; i++) {
        if (s[i].active == 1 && s[i].signal < 50) {
            count++;
        }
    }
    return count;
}

int main(void) {
    struct Satellite sats[5] = {
        {1, 90, 1}, {2, 45, 1}, {3, 70, 0}, {4, 30, 1}, {5, 20, 1}
    };

    int danger = count_danger(sats, 5);
    if (danger >= 3) {
        printf("긴급!\n");
    } else {
        printf("정상 (%d)\n", danger);
    }
    return 0;
}
```
**왜 이렇게?** 지금까지 배운 도구들이 한 팀이 되는 장면이에요.
- 구조체 = 위성 카드, 배열 = 카드 묶음, 함수 = 세어 주는 심부름꾼, 포인터 = 카드 묶음의 시작 주소, 반복문 = 하나씩 확인, 조건문 = 마지막 판단.
- 위성 목록으로 따라가 보면: 1번(신호 90) 양호, 2번(45, 작동) 위험, 3번(70, 꺼짐) 아님, 4번(30, 작동) 위험, 5번(20, 작동) 위험이라서 위험 위성이 3개 → "긴급!"이 출력돼요.
- 세는 일(함수)과 판단하는 일(`main`의 `if`)을 나눠 놓으면, 나중에 "위험 기준이 50에서 60으로 바뀌었어요!" 할 때 함수 한 곳만 고치면 돼요. 현업에서는 이렇게 역할을 나누는 게 아주 중요해요.

## 프로그램 1: Disney+ 영화 평점 추천기

### 조건문 정답
```c
if (score >= 9) {
    printf("명작\n");
} else if (score >= 7) {
    printf("추천\n");
} else {
    printf("보통\n");
}
```
**왜 이렇게?** 별점 가게 간판이에요. 높은 기준부터 차례로 물어요. 9점 이상이면 바로 "명작"으로 끝나고, 아니면 7점 이상인지 물어요. 7과 9의 순서를 거꾸로 하면 10점짜리도 "추천"이 돼 버려요.

### 반복문 정답
```c
for (int i = 0; i < 4; i++) {
    printf("%d번 후보: %s\n", i + 1, movies[i].title);
}
```
**왜 이렇게?** 컴퓨터는 0번부터 세지만 사람은 "1번 후보"부터 읽어요. 그래서 칸 번호 `i`는 0부터 돌리고, 화면에는 `i + 1`을 보여 줘요. 영화는 4편이니 `i < 4`예요. `%s`는 글자(문자열)를 찍는 자리 표시예요.

### 흐름제어 정답 (1)
```c
for (int i = 0; i < 4; i++) {
    if (movies[i].score == 0) {
        continue;
    }
    if (movies[i].score == 10) {
        printf("만점 영화!\n");
        break;
    }
}
```
**왜 이렇게?**
- `continue`: 아무도 평가하지 않은 영화(0점)는 후보가 아니니 "패스!"예요.
- `break`: 10점은 최고점이라 더 좋은 영화가 있을 수 없어요. 1등이 확정됐으니 그만 찾아요.
- 예시 값 `{A:8, B:0, C:10, D:6}`에서는 A는 확인, B는 패스, C(10점)에서 "만점 영화!"를 출력하고 D는 보지도 않아요.

### 배열 정답
```c
int sum = 0;
for (int i = 0; i < 5; i++) {
    sum += scores[i];
}
double avg = sum / 5.0;
printf("평균: %.1f\n", avg);
```
**왜 이렇게?** 먼저 모든 점수를 저금통에 넣어 합계를 구해요(합계 33). 그다음 나누는데, `sum / 5`처럼 정수끼리 나누면 컴퓨터가 소수점 아래를 버려 6이 돼요. 반면 `5.0`처럼 소수점이 있는 수로 나누면 6.6으로 정확해요. 피자 33조각을 5명이 나눠 먹을 때 "한 명당 6조각, 3조각은 버려"라고 하면 억울하잖아요. `%.1f`는 소수 첫째 자리까지 보여 달라는 뜻이에요.

### 포인터 변수 정답
```c
int *best = &scores[0];
for (int i = 1; i < 5; i++) {
    if (scores[i] > *best) {
        best = &scores[i];
    }
}
printf("가장 높은 점수: %d\n", *best);
```
**왜 이렇게?**
- `&scores[0]`의 `&`는 "주소를 알려 줘!"예요. `best`는 지금 1등 후보 집의 주소를 적어 둔 쪽지예요.
- `*best`는 쪽지에 적힌 집에 가서 값을 보는 거예요. 새 점수와 비교할 때는 `best`(주소)가 아니라 `*best`(값)와 비교해야 해요. 주소와 값은 완전히 다른 것이에요!
- 더 높은 점수를 만나면 값을 복사하는 게 아니라 쪽지에 **새 집 주소**를 적어요(`best = &scores[i];`).
- 정답은 10이에요.

### 구조체 정답
```c
struct Movie {
    char title[20];
    int score;
};

struct Movie one = {"Frozen", 9};
printf("%s %d\n", one.title, one.score);
```
**왜 이렇게?** 영화 카드 한 장에 제목 칸과 점수 칸이 있어요. 제목은 글자 여러 개라서 글자 칸 20개짜리 `char title[20]`로 만들어요. 카드를 만들 때 `{"Frozen", 9}`처럼 칸 순서대로 값을 채워 넣고, 읽을 때는 점(`.`)을 찍어서 `one.title`, `one.score`로 꺼내요. 점은 "카드의 어느 칸이냐"를 가리키는 표시예요.

### 함수 정답
```c
struct Movie *find_best(struct Movie *m, int n) {
    struct Movie *best = NULL;
    for (int i = 0; i < n; i++) {
        if (m[i].score == 0) {
            continue;
        }
        if (best == NULL || m[i].score > best->score) {
            best = &m[i];
        }
    }
    return best;
}
```
**왜 이렇게?**
- 처음에 `best`를 `NULL`(아무도 가리키지 않음)로 시작해요. 만약 모든 영화가 평가 전(0점)이면 끝까지 `NULL`이고, 그걸 돌려줘서 "1등이 없어요!"라고 알릴 수 있어요.
- `continue`로 0점 영화는 건너뛰어요.
- `best == NULL || ...`: 아직 1등 후보가 없으면 처음 만난 평가된 영화가 무조건 1등 후보예요. `||`는 "또는"이에요. 앞이 참이면 뒤는 검사하지 않기 때문에, `best`가 `NULL`일 때 `best->score`를 읽다가 사고 나는 일이 없어요. 순서가 바뀌면 프로그램이 터질 수 있어요!
- `best->score`는 "쪽지 `best`가 가리키는 카드의 score 칸"이에요. 주소를 쥐고 있을 때는 점 대신 화살표 `->`를 써요.
- 영화 전체를 복사해서 돌려주지 않고 **주소**만 돌려줘서 빠르고 가벼워요.

### 흐름제어 정답 (2, 종합)
```c
#include <stdio.h>

struct Movie {
    char title[20];
    int score;
};

struct Movie *find_best(struct Movie *m, int n) {
    struct Movie *best = NULL;
    for (int i = 0; i < n; i++) {
        if (m[i].score == 0) {
            continue;
        }
        if (best == NULL || m[i].score > best->score) {
            best = &m[i];
        }
    }
    return best;
}

int main(void) {
    struct Movie movies[4] = {
        {"A", 8}, {"B", 0}, {"C", 10}, {"D", 6}
    };

    struct Movie *b = find_best(movies, 4);
    if (b == NULL) {
        printf("평가 없음\n");
    } else {
        printf("추천: %s\n", b->title);
    }
    return 0;
}
```
**왜 이렇게?**
- 함수가 "1등 영화의 주소"를 알려 주면 `main`은 그 주소가 `NULL`인지부터 확인해요. 주소가 `NULL`인데 `b->title`을 읽으면 프로그램이 꺼져 버려요. 그래서 **먼저 `NULL`인지 확인**하고 그다음에 사용해요. 현업에서 가장 흔한 버그 예방 습관 중 하나예요.
- 예시 값으로 따라가면 A(8) → 1등 후보, B(0) → 패스, C(10) → 더 높으니 1등 후보 교체, D(6) → 더 낮아서 그대로. 결과는 "추천: C"예요.
- 반복문(후보 하나씩 보기), 조건문(더 높은지 비교), `continue`(평가 없는 영화 패스), 배열(영화 카드 묶음), 구조체(영화 카드), 포인터(1등 카드의 주소), 함수(1등 찾기 심부름)가 모두 한 팀으로 움직였어요!

## 오늘의 핵심 한 줄
- 배열은 같은 종류를 줄 세운 칸, 구조체는 서로 다른 정보를 한 카드에 모은 것, 포인터는 그 칸·카드의 주소 쪽지, 함수는 일을 나눠 주는 심부름꾼이에요. 그리고 주소를 쓰기 전에는 `NULL`부터 확인하는 습관을 가져요!
